1a:T1ee9,<p><strong>Worktree</strong> lets you have multiple directories (each on a different branch) for the same repo. <strong>Cursor CLI</strong> works on whichever directory it's run in. Combine them and you get multiple terminals running CLI Agents in parallel on different branches — no need for multiple Cursor windows, pure keyboard-driven multi-tasking.</p>
<h2 id="why-combine-them">Why Combine Them?</h2>
<table>
<thead>
<tr>
<th>Approach</th>
<th>How</th>
<th>Best For</th>
</tr>
</thead>
<tbody>
<tr>
<td>Worktree + multiple Cursor <strong>windows</strong></td>
<td>Open one worktree per window</td>
<td>IDE users who want the file tree and preview</td>
</tr>
<tr>
<td>Worktree + <strong>CLI</strong></td>
<td>Multiple terminals, each <code>cd</code> into a worktree, run <code>cursor agent</code></td>
<td>Keyboard-first users or server/SSH environments</td>
</tr>
</tbody>
</table>
<p>Common ground: each worktree is an independent directory → each has its own context → parallel development without stepping on each other's toes. Like having multiple clones working on different branches simultaneously.</p>
<h2 id="basic-usage-one-terminal-per-worktree">Basic Usage: One Terminal Per Worktree</h2>
<p>Assuming you've already created your worktrees:</p>
<pre><code>~/projects/
├── my-app/                  ← main
├── my-app--feature-auth/    ← feature/auth
└── my-app--feature-payment/  ← feature/payment
</code></pre>
<p><strong>Terminal 1</strong> (working on auth):</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#79C0FF">cd</span><span style="color:#A5D6FF"> ~/projects/my-app--feature-auth</span></span>
<span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#A5D6FF"> "Implement JWT login"</span></span></code></pre></figure>
<p><strong>Terminal 2</strong> (working on payment):</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#79C0FF">cd</span><span style="color:#A5D6FF"> ~/projects/my-app--feature-payment</span></span>
<span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#A5D6FF"> "Add Stripe checkout flow"</span></span></code></pre></figure>
<p>The CLI defaults to the <strong>current working directory</strong> as its context, so both terminals only modify their respective worktrees. This is "two CLI Agents running in parallel" — no need to open two Cursor windows, saves resources and avoids context switching.</p>
<h2 id="without-changing-directories-use---path-to-target-a-worktree">Without Changing Directories: Use <code>--path</code> to Target a Worktree</h2>
<p>Sitting in the main project directory but want the CLI to work on a specific worktree:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#79C0FF">cd</span><span style="color:#A5D6FF"> ~/projects/my-app</span></span>
<span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#A5D6FF"> "Add unit tests for feature/auth"</span><span style="color:#79C0FF"> --path</span><span style="color:#A5D6FF"> ../my-app--feature-auth</span></span></code></pre></figure>
<p><code>--path</code> tells it which directory to look at — the worktree path. Good for handling one worktree at a time, or when the path is fixed in a script.</p>
<h2 id="non-interactive--worktree-scripts--batch-operations">Non-Interactive + Worktree (Scripts / Batch Operations)</h2>
<p>Run the same type of task on multiple worktrees in sequence (e.g., add a README to all, fix lint in all):</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E"># Example: run "fix lint" on both worktrees</span></span>
<span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#A5D6FF"> "Fix all auto-fixable errors per .eslintrc"</span><span style="color:#79C0FF"> --path</span><span style="color:#A5D6FF"> ../my-app--feature-auth</span><span style="color:#79C0FF"> --no-interactive</span></span>
<span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#A5D6FF"> "Fix all auto-fixable errors per .eslintrc"</span><span style="color:#79C0FF"> --path</span><span style="color:#A5D6FF"> ../my-app--feature-payment</span><span style="color:#79C0FF"> --no-interactive</span></span></code></pre></figure>
<p>Or write a loop (adjust paths to match your setup):</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FF7B72">for</span><span style="color:#E6EDF3"> dir </span><span style="color:#FF7B72">in</span><span style="color:#A5D6FF"> ../my-app--feature-auth</span><span style="color:#A5D6FF"> ../my-app--feature-payment</span><span style="color:#E6EDF3">; </span><span style="color:#FF7B72">do</span></span>
<span data-line=""><span style="color:#FFA657">  cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#A5D6FF"> "Fix linter errors"</span><span style="color:#79C0FF"> --path</span><span style="color:#A5D6FF"> "</span><span style="color:#E6EDF3">$dir</span><span style="color:#A5D6FF">"</span><span style="color:#79C0FF"> --no-interactive</span></span>
<span data-line=""><span style="color:#FF7B72">done</span></span></code></pre></figure>
<p>Give one instruction, clean up multiple branches at once — great for a final sweep before raising PRs.</p>
<h2 id="relationship-to-worktree--multiple-windows">Relationship to "Worktree + Multiple Windows"</h2>
<ul>
<li><strong>Multiple windows</strong>: each Cursor window opens a worktree, using the IDE's Agent, Chat, Tab completion.</li>
<li><strong>CLI + Worktree</strong>: terminal + <code>cursor agent</code> — same idea of "one directory, one context," just open more terminals to parallelize.</li>
</ul>
<p>You can also mix and match: main development in the window, while using the CLI on a server to make small fixes to another branch.</p>
<h2 id="summary">Summary</h2>
<ul>
<li><strong>Worktree</strong> = multiple directories, multiple branches; <strong>CLI</strong> = acts on the current directory or <code>--path</code> → a natural pair.</li>
<li><strong>Parallel</strong>: open multiple terminals, each <code>cd</code> into a different worktree, then run <code>cursor agent</code>.</li>
<li><strong>Single terminal</strong>: use <code>--path &#x3C;worktree-path></code> to target the worktree you want.</li>
<li><strong>Scripts/batch</strong>: <code>--path</code> + <code>--no-interactive</code> to run the same task across multiple worktrees.</li>
</ul>

<p><code>--path</code> tells it which directory to look at — the worktree path. Good for handling one worktree at a time, or when the path is fixed in a script.</p>
<h2 id="non-interactive--worktree-scripts--batch-operations">Non-Interactive + Worktree (Scripts / Batch Operations)</h2>
<p>Run the same type of task on multiple worktrees in sequence (e.g., add a README to all, fix lint in all):</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E"># Example: run "fix lint" on both worktrees</span></span>
<span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#A5D6FF"> "Fix all auto-fixable errors per .eslintrc"</span><span style="color:#79C0FF"> --path</span><span style="color:#A5D6FF"> ../my-app--feature-auth</span><span style="color:#79C0FF"> --no-interactive</span></span>
<span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#A5D6FF"> "Fix all auto-fixable errors per .eslintrc"</span><span style="color:#79C0FF"> --path</span><span style="color:#A5D6FF"> ../my-app--feature-payment</span><span style="color:#79C0FF"> --no-interactive</span></span></code></pre></figure>
<p>Or write a loop (adjust paths to match your setup):</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FF7B72">for</span><span style="color:#E6EDF3"> dir </span><span style="color:#FF7B72">in</span><span style="color:#A5D6FF"> ../my-app--feature-auth</span><span style="color:#A5D6FF"> ../my-app--feature-payment</span><span style="color:#E6EDF3">; </span><span style="color:#FF7B72">do</span></span>
<span data-line=""><span style="color:#FFA657">  cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#A5D6FF"> "Fix linter errors"</span><span style="color:#79C0FF"> --path</span><span style="color:#A5D6FF"> "</span><span style="color:#E6EDF3">$dir</span><span style="color:#A5D6FF">"</span><span style="color:#79C0FF"> --no-interactive</span></span>
<span data-line=""><span style="color:#FF7B72">done</span></span></code></pre></figure>
<p>Give one instruction, clean up multiple branches at once — great for a final sweep before raising PRs.</p>
<h2 id="relationship-to-worktree--multiple-windows">Relationship to "Worktree + Multiple Windows"</h2>
<ul>
<li><strong>Multiple windows</strong>: each Cursor window opens a worktree, using the IDE's Agent, Chat, Tab completion.</li>
<li><strong>CLI + Worktree</strong>: terminal + <code>cursor agent</code> — same idea of "one directory, one context," just open more terminals to parallelize.</li>
</ul>
<p>You can also mix and match: main development in the window, while using the CLI on a server to make small fixes to another branch.</p>
<h2 id="summary">Summary</h2>
<ul>
<li><strong>Worktree</strong> = multiple directories, multiple branches; <strong>CLI</strong> = acts on the current directory or <code>--path</code> → a natural pair.</li>
<li><strong>Parallel</strong>: open multiple terminals, each <code>cd</code> into a different worktree, then run <code>cursor agent</code>.</li>
<li><strong>Single terminal</strong>: use <code>--path &#x3C;worktree-path></code> to target the worktree you want.</li>
<li><strong>Scripts/batch</strong>: <code>--path</code> + <code>--no-interactive</code> to run the same task across multiple worktrees.</li>
</ul>
