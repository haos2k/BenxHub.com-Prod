3:T204c,<p><a href="04-non-interactive">04-non-interactive</a> covered <code>--no-interactive</code> so the Agent runs to completion without waiting for you. This post goes further: <strong>headless mode</strong> with <strong><code>-p</code> / <code>--print</code></strong> for “output to terminal only” runs, plus <strong><code>--force</code></strong> (or <code>--yolo</code>), so the Agent <strong>actually modifies files in your project</strong>—suitable for CI, batch JSDoc, auto lint fixes, and report generation.</p>
<p>In short: <strong>no Cursor window, no key confirmations; a script invokes the CLI to change code, then the script continues.</strong></p>
<h2 id="--print-non-interactive-output-to-terminal">--print: Non-interactive, output to terminal</h2>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#A5D6FF"> "What does this project do?"</span></span>
<span data-line=""><span style="color:#8B949E"># or</span></span>
<span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> --print</span><span style="color:#A5D6FF"> "List all API endpoints under src/"</span></span></code></pre></figure>
<ul>
<li><strong>Without <code>--force</code></strong>: The Agent can read files, search the codebase, and return analysis, but <strong>won’t write to files</strong>—it only “suggests” or prints content in the output</li>
<li>Good for: Q&#x26;A, analysis, writing reports to stdout, piping or parsing in scripts</li>
</ul>
<p>So <code>-p</code> by itself means “run to completion, output to terminal”; whether it changes files depends on whether you add <code>--force</code>.</p>
<h2 id="--force-allow-direct-file-edits">--force: Allow direct file edits</h2>
<p>With <code>--print</code> and <strong><code>--force</code></strong> (or <strong><code>--yolo</code></strong>), the Agent <strong>can create, edit, and delete files</strong> without asking Y/N:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#79C0FF"> --force</span><span style="color:#A5D6FF"> "Refactor src/utils.js to ES6+ syntax"</span></span></code></pre></figure>
<table>
<thead>
<tr>
<th>Use case</th>
<th>Example</th>
</tr>
</thead>
<tbody>
<tr>
<td>Single-file refactor</td>
<td><code>agent -p --force "Refactor src/foo.ts to use async/await"</code></td>
</tr>
<tr>
<td>Fix lint per config</td>
<td><code>agent -p --force "Fix all auto-fixable errors per .eslintrc"</code></td>
</tr>
<tr>
<td>Batch JSDoc</td>
<td>See script example below</td>
</tr>
<tr>
<td>Generate file in project</td>
<td><code>agent -p --force "Generate CONTRIBUTING.md from README"</code></td>
</tr>
</tbody>
</table>
<blockquote>
<p>⚠️ Before using <code>--force</code> in scripts, run on a single file or small scope first to confirm behavior, then scale to the whole repo.</p>
</blockquote>
<h2 id="script-example-batch-jsdoc">Script example: Batch JSDoc</h2>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E">#!/bin/bash</span></span>
<span data-line=""><span style="color:#8B949E"># For each .js under src/, ask Agent to add JSDoc and write directly</span></span>
<span data-line=""><span style="color:#FFA657">find</span><span style="color:#A5D6FF"> src/</span><span style="color:#79C0FF"> -name</span><span style="color:#A5D6FF"> "*.js"</span><span style="color:#FF7B72"> |</span><span style="color:#FF7B72"> while</span><span style="color:#79C0FF"> read</span><span style="color:#79C0FF"> -r</span><span style="color:#A5D6FF"> file</span><span style="color:#E6EDF3">; </span><span style="color:#FF7B72">do</span></span>
<span data-line=""><span style="color:#79C0FF">  echo</span><span style="color:#A5D6FF"> "Processing </span><span style="color:#E6EDF3">$file</span><span style="color:#A5D6FF">..."</span></span>
<span data-line=""><span style="color:#FFA657">  cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#79C0FF"> --force</span><span style="color:#A5D6FF"> "Add full JSDoc comments to </span><span style="color:#E6EDF3">$file</span><span style="color:#A5D6FF">, editing the file in place"</span></span>

<h2 id="script-example-auto-code-review-and-write-report">Script example: Auto code review and write report</h2>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E">#!/bin/bash</span></span>
<span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#79C0FF"> --force</span><span style="color:#79C0FF"> --output-format</span><span style="color:#A5D6FF"> text</span><span style="color:#FF7B72"> \</span></span>
<span data-line=""><span style="color:#A5D6FF">  "Do a code review of recent changes: readability, potential bugs, security, best practices. Write conclusions and concrete suggestions to review.txt"</span></span></code></pre></figure>
<p><code>--output-format text</code> keeps output plain text for writing to a file or piping to <code>grep</code>/scripts. The next post covers <code>json</code> and <code>stream-json</code>.</p>
<h2 id="environment-api-key">Environment: API key</h2>
<p>Headless mode often runs where there’s no Cursor window (e.g. CI, remote machine), so you need auth:</p>
<ul>
<li>Set env: <code>export CURSOR_API_KEY=your_key</code></li>
<li>Or run <code>cursor auth login</code> in that environment first (if supported)</li>
</ul>
<p>Without it you’ll get errors and the Agent won’t run.</p>
<h2 id="difference-from---no-interactive-brief">Difference from --no-interactive (brief)</h2>
<table>
<thead>
<tr>
<th>Mode</th>
<th>Typical use</th>
<th>Edits files?</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>--no-interactive</code></td>
<td>Run in terminal, watch output step by step, no key press</td>
<td>Can edit, but may still ask (per settings)</td>
</tr>
<tr>
<td><code>-p</code> / <code>--print</code></td>
<td>Scripts, CI, fully non-interactive, output to stdout</td>
<td>By default no</td>
</tr>
<tr>
<td><code>-p --force</code></td>
<td>Same, but allow Agent to edit files</td>
<td>Yes, no prompt</td>
</tr>
</tbody>
</table>
<p>So: <strong>for scripts that “really change files,”</strong> use <code>-p --force</code>; for analysis or reports to the terminal only, <code>-p</code> is enough.</p>
<h2 id="summary">Summary</h2>
<ul>
<li><strong><code>-p</code> / <code>--print</code></strong>: Non-interactive, output to terminal when done; by default no file edits</li>
<li><strong><code>--force</code> / <code>--yolo</code></strong>: In print mode, allow the Agent to edit files; good for scripts and CI</li>
<li>In scripts/CI, set <code>CURSOR_API_KEY</code> or complete login</li>
<li>Try on a small scope before running on the whole repo</li>
</ul>

<p>So: <strong>for scripts that “really change files,”</strong> use <code>-p --force</code>; for analysis or reports to the terminal only, <code>-p</code> is enough.</p>
<h2 id="summary">Summary</h2>
<ul>
<li><strong><code>-p</code> / <code>--print</code></strong>: Non-interactive, output to terminal when done; by default no file edits</li>
<li><strong><code>--force</code> / <code>--yolo</code></strong>: In print mode, allow the Agent to edit files; good for scripts and CI</li>
<li>In scripts/CI, set <code>CURSOR_API_KEY</code> or complete login</li>
<li>Try on a small scope before running on the whole repo</li>
</ul>
