1a:T1f91,<p>This article focuses on <strong>the five most common daily operations</strong>, with practical templates you can use right away. Master these patterns and you can handle 80% of scenarios — the remaining 20% is for the advanced section.</p>
<h2 id="pattern-1-backup-a-virtual-machine">Pattern 1: Backup a Virtual Machine</h2>
<p>Goal: keep a periodic backup you can restore from — so if things break, you're not starting from scratch.</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E"># Manual backup of VM 100 to local (snapshot mode — VM stays running)</span></span>
<span data-line=""><span style="color:#FFA657">vzdump</span><span style="color:#79C0FF"> 100</span><span style="color:#79C0FF"> --storage</span><span style="color:#A5D6FF"> local</span><span style="color:#79C0FF"> --mode</span><span style="color:#A5D6FF"> snapshot</span><span style="color:#79C0FF"> --compress</span><span style="color:#A5D6FF"> zstd</span></span></code></pre></figure>
<p>Schedule it at: <code>Datacenter -> Backup -> Add</code>, set a time (e.g. 02:00 daily). Set it and forget it.</p>
<blockquote>
<p><code>snapshot</code> mode lets you back up while the VM is running — like photographing a sleeping cat without waking it up.</p>
</blockquote>
<h2 id="pattern-2-clone-a-virtual-machine">Pattern 2: Clone a Virtual Machine</h2>
<p>Goal: quickly copy an existing environment without reinstalling from scratch.</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E"># Full clone (independent disk, fully self-contained)</span></span>
<span data-line=""><span style="color:#FFA657">qm</span><span style="color:#A5D6FF"> clone</span><span style="color:#79C0FF"> 100</span><span style="color:#79C0FF"> 101</span><span style="color:#79C0FF"> --name</span><span style="color:#A5D6FF"> clone-vm</span><span style="color:#79C0FF"> --full</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#8B949E"># Linked clone (shares base disk, saves space)</span></span>
<span data-line=""><span style="color:#FFA657">qm</span><span style="color:#A5D6FF"> clone</span><span style="color:#79C0FF"> 100</span><span style="color:#79C0FF"> 102</span><span style="color:#79C0FF"> --name</span><span style="color:#A5D6FF"> linked-clone</span><span style="color:#79C0FF"> --linked</span></span></code></pre></figure>
<p>One-sentence difference: <strong>full</strong> = independent, takes space; <strong>linked</strong> = saves space, but depends on the parent disk. Don't delete the parent disk — the linked clones will break with it.</p>
<h2 id="pattern-3-live-migration">Pattern 3: Live Migration</h2>
<p>Goal: move a VM to another node without shutting it down — no service interruption.</p>
<p>Prerequisite: the target node must be able to access the <strong>same disk</strong> (shared storage is ideal).</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">qm</span><span style="color:#A5D6FF"> migrate</span><span style="color:#79C0FF"> 100</span><span style="color:#FF7B72"> &#x3C;</span><span style="color:#A5D6FF">target-nod</span><span style="color:#E6EDF3">e</span><span style="color:#FF7B72">></span><span style="color:#79C0FF"> --live</span></span></code></pre></figure>
<blockquote>
<p>If the disk is on <code>local</code>, you typically need to migrate the disk first or switch to shared storage — otherwise migrate will tell you "I can't find the disk."</p>
</blockquote>
<h2 id="pattern-4-create-an-lxc-container">Pattern 4: Create an LXC Container</h2>
<p>Goal: quickly spin up a lightweight Linux environment to run a service — uses fewer resources than a VM.</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E"># Update template list first</span></span>
<span data-line=""><span style="color:#FFA657">pveam</span><span style="color:#A5D6FF"> update</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#8B949E"># Download Debian template</span></span>
<span data-line=""><span style="color:#FFA657">pveam</span><span style="color:#A5D6FF"> download</span><span style="color:#A5D6FF"> local</span><span style="color:#A5D6FF"> debian-12-standard_12.2-1_amd64.tar.zst</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#8B949E"># Create container</span></span>
<span data-line=""><span style="color:#FFA657">pct</span><span style="color:#A5D6FF"> create</span><span style="color:#79C0FF"> 200</span><span style="color:#A5D6FF"> local:vztmpl/debian-12-standard_12.2-1_amd64.tar.zst</span><span style="color:#FF7B72"> \</span></span>
<span data-line=""><span style="color:#79C0FF">  --hostname</span><span style="color:#A5D6FF"> my-app</span><span style="color:#FF7B72"> \</span></span>
<span data-line=""><span style="color:#79C0FF">  --memory</span><span style="color:#79C0FF"> 512</span><span style="color:#FF7B72"> \</span></span>
<span data-line=""><span style="color:#79C0FF">  --cores</span><span style="color:#79C0FF"> 1</span><span style="color:#FF7B72"> \</span></span>
<span data-line=""><span style="color:#79C0FF">  --net0</span><span style="color:#A5D6FF"> name=eth0,bridge=vmbr0,ip=dhcp</span><span style="color:#FF7B72"> \</span></span>
<span data-line=""><span style="color:#79C0FF">  --rootfs</span><span style="color:#A5D6FF"> local-lvm:8</span></span></code></pre></figure>
<p>LXC starts fast and uses few resources — great for running lots of small services. Like a litter of small otters, each carrying very little overhead.</p>
<h2 id="pattern-5-snapshots-and-rollback">Pattern 5: Snapshots and Rollback</h2>
<p>Goal: before a major update or configuration change, leave a restore point you can "return to."</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E"># Create a snapshot</span></span>
<span data-line=""><span style="color:#FFA657">qm</span><span style="color:#A5D6FF"> snapshot</span><span style="color:#79C0FF"> 100</span><span style="color:#A5D6FF"> before-update</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#8B949E"># Something went wrong? Roll back</span></span>
<span data-line=""><span style="color:#FFA657">qm</span><span style="color:#A5D6FF"> rollback</span><span style="color:#79C0FF"> 100</span><span style="color:#A5D6FF"> before-update</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#8B949E"># All good? Delete the snapshot</span></span>
<span data-line=""><span style="color:#FFA657">qm</span><span style="color:#A5D6FF"> delsnapshot</span><span style="color:#79C0FF"> 100</span><span style="color:#A5D6FF"> before-update</span></span></code></pre></figure>
<p>Make it a habit to snapshot before major operations: snapshot first, then act. The debugging time you save can be spent on better things.</p>

<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">qm</span><span style="color:#A5D6FF"> migrate</span><span style="color:#79C0FF"> 100</span><span style="color:#FF7B72"> &#x3C;</span><span style="color:#A5D6FF">target-nod</span><span style="color:#E6EDF3">e</span><span style="color:#FF7B72">></span><span style="color:#79C0FF"> --live</span></span></code></pre></figure>
<blockquote>
<p>If the disk is on <code>local</code>, you typically need to migrate the disk first or switch to shared storage — otherwise migrate will tell you "I can't find the disk."</p>
</blockquote>
<h2 id="pattern-4-create-an-lxc-container">Pattern 4: Create an LXC Container</h2>
<p>Goal: quickly spin up a lightweight Linux environment to run a service — uses fewer resources than a VM.</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E"># Update template list first</span></span>
<span data-line=""><span style="color:#FFA657">pveam</span><span style="color:#A5D6FF"> update</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#8B949E"># Download Debian template</span></span>
<span data-line=""><span style="color:#FFA657">pveam</span><span style="color:#A5D6FF"> download</span><span style="color:#A5D6FF"> local</span><span style="color:#A5D6FF"> debian-12-standard_12.2-1_amd64.tar.zst</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#8B949E"># Create container</span></span>
<span data-line=""><span style="color:#FFA657">pct</span><span style="color:#A5D6FF"> create</span><span style="color:#79C0FF"> 200</span><span style="color:#A5D6FF"> local:vztmpl/debian-12-standard_12.2-1_amd64.tar.zst</span><span style="color:#FF7B72"> \</span></span>
<span data-line=""><span style="color:#79C0FF">  --hostname</span><span style="color:#A5D6FF"> my-app</span><span style="color:#FF7B72"> \</span></span>
<span data-line=""><span style="color:#79C0FF">  --memory</span><span style="color:#79C0FF"> 512</span><span style="color:#FF7B72"> \</span></span>
<span data-line=""><span style="color:#79C0FF">  --cores</span><span style="color:#79C0FF"> 1</span><span style="color:#FF7B72"> \</span></span>
<span data-line=""><span style="color:#79C0FF">  --net0</span><span style="color:#A5D6FF"> name=eth0,bridge=vmbr0,ip=dhcp</span><span style="color:#FF7B72"> \</span></span>
<span data-line=""><span style="color:#79C0FF">  --rootfs</span><span style="color:#A5D6FF"> local-lvm:8</span></span></code></pre></figure>
<p>LXC starts fast and uses few resources — great for running lots of small services. Like a litter of small otters, each carrying very little overhead.</p>
<h2 id="pattern-5-snapshots-and-rollback">Pattern 5: Snapshots and Rollback</h2>
<p>Goal: before a major update or configuration change, leave a restore point you can "return to."</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E"># Create a snapshot</span></span>
<span data-line=""><span style="color:#FFA657">qm</span><span style="color:#A5D6FF"> snapshot</span><span style="color:#79C0FF"> 100</span><span style="color:#A5D6FF"> before-update</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#8B949E"># Something went wrong? Roll back</span></span>
<span data-line=""><span style="color:#FFA657">qm</span><span style="color:#A5D6FF"> rollback</span><span style="color:#79C0FF"> 100</span><span style="color:#A5D6FF"> before-update</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#8B949E"># All good? Delete the snapshot</span></span>
<span data-line=""><span style="color:#FFA657">qm</span><span style="color:#A5D6FF"> delsnapshot</span><span style="color:#79C0FF"> 100</span><span style="color:#A5D6FF"> before-update</span></span></code></pre></figure>
<p>Make it a habit to snapshot before major operations: snapshot first, then act. The debugging time you save can be spent on better things.</p>
