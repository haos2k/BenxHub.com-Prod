1b:Tcbf,<p>You can think of <code>Crew</code> as a director that decides who goes on stage first and who follows.<br>
<code>Process</code> is the pacing script that defines how tasks flow.</p>
<h2 id="most-important-conclusion-first">Most important conclusion first</h2>
<p><strong>For 90% of beginner projects, start with <code>Process.sequential</code>.</strong><br>
Simple reason: predictable, easy to debug, easier to investigate when something fails.</p>
<h2 id="minimal-viable-crew">Minimal viable crew</h2>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="python" data-theme="github-dark"><code data-language="python" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#F97583">from</span><span style="color:#E1E4E8"> crewai </span><span style="color:#F97583">import</span><span style="color:#E1E4E8"> Crew, Process</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#F97583">def</span><span style="color:#B392F0"> build_crew</span><span style="color:#E1E4E8">(agents, tasks) -> Crew:</span></span>
<span data-line=""><span style="color:#F97583">    return</span><span style="color:#E1E4E8"> Crew(</span></span>
<span data-line=""><span style="color:#FFAB70">        agents</span><span style="color:#F97583">=</span><span style="color:#E1E4E8">agents,</span></span>
<span data-line=""><span style="color:#FFAB70">        tasks</span><span style="color:#F97583">=</span><span style="color:#E1E4E8">tasks,</span></span>
<span data-line=""><span style="color:#FFAB70">        process</span><span style="color:#F97583">=</span><span style="color:#E1E4E8">Process.sequential,</span></span>
<span data-line=""><span style="color:#FFAB70">        verbose</span><span style="color:#F97583">=</span><span style="color:#79B8FF">True</span><span style="color:#E1E4E8">,</span></span>
<span data-line=""><span style="color:#E1E4E8">    )</span></span></code></pre></figure>
<p>This looks ordinary, but it is critical:<br>
you have explicitly told the system to execute tasks in order, one by one.</p>
<h2 id="why-sequential-helps">Why sequential helps</h2>
<ul>
<li>Clear task dependencies</li>
<li>Reproducible outputs</li>
<li>Faster error localization</li>
<li>Better cost control</li>
</ul>
<p>For beginners, this is like clearing the main quest on normal difficulty before touching nightmare mode.</p>
<h2 id="when-to-consider-hierarchical">When to consider hierarchical?</h2>
<p>Consider it only when:</p>
<ul>
<li>Task count is very large and changes dynamically</li>
<li>You need a manager agent to auto-assign work</li>
<li>You already have stable monitoring and cost controls</li>
</ul>
<p>If you are still tuning <code>expected_output</code>, do not jump to hierarchical yet.</p>
<h2 id="practical-tip-make-crew-assembly-testable">Practical tip: make crew assembly testable</h2>
<p>Centralize crew construction in one function or class instead of scattering it.<br>
Then swapping model, process, or callbacks becomes much easier to maintain.</p>
