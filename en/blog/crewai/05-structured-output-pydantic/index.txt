1a:T1794,<p>If you have seen one task return markdown this time and a free-form essay next time, you are not alone.<br>
The fix is straightforward: <strong>define output schema with Pydantic</strong>.</p>
<h2 id="why-structured-output">Why structured output?</h2>
<ul>
<li>Downstream tasks can read fixed fields</li>
<li>No brittle string parsing every run</li>
<li>Failures are caught earlier (field mismatch throws errors)</li>
</ul>
<p>It is basically an API contract. Stable collaboration needs a contract.</p>

<h2 id="recommended-pairing-style">Recommended pairing style</h2>
<ul>
<li>Keep <code>expected_output</code> quality requirements explicit</li>
<li>Define field semantics (<code>summary</code> length, <code>source</code> format)</li>
<li>Make downstream tasks rely on fields, not writing style</li>
</ul>
<h2 id="common-beginner-mistakes">Common beginner mistakes</h2>
<ol>
<li>Thinking Pydantic means <code>expected_output</code> is unnecessary</li>
<li>Too few fields, resulting in missing information</li>
<li>Too many granular fields, causing frequent omissions</li>
</ol>
<blockquote>
<p>⚠️ Start with 3-5 key fields first. Expand only when needed.</p>
</blockquote>

<span data-line=""><span style="color:#FFA657">    output_pydantic</span><span style="color:#FF7B72">=</span><span style="color:#E6EDF3">ResearchReport,</span></span>
<span data-line=""><span style="color:#E6EDF3">)</span></span></code></pre></figure>
<p>After execution, you can access stable fields directly instead of guessing from text.</p>
<h2 id="recommended-pairing-style">Recommended pairing style</h2>
<ul>
<li>Keep <code>expected_output</code> quality requirements explicit</li>
<li>Define field semantics (<code>summary</code> length, <code>source</code> format)</li>
<li>Make downstream tasks rely on fields, not writing style</li>
</ul>
<h2 id="common-beginner-mistakes">Common beginner mistakes</h2>
<ol>
<li>Thinking Pydantic means <code>expected_output</code> is unnecessary</li>
<li>Too few fields, resulting in missing information</li>
<li>Too many granular fields, causing frequent omissions</li>
</ol>
<blockquote>
<p>⚠️ Start with 3-5 key fields first. Expand only when needed.</p>
</blockquote>
