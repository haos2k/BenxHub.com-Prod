1b:T240f,<p>This article focuses on <strong>the five most common daily development tasks</strong>, with practical templates you can use right away. Master these patterns and you can handle 80% of scenarios — the remaining 20% is for the advanced section.</p>
<h2 id="pattern-1-adding-and-removing-dependencies">Pattern 1: Adding and Removing Dependencies</h2>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># Add a dependency</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> add</span><span style="color:#9ECBFF"> requests</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> add</span><span style="color:#9ECBFF"> "requests>=2.31,&#x3C;3"</span><span style="color:#6A737D">   # with version constraints</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># Dev dependencies (tests, lint, type checking)</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> add</span><span style="color:#79B8FF"> --dev</span><span style="color:#9ECBFF"> pytest</span><span style="color:#9ECBFF"> ruff</span><span style="color:#9ECBFF"> mypy</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># Remove</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> remove</span><span style="color:#9ECBFF"> requests</span></span></code></pre></figure>
<p><code>uv add</code> simultaneously updates <code>pyproject.toml</code>, <code>uv.lock</code>, and <code>.venv</code> — one command does it all.</p>
<h2 id="pattern-2-uv-run-to-execute-project-commands">Pattern 2: uv run to Execute Project Commands</h2>
<p>For scripts, CLIs, and tests inside the project, always use <code>uv run</code>:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> run</span><span style="color:#9ECBFF"> python</span><span style="color:#9ECBFF"> main.py</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> run</span><span style="color:#9ECBFF"> pytest</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> run</span><span style="color:#9ECBFF"> ruff</span><span style="color:#9ECBFF"> check</span><span style="color:#9ECBFF"> .</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> run</span><span style="color:#9ECBFF"> mypy</span><span style="color:#9ECBFF"> src/</span></span></code></pre></figure>
<p>No activation needed, no worrying about the wrong Python.</p>
<h2 id="pattern-3-uvx-to-run-standalone-cli-tools">Pattern 3: uvx to Run Standalone CLI Tools</h2>
<p>Want to run a tool temporarily without adding it to the project? Use <code>uvx</code> (equivalent to <code>uv tool run</code>):</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># On-demand, disposable</span></span>
<span data-line=""><span style="color:#B392F0">uvx</span><span style="color:#9ECBFF"> ruff</span><span style="color:#9ECBFF"> check</span><span style="color:#9ECBFF"> .</span></span>
<span data-line=""><span style="color:#B392F0">uvx</span><span style="color:#9ECBFF"> pycowsay</span><span style="color:#9ECBFF"> "hello uv"</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># Pin a version</span></span>
<span data-line=""><span style="color:#B392F0">uvx</span><span style="color:#9ECBFF"> ruff@0.5.0</span><span style="color:#9ECBFF"> check</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># When the package name and command differ</span></span>
<span data-line=""><span style="color:#B392F0">uvx</span><span style="color:#79B8FF"> --from</span><span style="color:#9ECBFF"> httpie</span><span style="color:#9ECBFF"> http</span><span style="color:#9ECBFF"> https://httpbin.org/get</span></span></code></pre></figure>
<p>uvx creates a temporary environment to run the tool without polluting your project — like sampling food without buying the whole package. Perfect for "I just want to try this" moments.</p>
<h2 id="pattern-4-inline-script-dependencies-pep-723">Pattern 4: Inline Script Dependencies (PEP 723)</h2>
<p>Single script, don't want to create a project? Use inline script metadata:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="python" data-theme="github-dark"><code data-language="python" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># /// script</span></span>
<span data-line=""><span style="color:#6A737D"># dependencies = ["requests", "rich"]</span></span>
<span data-line=""><span style="color:#6A737D"># ///</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#F97583">import</span><span style="color:#E1E4E8"> requests</span></span>
<span data-line=""><span style="color:#F97583">from</span><span style="color:#E1E4E8"> rich.pretty </span><span style="color:#F97583">import</span><span style="color:#E1E4E8"> pprint</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#E1E4E8">r </span><span style="color:#F97583">=</span><span style="color:#E1E4E8"> requests.get(</span><span style="color:#9ECBFF">"https://api.github.com/zen"</span><span style="color:#E1E4E8">)</span></span>
<span data-line=""><span style="color:#E1E4E8">pprint(r.text)</span></span></code></pre></figure>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> add</span><span style="color:#79B8FF"> --script</span><span style="color:#9ECBFF"> fetch.py</span><span style="color:#9ECBFF"> requests</span><span style="color:#9ECBFF"> rich</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> run</span><span style="color:#9ECBFF"> fetch.py</span></span></code></pre></figure>
<p>Or in one line:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> run</span><span style="color:#79B8FF"> --with</span><span style="color:#9ECBFF"> requests</span><span style="color:#79B8FF"> --with</span><span style="color:#9ECBFF"> rich</span><span style="color:#9ECBFF"> fetch.py</span></span></code></pre></figure>
<h2 id="pattern-5-migrating-from-requirementstxt">Pattern 5: Migrating from requirements.txt</h2>
<p>Existing project with a <code>requirements.txt</code>? Take it in directly:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> add</span><span style="color:#79B8FF"> -r</span><span style="color:#9ECBFF"> requirements.txt</span></span></code></pre></figure>
<p>Or compile to a lockfile then sync:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> pip</span><span style="color:#9ECBFF"> compile</span><span style="color:#9ECBFF"> requirements.in</span><span style="color:#79B8FF"> -o</span><span style="color:#9ECBFF"> requirements.txt</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> pip</span><span style="color:#9ECBFF"> sync</span><span style="color:#9ECBFF"> requirements.txt</span></span></code></pre></figure>
<p>After migrating, treat <code>pyproject.toml</code> as the primary source — <code>requirements.txt</code> can be used as an export format.</p>

<p><code>uv add</code> simultaneously updates <code>pyproject.toml</code>, <code>uv.lock</code>, and <code>.venv</code> — one command does it all.</p>
<h2 id="pattern-2-uv-run-to-execute-project-commands">Pattern 2: uv run to Execute Project Commands</h2>
<p>For scripts, CLIs, and tests inside the project, always use <code>uv run</code>:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> run</span><span style="color:#9ECBFF"> python</span><span style="color:#9ECBFF"> main.py</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> run</span><span style="color:#9ECBFF"> pytest</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> run</span><span style="color:#9ECBFF"> ruff</span><span style="color:#9ECBFF"> check</span><span style="color:#9ECBFF"> .</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> run</span><span style="color:#9ECBFF"> mypy</span><span style="color:#9ECBFF"> src/</span></span></code></pre></figure>
<p>No activation needed, no worrying about the wrong Python.</p>
<h2 id="pattern-3-uvx-to-run-standalone-cli-tools">Pattern 3: uvx to Run Standalone CLI Tools</h2>
<p>Want to run a tool temporarily without adding it to the project? Use <code>uvx</code> (equivalent to <code>uv tool run</code>):</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># On-demand, disposable</span></span>
<span data-line=""><span style="color:#B392F0">uvx</span><span style="color:#9ECBFF"> ruff</span><span style="color:#9ECBFF"> check</span><span style="color:#9ECBFF"> .</span></span>
<span data-line=""><span style="color:#B392F0">uvx</span><span style="color:#9ECBFF"> pycowsay</span><span style="color:#9ECBFF"> "hello uv"</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># Pin a version</span></span>
<span data-line=""><span style="color:#B392F0">uvx</span><span style="color:#9ECBFF"> ruff@0.5.0</span><span style="color:#9ECBFF"> check</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># When the package name and command differ</span></span>
<span data-line=""><span style="color:#B392F0">uvx</span><span style="color:#79B8FF"> --from</span><span style="color:#9ECBFF"> httpie</span><span style="color:#9ECBFF"> http</span><span style="color:#9ECBFF"> https://httpbin.org/get</span></span></code></pre></figure>
<p>uvx creates a temporary environment to run the tool without polluting your project — like sampling food without buying the whole package. Perfect for "I just want to try this" moments.</p>
<h2 id="pattern-4-inline-script-dependencies-pep-723">Pattern 4: Inline Script Dependencies (PEP 723)</h2>
<p>Single script, don't want to create a project? Use inline script metadata:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="python" data-theme="github-dark"><code data-language="python" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># /// script</span></span>
<span data-line=""><span style="color:#6A737D"># dependencies = ["requests", "rich"]</span></span>
<span data-line=""><span style="color:#6A737D"># ///</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#F97583">import</span><span style="color:#E1E4E8"> requests</span></span>
<span data-line=""><span style="color:#F97583">from</span><span style="color:#E1E4E8"> rich.pretty </span><span style="color:#F97583">import</span><span style="color:#E1E4E8"> pprint</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#E1E4E8">r </span><span style="color:#F97583">=</span><span style="color:#E1E4E8"> requests.get(</span><span style="color:#9ECBFF">"https://api.github.com/zen"</span><span style="color:#E1E4E8">)</span></span>
<span data-line=""><span style="color:#E1E4E8">pprint(r.text)</span></span></code></pre></figure>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> add</span><span style="color:#79B8FF"> --script</span><span style="color:#9ECBFF"> fetch.py</span><span style="color:#9ECBFF"> requests</span><span style="color:#9ECBFF"> rich</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> run</span><span style="color:#9ECBFF"> fetch.py</span></span></code></pre></figure>
<p>Or in one line:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> run</span><span style="color:#79B8FF"> --with</span><span style="color:#9ECBFF"> requests</span><span style="color:#79B8FF"> --with</span><span style="color:#9ECBFF"> rich</span><span style="color:#9ECBFF"> fetch.py</span></span></code></pre></figure>
<h2 id="pattern-5-migrating-from-requirementstxt">Pattern 5: Migrating from requirements.txt</h2>
<p>Existing project with a <code>requirements.txt</code>? Take it in directly:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> add</span><span style="color:#79B8FF"> -r</span><span style="color:#9ECBFF"> requirements.txt</span></span></code></pre></figure>
<p>Or compile to a lockfile then sync:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> pip</span><span style="color:#9ECBFF"> compile</span><span style="color:#9ECBFF"> requirements.in</span><span style="color:#79B8FF"> -o</span><span style="color:#9ECBFF"> requirements.txt</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> pip</span><span style="color:#9ECBFF"> sync</span><span style="color:#9ECBFF"> requirements.txt</span></span></code></pre></figure>
<p>After migrating, treat <code>pyproject.toml</code> as the primary source — <code>requirements.txt</code> can be used as an export format.</p>
