1b:T1739,<p>Before typing commands at random, get these four concepts into your head: you'll be clearer on "where do dependencies go, what's the lockfile for, when does the venv get created." Like reading the skill descriptions before playing a game — otherwise you'll keep dying for no reason.</p>
<h2 id="concept-1-pyprojecttoml-is-your-projects-id-card">Concept 1: pyproject.toml Is Your Project's ID Card</h2>
<p>Project metadata and dependencies all live here — it's the PEP 518 standard format.</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="toml" data-theme="github-dark-default"><code data-language="toml" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#E6EDF3">[</span><span style="color:#FFA657">project</span><span style="color:#E6EDF3">]</span></span>
<span data-line=""><span style="color:#E6EDF3">name = </span><span style="color:#A5D6FF">"my-app"</span></span>
<span data-line=""><span style="color:#E6EDF3">version = </span><span style="color:#A5D6FF">"0.1.0"</span></span>
<span data-line=""><span style="color:#E6EDF3">requires-python = </span><span style="color:#A5D6FF">">=3.12"</span></span>
<span data-line=""><span style="color:#E6EDF3">dependencies = [</span></span>
<span data-line=""><span style="color:#A5D6FF">    "requests>=2.31"</span><span style="color:#E6EDF3">,</span></span>
<span data-line=""><span style="color:#E6EDF3">]</span></span></code></pre></figure>
<ul>
<li><strong>Manual editing</strong>: edit <code>pyproject.toml</code> directly</li>
<li><strong>Command-driven</strong>: <code>uv add requests</code> and <code>uv remove requests</code> update it automatically</li>
</ul>
<blockquote>
<p>Don't mix methods — either edit manually or use commands. Doing both causes conflicts.</p>
</blockquote>
<h2 id="concept-2-uvlock-is-a-dependency-snapshot">Concept 2: uv.lock Is a Dependency Snapshot</h2>
<p><code>pyproject.toml</code> says "what I want" (e.g. <code>requests>=2.31</code>). <code>uv.lock</code> records "what was actually installed" — precise down to every transitive dependency.</p>
<ul>
<li><strong>Why have a lockfile?</strong> Ensures everyone — all teammates, CI, production — installs the exact same dependency tree. No more "it works on my machine, it breaks on yours."</li>
<li><strong>Should you commit it?</strong> Yes. <code>uv.lock</code> should be in version control so the team and CI use the same dependency tree.</li>
</ul>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E"># Update the lockfile (e.g. upgrade a package)</span></span>
<span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> lock</span><span style="color:#79C0FF"> --upgrade-package</span><span style="color:#A5D6FF"> requests</span></span></code></pre></figure>
<h2 id="concept-3-venv-is-your-projects-sandbox">Concept 3: .venv Is Your Project's Sandbox</h2>
<p>uv creates <code>.venv</code> in the project root — all <code>uv add</code> packages go in here, isolated from the system Python.</p>
<ul>
<li><strong>Do you need to manually activate it?</strong> No. <code>uv run</code> automatically uses this environment.</li>
<li><strong>Should you commit it?</strong> No. <code>.venv</code> should be in <code>.gitignore</code>.</li>
</ul>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E"># Manually sync the environment (e.g. after a fresh clone)</span></span>
<span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> sync</span></span>
<span data-line=""><span style="color:#79C0FF">source</span><span style="color:#A5D6FF"> .venv/bin/activate</span><span style="color:#8B949E">  # after this you can use python, pytest, etc. directly</span></span></code></pre></figure>
<h2 id="concept-4-uv-run-is-the-effortless-entry-point">Concept 4: uv run Is the Effortless Entry Point</h2>
<p><code>uv run</code> will:</p>
<ol>
<li>Check if the lockfile is consistent with pyproject.toml</li>
<li>Ensure .venv is in sync with the lockfile</li>
<li>Execute your specified command in the correct environment</li>
</ol>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> run</span><span style="color:#A5D6FF"> python</span><span style="color:#A5D6FF"> main.py</span></span>
<span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> run</span><span style="color:#A5D6FF"> pytest</span></span>
<span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> run</span><span style="color:#A5D6FF"> flask</span><span style="color:#A5D6FF"> run</span><span style="color:#79C0FF"> -p</span><span style="color:#79C0FF"> 3000</span></span></code></pre></figure>
<p>No need to remember to activate, no worrying about the wrong environment — just hand it to uv. Like a cat that always finds the litter box without thinking about it. Once you experience this "just run it" feeling, there's no going back.</p>
