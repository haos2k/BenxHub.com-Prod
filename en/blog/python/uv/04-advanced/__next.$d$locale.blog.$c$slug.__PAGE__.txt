3:T21de,<p>When requirements move from "as long as it runs" to "multi-version testing, backward-compatible pipelines, and global tool management," uv can handle it. This article takes you from solo dungeon runs to raiding as a team.</p>
<h2 id="python-version-management">Python Version Management</h2>
<p>uv has built-in Python download and management — no need to install pyenv separately.</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># Install multiple versions</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> python</span><span style="color:#9ECBFF"> install</span><span style="color:#79B8FF"> 3.10</span><span style="color:#79B8FF"> 3.11</span><span style="color:#79B8FF"> 3.12</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># Pin a project to a specific version (creates .python-version)</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> python</span><span style="color:#9ECBFF"> pin</span><span style="color:#79B8FF"> 3.11</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># Create a venv with a specific version</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> venv</span><span style="color:#79B8FF"> --python</span><span style="color:#79B8FF"> 3.12</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># Run with a specific version</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> run</span><span style="color:#79B8FF"> --python</span><span style="color:#79B8FF"> 3.10</span><span style="color:#9ECBFF"> pytest</span></span></code></pre></figure>
<p>The first time you use a version, it downloads automatically — subsequent uses go straight from cache.</p>
<h2 id="pip-compatible-interface">pip-Compatible Interface</h2>
<p>Existing CI, Docker, and scripts still using <code>pip</code>? uv provides a drop-in replacement:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># Equivalent to pip install -r requirements.txt</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> pip</span><span style="color:#9ECBFF"> install</span><span style="color:#79B8FF"> -r</span><span style="color:#9ECBFF"> requirements.txt</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># Compile requirements (cross-platform, reproducible)</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> pip</span><span style="color:#9ECBFF"> compile</span><span style="color:#9ECBFF"> requirements.in</span><span style="color:#79B8FF"> --universal</span><span style="color:#79B8FF"> -o</span><span style="color:#9ECBFF"> requirements.txt</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># Sync environment (strictly from lockfile)</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> pip</span><span style="color:#9ECBFF"> sync</span><span style="color:#9ECBFF"> requirements.txt</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># Create venv</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> venv</span></span></code></pre></figure>
<p>Switch to <code>uv pip</code> and the parameters are almost identical, but the speed jumps by an order of magnitude — like upgrading from a bicycle to a motorcycle: same road, completely different experience. Want to upgrade your legacy project without major changes? Start with <code>uv pip</code>, painless lift-off.</p>
<h2 id="global-tool-installation-uv-tool">Global Tool Installation (uv tool)</h2>
<p>Don't want to run <code>uvx</code> every time for tools you use frequently? Install them globally:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> tool</span><span style="color:#9ECBFF"> install</span><span style="color:#9ECBFF"> ruff</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> tool</span><span style="color:#9ECBFF"> install</span><span style="color:#9ECBFF"> httpie</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># Call directly afterward</span></span>
<span data-line=""><span style="color:#B392F0">ruff</span><span style="color:#9ECBFF"> check</span><span style="color:#9ECBFF"> .</span></span>
<span data-line=""><span style="color:#B392F0">http</span><span style="color:#9ECBFF"> https://httpbin.org/get</span></span></code></pre></figure>
<p>Upgrade individual tools or all of them at once:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> tool</span><span style="color:#9ECBFF"> upgrade</span><span style="color:#9ECBFF"> ruff</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> tool</span><span style="color:#9ECBFF"> upgrade</span><span style="color:#79B8FF"> --all</span></span></code></pre></figure>
<blockquote>
<p><code>uv tool install</code> creates isolated environments that won't conflict with project dependencies. For project-pinned versions, still use <code>uv add --dev</code>.</p>
</blockquote>
<h2 id="script-lockfile-and-shebang">Script Lockfile and Shebang</h2>
<p>Want a single script to be reproducible too? You can lock its dependencies:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> lock</span><span style="color:#79B8FF"> --script</span><span style="color:#9ECBFF"> example.py</span></span></code></pre></figure>
<p>This creates <code>example.py.lock</code>. When you run <code>uv run example.py</code>, it uses that lockfile.</p>
<p>Or make it executable:</p>

<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">chmod</span><span style="color:#9ECBFF"> +x</span><span style="color:#9ECBFF"> fetch</span></span>
