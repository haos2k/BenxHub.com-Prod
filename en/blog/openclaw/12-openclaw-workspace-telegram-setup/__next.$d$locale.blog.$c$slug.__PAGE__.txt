3:T41dc,<p>Ever asked your assistant to "organize today's journal" and then watched it touch files from your work project instead?</p>
<p>That is what happens when <strong>workspaces are not configured correctly</strong>. This guide fixes that in one go.</p>
<h2 id="what-youll-learn">What You'll Learn</h2>
<ul>
<li>Understand the full flow: group → assistant → workspace</li>
<li>Initialize multiple workspaces</li>
<li>Configure Agents + Bindings completely</li>
<li>Verify that the setup really works</li>
</ul>
<hr>
<h2 id="the-overall-idea">The Overall Idea</h2>
<p>The target architecture is simple:</p>
<pre><code>Telegram Group A  →  Assistant A  →  Workspace A (touch only these files)
Telegram Group B  →  Assistant B  →  Workspace B (touch only these files)
Direct messages   →  Main assistant → Main workspace
</code></pre>
<p>To make that happen, you need three steps: <strong>create workspaces → define agents → define bindings</strong>.</p>
<hr>
<h2 id="step-1-create-the-workspaces">Step 1: Create the Workspaces</h2>
<p>Each assistant needs its own directory. Initialize them with:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">openclaw</span><span style="color:#9ECBFF"> setup</span><span style="color:#79B8FF"> --workspace</span><span style="color:#9ECBFF"> "~/.openclaw/workspace-main"</span></span>
<span data-line=""><span style="color:#B392F0">openclaw</span><span style="color:#9ECBFF"> setup</span><span style="color:#79B8FF"> --workspace</span><span style="color:#9ECBFF"> "~/.openclaw/workspace-project-a"</span></span>
<span data-line=""><span style="color:#B392F0">openclaw</span><span style="color:#9ECBFF"> setup</span><span style="color:#79B8FF"> --workspace</span><span style="color:#9ECBFF"> "~/.openclaw/workspace-project-b"</span></span></code></pre></figure>
<p>Each workspace gets the necessary files automatically, such as <code>AGENTS.md</code>, <code>SOUL.md</code>, and <code>IDENTITY.md</code>.</p>
<blockquote>
<p>💡 If the directory does not exist yet, the command creates it for you. If you cloned an existing workspace from Git, you can skip initialization and just point to the path in Config.</p>
</blockquote>
<hr>

<h2 id="step-3-save-and-verify">Step 3: Save and Verify</h2>
<p><strong>From the Web UI</strong>: click <strong>Save / Apply</strong> on the Config page.</p>
<p><strong>If you edit the file directly</strong>: save <code>~/.openclaw/openclaw.json</code>. The Gateway usually hot-reloads, but if you are unsure, restart it:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">openclaw</span><span style="color:#9ECBFF"> gateway</span></span></code></pre></figure>
<p><strong>How to verify</strong></p>
<ul>
<li>Send a message in each Telegram group and confirm the correct assistant replies</li>
<li>Run <code>openclaw doctor</code> for a quick health check</li>
</ul>

9:T41dc,<p>Ever asked your assistant to "organize today's journal" and then watched it touch files from your work project instead?</p>
<p>That is what happens when <strong>workspaces are not configured correctly</strong>. This guide fixes that in one go.</p>
<h2 id="what-youll-learn">What You'll Learn</h2>
<ul>
<li>Understand the full flow: group → assistant → workspace</li>
<li>Initialize multiple workspaces</li>
<li>Configure Agents + Bindings completely</li>
<li>Verify that the setup really works</li>
</ul>
<hr>
<h2 id="the-overall-idea">The Overall Idea</h2>
<p>The target architecture is simple:</p>
<pre><code>Telegram Group A  →  Assistant A  →  Workspace A (touch only these files)
Telegram Group B  →  Assistant B  →  Workspace B (touch only these files)
Direct messages   →  Main assistant → Main workspace
</code></pre>
<p>To make that happen, you need three steps: <strong>create workspaces → define agents → define bindings</strong>.</p>
<hr>
<h2 id="step-1-create-the-workspaces">Step 1: Create the Workspaces</h2>
<p>Each assistant needs its own directory. Initialize them with:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">openclaw</span><span style="color:#9ECBFF"> setup</span><span style="color:#79B8FF"> --workspace</span><span style="color:#9ECBFF"> "~/.openclaw/workspace-main"</span></span>
<span data-line=""><span style="color:#B392F0">openclaw</span><span style="color:#9ECBFF"> setup</span><span style="color:#79B8FF"> --workspace</span><span style="color:#9ECBFF"> "~/.openclaw/workspace-project-a"</span></span>
<span data-line=""><span style="color:#B392F0">openclaw</span><span style="color:#9ECBFF"> setup</span><span style="color:#79B8FF"> --workspace</span><span style="color:#9ECBFF"> "~/.openclaw/workspace-project-b"</span></span></code></pre></figure>
<p>Each workspace gets the necessary files automatically, such as <code>AGENTS.md</code>, <code>SOUL.md</code>, and <code>IDENTITY.md</code>.</p>
<blockquote>
<p>💡 If the directory does not exist yet, the command creates it for you. If you cloned an existing workspace from Git, you can skip initialization and just point to the path in Config.</p>
</blockquote>
