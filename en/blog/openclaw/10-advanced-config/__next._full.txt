<h2 id="where-is-the-config-file">Where Is the Config File?</h2>
<pre><code>~/.openclaw/openclaw.json
</code></pre>
<p>The format is <strong>JSON5</strong>, which means comments and trailing commas are allowed. Much friendlier than plain JSON.</p>
<p>You can edit it in two ways:</p>
<ul>
<li>Use the <strong>form mode</strong> in Control UI if you want something beginner-friendly</li>
<li>Switch to <strong>Raw JSON</strong> if you want precision and speed</li>
</ul>
<p>Both modes edit the same file and save back to the same path.</p>

<h2 id="the-right-way-to-store-api-keys">The Right Way to Store API Keys</h2>
<p><strong>Do not hard-code API keys into config if you can avoid it.</strong></p>
<p>Environment variables are safer:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E"># Put this in .env or in your system environment</span></span>
<span data-line=""><span style="color:#E6EDF3">ANTHROPIC_API_KEY</span><span style="color:#FF7B72">=</span><span style="color:#A5D6FF">sk-ant-xxxxx</span></span></code></pre></figure>
<blockquote>
<p>⚠️ If the Gateway runs as a system service such as <code>systemd</code>, make sure the service loads your <code>.env</code>. Otherwise the assistant may fail because it cannot see the API key, and you may run into errors like "Shell env off".</p>
</blockquote>

<p>When something feels wrong, start here:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">openclaw</span><span style="color:#A5D6FF"> logs</span><span style="color:#79C0FF"> --follow</span></span></code></pre></figure>
<p>Real-time logs answer a surprising number of questions.</p>

</tr>
<tr>
<td>Context got truncated</td>

</tr>

<span data-line=""><span style="color:#A5D6FF">      "botToken"</span><span style="color:#E6EDF3">: </span><span style="color:#A5D6FF">"your bot token"</span></span>
<span data-line=""><span style="color:#E6EDF3">    }</span></span>
<span data-line=""><span style="color:#E6EDF3">  },</span></span>
<span data-line=""><span style="color:#A5D6FF">  "bindings"</span><span style="color:#E6EDF3">: [</span></span>
<span data-line=""><span style="color:#E6EDF3">    { </span><span style="color:#A5D6FF">"agentId"</span><span style="color:#E6EDF3">: </span><span style="color:#A5D6FF">"main"</span><span style="color:#E6EDF3">, </span><span style="color:#A5D6FF">"match"</span><span style="color:#E6EDF3">: { </span><span style="color:#A5D6FF">"channel"</span><span style="color:#E6EDF3">: </span><span style="color:#A5D6FF">"telegram"</span><span style="color:#E6EDF3"> } }</span></span>
<span data-line=""><span style="color:#E6EDF3">  ]</span></span>
<span data-line=""><span style="color:#E6EDF3">}</span></span></code></pre></figure>
<p>Get the simple version working first. Then add more features gradually.</p>
<hr>
<h2 id="the-right-way-to-store-api-keys">The Right Way to Store API Keys</h2>
<p><strong>Do not hard-code API keys into config if you can avoid it.</strong></p>
<p>Environment variables are safer:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E"># Put this in .env or in your system environment</span></span>
<span data-line=""><span style="color:#E6EDF3">ANTHROPIC_API_KEY</span><span style="color:#FF7B72">=</span><span style="color:#A5D6FF">sk-ant-xxxxx</span></span></code></pre></figure>
<blockquote>
<p>⚠️ If the Gateway runs as a system service such as <code>systemd</code>, make sure the service loads your <code>.env</code>. Otherwise the assistant may fail because it cannot see the API key, and you may run into errors like "Shell env off".</p>
</blockquote>

<p>When something feels wrong, start here:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">openclaw</span><span style="color:#A5D6FF"> logs</span><span style="color:#79C0FF"> --follow</span></span></code></pre></figure>
