<h2 id="الممارسات-الموصى-بها">الممارسات الموصى بها</h2>
<h3 id="1-التزم-دائماً-بـ-uvlock">1) التزم دائماً بـ uv.lock</h3>
<p>lockfile هو أساس قابلية التكرار. عدم الالتزام به يعني أن الجميع — كل جهاز، كل تشغيل CI — قد يثبّتون تبعيات مختلفة. إعادة إنتاج الأخطاء تصبح وضعاً جهنمياً. مشروع بدون lockfile مثل حذاء جديد لم تجربه: تكتشف أنه يؤلم فقط في المعركة.</p>
<h3 id="2-لا-تلتزم-أبداً-بـ-venv">2) لا تلتزم أبداً بـ .venv</h3>
<p>البيئة الافتراضية قطعة أثرية محلية — يجب أن تكون في <code>.gitignore</code>. uv يضيف تلقائياً <code>.venv</code> لملف تجاهل المشروع؛ فقط تأكد من وجوده.</p>
<h3 id="3-قيّد-التبعيات-عند-الإمكان">3) قيّد التبعيات عند الإمكان</h3>
<p>في <code>pyproject.toml</code>، تجنب <code>requests</code> مجرداً — فضّل <code>requests>=2.31,&#x3C;3</code> أو أكثر تحديداً. <code>uv add</code> يضيف قيوداً معقولة بشكل افتراضي؛ عند التعديل اليدوي، لا تترك النطاق واسعاً جداً.</p>
<h3 id="4-استخدم-uv-sync-أو-uv-pip-sync-في-ci">4) استخدم uv sync أو uv pip sync في CI</h3>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="yaml" data-theme="github-dark-default"><code data-language="yaml" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E"># مثال GitHub Actions</span></span>

<span data-line=""><span style="color:#E6EDF3">- </span><span style="color:#7EE787">run</span><span style="color:#E6EDF3">: </span><span style="color:#A5D6FF">uv run pytest</span></span></code></pre></figure>
<p>زامن أولاً، ثم شغّل — يضمن أن البيئة تطابق lockfile. لا تشغّل <code>uv add</code> في CI؛ ذلك يعدّل lockfile وقد يخلق فروقات غير متوقعة.</p>
<h3 id="5-ضع-أدوات-التطوير-في-optional--dev">5) ضع أدوات التطوير في optional / dev</h3>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> add</span><span style="color:#79C0FF"> --dev</span><span style="color:#A5D6FF"> pytest</span><span style="color:#A5D6FF"> ruff</span><span style="color:#A5D6FF"> mypy</span></span></code></pre></figure>
<p>الاختبارات والـ lint وفحص الأنواع لا تؤثر على تبعيات الإنتاج ولن تُحزَّم في wheel. صور الإنتاج تحتاج فقط <code>uv sync --no-dev</code>.</p>
<h2 id="المخاطر-الشائعة">المخاطر الشائعة</h2>
<h3 id="المخطر-1-خلط-pip-وuv-add">المخطر 1: خلط pip وuv add</h3>
<p>لا تستخدم كلاً من <code>pip install</code> و<code>uv add</code> في نفس venv — lockfile سيُفقَد من المزامنة. اختر مساراً واحداً وتمسك به.</p>
<h3 id="المخطر-2-استخدام-uvx-لأدوات-المشروع">المخطر 2: استخدام uvx لأدوات المشروع</h3>
<p>أدوات المشروع التي تحتاج إصداراً مثبّتاً (مثل pytest وmypy) → استخدم <code>uv add --dev</code> + <code>uv run</code>.<br>
الاستخدام المؤقت لمرة واحدة → استخدم <code>uvx</code>.</p>
<h3 id="المخطر-3-تعديل-pyprojecttoml-يدوياً-بدون-قراءته-أولاً">المخطر 3: تعديل pyproject.toml يدوياً بدون قراءته أولاً</h3>
<p>لتغييرات التبعيات، فضّل <code>uv add</code> / <code>uv remove</code> — يتجنب مشاكل الصيغة والفقدان من تحديثات lockfile.</p>
<h3 id="المخطر-4-عدم-تثبيت-uv-في-ci">المخطر 4: عدم تثبيت uv في CI</h3>
<p>أنظمة CI كثيرة تدعم الآن uv — يثبّت بسرعة ويعمل أسرع. استخدم المثبّت الرسمي أو <code>pip install uv</code>؛ لا تستمر في استخدام pip لحل التبعيات إلى الأبد.</p>
<h3 id="المخطر-5-لا-requires-python-في-المشروع">المخطر 5: لا requires-python في المشروع</h3>
<p>في <code>pyproject.toml</code>، حدد <code>requires-python = ">=3.12"</code> إلخ.، حتى تعرف الأدوات والمتعاونون متطلب الحد الأدنى من الإصدار. يمنع كارثة "يعمل على 3.12 لديّ، ينهار على 3.8 لديك."</p>
