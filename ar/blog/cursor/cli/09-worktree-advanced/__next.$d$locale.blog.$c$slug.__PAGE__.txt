3:T30bc,<p>المنشور السابق <a href="08-worktree-merge">08-worktree-merge</a> غطى worktree التلقائي في Cursor وApply. هذا يتعمق في أمرين: <strong>Best-of-N</strong> (نفس الـ prompt، نماذج متعددة بالتوازي، ثم اختر واحداً لتطبيقه) و<strong>worktrees.json</strong> (تثبيت تلقائي للتبعيات، تشغيل migrations، نسخ <code>.env</code> عند إنشاء worktree).</p>
<h2 id="best-of-n-prompt-واحد-نماذج-متعددة-دفعة-واحدة">Best-of-N: prompt واحد، نماذج متعددة دفعة واحدة</h2>
<p><strong>Best-of-N</strong> يعني: ترسل مهمة واحدة، Cursor يشغّل <strong>نماذج متعددة</strong> في worktrees منفصلة، وتحصل على "بطاقات" متعددة كل واحدة بتغييرات نموذج واحد — <strong>اختر واحدة واضغط Apply</strong>.</p>

<p>باختصار: <strong>نماذج متعددة تنفّذ نفس المهمة، أنت تختار واحداً</strong> — خاصة للمهام الصعبة أو عندما تهتم بالجودة.</p>
<h3 id="كيف-تستخدمه">كيف تستخدمه</h3>
<p>في Cursor، عند بدء Agent اختر "نماذج متعددة" أو خيار Best-of-N (حسب الواجهة الحالية). بعد إرسال الـ prompt سترى بطاقات متعددة؛ انتقل بينها للمقارنة ثم <strong>Apply</strong> التي تريدها على main.</p>
<p>إن طبّقت أكثر من بطاقة من نفس تشغيل Best-of-N (مثلاً Apply A ثم B)، قد يسأل Cursor: <strong>دمج مع حل تعارضات</strong>، أو <strong>Full Overwrite</strong> (استبدال الملف بالكامل).</p>
<h2 id="worktreesjson-تجهيز-البيئة-عند-إنشاء-worktree">worktrees.json: تجهيز البيئة عند إنشاء worktree</h2>
<p>عند إنشاء Cursor لـ worktree، ينسخ <strong>الملفات المتتبعة</strong> من المجلد الرئيسي افتراضياً، لكنه لا يثبت التبعيات ولا ينسخ <code>.env</code> ولا يشغّل migrations قاعدة البيانات.<br>
مع <strong><code>.cursor/worktrees.json</code></strong> يمكنك تحديد <strong>أوامر تُشغّل بعد إنشاء كل worktree جديد</strong>، مثل <code>npm ci</code>، <code>cp .env</code>، <code>npm run db:migrate</code>.</p>
<h3 id="أين-يكون-الإعداد">أين يكون الإعداد؟</h3>
<p>Cursor يبحث بالترتيب:</p>
<ol>
<li>جذر المشروع: <code>.cursor/worktrees.json</code></li>
<li>مسار الـ worktree</li>
</ol>
<p>عادة ضعه في <strong>جذر المشروع</strong>: <code>.cursor/worktrees.json</code>.</p>

على Windows استخدم <code>.ps1</code> وفي السكربت استخدم <code>$env:ROOT_WORKTREE_PATH</code> لمسار المجلد الرئيسي.</p>
<blockquote>
<p>نصيحة: تجنّب ربط التبعيات بـ symlink في worktree — قد يتعارض مع worktree الرئيسي؛ استخدم <code>npm ci</code>، <code>pnpm</code>، <code>bun</code>، <code>uv</code>، إلخ للتثبيت من جديد.</p>
</blockquote>
<h2 id="تنظيف-worktree-والحدود">تنظيف worktree والحدود</h2>
<p>Cursor يدير عدد worktrees حتى لا ينفد القرص:</p>
<ul>
<li>كل workspace له <strong>عدد أقصى من worktrees</strong> (مثلاً 20)</li>
<li>عند تجاوز الحد، <strong>الأقل استخداماً مؤخراً</strong> يُزال</li>
<li>التنظيف <strong>لكل workspace</strong>؛ المستودعات المختلفة لا تؤثر على بعضها</li>
</ul>
<p>للضبط (إن كانت نسخة Cursor تدعمه)، ابحث عن إعدادات مثل:</p>
<ul>
<li><code>cursor.worktreeMaxCount</code>: أقصى worktrees للاحتفاظ بها</li>
<li><code>cursor.worktreeCleanupIntervalHours</code>: كم مرة تشغّل التنظيف</li>
</ul>
<p>أسماء المفاتيح الدقيقة تعتمد على إعدادات Cursor الحالية.</p>
<h2 id="تصحيح-إعداد-worktree">تصحيح إعداد worktree</h2>
<p>إنه بعد إنشاء worktree لم تُثبَّت التبعيات أو لم تُشغَّل migrations، افتح لوحة <strong>Output</strong> في Cursor، اختر <strong>"Worktrees Setup"</strong> من القائمة المنسدلة، وراجع الأوامر والأخطاء التي نُفّذت عند الإنشاء — يساعد في تصحيح <code>worktrees.json</code> أو مشاكل السكربتات.</p>
<h2 id="ملخص">ملخص</h2>
<ul>
<li><strong>Best-of-N</strong>: نفس الـ prompt، نماذج متعددة بالتوازي في worktrees منفصلة؛ قارن وطبّق بطاقة واحدة؛ جيد للمعايير والمهام الصعبة والجودة</li>
<li><strong>worktrees.json</strong>: في <code>.cursor/worktrees.json</code> استخدم <code>setup-worktree</code> / <code>setup-worktree-windows</code> / <code>setup-worktree-unix</code> لتشغيل أوامر أو سكربتات بعد الإنشاء</li>
<li>استخدم <code>$ROOT_WORKTREE_PATH</code> (Unix) أو <code>%ROOT_WORKTREE_PATH%</code> / <code>$env:ROOT_WORKTREE_PATH</code> (Windows) لنسخ <code>.env</code> إلخ من main</li>
<li>worktrees لها حد وتنظيف تلقائي؛ التصحيح عبر Output → Worktrees Setup</li>
</ul>

9:T30bc,<p>المنشور السابق <a href="08-worktree-merge">08-worktree-merge</a> غطى worktree التلقائي في Cursor وApply. هذا يتعمق في أمرين: <strong>Best-of-N</strong> (نفس الـ prompt، نماذج متعددة بالتوازي، ثم اختر واحداً لتطبيقه) و<strong>worktrees.json</strong> (تثبيت تلقائي للتبعيات، تشغيل migrations، نسخ <code>.env</code> عند إنشاء worktree).</p>
<h2 id="best-of-n-prompt-واحد-نماذج-متعددة-دفعة-واحدة">Best-of-N: prompt واحد، نماذج متعددة دفعة واحدة</h2>
<p><strong>Best-of-N</strong> يعني: ترسل مهمة واحدة، Cursor يشغّل <strong>نماذج متعددة</strong> في worktrees منفصلة، وتحصل على "بطاقات" متعددة كل واحدة بتغييرات نموذج واحد — <strong>اختر واحدة واضغط Apply</strong>.</p>

<h3 id="كيف-تستخدمه">كيف تستخدمه</h3>
<p>في Cursor، عند بدء Agent اختر "نماذج متعددة" أو خيار Best-of-N (حسب الواجهة الحالية). بعد إرسال الـ prompt سترى بطاقات متعددة؛ انتقل بينها للمقارنة ثم <strong>Apply</strong> التي تريدها على main.</p>
<p>إن طبّقت أكثر من بطاقة من نفس تشغيل Best-of-N (مثلاً Apply A ثم B)، قد يسأل Cursor: <strong>دمج مع حل تعارضات</strong>، أو <strong>Full Overwrite</strong> (استبدال الملف بالكامل).</p>
<h2 id="worktreesjson-تجهيز-البيئة-عند-إنشاء-worktree">worktrees.json: تجهيز البيئة عند إنشاء worktree</h2>
<p>عند إنشاء Cursor لـ worktree، ينسخ <strong>الملفات المتتبعة</strong> من المجلد الرئيسي افتراضياً، لكنه لا يثبت التبعيات ولا ينسخ <code>.env</code> ولا يشغّل migrations قاعدة البيانات.<br>
مع <strong><code>.cursor/worktrees.json</code></strong> يمكنك تحديد <strong>أوامر تُشغّل بعد إنشاء كل worktree جديد</strong>، مثل <code>npm ci</code>، <code>cp .env</code>، <code>npm run db:migrate</code>.</p>
<h3 id="أين-يكون-الإعداد">أين يكون الإعداد؟</h3>

<ol>
<li>جذر المشروع: <code>.cursor/worktrees.json</code></li>
<li>مسار الـ worktree</li>
</ol>
<p>عادة ضعه في <strong>جذر المشروع</strong>: <code>.cursor/worktrees.json</code>.</p>

<h2 id="تنظيف-worktree-والحدود">تنظيف worktree والحدود</h2>
<p>Cursor يدير عدد worktrees حتى لا ينفد القرص:</p>
<ul>
<li>كل workspace له <strong>عدد أقصى من worktrees</strong> (مثلاً 20)</li>
<li>عند تجاوز الحد، <strong>الأقل استخداماً مؤخراً</strong> يُزال</li>
<li>التنظيف <strong>لكل workspace</strong>؛ المستودعات المختلفة لا تؤثر على بعضها</li>
</ul>
<p>للضبط (إن كانت نسخة Cursor تدعمه)، ابحث عن إعدادات مثل:</p>
<ul>
<li><code>cursor.worktreeMaxCount</code>: أقصى worktrees للاحتفاظ بها</li>
<li><code>cursor.worktreeCleanupIntervalHours</code>: كم مرة تشغّل التنظيف</li>
</ul>
<p>أسماء المفاتيح الدقيقة تعتمد على إعدادات Cursor الحالية.</p>
<h2 id="تصحيح-إعداد-worktree">تصحيح إعداد worktree</h2>
<p>إنه بعد إنشاء worktree لم تُثبَّت التبعيات أو لم تُشغَّل migrations، افتح لوحة <strong>Output</strong> في Cursor، اختر <strong>"Worktrees Setup"</strong> من القائمة المنسدلة، وراجع الأوامر والأخطاء التي نُفّذت عند الإنشاء — يساعد في تصحيح <code>worktrees.json</code> أو مشاكل السكربتات.</p>
<h2 id="ملخص">ملخص</h2>
<ul>
<li><strong>Best-of-N</strong>: نفس الـ prompt، نماذج متعددة بالتوازي في worktrees منفصلة؛ قارن وطبّق بطاقة واحدة؛ جيد للمعايير والمهام الصعبة والجودة</li>
<li><strong>worktrees.json</strong>: في <code>.cursor/worktrees.json</code> استخدم <code>setup-worktree</code> / <code>setup-worktree-windows</code> / <code>setup-worktree-unix</code> لتشغيل أوامر أو سكربتات بعد الإنشاء</li>
<li>استخدم <code>$ROOT_WORKTREE_PATH</code> (Unix) أو <code>%ROOT_WORKTREE_PATH%</code> / <code>$env:ROOT_WORKTREE_PATH</code> (Windows) لنسخ <code>.env</code> إلخ من main</li>
<li>worktrees لها حد وتنظيف تلقائي؛ التصحيح عبر Output → Worktrees Setup</li>
</ul>
