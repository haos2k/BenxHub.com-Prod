1b:T2582,<p><a href="04-non-interactive">04-non-interactive</a> غطى <code>--no-interactive</code> ليشغّل الـ Agent حتى النهاية دون انتظارك. هذا المنشور يتقدّم: <strong>وضع headless</strong> مع <strong><code>-p</code> / <code>--print</code></strong> لتشغيلات "المخرجات إلى الطرفية فقط"، plus <strong><code>--force</code></strong> (أو <code>--yolo</code>) حتى يعدّل الـ Agent <strong>فعلياً الملفات في مشروعك</strong> — مناسب لـ CI، JSDoc دفعة، إصلاح lint تلقائي، وتوليد التقارير.</p>
<p>باختصار: <strong>لا نافذة Cursor، لا تأكيدات بأزرار؛ سكربت يستدعي CLI لتغيير الكود، ثم السكربت يكمل.</strong></p>
<h2 id="--print-غير-تفاعلي-مخرجات-إلى-الطرفية">--print: غير تفاعلي، مخرجات إلى الطرفية</h2>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#79B8FF"> -p</span><span style="color:#9ECBFF"> "What does this project do?"</span></span>
<span data-line=""><span style="color:#6A737D"># or</span></span>
<span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#79B8FF"> --print</span><span style="color:#9ECBFF"> "List all API endpoints under src/"</span></span></code></pre></figure>
<ul>
<li><strong>بدون <code>--force</code></strong>: الـ Agent يمكنه قراءة الملفات والبحث في الكود وإرجاع التحليل، لكن <strong>لا يكتب إلى الملفات</strong> — يقترح فقط أو يطبع المحتوى في المخرجات</li>
<li>جيد لـ: سؤال وجواب، تحليل، كتابة تقارير إلى stdout، piping أو تحليل في السكربتات</li>
</ul>
<p>إذن <code>-p</code> لوحدها تعني "شغّل حتى النهاية، مخرجات إلى الطرفية"؛ هل يغيّر الملفات يعتمد على إضافة <code>--force</code>.</p>
<h2 id="--force-السماح-بتعديل-الملفات-مباشرة">--force: السماح بتعديل الملفات مباشرة</h2>
<p>مع <code>--print</code> و**<code>--force</code>** (أو <strong><code>--yolo</code></strong>)، الـ Agent <strong>يستطيع إنشاء وتعديل وحذف ملفات</strong> دون سؤال Y/N:</p>

<h2 id="مثال-سكربت-مراجعة-كود-تلقائية-وكتابة-تقرير">مثال سكربت: مراجعة كود تلقائية وكتابة تقرير</h2>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D">#!/bin/bash</span></span>
<span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#79B8FF"> -p</span><span style="color:#79B8FF"> --force</span><span style="color:#79B8FF"> --output-format</span><span style="color:#9ECBFF"> text</span><span style="color:#79B8FF"> \</span></span>

<p><code>--output-format text</code> يبقي المخرجات نصاً عادياً للكتابة إلى ملف أو piping إلى <code>grep</code>/سكربتات. المنشور التالي يغطي <code>json</code> و<code>stream-json</code>.</p>
<h2 id="البيئة-مفتاح-api">البيئة: مفتاح API</h2>
<p>وضع headless غالباً يعمل حيث لا توجد نافذة Cursor (مثلاً CI، آلة بعيدة)، فتحتاج مصادقة:</p>
<ul>
<li>اضبط المتغير: <code>export CURSOR_API_KEY=your_key</code></li>
<li>أو شغّل <code>cursor auth login</code> في تلك البيئة أولاً (إن كان مدعوماً)</li>
</ul>
<p>بدون ذلك ستحصل على أخطاء ولن يعمل الـ Agent.</p>
<h2 id="الفرق-عن---no-interactive-باختصار">الفرق عن --no-interactive (باختصار)</h2>
<table>
<thead>
<tr>
<th>الوضع</th>

<th>يعدّل الملفات؟</th>

<tr>
<td><code>--no-interactive</code></td>
<td>تشغيل في الطرفية، مشاهدة المخرجات خطوة بخطوة، لا ضغط مفتاح</td>
<td>يمكنه التعديل، لكن قد يسأل (حسب الإعداد)</td>

<h2 id="ملخص">ملخص</h2>
<ul>
<li><strong><code>-p</code> / <code>--print</code></strong>: غير تفاعلي، مخرجات إلى الطرفية عند الانتهاء؛ افتراضياً لا تعديل ملفات</li>
<li><strong><code>--force</code> / <code>--yolo</code></strong>: في وضع print، السماح للـ Agent بتعديل الملفات؛ جيد للسكربتات وCI</li>
<li>في السكربتات/CI، اضبط <code>CURSOR_API_KEY</code> أو أكمِل تسجيل الدخول</li>
<li>جرّب على نطاق صغير قبل التشغيل على المستودع بالكامل</li>
</ul>

26:T2582,<p><a href="04-non-interactive">04-non-interactive</a> غطى <code>--no-interactive</code> ليشغّل الـ Agent حتى النهاية دون انتظارك. هذا المنشور يتقدّم: <strong>وضع headless</strong> مع <strong><code>-p</code> / <code>--print</code></strong> لتشغيلات "المخرجات إلى الطرفية فقط"، plus <strong><code>--force</code></strong> (أو <code>--yolo</code>) حتى يعدّل الـ Agent <strong>فعلياً الملفات في مشروعك</strong> — مناسب لـ CI، JSDoc دفعة، إصلاح lint تلقائي، وتوليد التقارير.</p>
<p>باختصار: <strong>لا نافذة Cursor، لا تأكيدات بأزرار؛ سكربت يستدعي CLI لتغيير الكود، ثم السكربت يكمل.</strong></p>
<h2 id="--print-غير-تفاعلي-مخرجات-إلى-الطرفية">--print: غير تفاعلي، مخرجات إلى الطرفية</h2>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#79B8FF"> -p</span><span style="color:#9ECBFF"> "What does this project do?"</span></span>
<span data-line=""><span style="color:#6A737D"># or</span></span>
<span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#79B8FF"> --print</span><span style="color:#9ECBFF"> "List all API endpoints under src/"</span></span></code></pre></figure>
<ul>
<li><strong>بدون <code>--force</code></strong>: الـ Agent يمكنه قراءة الملفات والبحث في الكود وإرجاع التحليل، لكن <strong>لا يكتب إلى الملفات</strong> — يقترح فقط أو يطبع المحتوى في المخرجات</li>
<li>جيد لـ: سؤال وجواب، تحليل، كتابة تقارير إلى stdout، piping أو تحليل في السكربتات</li>
</ul>
<p>إذن <code>-p</code> لوحدها تعني "شغّل حتى النهاية، مخرجات إلى الطرفية"؛ هل يغيّر الملفات يعتمد على إضافة <code>--force</code>.</p>
<h2 id="--force-السماح-بتعديل-الملفات-مباشرة">--force: السماح بتعديل الملفات مباشرة</h2>
<p>مع <code>--print</code> و**<code>--force</code>** (أو <strong><code>--yolo</code></strong>)، الـ Agent <strong>يستطيع إنشاء وتعديل وحذف ملفات</strong> دون سؤال Y/N:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#79B8FF"> -p</span><span style="color:#79B8FF"> --force</span><span style="color:#9ECBFF"> "Refactor src/utils.js to ES6+ syntax"</span></span></code></pre></figure>

</blockquote>
<h2 id="مثال-سكربت-jsdoc-دفعة">مثال سكربت: JSDoc دفعة</h2>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D">#!/bin/bash</span></span>
<span data-line=""><span style="color:#6A737D"># For each .js under src/, ask Agent to add JSDoc and write directly</span></span>
<span data-line=""><span style="color:#B392F0">find</span><span style="color:#9ECBFF"> src/</span><span style="color:#79B8FF"> -name</span><span style="color:#9ECBFF"> "*.js"</span><span style="color:#F97583"> |</span><span style="color:#F97583"> while</span><span style="color:#79B8FF"> read</span><span style="color:#79B8FF"> -r</span><span style="color:#9ECBFF"> file</span><span style="color:#E1E4E8">; </span><span style="color:#F97583">do</span></span>
<span data-line=""><span style="color:#79B8FF">  echo</span><span style="color:#9ECBFF"> "Processing </span><span style="color:#E1E4E8">$file</span><span style="color:#9ECBFF">..."</span></span>
<span data-line=""><span style="color:#B392F0">  cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#79B8FF"> -p</span><span style="color:#79B8FF"> --force</span><span style="color:#9ECBFF"> "Add full JSDoc comments to </span><span style="color:#E1E4E8">$file</span><span style="color:#9ECBFF">, editing the file in place"</span></span>
<span data-line=""><span style="color:#F97583">done</span></span></code></pre></figure>
<p>كل ملف يُقرأ ويُكتب من الـ Agent، فشغّله على نسخة من المشروع أو فرع، أو جرّب ملفاً أو اثنين أولاً.</p>
<h2 id="مثال-سكربت-مراجعة-كود-تلقائية-وكتابة-تقرير">مثال سكربت: مراجعة كود تلقائية وكتابة تقرير</h2>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D">#!/bin/bash</span></span>
<span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#79B8FF"> -p</span><span style="color:#79B8FF"> --force</span><span style="color:#79B8FF"> --output-format</span><span style="color:#9ECBFF"> text</span><span style="color:#79B8FF"> \</span></span>
<span data-line=""><span style="color:#9ECBFF">  "Do a code review of recent changes: readability, potential bugs, security, best practices. Write conclusions and concrete suggestions to review.txt"</span></span></code></pre></figure>
<p><code>--output-format text</code> يبقي المخرجات نصاً عادياً للكتابة إلى ملف أو piping إلى <code>grep</code>/سكربتات. المنشور التالي يغطي <code>json</code> و<code>stream-json</code>.</p>
<h2 id="البيئة-مفتاح-api">البيئة: مفتاح API</h2>
<p>وضع headless غالباً يعمل حيث لا توجد نافذة Cursor (مثلاً CI، آلة بعيدة)، فتحتاج مصادقة:</p>
<ul>
<li>اضبط المتغير: <code>export CURSOR_API_KEY=your_key</code></li>
<li>أو شغّل <code>cursor auth login</code> في تلك البيئة أولاً (إن كان مدعوماً)</li>
</ul>
<p>بدون ذلك ستحصل على أخطاء ولن يعمل الـ Agent.</p>
<h2 id="الفرق-عن---no-interactive-باختصار">الفرق عن --no-interactive (باختصار)</h2>
<table>
<thead>
<tr>
<th>الوضع</th>
<th>الاستخدام النموذجي</th>
<th>يعدّل الملفات؟</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>--no-interactive</code></td>
<td>تشغيل في الطرفية، مشاهدة المخرجات خطوة بخطوة، لا ضغط مفتاح</td>
<td>يمكنه التعديل، لكن قد يسأل (حسب الإعداد)</td>
</tr>
<tr>
<td><code>-p</code> / <code>--print</code></td>
<td>سكربتات، CI، غير تفاعلي كلياً، مخرجات إلى stdout</td>
<td>افتراضياً لا</td>
</tr>
<tr>
<td><code>-p --force</code></td>
<td>نفسه، لكن السماح للـ Agent بتعديل الملفات</td>
<td>نعم، بلا سؤال</td>
</tr>
</tbody>
</table>
<p>إذن: <strong>لسكربتات "تغيّر الملفات فعلياً"</strong> استخدم <code>-p --force</code>؛ للتحليل أو التقارير إلى الطرفية فقط، <code>-p</code> كافٍ.</p>
<h2 id="ملخص">ملخص</h2>
<ul>
<li><strong><code>-p</code> / <code>--print</code></strong>: غير تفاعلي، مخرجات إلى الطرفية عند الانتهاء؛ افتراضياً لا تعديل ملفات</li>
<li><strong><code>--force</code> / <code>--yolo</code></strong>: في وضع print، السماح للـ Agent بتعديل الملفات؛ جيد للسكربتات وCI</li>
<li>في السكربتات/CI، اضبط <code>CURSOR_API_KEY</code> أو أكمِل تسجيل الدخول</li>
<li>جرّب على نطاق صغير قبل التشغيل على المستودع بالكامل</li>
</ul>
