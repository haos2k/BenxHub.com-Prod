<table>
<thead>
<tr>
<th>現象</th>
<th>主な原因</th>
<th>すぐできる対処</th>
</tr>
</thead>
<tbody>
<tr>
<td>出力形式が毎回違う</td>
<td><code>expected_output</code> が曖昧</td>
<td>形式要件を追加、必要なら <code>output_pydantic</code></td>
</tr>
<tr>
<td>後続 Task がデータを受け取れない</td>
<td><code>context</code> がない</td>
<td><code>tasks.yaml</code> で明示的に接続</td>
</tr>
<tr>
<td>Tool が呼ばれない</td>
<td>Task 指示に使用条件がない</td>
<td>「先に Tool 使用」を必須化</td>
</tr>
<tr>
<td>コスト急増</td>
<td>タスクが長い、重複呼び出し</td>

</tr>

<td>source URL と引用形式を必須化</td>
</tr>
<tr>
<td>フローが停止する</td>
<td>分岐条件が不完全</td>
<td>router の戻り値と listener 対応確認</td>
</tr>
<tr>
<td>起動直後に失敗</td>
<td>環境変数未設定</td>
<td><code>.env</code> と API キー確認</td>
</tr>
<tr>
<td>品質が安定しない</td>

<td>固定入力と受け入れ基準を作成</td>
</tr>
</tbody>
</table>
<h2 id="おすすめのデバッグ順">おすすめのデバッグ順</h2>
<ol>
<li>設定確認：<code>agents.yaml</code>、<code>tasks.yaml</code></li>
<li>入力確認：<code>inputs</code> が安定しているか</li>
<li>Tool 確認：引数と返却形式</li>
<li>最後にモデル確認：温度、文脈長、コスト</li>
</ol>
<p>順番を逆にしないこと。モデルのせいに見えて、実は YAML 1 行不足というケースは多いです。</p>
<h2 id="便利な小技">便利な小技</h2>
<p>各 Task に「出力サマリ」と「重要項目チェック」を追加します:</p>
<ul>
<li>結論があるか</li>
<li>出典があるか</li>
<li>markdown 構造に沿っているか</li>
</ul>
<p>これはワークフロー内のミニ単体テストとして機能します。</p>
