1b:T2335,<p><a href="04-non-interactive">04-non-interactive</a> では <code>--no-interactive</code> で Agent が入力待ちせず最後まで実行することを扱った。今回はさらに <strong>ヘッドレスモード</strong> の <strong><code>-p</code> / <code>--print</code></strong>（「ターミナルへの出力のみ」の実行）と <strong><code>--force</code></strong>（または <code>--yolo</code>）で、Agent が <strong>プロジェクトのファイルを実際に変更</strong> できるようにする — CI・バッチ JSDoc・自動 lint 修正・レポート生成向け。</p>
<p>要するに：<strong>Cursor ウィンドウもキー確認も不要；スクリプトが CLI を呼んでコードを変更し、スクリプトが続行する。</strong></p>
<h2 id="--print-非対話出力はターミナルへ">--print: 非対話、出力はターミナルへ</h2>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#79B8FF"> -p</span><span style="color:#9ECBFF"> "What does this project do?"</span></span>
<span data-line=""><span style="color:#6A737D"># or</span></span>
<span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#79B8FF"> --print</span><span style="color:#9ECBFF"> "List all API endpoints under src/"</span></span></code></pre></figure>
<ul>
<li><strong><code>--force</code> なし</strong>: Agent はファイルの読み取り・コードベース検索・分析結果の返却はできるが、<strong>ファイルには書かない</strong> — 提案や内容の表示のみ</li>
<li>向いているのは: Q&#x26;A、分析、レポートを stdout に書く、パイプやスクリプトでのパース</li>
</ul>
<p>つまり <code>-p</code> 単体は「最後まで実行し、出力はターミナル」；ファイルを変えるかどうかは <code>--force</code> を付けるか次第。</p>
<h2 id="--force-ファイルの直接編集を許可">--force: ファイルの直接編集を許可</h2>
<p><code>--print</code> と <strong><code>--force</code></strong>（または <strong><code>--yolo</code></strong>）を組み合わせると、Agent は Y/N を聞かずに <strong>作成・編集・削除</strong> できる：</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#79B8FF"> -p</span><span style="color:#79B8FF"> --force</span><span style="color:#9ECBFF"> "Refactor src/utils.js to ES6+ syntax"</span></span></code></pre></figure>
<table>
<thead>
<tr>
<th>用途</th>
<th>例</th>
</tr>
</thead>
<tbody>
<tr>
<td>単一ファイルのリファクタ</td>
<td><code>agent -p --force "Refactor src/foo.ts to use async/await"</code></td>
</tr>
<tr>
<td>設定に沿った lint 修正</td>
<td><code>agent -p --force "Fix all auto-fixable errors per .eslintrc"</code></td>
</tr>
<tr>
<td>バッチ JSDoc</td>
<td>下記スクリプト例参照</td>
</tr>
<tr>
<td>プロジェクト内にファイル生成</td>
<td><code>agent -p --force "Generate CONTRIBUTING.md from README"</code></td>
</tr>
</tbody>
</table>
<blockquote>
<p>⚠️ スクリプトで <code>--force</code> を使う前に、単一ファイルや狭い範囲で挙動を確認してから全体に広げること。</p>
</blockquote>
<h2 id="スクリプト例-バッチ-jsdoc">スクリプト例: バッチ JSDoc</h2>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D">#!/bin/bash</span></span>
<span data-line=""><span style="color:#6A737D"># For each .js under src/, ask Agent to add JSDoc and write directly</span></span>
<span data-line=""><span style="color:#B392F0">find</span><span style="color:#9ECBFF"> src/</span><span style="color:#79B8FF"> -name</span><span style="color:#9ECBFF"> "*.js"</span><span style="color:#F97583"> |</span><span style="color:#F97583"> while</span><span style="color:#79B8FF"> read</span><span style="color:#79B8FF"> -r</span><span style="color:#9ECBFF"> file</span><span style="color:#E1E4E8">; </span><span style="color:#F97583">do</span></span>
<span data-line=""><span style="color:#79B8FF">  echo</span><span style="color:#9ECBFF"> "Processing </span><span style="color:#E1E4E8">$file</span><span style="color:#9ECBFF">..."</span></span>
<span data-line=""><span style="color:#B392F0">  cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#79B8FF"> -p</span><span style="color:#79B8FF"> --force</span><span style="color:#9ECBFF"> "Add full JSDoc comments to </span><span style="color:#E1E4E8">$file</span><span style="color:#9ECBFF">, editing the file in place"</span></span>
<span data-line=""><span style="color:#F97583">done</span></span></code></pre></figure>
<p>各ファイルを Agent が読み書きするので、プロジェクトのコピーやブランチで実行するか、まず 1〜2 ファイルで試すとよい。</p>
<h2 id="スクリプト例-自動コードレビューとレポート書き出し">スクリプト例: 自動コードレビューとレポート書き出し</h2>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D">#!/bin/bash</span></span>
<span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#79B8FF"> -p</span><span style="color:#79B8FF"> --force</span><span style="color:#79B8FF"> --output-format</span><span style="color:#9ECBFF"> text</span><span style="color:#79B8FF"> \</span></span>
<span data-line=""><span style="color:#9ECBFF">  "Do a code review of recent changes: readability, potential bugs, security, best practices. Write conclusions and concrete suggestions to review.txt"</span></span></code></pre></figure>
<p><code>--output-format text</code> で出力をプレーンテキストにし、ファイルへの書き出しや <code>grep</code>/スクリプトへのパイプがしやすくなる。次回は <code>json</code> と <code>stream-json</code> を扱う。</p>
<h2 id="環境-api-キー">環境: API キー</h2>
<p>ヘッドレスモードは Cursor ウィンドウのない環境（CI・リモートマシンなど）で動かすことが多いため、認証が必要：</p>
<ul>
<li>環境変数: <code>export CURSOR_API_KEY=your_key</code></li>
<li>またはその環境で先に <code>cursor auth login</code> を実行（サポートされていれば）</li>
</ul>
<p>ないとエラーになり、Agent は動かない。</p>
<h2 id="--no-interactive-との違い簡潔に">--no-interactive との違い（簡潔に）</h2>
<table>
<thead>
<tr>
<th>モード</th>
<th>主な用途</th>
<th>ファイルを編集する？</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>--no-interactive</code></td>
<td>ターミナルで実行、出力をステップごとに見る、キー不要</td>
<td>編集できるが、設定次第で確認する場合あり</td>
</tr>
<tr>
<td><code>-p</code> / <code>--print</code></td>
<td>スクリプト・CI、完全非対話、出力は stdout</td>
<td>デフォルトではしない</td>
</tr>
<tr>
<td><code>-p --force</code></td>
<td>同上だが、Agent のファイル編集を許可</td>
<td>する、確認なし</td>
</tr>
</tbody>
</table>
<p>つまり <strong>「本当にファイルを変える」スクリプト</strong> には <code>-p --force</code>；分析やレポートをターミナルに出すだけなら <code>-p</code> で十分。</p>
<h2 id="まとめ">まとめ</h2>
<ul>
<li><strong><code>-p</code> / <code>--print</code></strong>: 非対話、終了時にターミナルへ出力；デフォルトではファイル編集なし</li>
<li><strong><code>--force</code> / <code>--yolo</code></strong>: print モードで Agent のファイル編集を許可；スクリプト・CI 向け</li>
<li>スクリプト/CI では <code>CURSOR_API_KEY</code> を設定するかログインを完了させる</li>
<li>全体で回す前に狭い範囲で試す</li>
</ul>

26:T2335,<p><a href="04-non-interactive">04-non-interactive</a> では <code>--no-interactive</code> で Agent が入力待ちせず最後まで実行することを扱った。今回はさらに <strong>ヘッドレスモード</strong> の <strong><code>-p</code> / <code>--print</code></strong>（「ターミナルへの出力のみ」の実行）と <strong><code>--force</code></strong>（または <code>--yolo</code>）で、Agent が <strong>プロジェクトのファイルを実際に変更</strong> できるようにする — CI・バッチ JSDoc・自動 lint 修正・レポート生成向け。</p>
<p>要するに：<strong>Cursor ウィンドウもキー確認も不要；スクリプトが CLI を呼んでコードを変更し、スクリプトが続行する。</strong></p>
<h2 id="--print-非対話出力はターミナルへ">--print: 非対話、出力はターミナルへ</h2>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#79B8FF"> -p</span><span style="color:#9ECBFF"> "What does this project do?"</span></span>
<span data-line=""><span style="color:#6A737D"># or</span></span>
<span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#79B8FF"> --print</span><span style="color:#9ECBFF"> "List all API endpoints under src/"</span></span></code></pre></figure>
<ul>
<li><strong><code>--force</code> なし</strong>: Agent はファイルの読み取り・コードベース検索・分析結果の返却はできるが、<strong>ファイルには書かない</strong> — 提案や内容の表示のみ</li>
<li>向いているのは: Q&#x26;A、分析、レポートを stdout に書く、パイプやスクリプトでのパース</li>
</ul>
<p>つまり <code>-p</code> 単体は「最後まで実行し、出力はターミナル」；ファイルを変えるかどうかは <code>--force</code> を付けるか次第。</p>
<h2 id="--force-ファイルの直接編集を許可">--force: ファイルの直接編集を許可</h2>
<p><code>--print</code> と <strong><code>--force</code></strong>（または <strong><code>--yolo</code></strong>）を組み合わせると、Agent は Y/N を聞かずに <strong>作成・編集・削除</strong> できる：</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#79B8FF"> -p</span><span style="color:#79B8FF"> --force</span><span style="color:#9ECBFF"> "Refactor src/utils.js to ES6+ syntax"</span></span></code></pre></figure>
<table>
<thead>
<tr>
<th>用途</th>
<th>例</th>
</tr>
</thead>
<tbody>
<tr>
<td>単一ファイルのリファクタ</td>
<td><code>agent -p --force "Refactor src/foo.ts to use async/await"</code></td>
</tr>
<tr>
<td>設定に沿った lint 修正</td>
<td><code>agent -p --force "Fix all auto-fixable errors per .eslintrc"</code></td>
</tr>
<tr>
<td>バッチ JSDoc</td>
<td>下記スクリプト例参照</td>
</tr>
<tr>
<td>プロジェクト内にファイル生成</td>
<td><code>agent -p --force "Generate CONTRIBUTING.md from README"</code></td>
</tr>
</tbody>
</table>
<blockquote>
<p>⚠️ スクリプトで <code>--force</code> を使う前に、単一ファイルや狭い範囲で挙動を確認してから全体に広げること。</p>
</blockquote>
<h2 id="スクリプト例-バッチ-jsdoc">スクリプト例: バッチ JSDoc</h2>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D">#!/bin/bash</span></span>
<span data-line=""><span style="color:#6A737D"># For each .js under src/, ask Agent to add JSDoc and write directly</span></span>
<span data-line=""><span style="color:#B392F0">find</span><span style="color:#9ECBFF"> src/</span><span style="color:#79B8FF"> -name</span><span style="color:#9ECBFF"> "*.js"</span><span style="color:#F97583"> |</span><span style="color:#F97583"> while</span><span style="color:#79B8FF"> read</span><span style="color:#79B8FF"> -r</span><span style="color:#9ECBFF"> file</span><span style="color:#E1E4E8">; </span><span style="color:#F97583">do</span></span>
<span data-line=""><span style="color:#79B8FF">  echo</span><span style="color:#9ECBFF"> "Processing </span><span style="color:#E1E4E8">$file</span><span style="color:#9ECBFF">..."</span></span>
<span data-line=""><span style="color:#B392F0">  cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#79B8FF"> -p</span><span style="color:#79B8FF"> --force</span><span style="color:#9ECBFF"> "Add full JSDoc comments to </span><span style="color:#E1E4E8">$file</span><span style="color:#9ECBFF">, editing the file in place"</span></span>
<span data-line=""><span style="color:#F97583">done</span></span></code></pre></figure>
<p>各ファイルを Agent が読み書きするので、プロジェクトのコピーやブランチで実行するか、まず 1〜2 ファイルで試すとよい。</p>
<h2 id="スクリプト例-自動コードレビューとレポート書き出し">スクリプト例: 自動コードレビューとレポート書き出し</h2>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D">#!/bin/bash</span></span>
<span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#79B8FF"> -p</span><span style="color:#79B8FF"> --force</span><span style="color:#79B8FF"> --output-format</span><span style="color:#9ECBFF"> text</span><span style="color:#79B8FF"> \</span></span>
<span data-line=""><span style="color:#9ECBFF">  "Do a code review of recent changes: readability, potential bugs, security, best practices. Write conclusions and concrete suggestions to review.txt"</span></span></code></pre></figure>
<p><code>--output-format text</code> で出力をプレーンテキストにし、ファイルへの書き出しや <code>grep</code>/スクリプトへのパイプがしやすくなる。次回は <code>json</code> と <code>stream-json</code> を扱う。</p>
<h2 id="環境-api-キー">環境: API キー</h2>
<p>ヘッドレスモードは Cursor ウィンドウのない環境（CI・リモートマシンなど）で動かすことが多いため、認証が必要：</p>
<ul>
<li>環境変数: <code>export CURSOR_API_KEY=your_key</code></li>
<li>またはその環境で先に <code>cursor auth login</code> を実行（サポートされていれば）</li>
</ul>
<p>ないとエラーになり、Agent は動かない。</p>
<h2 id="--no-interactive-との違い簡潔に">--no-interactive との違い（簡潔に）</h2>
<table>
<thead>
<tr>
<th>モード</th>
<th>主な用途</th>
<th>ファイルを編集する？</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>--no-interactive</code></td>
<td>ターミナルで実行、出力をステップごとに見る、キー不要</td>
<td>編集できるが、設定次第で確認する場合あり</td>
</tr>
<tr>
<td><code>-p</code> / <code>--print</code></td>
<td>スクリプト・CI、完全非対話、出力は stdout</td>
<td>デフォルトではしない</td>
</tr>
<tr>
<td><code>-p --force</code></td>
<td>同上だが、Agent のファイル編集を許可</td>
<td>する、確認なし</td>
</tr>
</tbody>
</table>
<p>つまり <strong>「本当にファイルを変える」スクリプト</strong> には <code>-p --force</code>；分析やレポートをターミナルに出すだけなら <code>-p</code> で十分。</p>
<h2 id="まとめ">まとめ</h2>
<ul>
<li><strong><code>-p</code> / <code>--print</code></strong>: 非対話、終了時にターミナルへ出力；デフォルトではファイル編集なし</li>
<li><strong><code>--force</code> / <code>--yolo</code></strong>: print モードで Agent のファイル編集を許可；スクリプト・CI 向け</li>
<li>スクリプト/CI では <code>CURSOR_API_KEY</code> を設定するかログインを完了させる</li>
<li>全体で回す前に狭い範囲で試す</li>
</ul>
