Cursor CLI セッション管理とクラウド実行

2026年3月9日·4 min read

05-tips で既に cursor agent --resume で最後の会話を続けることを紹介した。この記事では セッション と クラウド実行 をまとめる：過去の会話一覧の見方、どれを再開するか、-c でタスクをクラウドに渡してターミナルやマシンを閉じてもバックグラウンドで完了させる方法。

セッション再開: --resume

会話の途中でターミナルを閉じた、またはタスクが長くて止めた — 次は同じスレッドから続けたいとき：

直近 の会話が読み込まれる。コンテキストと以前の指示はそのままなので、リクエストを改めて説明する必要はない。

特定の会話を再開する

会話が複数あり、特定のもの を再開したい場合：

chat-id は下の「会話一覧」で確認する。

会話一覧: cursor agent ls

過去の会話（ID や識別子付き）が一覧表示される。再開したいものを選び、その ID を --resume=ID に渡す。

早見表：

コマンド 用途
cursor agent ls 会話をすべて一覧
cursor agent --resume 直近を再開
cursor agent --resume=chat-id 指定した会話を再開

クラウド実行: -c / --cloud

重いタスク — リポジトリ全体の分析、大きなドキュメント生成、多段階のリファクタ — をローカルで回すと、ターミナルを開いたままにしておく必要がある。ノートPCを閉じたり接続が切れたりすると実行も止まる。

-c（または --cloud）を使うと、この会話 をクラウドの Agent に渡せる：

  • 送信後、タスクは Cursor のクラウドで実行される
  • ターミナルを閉じても、シャットダウンしても、別の作業に移ってもよい
  • 後から、同じ Cursor アカウントで別のデバイスから --resume でその会話に戻り、結果を確認したり追加の指示を送ったりできる

つまり -c = 「クラウドで実行；PCの前で待たなくてよい」。

-c を使うタイミング

状況 おすすめ
タスクに時間がかかりそう -c でクラウド実行；閉じたあとも完了まで動く
ちょっとした質問や小さい編集 -c は不要；ローカルで実行
ネットが不安定 or クラウドに頼りたくない ローカル実行のまま；接続は維持

セッションとクラウドの組み合わせ

典型的な流れ：

  1. -c でタスクを開始し、クラウドで実行させる
  2. ターミナルを閉じる
  3. 後で cursor agent ls でその会話を探す
  4. cursor agent --resume=that-id で再接続し、結果を確認するか、さらに指示を送る

これで「長時間タスク」と「複数デバイス・シャットダウン」の両方に対応できる。

まとめ

  • cursor agent ls: 再開したい会話を探すために一覧表示
  • --resume: 直近を再開；--resume=ID: 指定した会話を再開
  • -c / --cloud: いまのタスクをクラウドで実行；ターミナルを閉じても後から --resume で再開できる
