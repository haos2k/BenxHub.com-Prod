1b:T2ea0,<p>前回 <a href="08-worktree-merge">08-worktree-merge</a> では Cursor の自動作成 worktree と Apply を扱った。今回は <strong>Best-of-N</strong>（同じプロンプトを複数モデルで並列実行し、1 つを選んで Apply）と <strong>worktrees.json</strong>（worktree 作成時に deps インストール・マイグレーション実行・<code>.env</code> コピー）の二本立て。</p>
<h2 id="best-of-n-1-プロンプト複数モデルを一括">Best-of-N: 1 プロンプト、複数モデルを一括</h2>
<p><strong>Best-of-N</strong> とは：1 つのタスクを送ると、Cursor が <strong>複数モデル</strong> を別々の worktree で実行し、各モデルの変更が「カード」として複数出る — <strong>1 枚選んで Apply</strong> する。</p>
<h3 id="いつ使うか">いつ使うか</h3>
<table>
<thead>
<tr>
<th>状況</th>
<th>利点</th>
</tr>
</thead>
<tbody>
<tr>
<td>どのモデルがコードベースに合うか分からない</td>
<td>1 回実行して出力を比較、簡易ベンチマーク</td>
</tr>
<tr>
<td>難題で 1 モデルだと edge case を逃しそう</td>
<td>モデルが違えばアプローチも違う、カバー範囲が広がる</td>
</tr>
<tr>
<td>コード品質を比較したい</td>
<td>同じリクエストでスタイル・構造を横並びで比較</td>
</tr>
<tr>
<td>難易度が高く「一発」の成功率を上げたい</td>
<td>複数モデルがそれぞれ 1 回ずつ試し、ベストを Apply</td>
</tr>
</tbody>
</table>
<p>要するに：<strong>複数モデルが同じタスクをやり、その中から 1 つを選ぶ</strong> — 難易度が高いタスクや品質を重視するときに有効。</p>
<h3 id="使い方">使い方</h3>
<p>Cursor で Agent を開始する際、「複数モデル」または Best-of-N オプション（現行 UIに応じて）を選ぶ。プロンプト送信後、複数カードが表示される；切り替えて比較し、main に <strong>Apply</strong> したい 1 枚を選ぶ。</p>
<p>同一 Best-of-N 実行から 2 枚以上 Apply する（例：A を Apply してから B）と、Cursor が <strong>マージ（コンフリクト解消）</strong> か <strong>Full Overwrite</strong>（ファイル全体を置換）を聞くことがある。</p>
<h2 id="worktreesjson-worktree-作成時に環境を整える">worktrees.json: worktree 作成時に環境を整える</h2>
<p>Cursor が worktree を作成するとき、デフォルトでは <strong>追跡済みファイル</strong> をメインディレクトリからコピーするが、deps のインストール・<code>.env</code> のコピー・DB マイグレーションは行わない。<br>
<strong><code>.cursor/worktrees.json</code></strong> で、<strong>新規 worktree 作成後に実行するコマンド</strong> を指定できる（例：<code>npm ci</code>、<code>cp .env</code>、<code>npm run db:migrate</code>）。</p>
<h3 id="設定の置き場所">設定の置き場所</h3>
<p>Cursor は次の順で参照する：</p>
<ol>
<li>プロジェクトルート: <code>.cursor/worktrees.json</code></li>
<li>worktree のパス</li>
</ol>
<p>通常は <strong>プロジェクトルート</strong> に置く：<code>.cursor/worktrees.json</code>。</p>
<h3 id="設定の-3-キー">設定の 3 キー</h3>

<td>Windows 専用；<code>setup-worktree</code> を上書き</td>
</tr>
<tr>

<td>macOS / Linux 専用；<code>setup-worktree</code> を上書き</td>

<h2 id="worktree-のクリーンアップと上限">worktree のクリーンアップと上限</h2>
<p>Cursor は worktree の数を管理してディスクを圧迫しないようにする：</p>
<ul>
<li>各ワークスペースに <strong>最大 worktree 数</strong>（例: 20）がある</li>
<li>上限を超えると <strong>最も最近使っていない</strong> ものから削除される</li>
<li>クリーンアップは <strong>ワークスペース単位</strong>；別リポジトリ同士は影響しない</li>
</ul>
<p>調整するには（Cursor のバージョンが対応していれば）、次のような設定を探す：</p>
<ul>
<li><code>cursor.worktreeMaxCount</code>: 保持する worktree の最大数</li>
<li><code>cursor.worktreeCleanupIntervalHours</code>: クリーンアップの実行間隔</li>
</ul>
<p>キー名は Cursor の現行設定に依存する。</p>
<h2 id="worktree-セットアップのデバッグ">worktree セットアップのデバッグ</h2>
<p>worktree 作成後に deps が入っていない・マイグレーションが走っていない場合は、Cursor の <strong>Output</strong> パネルを開き、ドロップダウンで <strong>「Worktrees Setup」</strong> を選ぶ。作成時に実行されたコマンドとエラーが確認でき、<code>worktrees.json</code> やスクリプトの問題のデバッグに使える。</p>

26:T2ea0,<p>前回 <a href="08-worktree-merge">08-worktree-merge</a> では Cursor の自動作成 worktree と Apply を扱った。今回は <strong>Best-of-N</strong>（同じプロンプトを複数モデルで並列実行し、1 つを選んで Apply）と <strong>worktrees.json</strong>（worktree 作成時に deps インストール・マイグレーション実行・<code>.env</code> コピー）の二本立て。</p>
<h2 id="best-of-n-1-プロンプト複数モデルを一括">Best-of-N: 1 プロンプト、複数モデルを一括</h2>
<p><strong>Best-of-N</strong> とは：1 つのタスクを送ると、Cursor が <strong>複数モデル</strong> を別々の worktree で実行し、各モデルの変更が「カード」として複数出る — <strong>1 枚選んで Apply</strong> する。</p>
<h3 id="いつ使うか">いつ使うか</h3>
<table>
<thead>
<tr>
<th>状況</th>
<th>利点</th>
</tr>
</thead>
<tbody>
<tr>
<td>どのモデルがコードベースに合うか分からない</td>
<td>1 回実行して出力を比較、簡易ベンチマーク</td>
</tr>
<tr>
<td>難題で 1 モデルだと edge case を逃しそう</td>
<td>モデルが違えばアプローチも違う、カバー範囲が広がる</td>
</tr>
<tr>
<td>コード品質を比較したい</td>
<td>同じリクエストでスタイル・構造を横並びで比較</td>
</tr>
<tr>
<td>難易度が高く「一発」の成功率を上げたい</td>
<td>複数モデルがそれぞれ 1 回ずつ試し、ベストを Apply</td>
</tr>
</tbody>
</table>
<p>要するに：<strong>複数モデルが同じタスクをやり、その中から 1 つを選ぶ</strong> — 難易度が高いタスクや品質を重視するときに有効。</p>
<h3 id="使い方">使い方</h3>
<p>Cursor で Agent を開始する際、「複数モデル」または Best-of-N オプション（現行 UIに応じて）を選ぶ。プロンプト送信後、複数カードが表示される；切り替えて比較し、main に <strong>Apply</strong> したい 1 枚を選ぶ。</p>
<p>同一 Best-of-N 実行から 2 枚以上 Apply する（例：A を Apply してから B）と、Cursor が <strong>マージ（コンフリクト解消）</strong> か <strong>Full Overwrite</strong>（ファイル全体を置換）を聞くことがある。</p>
<h2 id="worktreesjson-worktree-作成時に環境を整える">worktrees.json: worktree 作成時に環境を整える</h2>
<p>Cursor が worktree を作成するとき、デフォルトでは <strong>追跡済みファイル</strong> をメインディレクトリからコピーするが、deps のインストール・<code>.env</code> のコピー・DB マイグレーションは行わない。<br>
<strong><code>.cursor/worktrees.json</code></strong> で、<strong>新規 worktree 作成後に実行するコマンド</strong> を指定できる（例：<code>npm ci</code>、<code>cp .env</code>、<code>npm run db:migrate</code>）。</p>
<h3 id="設定の置き場所">設定の置き場所</h3>
<p>Cursor は次の順で参照する：</p>
<ol>
<li>プロジェクトルート: <code>.cursor/worktrees.json</code></li>
<li>worktree のパス</li>
</ol>
<p>通常は <strong>プロジェクトルート</strong> に置く：<code>.cursor/worktrees.json</code>。</p>
<h3 id="設定の-3-キー">設定の 3 キー</h3>

<td>Windows 専用；<code>setup-worktree</code> を上書き</td>
</tr>
<tr>
<td><code>setup-worktree-unix</code></td>
<td>macOS / Linux 専用；<code>setup-worktree</code> を上書き</td>

<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="json" data-theme="github-dark-default"><code data-language="json" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#E6EDF3">{</span></span>

Windows では <code>.ps1</code> を使い、スクリプト内でメインディレクトリのパスは <code>$env:ROOT_WORKTREE_PATH</code> を使う。</p>
<blockquote>
<p>ヒント: worktree に deps を symlink するのは避ける — メイン worktree とぶつかることがある。<code>npm ci</code>、<code>pnpm</code>、<code>bun</code>、<code>uv</code> などで新規インストールする。</p>
</blockquote>
<h2 id="worktree-のクリーンアップと上限">worktree のクリーンアップと上限</h2>
<p>Cursor は worktree の数を管理してディスクを圧迫しないようにする：</p>
<ul>
<li>各ワークスペースに <strong>最大 worktree 数</strong>（例: 20）がある</li>
<li>上限を超えると <strong>最も最近使っていない</strong> ものから削除される</li>
<li>クリーンアップは <strong>ワークスペース単位</strong>；別リポジトリ同士は影響しない</li>
</ul>
<p>調整するには（Cursor のバージョンが対応していれば）、次のような設定を探す：</p>
<ul>
<li><code>cursor.worktreeMaxCount</code>: 保持する worktree の最大数</li>
<li><code>cursor.worktreeCleanupIntervalHours</code>: クリーンアップの実行間隔</li>
</ul>
<p>キー名は Cursor の現行設定に依存する。</p>
<h2 id="worktree-セットアップのデバッグ">worktree セットアップのデバッグ</h2>
<p>worktree 作成後に deps が入っていない・マイグレーションが走っていない場合は、Cursor の <strong>Output</strong> パネルを開き、ドロップダウンで <strong>「Worktrees Setup」</strong> を選ぶ。作成時に実行されたコマンドとエラーが確認でき、<code>worktrees.json</code> やスクリプトの問題のデバッグに使える。</p>
