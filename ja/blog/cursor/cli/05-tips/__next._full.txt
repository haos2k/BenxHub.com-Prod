<h2 id="ヒント">ヒント</h2>
<h3 id="1-前の会話を再開する">1. 前の会話を再開する</h3>
<p>途中で閉じてしまって、続きからやりたいとき。最初からやり直す必要はありません：</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> --resume</span></span></code></pre></figure>
<p>直近の会話がコンテキストごと読み込まれます — 一時停止した動画の「再開」を押すようなものです。</p>
<h3 id="2-コマンド実行前に確認させる">2. コマンド実行前に確認させる</h3>
<p>Agent が <code>npm install</code> や <code>git</code> などのコマンドを実行したがることがあります。</p>
<ul>
<li><strong>対話モード</strong>: その前に確認してくれます</li>
<li>慎重にやりたいなら、会話で「どんなコマンドも実行する前に確認して」と伝えておくとよいです</li>
</ul>
<p>「いつあれを実行した？」となる場面を防げます。</p>
<h3 id="3-cli-と-ide-を併用する">3. CLI と IDE を併用する</h3>
<p>CLI と Cursor のウィンドウは <strong>同時に使えます</strong> — どちらか一方ではありません：</p>
<ul>
<li>ウィンドウはメイン開発・ファイルツリーの閲覧・Tab 補完に</li>
<li>CLI は小さいタスク・検索・自動化に</li>
</ul>
<p>メインの戦いはウィンドウ、小競り合いは CLI — 役割分担です。</p>
<h2 id="faq">FAQ</h2>
<p><strong>Q: <code>cursor: command not found</code> になる？</strong>
A: インストール後にターミナルを再起動するか、<code>source ~/.zshrc</code>（または <code>~/.bashrc</code>）を実行してください。インストール先が <code>PATH</code> に入っているか確認を。よくある「入れたのに見つからない」はほぼ PATH の問題です。</p>
<p><strong>Q: CLI は有料？</strong>
A: はい。CLI を使うには Cursor のサブスクリプションが必要で、IDE と同じサブスクです。</p>
<p><strong>Q: サーバーや Docker で使える？</strong>
A: はい。条件は、インストールスクリプトが実行できることと、Cursor にログインできる（またはトークン設定できる）こと。ネットワークと認証には注意 — 制限されたネットワークでは Cursor のクラウドに届かない可能性があります。</p>
<p><strong>Q: Cursor ウィンドウの Agent と同じ？</strong>
A: 中身の能力は同じです。違いは、CLI はターミナル用で、非対話モードやスクリプト・CI との連携ができること。同じ AI、違うインターフェースです。</p>
<h2 id="まとめ">まとめ</h2>
<ul>
<li><strong>会話の再開</strong>: <code>cursor agent --resume</code></li>
<li><strong>コマンド確認</strong>: 「どんなコマンドも実行前に確認して」と伝えられる</li>
<li><strong>CLI と IDE</strong>: 同時利用可能、二者択一ではない</li>
<li><strong>詰まったら</strong>: <code>cursor --help</code> と公式ドキュメントを確認 — 多くの問題には既知の対処がある</li>
</ul>
