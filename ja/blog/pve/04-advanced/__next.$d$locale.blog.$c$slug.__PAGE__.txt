3:T1d6f,<p>環境が<strong>1台のマシン</strong>から<strong>複数台のマシン</strong>に変わると、運用の焦点は「動けばいい」から「可用性・スケーラビリティ・自動化」に移ります。この記事はソロダンジョンからレイドへのアップグレードです。</p>
<h2 id="クラスター構築">クラスター構築</h2>
<p>適用シナリオ：集中管理・クロスノードスケジューリング・移行をしたい場合はクラスターから始める。</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># 最初のノードでクラスターを作成</span></span>
<span data-line=""><span style="color:#B392F0">pvecm</span><span style="color:#9ECBFF"> create</span><span style="color:#9ECBFF"> my-cluster</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># 他のノードが参加（マスター IP を実際のものに変更）</span></span>
<span data-line=""><span style="color:#B392F0">pvecm</span><span style="color:#9ECBFF"> add</span><span style="color:#F97583"> &#x3C;</span><span style="color:#9ECBFF">cluster-master-i</span><span style="color:#E1E4E8">p</span><span style="color:#F97583">></span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># 状態確認</span></span>
<span data-line=""><span style="color:#B392F0">pvecm</span><span style="color:#9ECBFF"> status</span></span></code></pre></figure>
<blockquote>
<p>クラスター構築後は<strong>ノードのホスト名をできるだけ変更しない</strong>；参加前に DNS・時刻同期・ネットワークが正常かを確認 — そうしないと謎の問題が発生します。</p>
</blockquote>
<h2 id="ha高可用性の設定">HA（高可用性）の設定</h2>
<p>適用シナリオ：あるノードが落ちたとき、VM が別のノードで自動的に起動し、サービスが中断しない。</p>
<p>前提条件：</p>
<ul>
<li>クラスターが存在する</li>
<li>VM のディスクが<strong>共有ストレージ</strong>上にある</li>
<li>正しい <strong>fencing</strong> メカニズムがあり、スプリットブレインを防ぐ（両方が自分がリーダーだと思う状況）</li>
</ul>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># VM 100 を HA 管理下に置く</span></span>
<span data-line=""><span style="color:#B392F0">ha-manager</span><span style="color:#9ECBFF"> add</span><span style="color:#9ECBFF"> vm:100</span><span style="color:#79B8FF"> --maxrestart</span><span style="color:#79B8FF"> 3</span><span style="color:#79B8FF"> --maxrelocate</span><span style="color:#79B8FF"> 5</span></span></code></pre></figure>
<p>HA が正しく設定されていれば、単一ノードの障害時もユーザーはほぼ気づかない — 猫が常に別の寝場所を確保しているようなもの。</p>
<h2 id="ceph-ハイパーコンバージドストレージ">Ceph ハイパーコンバージドストレージ</h2>
<p>適用シナリオ：複数ノードで共有ストレージと高可用性の両方が必要 — Ceph で一緒に解決。</p>
<p>推奨前提条件：</p>
<ul>
<li>少なくとも <strong>3 ノード</strong>（Ceph は単一点が苦手）</li>
<li>各ノードに複数の<strong>専用ディスク</strong></li>
<li>専用ストレージネットワークがあればさらに良い</li>
</ul>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># Ceph を初期化</span></span>
<span data-line=""><span style="color:#B392F0">pveceph</span><span style="color:#9ECBFF"> init</span><span style="color:#79B8FF"> --network</span><span style="color:#9ECBFF"> 10.0.0.0/24</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># 各データディスクに OSD を作成</span></span>
<span data-line=""><span style="color:#B392F0">pveceph</span><span style="color:#9ECBFF"> osd</span><span style="color:#9ECBFF"> create</span><span style="color:#9ECBFF"> /dev/sdX</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># Pool を作成して PVE に接続</span></span>
<span data-line=""><span style="color:#B392F0">pveceph</span><span style="color:#9ECBFF"> pool</span><span style="color:#9ECBFF"> create</span><span style="color:#9ECBFF"> vm-data</span><span style="color:#79B8FF"> --add_storages</span></span></code></pre></figure>
<blockquote>
<p>Ceph は<strong>ベアディスクを直接管理</strong>することを推奨 — ハードウェア RAID を重ねないように。それだと Ceph のデータ保護と観測性が半減します。</p>
</blockquote>
<h2 id="ストレージ複製">ストレージ複製</h2>
<p>適用シナリオ：クロスノードの冗長性、障害時の迅速な引き継ぎ。</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">pvesr</span><span style="color:#9ECBFF"> create-local-job</span><span style="color:#79B8FF"> 100</span><span style="color:#9ECBFF"> local-zfs</span><span style="color:#9ECBFF"> remote-zfs</span><span style="color:#79B8FF"> --schedule</span><span style="color:#9ECBFF"> "0 2 * * *"</span></span></code></pre></figure>
<h2 id="api-と自動化の統合">API と自動化の統合</h2>
<p>適用シナリオ：スクリプトでの操作・CI/CD・他のプラットフォームとの統合。<strong>API トークン</strong>を使うことを推奨 — root パスワードをあちこちに貼り付けない。</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># API トークンで VM リストを取得</span></span>
<span data-line=""><span style="color:#B392F0">curl</span><span style="color:#79B8FF"> -k</span><span style="color:#79B8FF"> \</span></span>
<span data-line=""><span style="color:#79B8FF">  -H</span><span style="color:#9ECBFF"> "Authorization: PVEAPIToken=user@realm!tokenid=secret"</span><span style="color:#79B8FF"> \</span></span>
<span data-line=""><span style="color:#9ECBFF">  "https://&#x3C;PVE-IP>:8006/api2/json/nodes/&#x3C;node>/qemu"</span></span></code></pre></figure>
<p>自動化が整ったら、繰り返し作業はスクリプトに任せて、あなたはコーヒーと猫を楽しめます。</p>
