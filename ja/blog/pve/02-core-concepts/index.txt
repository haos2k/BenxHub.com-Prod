<h2 id="コンセプト-1vm-と-lxc-の違い">コンセプト 1：VM と LXC の違い</h2>
<table>
<thead>
<tr>
<th>種類</th>
<th>技術</th>
<th>特性</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>VM</strong></td>
<td>KVM/QEMU</td>
<td>フル OS、高い分離性、Windows/Linux 両方動作</td>
</tr>
<tr>
<td><strong>LXC</strong></td>
<td>Linux コンテナ</td>
<td>軽量・高速起動・高密度、ただし <strong>Linux のみ</strong></td>
</tr>
</tbody>
</table>
<p><strong>一言で判断</strong>：完全な分離が必要か Windows を動かしたい → VM；リソースを節約したくサービスが Linux → LXC。間違えるとビーチサンダルで登山するようなもの — 不可能ではないけど苦労します。</p>

<h2 id="コンセプト-2ストレージの選択が今後を決める">コンセプト 2：ストレージの選択が今後を決める</h2>
<p>ストレージを間違えると、後で HA や移行で詰まります。よくある種類：</p>
<ul>
<li><strong>local</strong>：シングルノードのディレクトリ型、入門に最適</li>
<li><strong>local-lvm</strong>：ローカル LVM、スナップショットとクローンに便利</li>
<li><strong>NFS/CIFS</strong>：共有ネットワークストレージ、クロスノード対応</li>
<li><strong>ZFS/Ceph</strong>：複製と高可用性のための高度なソリューション</li>
</ul>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E"># 現在のストレージ状態を確認</span></span>
<span data-line=""><span style="color:#FFA657">pvesm</span><span style="color:#A5D6FF"> status</span></span>
<span data-line=""><span style="color:#FFA657">pvesm</span><span style="color:#A5D6FF"> list</span><span style="color:#A5D6FF"> local</span></span></code></pre></figure>
<blockquote>
<p>ライブマイグレーションや HA をする場合、ディスクは通常<strong>共有ストレージ</strong>上にある必要があります — そうでないと VM を移動できません。まるで引っ越ししようとしたが家具が他人の家に鍵かけて保管されているようなもの。</p>
</blockquote>
<h2 id="コンセプト-3ネットワークモデルvmbr0">コンセプト 3：ネットワークモデル（vmbr0）</h2>
<p>PVE はデフォルトでブリッジネットワークを使用します：<code>vmbr0</code> が物理 NIC にブリッジされ、VM が物理スイッチに直接接続されているように見えます。簡単に言えば：<strong>1本の仮想ケーブル、全員が外向きの NIC を共有します。</strong></p>

<h2 id="コンセプト-4ノードとクラスター">コンセプト 4：ノードとクラスター</h2>
<ul>
<li><strong>シングルノード</strong>：1台のマシンですべてを処理、スタートアップとホームラボに適している</li>
<li><strong>クラスター</strong>：複数のホストをまとめて管理、移行と HA をサポート — パーティーを組んでダンジョンに挑戦するようなもの</li>
</ul>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="text" data-theme="github-dark-default"><code data-language="text" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span>[Node1] &#x3C;--> [Node2] &#x3C;--> [Node3]</span></span>

<p>重要な一言：管理プレーンが統一され、リソースがスケジュール可能で、障害を引き継げる。このコンセプトを先に理解していれば、上級編がずっと分かりやすくなります。</p>

<span data-line=""><span style="color:#FFA657">pct</span><span style="color:#A5D6FF"> create</span><span style="color:#79C0FF"> 200</span><span style="color:#A5D6FF"> local:vztmpl/debian-12-standard_12.2-1_amd64.tar.zst</span><span style="color:#79C0FF"> --hostname</span><span style="color:#A5D6FF"> my-ct</span><span style="color:#79C0FF"> --memory</span><span style="color:#79C0FF"> 512</span></span></code></pre></figure>
<h2 id="コンセプト-2ストレージの選択が今後を決める">コンセプト 2：ストレージの選択が今後を決める</h2>
<p>ストレージを間違えると、後で HA や移行で詰まります。よくある種類：</p>
<ul>
<li><strong>local</strong>：シングルノードのディレクトリ型、入門に最適</li>
<li><strong>local-lvm</strong>：ローカル LVM、スナップショットとクローンに便利</li>
<li><strong>NFS/CIFS</strong>：共有ネットワークストレージ、クロスノード対応</li>
<li><strong>ZFS/Ceph</strong>：複製と高可用性のための高度なソリューション</li>
</ul>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E"># 現在のストレージ状態を確認</span></span>
<span data-line=""><span style="color:#FFA657">pvesm</span><span style="color:#A5D6FF"> status</span></span>
<span data-line=""><span style="color:#FFA657">pvesm</span><span style="color:#A5D6FF"> list</span><span style="color:#A5D6FF"> local</span></span></code></pre></figure>
<blockquote>
<p>ライブマイグレーションや HA をする場合、ディスクは通常<strong>共有ストレージ</strong>上にある必要があります — そうでないと VM を移動できません。まるで引っ越ししようとしたが家具が他人の家に鍵かけて保管されているようなもの。</p>
</blockquote>
<h2 id="コンセプト-3ネットワークモデルvmbr0">コンセプト 3：ネットワークモデル（vmbr0）</h2>
<p>PVE はデフォルトでブリッジネットワークを使用します：<code>vmbr0</code> が物理 NIC にブリッジされ、VM が物理スイッチに直接接続されているように見えます。簡単に言えば：<strong>1本の仮想ケーブル、全員が外向きの NIC を共有します。</strong></p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="text" data-theme="github-dark-default"><code data-language="text" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span>[物理 NIC] --> [vmbr0] --> [VM1] [VM2] [VM3]</span></span></code></pre></figure>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E"># 現在のネットワーク設定を確認</span></span>
<span data-line=""><span style="color:#FFA657">cat</span><span style="color:#A5D6FF"> /etc/network/interfaces</span></span></code></pre></figure>
<h2 id="コンセプト-4ノードとクラスター">コンセプト 4：ノードとクラスター</h2>
<ul>
<li><strong>シングルノード</strong>：1台のマシンですべてを処理、スタートアップとホームラボに適している</li>
<li><strong>クラスター</strong>：複数のホストをまとめて管理、移行と HA をサポート — パーティーを組んでダンジョンに挑戦するようなもの</li>
</ul>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="text" data-theme="github-dark-default"><code data-language="text" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span>[Node1] &#x3C;--> [Node2] &#x3C;--> [Node3]</span></span>
<span data-line=""><span>   \\_______ shared config (pmxcfs) _______//</span></span></code></pre></figure>
<p>重要な一言：管理プレーンが統一され、リソースがスケジュール可能で、障害を引き継げる。このコンセプトを先に理解していれば、上級編がずっと分かりやすくなります。</p>
