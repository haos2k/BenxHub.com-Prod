<h2 id="vps-へのインストールはどんな感じ">VPS へのインストールはどんな感じ？</h2>
<p>Ubuntu や Debian の VPS にログインし、<a href="https://docs.openclaw.ai">docs.openclaw.ai</a> の Linux インストール手順に従います。基本的にはローカルインストールとほぼ同じで、実行場所がリモートになるだけです。</p>
<hr>
<h2 id="リモート認証の基本">リモート認証の基本</h2>
<p>Gateway を VPS に置いたら、OpenClaw はあなたが正規ユーザーかどうか確認する必要があります。</p>
<ul>
<li>token またはデバイスペアリングが必要</li>
<li><code>unauthorized</code> が出たら <code>gateway.bind</code> と token を確認</li>
</ul>
<hr>
<h2 id="tailscale-がいちばんきれい">Tailscale がいちばんきれい</h2>
<p><strong>Tailscale</strong> を使うと、スマホ、PC、VPS が同じプライベートネットワーク上にあるように扱えます。</p>
<ol>
<li>VPS と自分の PC の両方に Tailscale を入れる</li>
<li><code>gateway.bind: tailnet</code> を設定する</li>
<li>どの端末からでも Tailscale 経由で Gateway に接続する</li>
</ol>
<blockquote>
<p>💡 Tailscale は Serve で HTTPS を出すこともでき、生ポートを公開するより安全なことが多いです。</p>
</blockquote>
<hr>
<h2 id="node-とは">Node とは？</h2>
<p>ここが面白いところで、<strong>Gateway と Node は別々のマシンに置けます</strong>。</p>
<ul>
<li><strong>Gateway</strong>: VPS 上で動き、会話、メモリ、Telegram など「頭脳」の役割を担う</li>
<li><strong>Node</strong>: 自宅 PC 上で動き、ブラウザ操作、ローカルファイルアクセス、画面操作など「手足」を担う</li>
</ul>
<p>たとえば外出先から Telegram で「家の PC のブラウザを開いてこのサイトを見て」と頼むと、Gateway が自宅の Node に依頼し、結果を返してくれます。</p>
<p><strong>SSH と何が違う？</strong></p>
<p>SSH は自分でログインして自分でコマンドを打ちます。Node なら <strong>アシスタントが代わりにやってくれる</strong> ので、Skills やワークスペース、会話と一体で使えます。</p>
