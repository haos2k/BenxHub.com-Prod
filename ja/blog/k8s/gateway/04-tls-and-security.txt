<h2 id="gateway-で-tls-はどう動くのか">Gateway で TLS はどう動くのか</h2>
<p>最も一般的なやり方は、<strong>Gateway listener で TLS を terminate する</strong>ことです。</p>
<p>意味:</p>
<ul>
<li>client は HTTPS で接続する</li>
<li>Gateway が handshake と証明書を処理する</li>
<li>その後のトラフィックは内部では平文のまま Service へ転送される</li>
</ul>
<p>基本的な HTTPS listener はこうです。</p>

<p>ここで大事なのは 2 点です。</p>
<ul>
<li><code>protocol: HTTPS</code></li>
<li><code>tls.mode: Terminate</code></li>
</ul>
<p>つまり、TLS はここで終端し、Gateway が証明書を扱うということです。</p>
<h2 id="https--httproute-と-tlsroute-の違い"><code>HTTPS + HTTPRoute</code> と <code>TLSRoute</code> の違い</h2>
<p>ここは重要です。<code>TLSRoute</code> を見ると、多くの人がすぐこう思います。</p>
<p>「HTTPS listener があれば足りるのでは? なぜ別に <code>TLSRoute</code> が必要なの?」</p>
<p>違いは <strong>Gateway が TLS を terminate するかどうか</strong> にあります。</p>
<table>
<thead>
<tr>
<th>シナリオ</th>
<th>よくある組み合わせ</th>
<th>説明</th>
</tr>
</thead>
<tbody>
<tr>
<td>Gateway が TLS を terminate し、その後 HTTP ルールを適用する</td>
<td><code>HTTPS listener + HTTPRoute</code></td>
<td>最も一般的な web サイト / API パターン</td>
</tr>
<tr>
<td>Gateway は復号せず、SNI だけで暗号化トラフィックを route する</td>
<td><code>TLS listener + TLSRoute</code></td>
<td>TLS passthrough パターン</td>
</tr>
</tbody>
</table>
<p>つまり:</p>
<ul>
<li>Gateway で <code>path</code>、<code>header</code>、<code>method</code> を見たいなら、まず TLS を terminate してから <code>HTTPRoute</code> を使う必要がある</li>
<li>end-to-end 暗号化を保ち、Gateway で復号したくないなら <code>TLSRoute</code> が正しい道筋</li>
</ul>
<p>どちらが「より上級」かではありません。大事なのは、自分が欲しいのが「TLS を terminate して L7 routing したい」のか、「暗号化を保ったまま SNI ベース routing したい」のかを理解することです。</p>

<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">kubectl</span><span style="color:#9ECBFF"> get</span><span style="color:#9ECBFF"> gateway/eg</span><span style="color:#79B8FF"> -o</span><span style="color:#9ECBFF"> yaml</span></span></code></pre></figure>
<p>listener が正常そうなら HTTPS を試します。</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">curl</span><span style="color:#79B8FF"> -v</span><span style="color:#79B8FF"> -HHost:www.example.com</span><span style="color:#79B8FF">   --resolve</span><span style="color:#9ECBFF"> "www.example.com:443:${</span><span style="color:#E1E4E8">GATEWAY_HOST</span><span style="color:#9ECBFF">}"</span><span style="color:#79B8FF">   --cacert</span><span style="color:#9ECBFF"> example.com.crt</span><span style="color:#9ECBFF">   https://www.example.com/get</span></span></code></pre></figure>
<p>このコマンドはローカル検証にかなり便利です。特に DNS がまだ張られていない段階で役立ちます。</p>
<h2 id="1-つの-gateway-で複数-https-domain-を扱う">1 つの Gateway で複数 HTTPS domain を扱う</h2>
<p>複数 domain がある場合、同じ Gateway に複数の HTTPS listener を追加します。
たとえば <code>foo.example.com</code> を足すなら:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="yaml" data-theme="github-dark"><code data-language="yaml" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#85E89D">listeners</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">  - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">https-main</span></span>
<span data-line=""><span style="color:#85E89D">    protocol</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">HTTPS</span></span>
<span data-line=""><span style="color:#85E89D">    port</span><span style="color:#E1E4E8">: </span><span style="color:#79B8FF">443</span></span>
<span data-line=""><span style="color:#85E89D">    hostname</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">www.example.com</span></span>
<span data-line=""><span style="color:#85E89D">    tls</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">      mode</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">Terminate</span></span>
<span data-line=""><span style="color:#85E89D">      certificateRefs</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">        - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">example-cert</span></span>
<span data-line=""><span style="color:#E1E4E8">  - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">https-foo</span></span>
<span data-line=""><span style="color:#85E89D">    protocol</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">HTTPS</span></span>
<span data-line=""><span style="color:#85E89D">    port</span><span style="color:#E1E4E8">: </span><span style="color:#79B8FF">443</span></span>
<span data-line=""><span style="color:#85E89D">    hostname</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">foo.example.com</span></span>
<span data-line=""><span style="color:#85E89D">    tls</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">      mode</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">Terminate</span></span>
<span data-line=""><span style="color:#85E89D">      certificateRefs</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">        - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">foo-cert</span></span></code></pre></figure>
<p>対応する <code>HTTPRoute</code> 側の hostname も正しく更新するのを忘れないでください。listener が待ち受けていても、route が送信先を知らなければトラフィックは流れません。</p>
<h2 id="tlsroute-のメンタルモデル"><code>TLSRoute</code> のメンタルモデル</h2>
<p>TLS passthrough では、<code>TLSRoute</code> を次のように捉えるとわかりやすいです。</p>
<blockquote>
<p>💡 <code>TLSRoute</code> の <code>apiVersion</code> は、インストールしている Gateway API CRD の version によって異なる場合があります。以下は概念説明用の例です。適用前に cluster に入っている version を確認してください。</p>
</blockquote>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="yaml" data-theme="github-dark"><code data-language="yaml" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#85E89D">apiVersion</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">gateway.networking.k8s.io/v1</span></span>
<span data-line=""><span style="color:#85E89D">kind</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">Gateway</span></span>
<span data-line=""><span style="color:#85E89D">metadata</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">  name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">eg-tls</span></span>
<span data-line=""><span style="color:#85E89D">spec</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">  gatewayClassName</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">eg</span></span>
<span data-line=""><span style="color:#85E89D">  listeners</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">    - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">tls</span></span>
<span data-line=""><span style="color:#85E89D">      protocol</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">TLS</span></span>
<span data-line=""><span style="color:#85E89D">      port</span><span style="color:#E1E4E8">: </span><span style="color:#79B8FF">443</span></span>
<span data-line=""><span style="color:#B392F0">---</span></span>
<span data-line=""><span style="color:#85E89D">apiVersion</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">gateway.networking.k8s.io/v1alpha2</span></span>
<span data-line=""><span style="color:#85E89D">kind</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">TLSRoute</span></span>
<span data-line=""><span style="color:#85E89D">metadata</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">  name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">passthrough-route</span></span>
<span data-line=""><span style="color:#85E89D">spec</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">  parentRefs</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">    - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">eg-tls</span></span>
<span data-line=""><span style="color:#85E89D">  hostnames</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">    - </span><span style="color:#9ECBFF">"db.example.com"</span></span>
<span data-line=""><span style="color:#85E89D">  rules</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">    - </span><span style="color:#85E89D">backendRefs</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">        - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">db-service</span></span>
<span data-line=""><span style="color:#85E89D">          port</span><span style="color:#E1E4E8">: </span><span style="color:#79B8FF">5432</span></span></code></pre></figure>
<p>このパターンのよくある用途:</p>
<ul>
<li>SNI hostname だけで route する</li>
<li>暗号化を backend まで保つ</li>
<li>Gateway では HTTP path/header を解釈しない</li>
</ul>
<p>つまり <code>TLSRoute</code> と <code>HTTPRoute</code> の違いは名前だけではなく、扱っているトラフィック層がまったく違います。</p>
<h2 id="cross-namespace-の証明書参照">Cross-Namespace の証明書参照</h2>
<p>公式ドキュメントが強調している便利な機能があります。
<strong>Gateway は他 namespace の certificate Secret を参照できますが、そのためには <code>ReferenceGrant</code> が必要です。</strong></p>
<p>たとえば platform team が <code>envoy-gateway-system</code> に証明書を集約し、application 側の Gateway が <code>default</code> にある場合、明示的な許可なしに namespace をまたいで参照することはできません。</p>
<p>例:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="yaml" data-theme="github-dark"><code data-language="yaml" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#85E89D">apiVersion</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">gateway.networking.k8s.io/v1beta1</span></span>
<span data-line=""><span style="color:#85E89D">kind</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">ReferenceGrant</span></span>
<span data-line=""><span style="color:#85E89D">metadata</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">  name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">allow-default-to-read-cert</span></span>
<span data-line=""><span style="color:#85E89D">  namespace</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">envoy-gateway-system</span></span>
<span data-line=""><span style="color:#85E89D">spec</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">  from</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">    - </span><span style="color:#85E89D">group</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">gateway.networking.k8s.io</span></span>
<span data-line=""><span style="color:#85E89D">      kind</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">Gateway</span></span>
<span data-line=""><span style="color:#85E89D">      namespace</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">default</span></span>
<span data-line=""><span style="color:#85E89D">  to</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">    - </span><span style="color:#85E89D">group</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">""</span></span>
<span data-line=""><span style="color:#85E89D">      kind</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">Secret</span></span></code></pre></figure>
<p>意味:</p>
<ul>
<li><code>default</code> namespace の <code>Gateway</code> が</li>
<li><code>envoy-gateway-system</code> にある <code>Secret</code> を参照することを許可する</li>
</ul>
<p><code>ReferenceGrant</code> がなければ、この cross-namespace reference は invalid として扱われます。Gateway API が意地悪なのではなく、防御のための仕組みです。</p>
<h2 id="一文まとめ">一文まとめ</h2>
<p>Envoy Gateway の TLS は、響きほど謎ではありません。certificate Secret を用意し、HTTPS listener を設定し、route と hostname を揃える。基本はこれでほぼ完了です。</p>
<blockquote>
<p>💡 初心者が最もやりがちな失敗は、TLS が難しすぎることではありません。<code>hostname</code>、<code>certificateRefs</code>、<code>HTTPRoute hostnames</code> の 3 つが揃っていないことです。どれか 1 つずれると、トラフィックはすぐ不機嫌になります。</p>
</blockquote>

<h2 id="gateway-で-tls-はどう動くのか">Gateway で TLS はどう動くのか</h2>
<p>最も一般的なやり方は、<strong>Gateway listener で TLS を terminate する</strong>ことです。</p>
<p>意味:</p>
<ul>
<li>client は HTTPS で接続する</li>
<li>Gateway が handshake と証明書を処理する</li>
<li>その後のトラフィックは内部では平文のまま Service へ転送される</li>
</ul>
<p>基本的な HTTPS listener はこうです。</p>

<ul>

<h2 id="https--httproute-と-tlsroute-の違い"><code>HTTPS + HTTPRoute</code> と <code>TLSRoute</code> の違い</h2>
<p>ここは重要です。<code>TLSRoute</code> を見ると、多くの人がすぐこう思います。</p>
<p>「HTTPS listener があれば足りるのでは? なぜ別に <code>TLSRoute</code> が必要なの?」</p>
<p>違いは <strong>Gateway が TLS を terminate するかどうか</strong> にあります。</p>
<table>
<thead>
<tr>
<th>シナリオ</th>
<th>よくある組み合わせ</th>
<th>説明</th>
</tr>
</thead>
<tbody>
<tr>
<td>Gateway が TLS を terminate し、その後 HTTP ルールを適用する</td>
<td><code>HTTPS listener + HTTPRoute</code></td>
<td>最も一般的な web サイト / API パターン</td>
</tr>
<tr>
<td>Gateway は復号せず、SNI だけで暗号化トラフィックを route する</td>
<td><code>TLS listener + TLSRoute</code></td>
<td>TLS passthrough パターン</td>
</tr>
</tbody>
</table>
<p>つまり:</p>
<ul>
<li>Gateway で <code>path</code>、<code>header</code>、<code>method</code> を見たいなら、まず TLS を terminate してから <code>HTTPRoute</code> を使う必要がある</li>
<li>end-to-end 暗号化を保ち、Gateway で復号したくないなら <code>TLSRoute</code> が正しい道筋</li>
</ul>
<p>どちらが「より上級」かではありません。大事なのは、自分が欲しいのが「TLS を terminate して L7 routing したい」のか、「暗号化を保ったまま SNI ベース routing したい」のかを理解することです。</p>
<h2 id="証明書-secret-を用意する">証明書 Secret を用意する</h2>
<p>テスト環境なら self-signed certificate で十分です。公式例でもこの形を使っています。</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">openssl</span><span style="color:#9ECBFF"> req</span><span style="color:#79B8FF"> -x509</span><span style="color:#79B8FF"> -sha256</span><span style="color:#79B8FF"> -nodes</span><span style="color:#79B8FF"> -days</span><span style="color:#79B8FF"> 365</span><span style="color:#79B8FF"> -newkey</span><span style="color:#9ECBFF"> rsa:2048</span><span style="color:#79B8FF">   -subj</span><span style="color:#9ECBFF"> '/O=example Inc./CN=example.com'</span><span style="color:#79B8FF">   -keyout</span><span style="color:#9ECBFF"> example.com.key</span><span style="color:#79B8FF">   -out</span><span style="color:#9ECBFF"> example.com.crt</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#B392F0">openssl</span><span style="color:#9ECBFF"> req</span><span style="color:#79B8FF"> -out</span><span style="color:#9ECBFF"> www.example.com.csr</span><span style="color:#79B8FF"> -newkey</span><span style="color:#9ECBFF"> rsa:2048</span><span style="color:#79B8FF"> -nodes</span><span style="color:#79B8FF">   -keyout</span><span style="color:#9ECBFF"> www.example.com.key</span><span style="color:#79B8FF">   -subj</span><span style="color:#9ECBFF"> "/CN=www.example.com/O=example organization"</span></span>

<p>cert/key を Kubernetes Secret として保存します。</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">kubectl</span><span style="color:#9ECBFF"> create</span><span style="color:#9ECBFF"> secret</span><span style="color:#9ECBFF"> tls</span><span style="color:#9ECBFF"> example-cert</span><span style="color:#79B8FF">   --key=www.example.com.key</span><span style="color:#79B8FF">   --cert=www.example.com.crt</span></span></code></pre></figure>
<p>その後 <code>Gateway</code> から <code>certificateRefs</code> 経由でこの Secret を参照できます。</p>
<blockquote>
<p>⚠️ self-signed cert はテスト用に限ります。本番では cert-manager など既存の証明書管理フローを使ってください。デモ構成をそのまま本番へ持ち込むのは、カップ麺だけで生活するようなもので、たまにならいいけれど長期運用には向きません。</p>
</blockquote>
<h2 id="既存-gateway-に-https-listener-を追加する">既存 Gateway に HTTPS listener を追加する</h2>
<p>前の記事の <code>eg</code> Gateway がすでにあるなら、そのまま patch できます。</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">kubectl</span><span style="color:#9ECBFF"> patch</span><span style="color:#9ECBFF"> gateway</span><span style="color:#9ECBFF"> eg</span><span style="color:#79B8FF"> --type=json</span><span style="color:#79B8FF"> --patch</span><span style="color:#9ECBFF"> '</span></span>
<span data-line=""><span style="color:#9ECBFF">  - op: add</span></span>
<span data-line=""><span style="color:#9ECBFF">    path: /spec/listeners/-</span></span>
<span data-line=""><span style="color:#9ECBFF">    value:</span></span>
<span data-line=""><span style="color:#9ECBFF">      name: https</span></span>
<span data-line=""><span style="color:#9ECBFF">      protocol: HTTPS</span></span>
<span data-line=""><span style="color:#9ECBFF">      port: 443</span></span>
<span data-line=""><span style="color:#9ECBFF">      tls:</span></span>
<span data-line=""><span style="color:#9ECBFF">        mode: Terminate</span></span>
<span data-line=""><span style="color:#9ECBFF">        certificateRefs:</span></span>
<span data-line=""><span style="color:#9ECBFF">        - kind: Secret</span></span>

<span data-line=""><span style="color:#9ECBFF">          name: example-cert</span></span>
<span data-line=""><span style="color:#9ECBFF">'</span></span></code></pre></figure>
<p>status を確認します。</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">kubectl</span><span style="color:#9ECBFF"> get</span><span style="color:#9ECBFF"> gateway/eg</span><span style="color:#79B8FF"> -o</span><span style="color:#9ECBFF"> yaml</span></span></code></pre></figure>
<p>listener が正常そうなら HTTPS を試します。</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">curl</span><span style="color:#79B8FF"> -v</span><span style="color:#79B8FF"> -HHost:www.example.com</span><span style="color:#79B8FF">   --resolve</span><span style="color:#9ECBFF"> "www.example.com:443:${</span><span style="color:#E1E4E8">GATEWAY_HOST</span><span style="color:#9ECBFF">}"</span><span style="color:#79B8FF">   --cacert</span><span style="color:#9ECBFF"> example.com.crt</span><span style="color:#9ECBFF">   https://www.example.com/get</span></span></code></pre></figure>
<p>このコマンドはローカル検証にかなり便利です。特に DNS がまだ張られていない段階で役立ちます。</p>
<h2 id="1-つの-gateway-で複数-https-domain-を扱う">1 つの Gateway で複数 HTTPS domain を扱う</h2>
<p>複数 domain がある場合、同じ Gateway に複数の HTTPS listener を追加します。
たとえば <code>foo.example.com</code> を足すなら:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="yaml" data-theme="github-dark"><code data-language="yaml" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#85E89D">listeners</span><span style="color:#E1E4E8">:</span></span>

<span data-line=""><span style="color:#85E89D">      certificateRefs</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">        - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">example-cert</span></span>
<span data-line=""><span style="color:#E1E4E8">  - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">https-foo</span></span>

<span data-line=""><span style="color:#85E89D">    tls</span><span style="color:#E1E4E8">:</span></span>

<h2 id="tlsroute-のメンタルモデル"><code>TLSRoute</code> のメンタルモデル</h2>
<p>TLS passthrough では、<code>TLSRoute</code> を次のように捉えるとわかりやすいです。</p>
<blockquote>
<p>💡 <code>TLSRoute</code> の <code>apiVersion</code> は、インストールしている Gateway API CRD の version によって異なる場合があります。以下は概念説明用の例です。適用前に cluster に入っている version を確認してください。</p>
</blockquote>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="yaml" data-theme="github-dark"><code data-language="yaml" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#85E89D">apiVersion</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">gateway.networking.k8s.io/v1</span></span>

<span data-line=""><span style="color:#85E89D">metadata</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">  name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">eg-tls</span></span>
<span data-line=""><span style="color:#85E89D">spec</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">  gatewayClassName</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">eg</span></span>
<span data-line=""><span style="color:#85E89D">  listeners</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">    - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">tls</span></span>

<span data-line=""><span style="color:#85E89D">      port</span><span style="color:#E1E4E8">: </span><span style="color:#79B8FF">443</span></span>
<span data-line=""><span style="color:#B392F0">---</span></span>
<span data-line=""><span style="color:#85E89D">apiVersion</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">gateway.networking.k8s.io/v1alpha2</span></span>
<span data-line=""><span style="color:#85E89D">kind</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">TLSRoute</span></span>
<span data-line=""><span style="color:#85E89D">metadata</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">  name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">passthrough-route</span></span>
<span data-line=""><span style="color:#85E89D">spec</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">  parentRefs</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">    - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">eg-tls</span></span>
<span data-line=""><span style="color:#85E89D">  hostnames</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">    - </span><span style="color:#9ECBFF">"db.example.com"</span></span>
<span data-line=""><span style="color:#85E89D">  rules</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">    - </span><span style="color:#85E89D">backendRefs</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">        - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">db-service</span></span>
<span data-line=""><span style="color:#85E89D">          port</span><span style="color:#E1E4E8">: </span><span style="color:#79B8FF">5432</span></span></code></pre></figure>
<p>このパターンのよくある用途:</p>
<ul>
<li>SNI hostname だけで route する</li>
<li>暗号化を backend まで保つ</li>
<li>Gateway では HTTP path/header を解釈しない</li>
</ul>
<p>つまり <code>TLSRoute</code> と <code>HTTPRoute</code> の違いは名前だけではなく、扱っているトラフィック層がまったく違います。</p>
<h2 id="cross-namespace-の証明書参照">Cross-Namespace の証明書参照</h2>
<p>公式ドキュメントが強調している便利な機能があります。
<strong>Gateway は他 namespace の certificate Secret を参照できますが、そのためには <code>ReferenceGrant</code> が必要です。</strong></p>
<p>たとえば platform team が <code>envoy-gateway-system</code> に証明書を集約し、application 側の Gateway が <code>default</code> にある場合、明示的な許可なしに namespace をまたいで参照することはできません。</p>
<p>例:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="yaml" data-theme="github-dark"><code data-language="yaml" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#85E89D">apiVersion</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">gateway.networking.k8s.io/v1beta1</span></span>
<span data-line=""><span style="color:#85E89D">kind</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">ReferenceGrant</span></span>
<span data-line=""><span style="color:#85E89D">metadata</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">  name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">allow-default-to-read-cert</span></span>
<span data-line=""><span style="color:#85E89D">  namespace</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">envoy-gateway-system</span></span>
<span data-line=""><span style="color:#85E89D">spec</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">  from</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">    - </span><span style="color:#85E89D">group</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">gateway.networking.k8s.io</span></span>
<span data-line=""><span style="color:#85E89D">      kind</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">Gateway</span></span>
<span data-line=""><span style="color:#85E89D">      namespace</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">default</span></span>
<span data-line=""><span style="color:#85E89D">  to</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">    - </span><span style="color:#85E89D">group</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">""</span></span>
<span data-line=""><span style="color:#85E89D">      kind</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">Secret</span></span></code></pre></figure>
<p>意味:</p>
<ul>
<li><code>default</code> namespace の <code>Gateway</code> が</li>
<li><code>envoy-gateway-system</code> にある <code>Secret</code> を参照することを許可する</li>
</ul>
<p><code>ReferenceGrant</code> がなければ、この cross-namespace reference は invalid として扱われます。Gateway API が意地悪なのではなく、防御のための仕組みです。</p>
<h2 id="一文まとめ">一文まとめ</h2>
<p>Envoy Gateway の TLS は、響きほど謎ではありません。certificate Secret を用意し、HTTPS listener を設定し、route と hostname を揃える。基本はこれでほぼ完了です。</p>
<blockquote>
<p>💡 初心者が最もやりがちな失敗は、TLS が難しすぎることではありません。<code>hostname</code>、<code>certificateRefs</code>、<code>HTTPRoute hostnames</code> の 3 つが揃っていないことです。どれか 1 つずれると、トラフィックはすぐ不機嫌になります。</p>
</blockquote>
