1b:T31f5,<p>この記事のゴールはシンプルです。<strong>思想はひとまず飛ばして、Envoy Gateway をまず動かします。</strong> 例の service にアクセスできれば、ドキュメントのトップページで止まっている人たちより、もう一歩先に進めています。</p>
<h2 id="前提条件">前提条件</h2>
<p>少なくとも 1 つ、動作する Kubernetes cluster が必要です。たとえば:</p>
<ul>
<li>ローカル: <code>kind</code>, <code>minikube</code>, <code>k3d</code></li>
<li>クラウド: EKS, GKE, AKS</li>
<li>自宅 lab: K3s + MetalLB でも可</li>
</ul>
<p>さらに必要なもの:</p>
<ul>
<li><code>kubectl</code></li>
<li><code>helm</code></li>
<li><code>LoadBalancer</code> address を払い出せる cluster、または <code>port-forward</code> で試してもよい環境</li>
</ul>
<blockquote>
<p>⚠️ cluster が <code>LoadBalancer</code> をサポートしていない場合、公式ドキュメントは MetalLB との組み合わせを勧めています。外部 address がなくても終わりではありません。単に <code>port-forward</code> で検証するだけです。</p>
</blockquote>
<h2 id="step-1-envoy-gateway-をインストールする">Step 1: Envoy Gateway をインストールする</h2>
<p>コントロールプレーンを入れます。</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">helm</span><span style="color:#A5D6FF"> install</span><span style="color:#A5D6FF"> eg</span><span style="color:#A5D6FF"> oci://docker.io/envoyproxy/gateway-helm</span><span style="color:#79C0FF">   --version</span><span style="color:#A5D6FF"> v1.7.0</span><span style="color:#79C0FF">   -n</span><span style="color:#A5D6FF"> envoy-gateway-system</span><span style="color:#79C0FF">   --create-namespace</span></span></code></pre></figure>
<p>起動完了を待ちます。</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">kubectl</span><span style="color:#A5D6FF"> wait</span><span style="color:#79C0FF"> --timeout=5m</span><span style="color:#79C0FF"> -n</span><span style="color:#A5D6FF"> envoy-gateway-system</span><span style="color:#A5D6FF">   deployment/envoy-gateway</span><span style="color:#79C0FF">   --for=condition=Available</span></span></code></pre></figure>
<p>これが完了したら、Envoy Gateway controller は cluster 上で稼働しています。以後は <code>Gateway API</code> リソースを読み取り、対応する Envoy 設定を生成できます。</p>
<h2 id="step-2-公式-quickstart-リソースを適用する">Step 2: 公式 Quickstart リソースを適用する</h2>
<p>公式 repo には、次をまとめたサンプルが用意されています。</p>
<ul>
<li><code>GatewayClass</code></li>
<li><code>Gateway</code></li>
<li><code>HTTPRoute</code></li>
<li>サンプル backend app</li>
</ul>
<p>そのまま適用します。</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">kubectl</span><span style="color:#A5D6FF"> apply</span><span style="color:#79C0FF"> -f</span><span style="color:#A5D6FF">   https://github.com/envoyproxy/gateway/releases/download/v1.7.0/quickstart.yaml</span><span style="color:#79C0FF">   -n</span><span style="color:#A5D6FF"> default</span></span></code></pre></figure>
<p>これは、公式チームがあなたのために完成済みのデモ一式を並べてくれているようなものです。まずは動かし、その後で分解して理解すれば十分です。</p>
<h2 id="step-3-トラフィックが流れていることを確認する">Step 3: トラフィックが流れていることを確認する</h2>
<h3 id="option-a-cluster-に-loadbalancer-がある場合">Option A: Cluster に LoadBalancer がある場合</h3>
<p>Gateway の address を取得します。</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FF7B72">export</span><span style="color:#E6EDF3"> GATEWAY_HOST</span><span style="color:#FF7B72">=</span><span style="color:#E6EDF3">$(</span><span style="color:#FFA657">kubectl</span><span style="color:#A5D6FF"> get</span><span style="color:#A5D6FF"> gateway/eg</span><span style="color:#79C0FF"> -o</span><span style="color:#A5D6FF"> jsonpath='{.status.addresses[0].value}'</span><span style="color:#E6EDF3">)</span></span></code></pre></figure>
<p>リクエストを送ります。</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">curl</span><span style="color:#79C0FF"> --verbose</span><span style="color:#79C0FF">   --header</span><span style="color:#A5D6FF"> "Host: www.example.com"</span><span style="color:#A5D6FF">   http://</span><span style="color:#E6EDF3">$GATEWAY_HOST</span><span style="color:#A5D6FF">/get</span></span></code></pre></figure>
<p>HTTP <code>200</code> が返れば、次を意味します。</p>
<ul>
<li>Gateway が有効な入口として動作している</li>
<li>HTTPRoute が正常に attach されている</li>
<li>backend service へ正しくルーティングされている</li>
</ul>
<h3 id="option-b-loadbalancer-がない場合は-port-forward-を使う">Option B: LoadBalancer がない場合は Port-Forward を使う</h3>
<p>Envoy service を探します。</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FF7B72">export</span><span style="color:#E6EDF3"> ENVOY_SERVICE</span><span style="color:#FF7B72">=</span><span style="color:#E6EDF3">$(</span><span style="color:#FFA657">kubectl</span><span style="color:#A5D6FF"> get</span><span style="color:#A5D6FF"> svc</span><span style="color:#79C0FF"> -n</span><span style="color:#A5D6FF"> envoy-gateway-system</span><span style="color:#79C0FF">   --selector=gateway.envoyproxy.io/owning-gateway-namespace=default,gateway.envoyproxy.io/owning-gateway-name=eg</span><span style="color:#79C0FF">   -o</span><span style="color:#A5D6FF"> jsonpath='{.items[0].metadata.name}'</span><span style="color:#E6EDF3">)</span></span></code></pre></figure>
<p>ローカルの <code>8888</code> を Gateway の <code>80</code> へ forward します。</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">kubectl</span><span style="color:#79C0FF"> -n</span><span style="color:#A5D6FF"> envoy-gateway-system</span><span style="color:#A5D6FF"> port-forward</span><span style="color:#A5D6FF"> service/</span><span style="color:#E6EDF3">${ENVOY_SERVICE} </span><span style="color:#A5D6FF">8888:80</span></span></code></pre></figure>
<p>別の terminal で:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">curl</span><span style="color:#79C0FF"> --verbose</span><span style="color:#79C0FF">   --header</span><span style="color:#A5D6FF"> "Host: www.example.com"</span><span style="color:#A5D6FF">   http://localhost:8888/get</span></span></code></pre></figure>

<ol>
<li><code>Envoy Gateway</code> をインストールした</li>
<li>cluster にどの gateway controller を使うか伝える <code>GatewayClass</code> を作成した</li>
<li>入口 port と protocol を宣言する <code>Gateway</code> を作成した</li>
<li>backend service へトラフィックを流す <code>HTTPRoute</code> を作成した</li>
<li>Envoy Gateway がその宣言を Envoy Proxy が実行できる設定へ変換した</li>
</ol>
<p>これこそ Gateway API を使う価値です。書くのは Kubernetes リソースであって、proxy の設定ファイルを手で積み上げることではありません。</p>

<h2 id="前提条件">前提条件</h2>
<p>少なくとも 1 つ、動作する Kubernetes cluster が必要です。たとえば:</p>
