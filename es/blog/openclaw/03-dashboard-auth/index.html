¿El dashboard siempre te bloquea? Entiende la autenticación de OpenClaw en 3 minutos

8 3月 2026·2 min read

"¿Token? ¿Pairing? Yo solo quería abrir una página web."

Reacción completamente válida. Este artículo existe para que dejes de temerle a la pantalla de login.

Qué vas a aprender

  • Entender la relación entre Gateway y dashboard
  • Identificar los tres escenarios de autenticación más comunes
  • Aprender cómo se configura el acceso remoto
  • Cambiar el idioma de la interfaz

Primero arranca el Gateway

El dashboard es solo una ventana. El trabajo real lo hace el Gateway. Sin Gateway, la página es puro decorado.

Sigue solo cuando veas algo como "Gateway running".

Abre el dashboard

http://127.0.0.1:18789/

Si configuraste basePath, por ejemplo /openclaw:

http://127.0.0.1:18789/openclaw

Autenticación: ¿qué se supone que tengo que poner?

Caso 1: aparece pairing required

OpenClaw te está preguntando: "¿quién eres? Todavía no conozco este dispositivo".

Recarga el navegador y listo.

Caso 2: pide un token

El onboarding te dio un token antes. Eso es lo que debes pegar aquí. Si lo guardas en Settings, normalmente no tendrás que volver a pegarlo.

💡 Los tokens se guardan en la configuración de la UI. Las contraseñas solo viven en memoria y desaparecen al cerrar la sesión: es una decisión intencional de seguridad.

Caso 3: acceso remoto desde VPS o LAN

Si el Gateway no corre en local sino en un servidor remoto:

  • Debes usar token o pairing de dispositivo
  • Si ves unauthorized, revisa gateway.bind y confirma que el token está bien

¿Quieres otro idioma?

La Control UI soporta varios idiomas de interfaz.

En la sección Access puedes elegir el idioma y el navegador lo recordará la próxima vez.

Siguiente paso

Una vez que entras, ya estás en la sala de control de OpenClaw. Ahora toca conectar Telegram para invocar al asistente desde el móvil.
