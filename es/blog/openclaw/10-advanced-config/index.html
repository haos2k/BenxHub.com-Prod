¿El sistema se comporta raro? Guía de configuración avanzada y debugging

8 3月 2026·3 min read

Si llegaste hasta aquí, ya montaste OpenClaw desde cero hasta tenerlo funcionando. Nada mal.

Este artículo final reúne los hábitos que vuelven tu sistema más estable y más fácil de mantener.

Qué vas a aprender

  • Encontrar el archivo de configuración y entender sus dos modos de edición
  • Reconocer la forma de una configuración mínima funcional
  • Guardar API keys con variables de entorno
  • Usar el comando de debugging más útil e interpretar errores comunes
  • Elegir la rama de versión adecuada

¿Dónde está el archivo de configuración?

~/.openclaw/openclaw.json

El formato es JSON5, así que permite comentarios y comas finales. Mucho más amable que JSON puro.

Puedes editarlo de dos maneras:

  • En modo formulario dentro de Control UI si quieres algo más amigable
  • En Raw JSON si quieres precisión y rapidez

Ambos modos editan exactamente el mismo archivo.

¿Cómo se ve una configuración mínima?

Haz que la versión simple funcione primero; luego añade complejidad poco a poco.

La forma correcta de guardar API keys

Evita meter la API key directamente en la config si puedes.

Las variables de entorno son más seguras:

⚠️ Si el Gateway corre como servicio del sistema, por ejemplo con systemd, asegúrate de que ese servicio carga tu .env. Si no, el asistente puede fallar porque no ve la API key y aparecerán errores como "Shell env off".

La herramienta universal de debugging

Cuando algo se comporte raro, empieza aquí:

Los logs en tiempo real responden a muchísimas preguntas.

Errores comunes:

Error Causa probable
HTTP 429 Demasiadas peticiones a la API; rate limit
unauthorized Problema con token o con gateway.bind
content tool_use input field required Incompatibilidad de modelo; revisa la documentación
Contexto truncado Abre una sesión nueva o compacta el contexto
