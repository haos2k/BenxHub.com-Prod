3:T2ad6,<p>El post anterior <a href="08-worktree-merge">08-worktree-merge</a> cubrió el worktree automático de Cursor y Apply. Este profundiza en dos cosas: <strong>Best-of-N</strong> (mismo prompt, varios modelos en paralelo, luego eliges uno para Apply) y <strong>worktrees.json</strong> (instalar deps automáticamente, ejecutar migraciones, copiar <code>.env</code> al crear un worktree).</p>
<h2 id="best-of-n-un-prompt-varios-modelos-a-la-vez">Best-of-N: Un prompt, varios modelos a la vez</h2>
<p><strong>Best-of-N</strong> significa: envías una tarea, Cursor ejecuta <strong>varios modelos</strong> en worktrees separados y obtienes varias "tarjetas", cada una con los cambios de un modelo — <strong>elige una y pulsa Apply</strong>.</p>
<h3 id="cuándo-usar-best-of-n">¿Cuándo usar Best-of-N?</h3>
<table>
<thead>
<tr>
<th>Situación</th>
<th>Por qué ayuda</th>
</tr>
</thead>
<tbody>
<tr>
<td>No sabes qué modelo encaja mejor con tu código</td>
<td>Ejecuta una vez, compara salidas, pequeño benchmark</td>
</tr>
<tr>
<td>Problema difícil, te preocupa que un modelo pierda edge cases</td>
<td>Modelos distintos, enfoques distintos, más cobertura</td>
</tr>
<tr>
<td>Comparar calidad de código</td>
<td>Mismo request, estilo y estructura distintos lado a lado</td>
</tr>
<tr>
<td>Tarea difícil, quieres más éxito "al primer intento"</td>
<td>Varios modelos intentan una vez cada uno, Apply el mejor</td>
</tr>
</tbody>
</table>
<p>En resumen: <strong>varios modelos hacen la misma tarea, tú eliges uno</strong> — sobre todo para tareas difíciles o cuando te importa la calidad.</p>
<h3 id="cómo-usarlo">Cómo usarlo</h3>
<p>En Cursor, al iniciar un Agent elige "varios modelos" o la opción Best-of-N (según la UI actual). Tras enviar el prompt verás varias tarjetas; cambia entre ellas para comparar y <strong>Apply</strong> la que quieras a main.</p>
<p>Si aplicas más de una tarjeta del mismo run Best-of-N (p. ej. Apply A y luego B), Cursor puede preguntar: <strong>merge con resolución de conflictos</strong> o <strong>Full Overwrite</strong> (reemplazar el archivo entero).</p>
<h2 id="worktreesjson-preparar-el-entorno-al-crear-un-worktree">worktrees.json: Preparar el entorno al crear un worktree</h2>
<p>Cuando Cursor crea un worktree, copia por defecto los <strong>archivos rastreados</strong> del directorio principal, pero no instala deps, no copia <code>.env</code> ni ejecuta migraciones de BD.<br>
Con <strong><code>.cursor/worktrees.json</code></strong> puedes indicar <strong>comandos a ejecutar tras cada worktree nuevo</strong>, p. ej. <code>npm ci</code>, <code>cp .env</code>, <code>npm run db:migrate</code>.</p>
<h3 id="dónde-va-la-config">¿Dónde va la config?</h3>
<p>Cursor busca en este orden:</p>
<ol>
<li>Raíz del proyecto: <code>.cursor/worktrees.json</code></li>
<li>Ruta del worktree</li>
</ol>
<p>Suele ponerse en la <strong>raíz del proyecto</strong>: <code>.cursor/worktrees.json</code>.</p>
<h3 id="tres-claves-de-config">Tres claves de config</h3>
<table>
<thead>
<tr>
<th>Clave</th>
<th>Descripción</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>setup-worktree</code></td>
<td>Genérico; se usa en todos los OS si no hay clave por OS</td>
</tr>
<tr>
<td><code>setup-worktree-windows</code></td>
<td>Solo Windows; sobrescribe <code>setup-worktree</code></td>
</tr>
<tr>
<td><code>setup-worktree-unix</code></td>
<td>Solo macOS / Linux; sobrescribe <code>setup-worktree</code></td>
</tr>
</tbody>
</table>
<p>Cada clave puede ser:</p>
<ul>
<li><strong>String</strong>: ruta a un script (relativa al directorio que contiene <code>.cursor/worktrees.json</code>)</li>
<li><strong>Array</strong>: lista de comandos shell, ejecutados en orden</li>
</ul>

<h3 id="más-complejo-usar-archivos-de-script">Más complejo: usar archivos de script</h3>
<p>Para muchos comandos o lógica, usa un script y referéncialo en <code>worktrees.json</code>:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="json" data-theme="github-dark-default"><code data-language="json" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#E6EDF3">{</span></span>

<span data-line=""><span style="color:#7EE787">  "setup-worktree"</span><span style="color:#E6EDF3">: [</span><span style="color:#A5D6FF">"echo 'Using generic fallback'"</span><span style="color:#E6EDF3">]</span></span>

<p>Pon los scripts bajo <code>.cursor/</code>, p. ej. <code>.cursor/setup-worktree-unix.sh</code>, con <code>npm ci</code>, copiar <code>.env</code>, <code>chmod</code>, migraciones, etc.<br>
En Windows usa <code>.ps1</code> y en el script usa <code>$env:ROOT_WORKTREE_PATH</code> para la ruta del directorio principal.</p>
<blockquote>
<p>Tip: evita enlazar deps con symlink en el worktree — puede chocar con el worktree principal; usa <code>npm ci</code>, <code>pnpm</code>, <code>bun</code>, <code>uv</code>, etc. para instalar fresco.</p>
</blockquote>
<h2 id="limpieza-y-límites-de-worktree">Limpieza y límites de worktree</h2>
<p>Cursor limita el número de worktrees para no llenar el disco:</p>
<ul>
<li>Cada workspace tiene un <strong>máximo de worktrees</strong> (p. ej. 20)</li>
<li>Al superar el límite se eliminan los <strong>menos usados recientemente</strong></li>
<li>La limpieza es <strong>por workspace</strong>; repos distintos no se afectan</li>
</ul>
<p>Para ajustar (si tu versión de Cursor lo permite), busca opciones como:</p>
<ul>
<li><code>cursor.worktreeMaxCount</code>: máximo de worktrees a mantener</li>
<li><code>cursor.worktreeCleanupIntervalHours</code>: cada cuánto ejecutar limpieza</li>
</ul>
<p>Los nombres exactos dependen de la configuración actual de Cursor.</p>
<h2 id="depurar-el-setup-del-worktree">Depurar el setup del worktree</h2>
<p>Si tras crear un worktree no se instalaron deps o no se ejecutaron migraciones, abre el panel <strong>Output</strong> de Cursor, elige <strong>"Worktrees Setup"</strong> en el desplegable y revisa los comandos y errores ejecutados al crear — ayuda a depurar <code>worktrees.json</code> o problemas de scripts.</p>
<h2 id="resumen">Resumen</h2>
<ul>
<li><strong>Best-of-N</strong>: Mismo prompt, varios modelos en paralelo en worktrees separados; compara y Apply una tarjeta; útil para benchmarks, tareas difíciles y calidad</li>
<li><strong>worktrees.json</strong>: En <code>.cursor/worktrees.json</code> usa <code>setup-worktree</code> / <code>setup-worktree-windows</code> / <code>setup-worktree-unix</code> para ejecutar comandos o scripts tras la creación</li>
<li>Usa <code>$ROOT_WORKTREE_PATH</code> (Unix) o <code>%ROOT_WORKTREE_PATH%</code> / <code>$env:ROOT_WORKTREE_PATH</code> (Windows) para copiar <code>.env</code> etc. desde main</li>
<li>Los worktrees tienen límite y limpieza automática; depura con Output → Worktrees Setup</li>
</ul>

<h3 id="más-complejo-usar-archivos-de-script">Más complejo: usar archivos de script</h3>
<p>Para muchos comandos o lógica, usa un script y referéncialo en <code>worktrees.json</code>:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="json" data-theme="github-dark-default"><code data-language="json" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#E6EDF3">{</span></span>
<span data-line=""><span style="color:#7EE787">  "setup-worktree-unix"</span><span style="color:#E6EDF3">: </span><span style="color:#A5D6FF">"setup-worktree-unix.sh"</span><span style="color:#E6EDF3">,</span></span>
<span data-line=""><span style="color:#7EE787">  "setup-worktree-windows"</span><span style="color:#E6EDF3">: </span><span style="color:#A5D6FF">"setup-worktree-windows.ps1"</span><span style="color:#E6EDF3">,</span></span>
<span data-line=""><span style="color:#7EE787">  "setup-worktree"</span><span style="color:#E6EDF3">: [</span><span style="color:#A5D6FF">"echo 'Using generic fallback'"</span><span style="color:#E6EDF3">]</span></span>
<span data-line=""><span style="color:#E6EDF3">}</span></span></code></pre></figure>
<p>Pon los scripts bajo <code>.cursor/</code>, p. ej. <code>.cursor/setup-worktree-unix.sh</code>, con <code>npm ci</code>, copiar <code>.env</code>, <code>chmod</code>, migraciones, etc.<br>
En Windows usa <code>.ps1</code> y en el script usa <code>$env:ROOT_WORKTREE_PATH</code> para la ruta del directorio principal.</p>
<blockquote>
<p>Tip: evita enlazar deps con symlink en el worktree — puede chocar con el worktree principal; usa <code>npm ci</code>, <code>pnpm</code>, <code>bun</code>, <code>uv</code>, etc. para instalar fresco.</p>
</blockquote>
<h2 id="limpieza-y-límites-de-worktree">Limpieza y límites de worktree</h2>
<p>Cursor limita el número de worktrees para no llenar el disco:</p>
<ul>
<li>Cada workspace tiene un <strong>máximo de worktrees</strong> (p. ej. 20)</li>
<li>Al superar el límite se eliminan los <strong>menos usados recientemente</strong></li>
<li>La limpieza es <strong>por workspace</strong>; repos distintos no se afectan</li>
</ul>
<p>Para ajustar (si tu versión de Cursor lo permite), busca opciones como:</p>
<ul>
<li><code>cursor.worktreeMaxCount</code>: máximo de worktrees a mantener</li>
<li><code>cursor.worktreeCleanupIntervalHours</code>: cada cuánto ejecutar limpieza</li>
</ul>
<p>Los nombres exactos dependen de la configuración actual de Cursor.</p>
<h2 id="depurar-el-setup-del-worktree">Depurar el setup del worktree</h2>
<p>Si tras crear un worktree no se instalaron deps o no se ejecutaron migraciones, abre el panel <strong>Output</strong> de Cursor, elige <strong>"Worktrees Setup"</strong> en el desplegable y revisa los comandos y errores ejecutados al crear — ayuda a depurar <code>worktrees.json</code> o problemas de scripts.</p>
<h2 id="resumen">Resumen</h2>
<ul>
<li><strong>Best-of-N</strong>: Mismo prompt, varios modelos en paralelo en worktrees separados; compara y Apply una tarjeta; útil para benchmarks, tareas difíciles y calidad</li>
<li><strong>worktrees.json</strong>: En <code>.cursor/worktrees.json</code> usa <code>setup-worktree</code> / <code>setup-worktree-windows</code> / <code>setup-worktree-unix</code> para ejecutar comandos o scripts tras la creación</li>
<li>Usa <code>$ROOT_WORKTREE_PATH</code> (Unix) o <code>%ROOT_WORKTREE_PATH%</code> / <code>$env:ROOT_WORKTREE_PATH</code> (Windows) para copiar <code>.env</code> etc. desde main</li>
<li>Los worktrees tienen límite y limpieza automática; depura con Output → Worktrees Setup</li>
</ul>
