1b:T2204,<p>El post anterior <a href="10-headless-scripts">10-headless-scripts</a> usó <code>-p --force</code> para cambiar archivos desde scripts. Este trata el <strong>formato de salida</strong>: para la misma ejecución del Agent puedes elegir "solo texto final", "JSON estructurado completo" o "JSON en streaming mientras corre" — en CI parseas resultados, mides tiempo o muestras progreso con estos tres formatos.</p>
<h2 id="tres-formatos-de-salida">Tres formatos de salida</h2>
<table>
<thead>
<tr>
<th>Formato</th>
<th>Flag</th>
<th>Mejor para</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>text</strong></td>
<td>Por defecto, o <code>--output-format text</code></td>
<td>Lectura humana, solo respuesta final, escribir a archivo</td>
</tr>
<tr>
<td><strong>json</strong></td>
<td><code>--output-format json</code></td>
<td>Parseo en scripts, pass/fail en CI, extraer campos</td>
</tr>
<tr>
<td><strong>stream-json</strong></td>
<td><code>--output-format stream-json</code></td>
<td>Progreso en vivo, seguimiento de tool calls, monitoreo de runs largos</td>
</tr>
</tbody>
</table>
<h3 id="text-respuesta-final-limpia">text: Respuesta final limpia</h3>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#A5D6FF"> "What is the entry point of this repo?"</span></span></code></pre></figure>
<p>Sin <code>--output-format</code> obtienes text: la salida es <strong>solo la respuesta final</strong>, sin tool calls ni pasos intermedios — útil para pegar en docs o como descripción corta.</p>
<p>En CI, para escribir la conclusión del Agent a un archivo:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#A5D6FF"> "Generate release notes for this version from CHANGELOG"</span><span style="color:#FF7B72"> ></span><span style="color:#A5D6FF"> release_notes.txt</span></span></code></pre></figure>
<h3 id="json-para-scripts-y-ci">json: Para scripts y CI</h3>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#79C0FF"> --output-format</span><span style="color:#A5D6FF"> json</span><span style="color:#A5D6FF"> "Analyze src/ dependencies and return JSON: { </span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">entry</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">: </span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">...</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">, </span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">deps</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">: [...] }"</span></span></code></pre></figure>
<p>La salida es JSON estructurado, con <code>result</code>, <code>duration_ms</code> o campos que pidas en el prompt.<br>
En CI puedes:</p>
<ul>
<li>Usar <code>jq</code> para obtener campos, comprobar vacíos o buscar palabras clave</li>
<li>Usar código de salida y contenido para decidir pass/fail del job</li>
</ul>
<p>Ejemplo conceptual:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#79C0FF"> --output-format</span><span style="color:#A5D6FF"> json</span><span style="color:#A5D6FF"> "Do a short code review; return {</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">ok</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">: true/false, </span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">summary</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">: </span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">...</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">}"</span><span style="color:#FF7B72"> |</span><span style="color:#FFA657"> jq</span><span style="color:#79C0FF"> -r</span><span style="color:#A5D6FF"> '.result'</span></span>
<span data-line=""><span style="color:#8B949E"># Then use .ok or .summary for next steps or to fail the build</span></span></code></pre></figure>
<p>Los campos exactos dependen de la doc de Cursor; la idea es "json para parseo programático."</p>
<h3 id="stream-json-progreso-en-vivo-y-seguimiento-de-herramientas">stream-json: Progreso en vivo y seguimiento de herramientas</h3>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#79C0FF"> --output-format</span><span style="color:#A5D6FF"> stream-json</span><span style="color:#79C0FF"> --stream-partial-output</span><span style="color:#A5D6FF"> "Analyze project and write analysis.txt"</span></span></code></pre></figure>
<ul>
<li>Cada línea es un evento JSON (p. ej. <code>system</code>, <code>assistant</code>, <code>tool_call</code>, <code>result</code>)</li>
<li><code>--stream-partial-output</code> envía el texto del assistant como <strong>deltas incrementales</strong>, para mostrar "contador de caracteres en vivo" o "progreso %"</li>
<li>Parsea tool_call started/completed para ver qué archivo lee/escribe el Agent y cuánto tarda</li>
</ul>
<p>Útil para: runs largos, mostrar "procesando archivo N" en logs de CI o en una UI, o contar tool calls y duración.</p>
<h2 id="consejos-de-integración-ci">Consejos de integración CI</h2>
<table>
<thead>
<tr>
<th>Necesidad</th>
<th>Sugerencia</th>
</tr>
</thead>
<tbody>
<tr>
<td>Solo importa "¿terminó y cuál es la conclusión?"</td>
<td><code>text</code> + redirigir a archivo o variable; comprobar código de salida</td>
</tr>
<tr>
<td>Pass/fail según contenido</td>
<td><code>json</code> + parseo con <code>jq</code></td>
</tr>
<tr>
<td>Log en vivo o progreso</td>
<td><code>stream-json</code> + parsear línea a línea por tipo/subtipo</td>
</tr>
<tr>
<td>El Agent debe editar archivos</td>
<td>Añade <code>--force</code> (ver <a href="10-headless-scripts">10-headless-scripts</a>)</td>
</tr>
<tr>
<td>Ejecutar en CI</td>
<td>Configura <code>CURSOR_API_KEY</code>; usa <code>--model</code> para fijar modelo si hace falta</td>
</tr>
</tbody>
</table>
<h2 id="manejo-de-fallos">Manejo de fallos</h2>
<ul>
<li>Cuando falla la ejecución del Agent, la CLI suele devolver <strong>código de salida distinto de cero</strong></li>
<li>En scripts usa <code>if [ $? -ne 0 ]; then exit 1; fi</code> o <code>set -e</code> para que CI falle correctamente</li>
<li>Con json también puedes comprobar un campo <code>error</code> o tu <code>ok: false</code> personalizado como refuerzo</li>
</ul>
<h2 id="resumen">Resumen</h2>
<ul>
<li><strong>text</strong>: Por defecto, legible, salida mínima; bueno para escribir a archivo o como descripción</li>
<li><strong>json</strong>: Estructurado para <code>jq</code> o scripts; bueno para decisiones CI y extracción</li>
<li><strong>stream-json</strong> + <strong>--stream-partial-output</strong>: Flujo de eventos en vivo; bueno para progreso y seguimiento de herramientas</li>
<li>En CI: configura <code>CURSOR_API_KEY</code>, respeta el código de salida y parsea JSON para pass/fail cuando haga falta</li>
</ul>

<td>Lectura humana, solo respuesta final, escribir a archivo</td>
</tr>
<tr>
<td><strong>json</strong></td>
<td><code>--output-format json</code></td>
<td>Parseo en scripts, pass/fail en CI, extraer campos</td>
</tr>
<tr>
<td><strong>stream-json</strong></td>
<td><code>--output-format stream-json</code></td>
<td>Progreso en vivo, seguimiento de tool calls, monitoreo de runs largos</td>
</tr>
</tbody>
</table>
<h3 id="text-respuesta-final-limpia">text: Respuesta final limpia</h3>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#A5D6FF"> "What is the entry point of this repo?"</span></span></code></pre></figure>
<p>Sin <code>--output-format</code> obtienes text: la salida es <strong>solo la respuesta final</strong>, sin tool calls ni pasos intermedios — útil para pegar en docs o como descripción corta.</p>
<p>En CI, para escribir la conclusión del Agent a un archivo:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#A5D6FF"> "Generate release notes for this version from CHANGELOG"</span><span style="color:#FF7B72"> ></span><span style="color:#A5D6FF"> release_notes.txt</span></span></code></pre></figure>
<h3 id="json-para-scripts-y-ci">json: Para scripts y CI</h3>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#79C0FF"> --output-format</span><span style="color:#A5D6FF"> json</span><span style="color:#A5D6FF"> "Analyze src/ dependencies and return JSON: { </span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">entry</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">: </span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">...</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">, </span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">deps</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">: [...] }"</span></span></code></pre></figure>
<p>La salida es JSON estructurado, con <code>result</code>, <code>duration_ms</code> o campos que pidas en el prompt.<br>
En CI puedes:</p>
<ul>
<li>Usar <code>jq</code> para obtener campos, comprobar vacíos o buscar palabras clave</li>
<li>Usar código de salida y contenido para decidir pass/fail del job</li>
</ul>
<p>Ejemplo conceptual:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#79C0FF"> --output-format</span><span style="color:#A5D6FF"> json</span><span style="color:#A5D6FF"> "Do a short code review; return {</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">ok</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">: true/false, </span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">summary</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">: </span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">...</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">}"</span><span style="color:#FF7B72"> |</span><span style="color:#FFA657"> jq</span><span style="color:#79C0FF"> -r</span><span style="color:#A5D6FF"> '.result'</span></span>
<span data-line=""><span style="color:#8B949E"># Then use .ok or .summary for next steps or to fail the build</span></span></code></pre></figure>
<p>Los campos exactos dependen de la doc de Cursor; la idea es "json para parseo programático."</p>
<h3 id="stream-json-progreso-en-vivo-y-seguimiento-de-herramientas">stream-json: Progreso en vivo y seguimiento de herramientas</h3>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#79C0FF"> --output-format</span><span style="color:#A5D6FF"> stream-json</span><span style="color:#79C0FF"> --stream-partial-output</span><span style="color:#A5D6FF"> "Analyze project and write analysis.txt"</span></span></code></pre></figure>
<ul>
<li>Cada línea es un evento JSON (p. ej. <code>system</code>, <code>assistant</code>, <code>tool_call</code>, <code>result</code>)</li>
<li><code>--stream-partial-output</code> envía el texto del assistant como <strong>deltas incrementales</strong>, para mostrar "contador de caracteres en vivo" o "progreso %"</li>
<li>Parsea tool_call started/completed para ver qué archivo lee/escribe el Agent y cuánto tarda</li>
</ul>
<p>Útil para: runs largos, mostrar "procesando archivo N" en logs de CI o en una UI, o contar tool calls y duración.</p>
<h2 id="consejos-de-integración-ci">Consejos de integración CI</h2>
<table>
<thead>
<tr>
<th>Necesidad</th>
<th>Sugerencia</th>
</tr>
</thead>
<tbody>
<tr>
<td>Solo importa "¿terminó y cuál es la conclusión?"</td>
<td><code>text</code> + redirigir a archivo o variable; comprobar código de salida</td>
</tr>
<tr>
<td>Pass/fail según contenido</td>
<td><code>json</code> + parseo con <code>jq</code></td>
</tr>
<tr>
<td>Log en vivo o progreso</td>
<td><code>stream-json</code> + parsear línea a línea por tipo/subtipo</td>
</tr>
<tr>
<td>El Agent debe editar archivos</td>
<td>Añade <code>--force</code> (ver <a href="10-headless-scripts">10-headless-scripts</a>)</td>
</tr>
<tr>
<td>Ejecutar en CI</td>
<td>Configura <code>CURSOR_API_KEY</code>; usa <code>--model</code> para fijar modelo si hace falta</td>
</tr>
</tbody>
</table>
<h2 id="manejo-de-fallos">Manejo de fallos</h2>
<ul>
<li>Cuando falla la ejecución del Agent, la CLI suele devolver <strong>código de salida distinto de cero</strong></li>
<li>En scripts usa <code>if [ $? -ne 0 ]; then exit 1; fi</code> o <code>set -e</code> para que CI falle correctamente</li>
<li>Con json también puedes comprobar un campo <code>error</code> o tu <code>ok: false</code> personalizado como refuerzo</li>
</ul>
<h2 id="resumen">Resumen</h2>
<ul>
<li><strong>text</strong>: Por defecto, legible, salida mínima; bueno para escribir a archivo o como descripción</li>
<li><strong>json</strong>: Estructurado para <code>jq</code> o scripts; bueno para decisiones CI y extracción</li>
<li><strong>stream-json</strong> + <strong>--stream-partial-output</strong>: Flujo de eventos en vivo; bueno para progreso y seguimiento de herramientas</li>
<li>En CI: configura <code>CURSOR_API_KEY</code>, respeta el código de salida y parsea JSON para pass/fail cuando haga falta</li>
</ul>
