3:T4314,<p>Escribe un script de shell que haga que <code>cursor agent</code> arregle el código automáticamente, ejecute los tests y si fallan deje que la IA arregle de nuevo — <strong>repitiendo hasta que pasen todos los tests</strong>. No hace falta quedarse pulsando Y/N. Delega el bucle a la IA y haz otra cosa — vuelve cuando la terminal muestre "tests passed."</p>
<h2 id="concepto-central">Concepto central</h2>
<pre><code>while tests don't pass:
    run tests → collect error output
    feed error output to cursor agent
    cursor agent fixes the code
    run tests again
</code></pre>
<p>Es un bucle "ejecutar tests → fallar → decir a la IA que arregle → repetir" hasta que pasen. Simple y directo, pero efectivo.</p>
<h2 id="paso-1-comprobar-requisitos">Paso 1: Comprobar requisitos</h2>
<ul>
<li><code>cursor</code> está instalado y con sesión iniciada (<code>cursor --version</code> para comprobar)</li>
<li>El proyecto tiene un <strong>comando de tests que se ejecuta en la terminal</strong>, por ejemplo:
<ul>
<li><code>npm test</code></li>
<li><code>pytest</code></li>
<li><code>go test ./...</code></li>
<li><code>cargo test</code></li>
</ul>
</li>
<li>Los tests devuelven código de salida distinto de cero al fallar (casi todos los frameworks lo hacen por defecto)</li>
</ul>
<h2 id="paso-2-el-script-más-simple">Paso 2: El script más simple</h2>
<p>Crea <code>debug-loop.sh</code>:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E">#!/bin/bash</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#E6EDF3">MAX_LOOPS</span><span style="color:#FF7B72">=</span><span style="color:#A5D6FF">10</span><span style="color:#8B949E">        # max iterations to prevent truly infinite loops</span></span>
<span data-line=""><span style="color:#E6EDF3">TEST_CMD</span><span style="color:#FF7B72">=</span><span style="color:#A5D6FF">"npm test"</span><span style="color:#8B949E"> # replace with your test command</span></span>

<span data-line=""><span style="color:#79C0FF">  echo</span><span style="color:#A5D6FF"> ""</span></span>

<span data-line=""> </span>
<span data-line=""><span style="color:#8B949E">  # run tests and capture stdout + stderr</span></span>
<span data-line=""><span style="color:#E6EDF3">  TEST_OUTPUT</span><span style="color:#FF7B72">=</span><span style="color:#E6EDF3">$(</span><span style="color:#79C0FF">eval</span><span style="color:#A5D6FF"> "</span><span style="color:#E6EDF3">$TEST_CMD</span><span style="color:#A5D6FF">"</span><span style="color:#FF7B72"> 2>&#x26;1</span><span style="color:#E6EDF3">)</span></span>

<span data-line=""> </span>
<span data-line=""><span style="color:#FF7B72">  if</span><span style="color:#E6EDF3"> [ $EXIT_CODE </span><span style="color:#FF7B72">-eq</span><span style="color:#79C0FF"> 0</span><span style="color:#E6EDF3"> ]; </span><span style="color:#FF7B72">then</span></span>

<h2 id="paso-3-ejecutar-el-script">Paso 3: Ejecutar el script</h2>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">chmod</span><span style="color:#A5D6FF"> +x</span><span style="color:#A5D6FF"> debug-loop.sh</span></span>

<p>Ahora puedes ir a por un café, responder mensajes y volver cuando veas <code>✅ Tests passed!</code> en la terminal. Si llega a MAX_LOOPS sin pasar, toca intervención humana.</p>

<h2 id="consideraciones-de-seguridad">Consideraciones de seguridad</h2>
<table>
<thead>
<tr>
<th>Riesgo</th>
<th>Cómo mitigar</th>
</tr>
</thead>
<tbody>
<tr>
<td>La IA rompe más archivos</td>
<td><code>git commit</code> antes para guardar estado, <code>git checkout .</code> para revertir si hace falta</td>
</tr>
<tr>
<td>Demasiadas iteraciones gastan cuota</td>
<td>Pon un <code>MAX_LOOPS</code> razonable (5–15 recomendado)</td>
</tr>
<tr>
<td>La IA modifica archivos de test</td>
<td>Di explícitamente en el prompt "do not modify test files"</td>
</tr>
<tr>
<td>Fallos distintos en cada iteración</td>
<td>Guarda logs (versión mejorada) para analizar después</td>
</tr>
</tbody>
</table>
<h2 id="resumen">Resumen</h2>
<ol>
<li><strong>Estructura del script</strong>: ejecutar tests → fallar → pasar a la IA → repetir hasta pasar o límite</li>
<li><strong>Parámetros clave</strong>: <code>TEST_CMD</code> (comando de tests), <code>MAX_LOOPS</code> (máximo de iteraciones)</li>
<li><strong>Sé concreto en el prompt</strong>: indica el lenguaje, restringe qué directorios modificar, no tocar tests</li>
<li><strong><code>git commit</code> antes</strong> — fácil de revertir si algo sale mal y más tranquilidad</li>
</ol>

9:T4314,<p>Escribe un script de shell que haga que <code>cursor agent</code> arregle el código automáticamente, ejecute los tests y si fallan deje que la IA arregle de nuevo — <strong>repitiendo hasta que pasen todos los tests</strong>. No hace falta quedarse pulsando Y/N. Delega el bucle a la IA y haz otra cosa — vuelve cuando la terminal muestre "tests passed."</p>
<h2 id="concepto-central">Concepto central</h2>
<pre><code>while tests don't pass:
    run tests → collect error output
    feed error output to cursor agent
    cursor agent fixes the code
    run tests again
</code></pre>
<p>Es un bucle "ejecutar tests → fallar → decir a la IA que arregle → repetir" hasta que pasen. Simple y directo, pero efectivo.</p>
<h2 id="paso-1-comprobar-requisitos">Paso 1: Comprobar requisitos</h2>
<ul>
<li><code>cursor</code> está instalado y con sesión iniciada (<code>cursor --version</code> para comprobar)</li>
<li>El proyecto tiene un <strong>comando de tests que se ejecuta en la terminal</strong>, por ejemplo:
<ul>
<li><code>npm test</code></li>
<li><code>pytest</code></li>
<li><code>go test ./...</code></li>
<li><code>cargo test</code></li>
</ul>
</li>
<li>Los tests devuelven código de salida distinto de cero al fallar (casi todos los frameworks lo hacen por defecto)</li>
</ul>
