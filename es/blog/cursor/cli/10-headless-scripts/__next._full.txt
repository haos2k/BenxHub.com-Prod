1b:T2108,<p><a href="04-non-interactive">04-non-interactive</a> cubrió <code>--no-interactive</code> para que el Agent corra hasta el final sin esperarte. Este post va más allá: <strong>modo headless</strong> con <strong><code>-p</code> / <code>--print</code></strong> para ejecuciones "solo salida a terminal", más <strong><code>--force</code></strong> (o <code>--yolo</code>) para que el Agent <strong>modifique de verdad los archivos del proyecto</strong> — adecuado para CI, JSDoc por lotes, arreglo de lint automático y generación de informes.</p>
<p>En resumen: <strong>sin ventana de Cursor, sin confirmaciones por tecla; un script invoca la CLI para cambiar código y el script sigue.</strong></p>
<h2 id="--print-no-interactivo-salida-a-terminal">--print: No interactivo, salida a terminal</h2>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#79B8FF"> -p</span><span style="color:#9ECBFF"> "What does this project do?"</span></span>
<span data-line=""><span style="color:#6A737D"># or</span></span>
<span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#79B8FF"> --print</span><span style="color:#9ECBFF"> "List all API endpoints under src/"</span></span></code></pre></figure>
<ul>
<li><strong>Sin <code>--force</code></strong>: El Agent puede leer archivos, buscar en el código y devolver análisis, pero <strong>no escribe en archivos</strong> — solo sugiere o imprime en la salida</li>
<li>Útil para: preguntas y respuestas, análisis, escribir informes a stdout, piping o parseo en scripts</li>
</ul>
<p>Así que <code>-p</code> sola significa "ejecutar hasta el final, salida a terminal"; si cambia archivos depende de si añades <code>--force</code>.</p>
<h2 id="--force-permitir-edición-directa-de-archivos">--force: Permitir edición directa de archivos</h2>
<p>Con <code>--print</code> y <strong><code>--force</code></strong> (o <strong><code>--yolo</code></strong>), el Agent <strong>puede crear, editar y borrar archivos</strong> sin preguntar Y/N:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#79B8FF"> -p</span><span style="color:#79B8FF"> --force</span><span style="color:#9ECBFF"> "Refactor src/utils.js to ES6+ syntax"</span></span></code></pre></figure>
<table>
<thead>
<tr>
<th>Caso de uso</th>
<th>Ejemplo</th>
</tr>
</thead>
<tbody>
<tr>
<td>Refactor de un archivo</td>
<td><code>agent -p --force "Refactor src/foo.ts to use async/await"</code></td>
</tr>
<tr>
<td>Arreglar lint según config</td>
<td><code>agent -p --force "Fix all auto-fixable errors per .eslintrc"</code></td>
</tr>
<tr>
<td>JSDoc por lotes</td>
<td>Ver ejemplo de script abajo</td>
</tr>
<tr>
<td>Generar archivo en el proyecto</td>
<td><code>agent -p --force "Generate CONTRIBUTING.md from README"</code></td>
</tr>
</tbody>
</table>
<blockquote>

<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D">#!/bin/bash</span></span>

<p><code>--output-format text</code> deja la salida en texto plano para escribir a archivo o pipe a <code>grep</code>/scripts. El siguiente post cubre <code>json</code> y <code>stream-json</code>.</p>
<h2 id="entorno-api-key">Entorno: API key</h2>
<p>El modo headless suele ejecutarse donde no hay ventana de Cursor (p. ej. CI, máquina remota), así que hace falta autenticación:</p>
<ul>
<li>Variable de entorno: <code>export CURSOR_API_KEY=your_key</code></li>
<li>O ejecuta <code>cursor auth login</code> en ese entorno antes (si está soportado)</li>
</ul>
<p>Sin ello obtendrás errores y el Agent no correrá.</p>
<h2 id="diferencia-con---no-interactive-breve">Diferencia con --no-interactive (breve)</h2>
<table>
<thead>
<tr>
<th>Modo</th>
<th>Uso típico</th>
<th>¿Edita archivos?</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>--no-interactive</code></td>
<td>Ejecutar en terminal, ver salida paso a paso, sin pulsar tecla</td>
<td>Puede editar, pero puede preguntar (según config)</td>
</tr>
<tr>
<td><code>-p</code> / <code>--print</code></td>
<td>Scripts, CI, totalmente no interactivo, salida a stdout</td>
<td>Por defecto no</td>
</tr>
<tr>
<td><code>-p --force</code></td>
<td>Igual, pero permitir que el Agent edite archivos</td>
<td>Sí, sin preguntar</td>
</tr>
</tbody>
</table>
<p>Para <strong>scripts que "realmente cambian archivos"</strong> usa <code>-p --force</code>; para análisis o informes solo a terminal, basta <code>-p</code>.</p>
<h2 id="resumen">Resumen</h2>
<ul>
<li><strong><code>-p</code> / <code>--print</code></strong>: No interactivo, salida a terminal al terminar; por defecto no edita archivos</li>
<li><strong><code>--force</code> / <code>--yolo</code></strong>: En modo print, permitir que el Agent edite archivos; útil para scripts y CI</li>
<li>En scripts/CI, configura <code>CURSOR_API_KEY</code> o completa el login</li>
<li>Prueba en un ámbito pequeño antes de ejecutar en todo el repo</li>
</ul>

<h2 id="--print-no-interactivo-salida-a-terminal">--print: No interactivo, salida a terminal</h2>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#79B8FF"> -p</span><span style="color:#9ECBFF"> "What does this project do?"</span></span>
<span data-line=""><span style="color:#6A737D"># or</span></span>
<span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#79B8FF"> --print</span><span style="color:#9ECBFF"> "List all API endpoints under src/"</span></span></code></pre></figure>
<ul>
<li><strong>Sin <code>--force</code></strong>: El Agent puede leer archivos, buscar en el código y devolver análisis, pero <strong>no escribe en archivos</strong> — solo sugiere o imprime en la salida</li>
<li>Útil para: preguntas y respuestas, análisis, escribir informes a stdout, piping o parseo en scripts</li>
</ul>
<p>Así que <code>-p</code> sola significa "ejecutar hasta el final, salida a terminal"; si cambia archivos depende de si añades <code>--force</code>.</p>
<h2 id="--force-permitir-edición-directa-de-archivos">--force: Permitir edición directa de archivos</h2>
<p>Con <code>--print</code> y <strong><code>--force</code></strong> (o <strong><code>--yolo</code></strong>), el Agent <strong>puede crear, editar y borrar archivos</strong> sin preguntar Y/N:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#79B8FF"> -p</span><span style="color:#79B8FF"> --force</span><span style="color:#9ECBFF"> "Refactor src/utils.js to ES6+ syntax"</span></span></code></pre></figure>
<table>
<thead>
<tr>
<th>Caso de uso</th>
<th>Ejemplo</th>
</tr>
</thead>
<tbody>
<tr>
<td>Refactor de un archivo</td>
<td><code>agent -p --force "Refactor src/foo.ts to use async/await"</code></td>
</tr>
<tr>
<td>Arreglar lint según config</td>
<td><code>agent -p --force "Fix all auto-fixable errors per .eslintrc"</code></td>
</tr>
<tr>
<td>JSDoc por lotes</td>
<td>Ver ejemplo de script abajo</td>
</tr>
<tr>
<td>Generar archivo en el proyecto</td>
<td><code>agent -p --force "Generate CONTRIBUTING.md from README"</code></td>
</tr>
</tbody>
</table>
<blockquote>
<p>⚠️ Antes de usar <code>--force</code> en scripts, prueba en un archivo o ámbito pequeño para confirmar el comportamiento y luego escala al repo completo.</p>
</blockquote>
<h2 id="ejemplo-de-script-jsdoc-por-lotes">Ejemplo de script: JSDoc por lotes</h2>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D">#!/bin/bash</span></span>
<span data-line=""><span style="color:#6A737D"># For each .js under src/, ask Agent to add JSDoc and write directly</span></span>
<span data-line=""><span style="color:#B392F0">find</span><span style="color:#9ECBFF"> src/</span><span style="color:#79B8FF"> -name</span><span style="color:#9ECBFF"> "*.js"</span><span style="color:#F97583"> |</span><span style="color:#F97583"> while</span><span style="color:#79B8FF"> read</span><span style="color:#79B8FF"> -r</span><span style="color:#9ECBFF"> file</span><span style="color:#E1E4E8">; </span><span style="color:#F97583">do</span></span>
<span data-line=""><span style="color:#79B8FF">  echo</span><span style="color:#9ECBFF"> "Processing </span><span style="color:#E1E4E8">$file</span><span style="color:#9ECBFF">..."</span></span>
<span data-line=""><span style="color:#B392F0">  cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#79B8FF"> -p</span><span style="color:#79B8FF"> --force</span><span style="color:#9ECBFF"> "Add full JSDoc comments to </span><span style="color:#E1E4E8">$file</span><span style="color:#9ECBFF">, editing the file in place"</span></span>
<span data-line=""><span style="color:#F97583">done</span></span></code></pre></figure>
<p>Cada archivo lo lee y escribe el Agent; ejecuta en una copia del proyecto o en una rama, o prueba con uno o dos archivos primero.</p>
<h2 id="ejemplo-de-script-code-review-automático-y-escribir-informe">Ejemplo de script: Code review automático y escribir informe</h2>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D">#!/bin/bash</span></span>
<span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#79B8FF"> -p</span><span style="color:#79B8FF"> --force</span><span style="color:#79B8FF"> --output-format</span><span style="color:#9ECBFF"> text</span><span style="color:#79B8FF"> \</span></span>
<span data-line=""><span style="color:#9ECBFF">  "Do a code review of recent changes: readability, potential bugs, security, best practices. Write conclusions and concrete suggestions to review.txt"</span></span></code></pre></figure>
<p><code>--output-format text</code> deja la salida en texto plano para escribir a archivo o pipe a <code>grep</code>/scripts. El siguiente post cubre <code>json</code> y <code>stream-json</code>.</p>
<h2 id="entorno-api-key">Entorno: API key</h2>
<p>El modo headless suele ejecutarse donde no hay ventana de Cursor (p. ej. CI, máquina remota), así que hace falta autenticación:</p>
<ul>
<li>Variable de entorno: <code>export CURSOR_API_KEY=your_key</code></li>
<li>O ejecuta <code>cursor auth login</code> en ese entorno antes (si está soportado)</li>
</ul>
<p>Sin ello obtendrás errores y el Agent no correrá.</p>
<h2 id="diferencia-con---no-interactive-breve">Diferencia con --no-interactive (breve)</h2>
<table>
<thead>
<tr>
<th>Modo</th>
<th>Uso típico</th>
<th>¿Edita archivos?</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>--no-interactive</code></td>
<td>Ejecutar en terminal, ver salida paso a paso, sin pulsar tecla</td>
<td>Puede editar, pero puede preguntar (según config)</td>
</tr>
<tr>
<td><code>-p</code> / <code>--print</code></td>
<td>Scripts, CI, totalmente no interactivo, salida a stdout</td>
<td>Por defecto no</td>
</tr>
<tr>
<td><code>-p --force</code></td>
<td>Igual, pero permitir que el Agent edite archivos</td>
<td>Sí, sin preguntar</td>
</tr>
</tbody>
</table>
<p>Para <strong>scripts que "realmente cambian archivos"</strong> usa <code>-p --force</code>; para análisis o informes solo a terminal, basta <code>-p</code>.</p>
<h2 id="resumen">Resumen</h2>
<ul>
<li><strong><code>-p</code> / <code>--print</code></strong>: No interactivo, salida a terminal al terminar; por defecto no edita archivos</li>
<li><strong><code>--force</code> / <code>--yolo</code></strong>: En modo print, permitir que el Agent edite archivos; útil para scripts y CI</li>
<li>En scripts/CI, configura <code>CURSOR_API_KEY</code> o completa el login</li>
<li>Prueba en un ámbito pequeño antes de ejecutar en todo el repo</li>
</ul>
