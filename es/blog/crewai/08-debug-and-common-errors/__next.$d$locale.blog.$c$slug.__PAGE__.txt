3:Ta1b,<p>Verdad incómoda: desarrollar agentes no es lo más difícil. <strong>Depurar</strong> es lo que más tiempo consume.<br>
Este artículo es tu mapa de trampas para evitar desvíos innecesarios.</p>
<h2 id="8-problemas-más-comunes">8 problemas más comunes</h2>
<table>
<thead>
<tr>
<th>Síntoma</th>
<th>Causa común</th>
<th>Solución rápida</th>
</tr>
</thead>
<tbody>
<tr>
<td>El formato de salida cambia en cada ejecución</td>
<td><code>expected_output</code> demasiado vago</td>
<td>Añade restricciones de formato; usa <code>output_pydantic</code> si hace falta</td>
</tr>
<tr>
<td>La tarea siguiente no recibe datos</td>
<td>Falta <code>context</code></td>
<td>Define encadenamiento explícito en <code>tasks.yaml</code></td>
</tr>
<tr>
<td>La tool nunca se invoca</td>
<td>El prompt no exige uso de tool</td>
<td>Fuerza "use tool first" en la instrucción</td>
</tr>
<tr>
<td>El costo se dispara</td>
<td>Tarea muy larga y llamadas repetidas</td>
<td>Divide tareas, acorta prompts y añade caché</td>
</tr>
<tr>
<td>Muchas alucinaciones</td>
<td>Falta de restricciones de fuente</td>
<td>Exige URL de fuente y formato de cita</td>
</tr>
<tr>
<td>El flujo se queda atascado</td>
<td>Condiciones de rama incompletas</td>
<td>Verifica retornos del router y mapeos de listener</td>
</tr>
<tr>
<td>Falla al iniciar</td>
<td>Variables de entorno faltantes</td>
<td>Revisa <code>.env</code> y API keys</td>
</tr>
<tr>
<td>Rendimiento inestable</td>
<td>Inputs de prueba no fijos</td>
<td>Crea inputs fijos y criterios de aceptación</td>
</tr>
</tbody>
</table>
<h2 id="orden-recomendado-para-depurar">Orden recomendado para depurar</h2>
<ol>
<li>Revisa primero configuración: <code>agents.yaml</code>, <code>tasks.yaml</code></li>
<li>Luego revisa entradas: si <code>inputs</code> son estables</li>
<li>Después revisa tools: parámetros y formato de retorno</li>
<li>Finalmente revisa modelo: temperatura, ventana de contexto y costo</li>
</ol>
<p>No inviertas este orden. Mucha gente culpa primero al modelo, cuando el problema real es una línea YAML faltante.</p>
<h2 id="un-truco-muy-útil">Un truco muy útil</h2>
<p>En cada tarea, añade "resumen de salida" y "verificación de campos clave", por ejemplo:</p>
<ul>
<li>¿Hay conclusión?</li>
<li>¿Hay fuentes?</li>
<li>¿Respeta estructura markdown?</li>
</ul>
<p>Trátalo como mini pruebas unitarias dentro del flujo.</p>
