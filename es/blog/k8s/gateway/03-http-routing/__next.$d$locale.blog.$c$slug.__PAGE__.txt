3:T671d,<p>Los dos primeros artículos te dieron la base de "qué es esto." Este entra en lo que realmente estarás editando día a día: <code>HTTPRoute</code>.</p>
<p>Piensa en <code>HTTPRoute</code> como un script de enrutamiento para el tráfico entrante — excepto que en lugar de escribir reglas de Nginx o memorizar anotaciones de controlador, estás usando recursos nativos de Kubernetes.</p>
<p>Una cosa que dejar clara primero: este artículo solo cubre <code>HTTPRoute</code>, porque maneja la semántica HTTP/HTTPS. Para gRPC, te inclinarías hacia <code>GRPCRoute</code>; para TCP sin procesar, <code>TCPRoute</code>; para TLS passthrough, <code>TLSRoute</code>. No fuerces todo en <code>HTTPRoute</code> — el YAML empieza a transmitir una vibra de "arreglándoselas."</p>

<ul>
<li>Solo <code>Host: app.example.com</code> coincidirá con esta ruta</li>
<li>El path debe comenzar con <code>/api</code></li>
<li>El tráfico se reenvía a <code>api-service:8080</code></li>
</ul>
<p>Si eliminas <code>hostnames</code>, la ruta se convierte en "solo path, cualquier dominio."</p>
<h2 id="qué-puede-coincidir-matches">Qué Puede Coincidir <code>matches</code></h2>
<p><code>matches</code> es uno de los conceptos más centrales en <code>HTTPRoute</code>.
Piénsalo como "qué condiciones activan esta regla."</p>
<p>Condiciones de coincidencia comunes:</p>
<ul>
<li><code>path</code></li>
<li><code>headers</code></li>
<li><code>queryParams</code></li>
<li><code>method</code></li>
</ul>
<p>Ejemplo:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="yaml" data-theme="github-dark"><code data-language="yaml" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#85E89D">matches</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">  - </span><span style="color:#85E89D">method</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">GET</span></span>
<span data-line=""><span style="color:#85E89D">    path</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">      type</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">PathPrefix</span></span>
<span data-line=""><span style="color:#85E89D">      value</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">/api</span></span>
<span data-line=""><span style="color:#85E89D">    headers</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">      - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">version</span></span>
<span data-line=""><span style="color:#85E89D">        value</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">v2</span></span></code></pre></figure>
<p>Significado:</p>
<ul>
<li>Solo solicitudes <code>GET</code></li>
<li>El path comienza con <code>/api</code></li>
<li>La solicitud debe incluir el header <code>version: v2</code></li>
</ul>
<p>Este patrón es ideal para pruebas de versiones de API o lanzamientos graduales a usuarios específicos.</p>

<p>Esto es excelente para dividir sub-paths bajo un mismo dominio — por ejemplo:</p>
<ul>
<li><code>/api</code> va al servicio de API</li>
<li><code>/admin</code> va al backend de administración</li>
</ul>
<p>La lógica de enrutamiento es inmediatamente visible. A diferencia de algunos archivos de configuración heredados donde lees hasta la mitad y empiezas a dudar de tu propia existencia.</p>

<h2 id="filters-procesar-solicitudes-antes-de-reenviarlas"><code>filters</code>: Procesar Solicitudes Antes de Reenviarlas</h2>
<p><code>HTTPRoute</code> no solo "hace coincidir y reenvía" — también puede aplicar transformaciones antes o después del reenvío. Para eso están los <code>filters</code>.</p>
<p>Un caso de uso común es agregar headers:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="yaml" data-theme="github-dark"><code data-language="yaml" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#85E89D">rules</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">  - </span><span style="color:#85E89D">filters</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">      - </span><span style="color:#85E89D">type</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">RequestHeaderModifier</span></span>
<span data-line=""><span style="color:#85E89D">        requestHeaderModifier</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">          add</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">            - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">x-env</span></span>
<span data-line=""><span style="color:#85E89D">              value</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">prod</span></span>
<span data-line=""><span style="color:#85E89D">    backendRefs</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">      - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">api-service</span></span>
<span data-line=""><span style="color:#85E89D">        port</span><span style="color:#E1E4E8">: </span><span style="color:#79B8FF">8080</span></span></code></pre></figure>
<p>Esto es útil para:</p>
<ul>
<li>Inyectar metadatos de rastreo antes de reenviar al backend</li>
<li>Agregar headers fijos en la capa de ingreso</li>
<li>Transformaciones de solicitud/respuesta</li>
</ul>
<p>Dicho esto, los filters son poderosos pero no son un pase libre para convertir la capa de ingreso en un blob gigante de middleware. Demasiada lógica acumulada en las rutas hará que depurar se sienta como si necesitara su propia sesión de terapia.</p>

<span data-line=""><span style="color:#85E89D">    timeouts</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">      request</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">10s</span></span>
<span data-line=""><span style="color:#85E89D">      backendRequest</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">2s</span></span>
<span data-line=""><span style="color:#85E89D">    backendRefs</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">      - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">report-service</span></span>
<span data-line=""><span style="color:#85E89D">        port</span><span style="color:#E1E4E8">: </span><span style="color:#79B8FF">8080</span></span></code></pre></figure>
<p>Entendiendo los dos campos:</p>
<ul>
<li><code>request</code>: Tiempo máximo de espera total para la solicitud del cliente</li>
<li><code>backendRequest</code>: Espera máxima para una solicitud individual al backend</li>
</ul>
<p>Ten en cuenta que <code>backendRequest</code> no debería exceder <code>request</code> — la lógica sería como decir "el viaje completo toma 10 minutos, pero un tramo en autobús puede esperar 20 minutos." El universo se confunde.</p>
<h2 id="dos-matices-comunes">Dos Matices Comunes</h2>
<h3 id="1-parentrefs-puede-apuntar-a-un-listener-específico">1. <code>parentRefs</code> Puede Apuntar a un Listener Específico</h3>
<p>Si un Gateway tiene múltiples listeners, puedes vincularte solo a uno:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="yaml" data-theme="github-dark"><code data-language="yaml" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#85E89D">parentRefs</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">  - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">eg</span></span>
<span data-line=""><span style="color:#85E89D">    sectionName</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">http</span></span></code></pre></figure>
<p>Esto significa que la ruta solo se adjunta al listener <code>http</code>.
En configuraciones con múltiples listeners, esto es mucho más predecible que adjuntarse a todo.</p>
<h3 id="2-sin-matches--coincide-con-todo">2. Sin <code>matches</code> = Coincide con Todo</h3>
<p>Si una regla no tiene <code>matches</code>, por defecto coincide con <code>/</code> — esencialmente un catch-all.</p>
<p>Esto es conveniente, pero puede silenciosamente absorber lo que pensabas que eran reglas más específicas. No lo omitas por pereza y luego pases una hora preguntándote por qué tus reglas precisas no se están disparando.</p>
<h2 id="verificando-que-el-enrutamiento-funciona">Verificando que el Enrutamiento Funciona</h2>

<h2 id="resumen-en-una-línea">Resumen en Una Línea</h2>
<p>El núcleo de <code>HTTPRoute</code> es "primero hacer coincidir, luego reenviar." Una vez que tienes cubiertos host, path, header y weight, puedes manejar alrededor del 80% de los requisitos de ingreso HTTP del día a día.</p>

9:T671d,<p>Los dos primeros artículos te dieron la base de "qué es esto." Este entra en lo que realmente estarás editando día a día: <code>HTTPRoute</code>.</p>
<p>Piensa en <code>HTTPRoute</code> como un script de enrutamiento para el tráfico entrante — excepto que en lugar de escribir reglas de Nginx o memorizar anotaciones de controlador, estás usando recursos nativos de Kubernetes.</p>
<p>Una cosa que dejar clara primero: este artículo solo cubre <code>HTTPRoute</code>, porque maneja la semántica HTTP/HTTPS. Para gRPC, te inclinarías hacia <code>GRPCRoute</code>; para TCP sin procesar, <code>TCPRoute</code>; para TLS passthrough, <code>TLSRoute</code>. No fuerces todo en <code>HTTPRoute</code> — el YAML empieza a transmitir una vibra de "arreglándoselas."</p>
<h2 id="el-enrutamiento-más-común-host-y-path">El Enrutamiento Más Común: Host y Path</h2>
<p>Aquí está el ejemplo más típico:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="yaml" data-theme="github-dark"><code data-language="yaml" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#85E89D">apiVersion</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">gateway.networking.k8s.io/v1</span></span>
<span data-line=""><span style="color:#85E89D">kind</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">HTTPRoute</span></span>
<span data-line=""><span style="color:#85E89D">metadata</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">  name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">app-route</span></span>
<span data-line=""><span style="color:#85E89D">spec</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">  parentRefs</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">    - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">eg</span></span>
<span data-line=""><span style="color:#85E89D">  hostnames</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">    - </span><span style="color:#9ECBFF">"app.example.com"</span></span>
<span data-line=""><span style="color:#85E89D">  rules</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">    - </span><span style="color:#85E89D">matches</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">        - </span><span style="color:#85E89D">path</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">            type</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">PathPrefix</span></span>
<span data-line=""><span style="color:#85E89D">            value</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">/api</span></span>
<span data-line=""><span style="color:#85E89D">      backendRefs</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">        - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">api-service</span></span>
<span data-line=""><span style="color:#85E89D">          port</span><span style="color:#E1E4E8">: </span><span style="color:#79B8FF">8080</span></span></code></pre></figure>
<p>Lo que esto significa:</p>
<ul>
<li>Solo <code>Host: app.example.com</code> coincidirá con esta ruta</li>
<li>El path debe comenzar con <code>/api</code></li>
<li>El tráfico se reenvía a <code>api-service:8080</code></li>
</ul>
<p>Si eliminas <code>hostnames</code>, la ruta se convierte en "solo path, cualquier dominio."</p>
<h2 id="qué-puede-coincidir-matches">Qué Puede Coincidir <code>matches</code></h2>
<p><code>matches</code> es uno de los conceptos más centrales en <code>HTTPRoute</code>.
Piénsalo como "qué condiciones activan esta regla."</p>
<p>Condiciones de coincidencia comunes:</p>
<ul>
<li><code>path</code></li>
<li><code>headers</code></li>
<li><code>queryParams</code></li>
<li><code>method</code></li>
</ul>
<p>Ejemplo:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="yaml" data-theme="github-dark"><code data-language="yaml" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#85E89D">matches</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">  - </span><span style="color:#85E89D">method</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">GET</span></span>
<span data-line=""><span style="color:#85E89D">    path</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">      type</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">PathPrefix</span></span>
<span data-line=""><span style="color:#85E89D">      value</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">/api</span></span>
<span data-line=""><span style="color:#85E89D">    headers</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">      - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">version</span></span>
<span data-line=""><span style="color:#85E89D">        value</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">v2</span></span></code></pre></figure>
<p>Significado:</p>
<ul>
<li>Solo solicitudes <code>GET</code></li>
<li>El path comienza con <code>/api</code></li>
<li>La solicitud debe incluir el header <code>version: v2</code></li>
</ul>
<p>Este patrón es ideal para pruebas de versiones de API o lanzamientos graduales a usuarios específicos.</p>
<h2 id="una-route-múltiples-reglas">Una Route, Múltiples Reglas</h2>
<p>Un solo <code>HTTPRoute</code> puede enrutar diferentes paths a diferentes servicios:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="yaml" data-theme="github-dark"><code data-language="yaml" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#85E89D">rules</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">  - </span><span style="color:#85E89D">matches</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">      - </span><span style="color:#85E89D">path</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">          type</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">PathPrefix</span></span>
<span data-line=""><span style="color:#85E89D">          value</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">/api</span></span>
<span data-line=""><span style="color:#85E89D">    backendRefs</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">      - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">api-service</span></span>
<span data-line=""><span style="color:#85E89D">        port</span><span style="color:#E1E4E8">: </span><span style="color:#79B8FF">8080</span></span>
<span data-line=""><span style="color:#E1E4E8">  - </span><span style="color:#85E89D">matches</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">      - </span><span style="color:#85E89D">path</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">          type</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">PathPrefix</span></span>
<span data-line=""><span style="color:#85E89D">          value</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">/admin</span></span>
<span data-line=""><span style="color:#85E89D">    backendRefs</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">      - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">admin-service</span></span>

<ul>
<li><code>/api</code> va al servicio de API</li>
<li><code>/admin</code> va al backend de administración</li>
</ul>

<h2 id="header-method-y-query-como-condiciones">Header, Method y Query como Condiciones</h2>
<p><code>HTTPRoute</code> no se limita a la coincidencia por path — también puede hacer coincidir por headers de solicitud, métodos y parámetros de query.</p>
<p>Por ejemplo, solo enrutar solicitudes con <code>version: v2</code> al nuevo servicio:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="yaml" data-theme="github-dark"><code data-language="yaml" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#85E89D">apiVersion</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">gateway.networking.k8s.io/v1</span></span>
<span data-line=""><span style="color:#85E89D">kind</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">HTTPRoute</span></span>
<span data-line=""><span style="color:#85E89D">metadata</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">  name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">versioned-route</span></span>
<span data-line=""><span style="color:#85E89D">spec</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">  parentRefs</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">    - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">eg</span></span>
<span data-line=""><span style="color:#85E89D">  rules</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">    - </span><span style="color:#85E89D">matches</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">        - </span><span style="color:#85E89D">path</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">            type</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">PathPrefix</span></span>
<span data-line=""><span style="color:#85E89D">            value</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">/api</span></span>
<span data-line=""><span style="color:#85E89D">          headers</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">            - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">version</span></span>
<span data-line=""><span style="color:#85E89D">              value</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">v2</span></span>
<span data-line=""><span style="color:#85E89D">      backendRefs</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">        - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">api-v2</span></span>
<span data-line=""><span style="color:#85E89D">          port</span><span style="color:#E1E4E8">: </span><span style="color:#79B8FF">8080</span></span>
<span data-line=""><span style="color:#E1E4E8">    - </span><span style="color:#85E89D">matches</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">        - </span><span style="color:#85E89D">path</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">            type</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">PathPrefix</span></span>
<span data-line=""><span style="color:#85E89D">            value</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">/api</span></span>
<span data-line=""><span style="color:#85E89D">      backendRefs</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">        - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">api-v1</span></span>
<span data-line=""><span style="color:#85E89D">          port</span><span style="color:#E1E4E8">: </span><span style="color:#79B8FF">8080</span></span></code></pre></figure>
<p>Este patrón funciona bien para:</p>
<ul>
<li>Lanzamientos canary</li>
<li>Permitir que clientes específicos prueben nuevas versiones antes</li>
<li>Validación manual de nuevas características</li>
</ul>
<p>Comparado con cambiar a un dominio completamente nuevo, el enrutamiento basado en headers es más granular y más fácil de experimentar.</p>
<h2 id="filters-procesar-solicitudes-antes-de-reenviarlas"><code>filters</code>: Procesar Solicitudes Antes de Reenviarlas</h2>
<p><code>HTTPRoute</code> no solo "hace coincidir y reenvía" — también puede aplicar transformaciones antes o después del reenvío. Para eso están los <code>filters</code>.</p>
<p>Un caso de uso común es agregar headers:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="yaml" data-theme="github-dark"><code data-language="yaml" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#85E89D">rules</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">  - </span><span style="color:#85E89D">filters</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">      - </span><span style="color:#85E89D">type</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">RequestHeaderModifier</span></span>
<span data-line=""><span style="color:#85E89D">        requestHeaderModifier</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">          add</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">            - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">x-env</span></span>
<span data-line=""><span style="color:#85E89D">              value</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">prod</span></span>
<span data-line=""><span style="color:#85E89D">    backendRefs</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">      - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">api-service</span></span>
<span data-line=""><span style="color:#85E89D">        port</span><span style="color:#E1E4E8">: </span><span style="color:#79B8FF">8080</span></span></code></pre></figure>
<p>Esto es útil para:</p>
<ul>
<li>Inyectar metadatos de rastreo antes de reenviar al backend</li>
<li>Agregar headers fijos en la capa de ingreso</li>
<li>Transformaciones de solicitud/respuesta</li>
</ul>
<p>Dicho esto, los filters son poderosos pero no son un pase libre para convertir la capa de ingreso en un blob gigante de middleware. Demasiada lógica acumulada en las rutas hará que depurar se sienta como si necesitara su propia sesión de terapia.</p>
<h2 id="división-de-tráfico-ponderada-el-patrón-canary-más-común">División de Tráfico Ponderada: El Patrón Canary Más Común</h2>
<p>Para enviar el 90% del tráfico a la versión anterior y el 10% a la nueva, usa <code>weight</code>:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="yaml" data-theme="github-dark"><code data-language="yaml" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#85E89D">apiVersion</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">gateway.networking.k8s.io/v1</span></span>
<span data-line=""><span style="color:#85E89D">kind</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">HTTPRoute</span></span>
<span data-line=""><span style="color:#85E89D">metadata</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">  name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">canary-route</span></span>
<span data-line=""><span style="color:#85E89D">spec</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">  parentRefs</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">    - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">eg</span></span>
<span data-line=""><span style="color:#85E89D">  hostnames</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">    - </span><span style="color:#9ECBFF">"app.example.com"</span></span>
<span data-line=""><span style="color:#85E89D">  rules</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">    - </span><span style="color:#85E89D">backendRefs</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">        - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">api-v1</span></span>
<span data-line=""><span style="color:#85E89D">          port</span><span style="color:#E1E4E8">: </span><span style="color:#79B8FF">8080</span></span>
<span data-line=""><span style="color:#85E89D">          weight</span><span style="color:#E1E4E8">: </span><span style="color:#79B8FF">90</span></span>
<span data-line=""><span style="color:#E1E4E8">        - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">api-v2</span></span>
<span data-line=""><span style="color:#85E89D">          port</span><span style="color:#E1E4E8">: </span><span style="color:#79B8FF">8080</span></span>
<span data-line=""><span style="color:#85E89D">          weight</span><span style="color:#E1E4E8">: </span><span style="color:#79B8FF">10</span></span></code></pre></figure>
<p>Este es el canary básico / división de tráfico.</p>
<p>No necesitas un service mesh completo solo para ejecutar un experimento de tráfico. Para muchos servicios de API, esto es más que suficiente — y es mucho más limpio de configurar.</p>
<blockquote>
<p>💡 <code>weight</code> es relativo, no es necesario que sume 100. <code>9</code> y <code>1</code> expresan la misma proporción que <code>90</code> y <code>10</code>.</p>
</blockquote>
<h2 id="timeouts-no-dejes-que-las-solicitudes-queden-colgadas-para-siempre"><code>timeouts</code>: No Dejes que las Solicitudes Queden Colgadas para Siempre</h2>
<p>HTTPRoute admite configuración de timeout a nivel de regla. Esto importa — si la capa de ingreso no tiene límites, las solicitudes malas se quedan indefinidamente como un cliente maleducado que no se quiere ir.</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="yaml" data-theme="github-dark"><code data-language="yaml" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#85E89D">rules</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">  - </span><span style="color:#85E89D">matches</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">      - </span><span style="color:#85E89D">path</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">          type</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">PathPrefix</span></span>
<span data-line=""><span style="color:#85E89D">          value</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">/reports</span></span>
<span data-line=""><span style="color:#85E89D">    timeouts</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">      request</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">10s</span></span>
<span data-line=""><span style="color:#85E89D">      backendRequest</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">2s</span></span>
<span data-line=""><span style="color:#85E89D">    backendRefs</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">      - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">report-service</span></span>
<span data-line=""><span style="color:#85E89D">        port</span><span style="color:#E1E4E8">: </span><span style="color:#79B8FF">8080</span></span></code></pre></figure>
<p>Entendiendo los dos campos:</p>
<ul>
<li><code>request</code>: Tiempo máximo de espera total para la solicitud del cliente</li>
<li><code>backendRequest</code>: Espera máxima para una solicitud individual al backend</li>
</ul>
<p>Ten en cuenta que <code>backendRequest</code> no debería exceder <code>request</code> — la lógica sería como decir "el viaje completo toma 10 minutos, pero un tramo en autobús puede esperar 20 minutos." El universo se confunde.</p>
<h2 id="dos-matices-comunes">Dos Matices Comunes</h2>
<h3 id="1-parentrefs-puede-apuntar-a-un-listener-específico">1. <code>parentRefs</code> Puede Apuntar a un Listener Específico</h3>
<p>Si un Gateway tiene múltiples listeners, puedes vincularte solo a uno:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="yaml" data-theme="github-dark"><code data-language="yaml" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#85E89D">parentRefs</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">  - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">eg</span></span>
<span data-line=""><span style="color:#85E89D">    sectionName</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">http</span></span></code></pre></figure>
<p>Esto significa que la ruta solo se adjunta al listener <code>http</code>.
En configuraciones con múltiples listeners, esto es mucho más predecible que adjuntarse a todo.</p>
<h3 id="2-sin-matches--coincide-con-todo">2. Sin <code>matches</code> = Coincide con Todo</h3>
<p>Si una regla no tiene <code>matches</code>, por defecto coincide con <code>/</code> — esencialmente un catch-all.</p>
<p>Esto es conveniente, pero puede silenciosamente absorber lo que pensabas que eran reglas más específicas. No lo omitas por pereza y luego pases una hora preguntándote por qué tus reglas precisas no se están disparando.</p>

<h2 id="resumen-en-una-línea">Resumen en Una Línea</h2>
<p>El núcleo de <code>HTTPRoute</code> es "primero hacer coincidir, luego reenviar." Una vez que tienes cubiertos host, path, header y weight, puedes manejar alrededor del 80% de los requisitos de ingreso HTTP del día a día.</p>
