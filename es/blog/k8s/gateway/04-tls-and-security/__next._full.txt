1c:T5fff,<p>Hacer funcionar HTTP es solo el calentamiento. A menos que tu servicio viva en la Edad de Piedra, producción casi con certeza necesita HTTPS. Este post cubre los fundamentos de TLS para Envoy Gateway para que tus APIs dejen de correr en texto claro.</p>
<h2 id="cómo-funciona-tls-en-gateway">Cómo Funciona TLS en Gateway</h2>
<p>El enfoque más común: <strong>terminar TLS en el listener del Gateway.</strong></p>
<p>Esto significa:</p>
<ul>
<li>El cliente se conecta vía HTTPS</li>
<li>El Gateway gestiona el handshake y el certificado</li>
<li>El tráfico se reenvía a tu Service sin cifrar internamente</li>
</ul>
<p>Un listener HTTPS básico luce así:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="yaml" data-theme="github-dark"><code data-language="yaml" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#85E89D">apiVersion</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">gateway.networking.k8s.io/v1</span></span>

<p>Dos cosas importan aquí:</p>
<ul>
<li><code>protocol: HTTPS</code></li>
<li><code>tls.mode: Terminate</code></li>
</ul>
<p>Esto significa: TLS termina aquí, y el Gateway se encarga del certificado.</p>
<h2 id="https--httproute-vs-tlsroute-cuál-es-la-diferencia"><code>HTTPS + HTTPRoute</code> vs <code>TLSRoute</code>: Cuál es la Diferencia</h2>
<p>Esto es importante, porque mucha gente ve <code>TLSRoute</code> y enseguida pregunta:</p>
<p>"¿No es suficiente con un listener HTTPS? ¿Para qué necesitamos un <code>TLSRoute</code> separado?"</p>
<p>La diferencia está en <strong>si el Gateway termina TLS o no</strong>:</p>
<table>
<thead>
<tr>
<th>Escenario</th>
<th>Combinación Habitual</th>
<th>Descripción</th>
</tr>
</thead>
<tbody>
<tr>
<td>El Gateway termina TLS y luego aplica reglas HTTP</td>
<td><code>listener HTTPS + HTTPRoute</code></td>
<td>El escenario más común para sitios web y APIs</td>
</tr>
<tr>
<td>El Gateway no descifra — enruta tráfico cifrado basándose solo en SNI</td>
<td><code>listener TLS + TLSRoute</code></td>
<td>Escenario de TLS passthrough</td>
</tr>
</tbody>
</table>
<p>En otras palabras:</p>
<ul>
<li>Si quieres inspeccionar <code>path</code>, <code>header</code>, <code>method</code> en el Gateway, primero necesitas terminar TLS y luego usar <code>HTTPRoute</code></li>
<li>Si quieres preservar el cifrado de extremo a extremo y no descifrar en el Gateway, <code>TLSRoute</code> es el camino correcto</li>
</ul>
<p>Ningún enfoque es "más avanzado" — lo importante es saber qué quieres: "terminar TLS y hacer routing L7," o "mantener el cifrado intacto y hacer routing basado en SNI."</p>

<p>Si el listener se ve saludable, prueba HTTPS:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">curl</span><span style="color:#79B8FF"> -v</span><span style="color:#79B8FF"> -HHost:www.example.com</span><span style="color:#79B8FF"> \</span></span>
<span data-line=""><span style="color:#79B8FF">  --resolve</span><span style="color:#9ECBFF"> "www.example.com:443:${</span><span style="color:#E1E4E8">GATEWAY_HOST</span><span style="color:#9ECBFF">}"</span><span style="color:#79B8FF"> \</span></span>

<p>Este comando es excelente para validación local, especialmente cuando el DNS todavía no está configurado.</p>
<h2 id="un-gateway-múltiples-dominios-https">Un Gateway, Múltiples Dominios HTTPS</h2>
<p>Si tienes múltiples dominios, agrega múltiples listeners HTTPS al mismo Gateway.
Por ejemplo, para agregar <code>foo.example.com</code>:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="yaml" data-theme="github-dark"><code data-language="yaml" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#85E89D">listeners</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">  - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">https-main</span></span>
<span data-line=""><span style="color:#85E89D">    protocol</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">HTTPS</span></span>
<span data-line=""><span style="color:#85E89D">    port</span><span style="color:#E1E4E8">: </span><span style="color:#79B8FF">443</span></span>
<span data-line=""><span style="color:#85E89D">    hostname</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">www.example.com</span></span>
<span data-line=""><span style="color:#85E89D">    tls</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">      mode</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">Terminate</span></span>
<span data-line=""><span style="color:#85E89D">      certificateRefs</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">        - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">example-cert</span></span>
<span data-line=""><span style="color:#E1E4E8">  - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">https-foo</span></span>
<span data-line=""><span style="color:#85E89D">    protocol</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">HTTPS</span></span>
<span data-line=""><span style="color:#85E89D">    port</span><span style="color:#E1E4E8">: </span><span style="color:#79B8FF">443</span></span>
<span data-line=""><span style="color:#85E89D">    hostname</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">foo.example.com</span></span>
<span data-line=""><span style="color:#85E89D">    tls</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">      mode</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">Terminate</span></span>
<span data-line=""><span style="color:#85E89D">      certificateRefs</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">        - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">foo-cert</span></span></code></pre></figure>
<p>No olvides actualizar el <code>HTTPRoute</code> correspondiente con el hostname correcto — de lo contrario, el listener puede estar escuchando, pero la ruta no sabe a dónde enviar el tráfico.</p>
<h2 id="modelo-mental-para-tlsroute">Modelo Mental para <code>TLSRoute</code></h2>
<p>Para TLS passthrough, piensa en <code>TLSRoute</code> así:</p>
<blockquote>
<p>💡 El <code>apiVersion</code> para <code>TLSRoute</code> puede variar dependiendo de qué versión de los CRDs de Gateway API tengas instalada. El ejemplo a continuación es solo para ilustración conceptual — verifica la versión instalada en tu clúster antes de aplicarlo.</p>
</blockquote>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="yaml" data-theme="github-dark"><code data-language="yaml" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#85E89D">apiVersion</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">gateway.networking.k8s.io/v1</span></span>
<span data-line=""><span style="color:#85E89D">kind</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">Gateway</span></span>
<span data-line=""><span style="color:#85E89D">metadata</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">  name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">eg-tls</span></span>
<span data-line=""><span style="color:#85E89D">spec</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">  gatewayClassName</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">eg</span></span>
<span data-line=""><span style="color:#85E89D">  listeners</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">    - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">tls</span></span>
<span data-line=""><span style="color:#85E89D">      protocol</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">TLS</span></span>

<span data-line=""><span style="color:#B392F0">---</span></span>
<span data-line=""><span style="color:#85E89D">apiVersion</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">gateway.networking.k8s.io/v1alpha2</span></span>
<span data-line=""><span style="color:#85E89D">kind</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">TLSRoute</span></span>

<span data-line=""><span style="color:#85E89D">  parentRefs</span><span style="color:#E1E4E8">:</span></span>

<span data-line=""><span style="color:#85E89D">  rules</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">    - </span><span style="color:#85E89D">backendRefs</span><span style="color:#E1E4E8">:</span></span>

<p>Casos de uso comunes para este patrón:</p>
<ul>
<li>Routing basado únicamente en el hostname SNI</li>
<li>Preservar el cifrado hasta el backend</li>
<li>Sin análisis de path o headers HTTP en el Gateway</li>
</ul>
<p>Así que la mayor diferencia entre <code>TLSRoute</code> y <code>HTTPRoute</code> no es solo el nombre — operan en capas de tráfico completamente distintas.</p>
<h2 id="referencias-de-certificados-entre-namespaces">Referencias de Certificados Entre Namespaces</h2>
<p>La documentación oficial destaca una capacidad útil:
<strong>Un Gateway puede referenciar Secrets de certificados de otros namespaces — pero requiere un <code>ReferenceGrant</code>.</strong></p>
<p>Por ejemplo, si el equipo de plataforma almacena los certificados de forma centralizada en <code>envoy-gateway-system</code>, pero el Gateway de la aplicación está en <code>default</code>, no puedes simplemente referenciar entre namespaces sin autorización explícita.</p>
<p>Ejemplo:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="yaml" data-theme="github-dark"><code data-language="yaml" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#85E89D">apiVersion</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">gateway.networking.k8s.io/v1beta1</span></span>
<span data-line=""><span style="color:#85E89D">kind</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">ReferenceGrant</span></span>
<span data-line=""><span style="color:#85E89D">metadata</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">  name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">allow-default-to-read-cert</span></span>
<span data-line=""><span style="color:#85E89D">  namespace</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">envoy-gateway-system</span></span>
<span data-line=""><span style="color:#85E89D">spec</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">  from</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">    - </span><span style="color:#85E89D">group</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">gateway.networking.k8s.io</span></span>
<span data-line=""><span style="color:#85E89D">      kind</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">Gateway</span></span>
<span data-line=""><span style="color:#85E89D">      namespace</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">default</span></span>
<span data-line=""><span style="color:#85E89D">  to</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">    - </span><span style="color:#85E89D">group</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">""</span></span>
<span data-line=""><span style="color:#85E89D">      kind</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">Secret</span></span></code></pre></figure>
<p>Esto significa:</p>
<ul>
<li>Un <code>Gateway</code> en el namespace <code>default</code></li>
<li>Está autorizado a referenciar recursos <code>Secret</code> en <code>envoy-gateway-system</code></li>
</ul>
<p>Sin un <code>ReferenceGrant</code>, esta referencia entre namespaces se trata como inválida. Es un mecanismo de protección — no Gateway API siendo innecesariamente estricta.</p>
<h2 id="resumen-en-una-línea">Resumen en Una Línea</h2>
<p>TLS en Envoy Gateway no es tan misterioso como suena: prepara el Secret del certificado, configura el listener HTTPS, confirma que tu ruta y hostname coincidan — y básicamente eso es todo.</p>
<blockquote>
<p>💡 El error más común de los principiantes no es que TLS sea difícil — es que tres cosas no están alineadas: <code>hostname</code>, <code>certificateRefs</code> y los hostnames de <code>HTTPRoute</code>. Si cualquiera de ellas está mal, el tráfico empieza a comportarse de forma extraña.</p>
</blockquote>

<h2 id="https--httproute-vs-tlsroute-cuál-es-la-diferencia"><code>HTTPS + HTTPRoute</code> vs <code>TLSRoute</code>: Cuál es la Diferencia</h2>
<p>Esto es importante, porque mucha gente ve <code>TLSRoute</code> y enseguida pregunta:</p>
<p>"¿No es suficiente con un listener HTTPS? ¿Para qué necesitamos un <code>TLSRoute</code> separado?"</p>
<p>La diferencia está en <strong>si el Gateway termina TLS o no</strong>:</p>
<table>
<thead>
<tr>
<th>Escenario</th>
<th>Combinación Habitual</th>
<th>Descripción</th>
</tr>
</thead>
<tbody>
<tr>
<td>El Gateway termina TLS y luego aplica reglas HTTP</td>
<td><code>listener HTTPS + HTTPRoute</code></td>
<td>El escenario más común para sitios web y APIs</td>
</tr>
<tr>
<td>El Gateway no descifra — enruta tráfico cifrado basándose solo en SNI</td>
<td><code>listener TLS + TLSRoute</code></td>
<td>Escenario de TLS passthrough</td>
</tr>
</tbody>
</table>
<p>En otras palabras:</p>
<ul>
<li>Si quieres inspeccionar <code>path</code>, <code>header</code>, <code>method</code> en el Gateway, primero necesitas terminar TLS y luego usar <code>HTTPRoute</code></li>
<li>Si quieres preservar el cifrado de extremo a extremo y no descifrar en el Gateway, <code>TLSRoute</code> es el camino correcto</li>
</ul>
<p>Ningún enfoque es "más avanzado" — lo importante es saber qué quieres: "terminar TLS y hacer routing L7," o "mantener el cifrado intacto y hacer routing basado en SNI."</p>
<h2 id="preparar-el-secret-del-certificado">Preparar el Secret del Certificado</h2>
<p>Para entornos de prueba, un certificado autofirmado funciona bien. Los ejemplos oficiales usan exactamente esto:</p>

<p>El <code>Gateway</code> puede entonces referenciar este Secret mediante <code>certificateRefs</code>.</p>
<blockquote>
<p>⚠️ Los certificados autofirmados son solo para pruebas. En producción, usa cert-manager o tu flujo de gestión de certificados existente. No lleves la configuración del demo directamente a producción — es como sobrevivir a base de fideos instantáneos: está bien de vez en cuando, pero no es sostenible a largo plazo.</p>
</blockquote>
<h2 id="agregar-un-listener-https-a-un-gateway-existente">Agregar un Listener HTTPS a un Gateway Existente</h2>
<p>Si ya tienes un Gateway <code>eg</code> del post anterior, puedes parchearlo directamente:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">kubectl</span><span style="color:#9ECBFF"> patch</span><span style="color:#9ECBFF"> gateway</span><span style="color:#9ECBFF"> eg</span><span style="color:#79B8FF"> --type=json</span><span style="color:#79B8FF"> --patch</span><span style="color:#9ECBFF"> '</span></span>
<span data-line=""><span style="color:#9ECBFF">  - op: add</span></span>

<h2 id="modelo-mental-para-tlsroute">Modelo Mental para <code>TLSRoute</code></h2>

</blockquote>

<span data-line=""><span style="color:#85E89D">spec</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">  gatewayClassName</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">eg</span></span>
<span data-line=""><span style="color:#85E89D">  listeners</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">    - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">tls</span></span>

<span data-line=""><span style="color:#85E89D">spec</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">  parentRefs</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">    - </span><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">eg-tls</span></span>

<ul>
<li>Routing basado únicamente en el hostname SNI</li>
<li>Preservar el cifrado hasta el backend</li>
<li>Sin análisis de path o headers HTTP en el Gateway</li>
</ul>
<p>Así que la mayor diferencia entre <code>TLSRoute</code> y <code>HTTPRoute</code> no es solo el nombre — operan en capas de tráfico completamente distintas.</p>
<h2 id="referencias-de-certificados-entre-namespaces">Referencias de Certificados Entre Namespaces</h2>
<p>La documentación oficial destaca una capacidad útil:
<strong>Un Gateway puede referenciar Secrets de certificados de otros namespaces — pero requiere un <code>ReferenceGrant</code>.</strong></p>
<p>Por ejemplo, si el equipo de plataforma almacena los certificados de forma centralizada en <code>envoy-gateway-system</code>, pero el Gateway de la aplicación está en <code>default</code>, no puedes simplemente referenciar entre namespaces sin autorización explícita.</p>
<p>Ejemplo:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="yaml" data-theme="github-dark"><code data-language="yaml" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#85E89D">apiVersion</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">gateway.networking.k8s.io/v1beta1</span></span>
<span data-line=""><span style="color:#85E89D">kind</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">ReferenceGrant</span></span>
<span data-line=""><span style="color:#85E89D">metadata</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">  name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">allow-default-to-read-cert</span></span>
<span data-line=""><span style="color:#85E89D">  namespace</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">envoy-gateway-system</span></span>
<span data-line=""><span style="color:#85E89D">spec</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#85E89D">  from</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">    - </span><span style="color:#85E89D">group</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">gateway.networking.k8s.io</span></span>
<span data-line=""><span style="color:#85E89D">      kind</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">Gateway</span></span>
<span data-line=""><span style="color:#85E89D">      namespace</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">default</span></span>
<span data-line=""><span style="color:#85E89D">  to</span><span style="color:#E1E4E8">:</span></span>
<span data-line=""><span style="color:#E1E4E8">    - </span><span style="color:#85E89D">group</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">""</span></span>
<span data-line=""><span style="color:#85E89D">      kind</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">Secret</span></span></code></pre></figure>
<p>Esto significa:</p>
<ul>
<li>Un <code>Gateway</code> en el namespace <code>default</code></li>
<li>Está autorizado a referenciar recursos <code>Secret</code> en <code>envoy-gateway-system</code></li>
</ul>
<p>Sin un <code>ReferenceGrant</code>, esta referencia entre namespaces se trata como inválida. Es un mecanismo de protección — no Gateway API siendo innecesariamente estricta.</p>
<h2 id="resumen-en-una-línea">Resumen en Una Línea</h2>
<p>TLS en Envoy Gateway no es tan misterioso como suena: prepara el Secret del certificado, configura el listener HTTPS, confirma que tu ruta y hostname coincidan — y básicamente eso es todo.</p>
<blockquote>
<p>💡 El error más común de los principiantes no es que TLS sea difícil — es que tres cosas no están alineadas: <code>hostname</code>, <code>certificateRefs</code> y los hostnames de <code>HTTPRoute</code>. Si cualquiera de ellas está mal, el tráfico empieza a comportarse de forma extraña.</p>
</blockquote>
