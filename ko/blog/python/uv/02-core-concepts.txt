1b:T1847,<p>명령어를 마구 치기 전에 이 4가지 개념을 머리에 넣으세요: "의존성은 어디에 쓰는지, 잠금 파일은 무엇을 위한 건지, venv는 언제 만들어지는지"가 명확해집니다. 게임하기 전에 스킬 설명을 읽는 것처럼 — 읽지 않으면 이유 없이 계속 죽습니다.</p>
<h2 id="개념-1-pyprojecttoml은-프로젝트의-신분증">개념 1: pyproject.toml은 프로젝트의 신분증</h2>
<p>프로젝트 메타데이터와 의존성 모두 여기에 씁니다. PEP 518 표준 형식입니다.</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="toml" data-theme="github-dark"><code data-language="toml" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#E1E4E8">[</span><span style="color:#B392F0">project</span><span style="color:#E1E4E8">]</span></span>
<span data-line=""><span style="color:#E1E4E8">name = </span><span style="color:#9ECBFF">"my-app"</span></span>
<span data-line=""><span style="color:#E1E4E8">version = </span><span style="color:#9ECBFF">"0.1.0"</span></span>
<span data-line=""><span style="color:#E1E4E8">requires-python = </span><span style="color:#9ECBFF">">=3.12"</span></span>
<span data-line=""><span style="color:#E1E4E8">dependencies = [</span></span>
<span data-line=""><span style="color:#9ECBFF">    "requests>=2.31"</span><span style="color:#E1E4E8">,</span></span>
<span data-line=""><span style="color:#E1E4E8">]</span></span></code></pre></figure>
<ul>
<li><strong>수동 편집</strong>: <code>pyproject.toml</code> 직접 편집</li>
<li><strong>명령어로 변경</strong>: <code>uv add requests</code>·<code>uv remove requests</code>가 자동으로 업데이트</li>
</ul>
<blockquote>
<p>혼용하지 마세요 — 수동 또는 명령어, 하나로 통일. 둘 다 쓰면 충돌합니다.</p>
</blockquote>
<h2 id="개념-2-uvlock은-의존성-스냅샷">개념 2: uv.lock은 의존성 스냅샷</h2>
<p><code>pyproject.toml</code>은 "무엇을 원하는지"를 씁니다 (예: <code>requests>=2.31</code>). <code>uv.lock</code>은 "실제로 설치된 버전"을 기록합니다 — 모든 전이 의존성까지 정확하게.</p>
<ul>
<li><strong>왜 잠금 파일이 필요한가?</strong> 모든 팀원·CI·프로덕션이 완전히 같은 의존성 트리를 설치하도록 보장합니다. "내 환경에서는 되는데 네 환경에서는 터진다"는 더 이상 없습니다.</li>
<li><strong>커밋해야 하나?</strong> 예. <code>uv.lock</code>은 버전 관리에 포함해서 팀과 CI가 같은 의존성 트리를 사용하게 하세요.</li>
</ul>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># 잠금 파일 업데이트 (예: 패키지 업그레이드)</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> lock</span><span style="color:#79B8FF"> --upgrade-package</span><span style="color:#9ECBFF"> requests</span></span></code></pre></figure>
<h2 id="개념-3-venv는-프로젝트-전용-샌드박스">개념 3: .venv는 프로젝트 전용 샌드박스</h2>
<p>uv는 프로젝트 루트에 <code>.venv</code>를 만듭니다 — <code>uv add</code>한 모든 패키지가 여기에 들어가고 시스템 Python과 격리됩니다.</p>
<ul>
<li><strong>수동으로 activate해야 하나?</strong> 아니요. <code>uv run</code>이 자동으로 이 환경을 사용합니다.</li>
<li><strong>커밋해야 하나?</strong> 아니요. <code>.venv</code>는 <code>.gitignore</code>에 넣으세요.</li>
</ul>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># 환경 수동 동기화 (예: 새로 클론한 후)</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> sync</span></span>
<span data-line=""><span style="color:#79B8FF">source</span><span style="color:#9ECBFF"> .venv/bin/activate</span><span style="color:#6A737D">  # 이후 python, pytest 등을 직접 사용 가능</span></span></code></pre></figure>
<h2 id="개념-4-uv-run은-편리한-실행-진입점">개념 4: uv run은 편리한 실행 진입점</h2>
<p><code>uv run</code>이 하는 일:</p>
<ol>
<li>잠금 파일이 pyproject.toml과 일치하는지 확인</li>
<li>.venv가 잠금 파일과 동기화되었는지 확인</li>
<li>올바른 환경에서 지정한 명령을 실행</li>
</ol>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> run</span><span style="color:#9ECBFF"> python</span><span style="color:#9ECBFF"> main.py</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> run</span><span style="color:#9ECBFF"> pytest</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> run</span><span style="color:#9ECBFF"> flask</span><span style="color:#9ECBFF"> run</span><span style="color:#79B8FF"> -p</span><span style="color:#79B8FF"> 3000</span></span></code></pre></figure>
<p>activate를 기억할 필요도, 잘못된 환경을 걱정할 필요도 없음 — uv에게 맡기면 됩니다. 화장실 위치를 생각하지 않아도 자연스럽게 가는 고양이처럼. 이 "열면 바로 실행되는" 경험은 한 번 써보면 돌아갈 수 없습니다.</p>

<h2 id="개념-1-pyprojecttoml은-프로젝트의-신분증">개념 1: pyproject.toml은 프로젝트의 신분증</h2>
<p>프로젝트 메타데이터와 의존성 모두 여기에 씁니다. PEP 518 표준 형식입니다.</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="toml" data-theme="github-dark"><code data-language="toml" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#E1E4E8">[</span><span style="color:#B392F0">project</span><span style="color:#E1E4E8">]</span></span>
<span data-line=""><span style="color:#E1E4E8">name = </span><span style="color:#9ECBFF">"my-app"</span></span>
<span data-line=""><span style="color:#E1E4E8">version = </span><span style="color:#9ECBFF">"0.1.0"</span></span>
<span data-line=""><span style="color:#E1E4E8">requires-python = </span><span style="color:#9ECBFF">">=3.12"</span></span>
<span data-line=""><span style="color:#E1E4E8">dependencies = [</span></span>
<span data-line=""><span style="color:#9ECBFF">    "requests>=2.31"</span><span style="color:#E1E4E8">,</span></span>
<span data-line=""><span style="color:#E1E4E8">]</span></span></code></pre></figure>
<ul>
<li><strong>수동 편집</strong>: <code>pyproject.toml</code> 직접 편집</li>
<li><strong>명령어로 변경</strong>: <code>uv add requests</code>·<code>uv remove requests</code>가 자동으로 업데이트</li>
</ul>
<blockquote>
<p>혼용하지 마세요 — 수동 또는 명령어, 하나로 통일. 둘 다 쓰면 충돌합니다.</p>
</blockquote>
<h2 id="개념-2-uvlock은-의존성-스냅샷">개념 2: uv.lock은 의존성 스냅샷</h2>
<p><code>pyproject.toml</code>은 "무엇을 원하는지"를 씁니다 (예: <code>requests>=2.31</code>). <code>uv.lock</code>은 "실제로 설치된 버전"을 기록합니다 — 모든 전이 의존성까지 정확하게.</p>
<ul>
<li><strong>왜 잠금 파일이 필요한가?</strong> 모든 팀원·CI·프로덕션이 완전히 같은 의존성 트리를 설치하도록 보장합니다. "내 환경에서는 되는데 네 환경에서는 터진다"는 더 이상 없습니다.</li>
<li><strong>커밋해야 하나?</strong> 예. <code>uv.lock</code>은 버전 관리에 포함해서 팀과 CI가 같은 의존성 트리를 사용하게 하세요.</li>
</ul>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># 잠금 파일 업데이트 (예: 패키지 업그레이드)</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> lock</span><span style="color:#79B8FF"> --upgrade-package</span><span style="color:#9ECBFF"> requests</span></span></code></pre></figure>
<h2 id="개념-3-venv는-프로젝트-전용-샌드박스">개념 3: .venv는 프로젝트 전용 샌드박스</h2>
<p>uv는 프로젝트 루트에 <code>.venv</code>를 만듭니다 — <code>uv add</code>한 모든 패키지가 여기에 들어가고 시스템 Python과 격리됩니다.</p>
<ul>
<li><strong>수동으로 activate해야 하나?</strong> 아니요. <code>uv run</code>이 자동으로 이 환경을 사용합니다.</li>
<li><strong>커밋해야 하나?</strong> 아니요. <code>.venv</code>는 <code>.gitignore</code>에 넣으세요.</li>
</ul>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># 환경 수동 동기화 (예: 새로 클론한 후)</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> sync</span></span>
<span data-line=""><span style="color:#79B8FF">source</span><span style="color:#9ECBFF"> .venv/bin/activate</span><span style="color:#6A737D">  # 이후 python, pytest 등을 직접 사용 가능</span></span></code></pre></figure>
<h2 id="개념-4-uv-run은-편리한-실행-진입점">개념 4: uv run은 편리한 실행 진입점</h2>
<p><code>uv run</code>이 하는 일:</p>
<ol>
<li>잠금 파일이 pyproject.toml과 일치하는지 확인</li>
<li>.venv가 잠금 파일과 동기화되었는지 확인</li>
<li>올바른 환경에서 지정한 명령을 실행</li>
</ol>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> run</span><span style="color:#9ECBFF"> python</span><span style="color:#9ECBFF"> main.py</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> run</span><span style="color:#9ECBFF"> pytest</span></span>
<span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> run</span><span style="color:#9ECBFF"> flask</span><span style="color:#9ECBFF"> run</span><span style="color:#79B8FF"> -p</span><span style="color:#79B8FF"> 3000</span></span></code></pre></figure>
<p>activate를 기억할 필요도, 잘못된 환경을 걱정할 필요도 없음 — uv에게 맡기면 됩니다. 화장실 위치를 생각하지 않아도 자연스럽게 가는 고양이처럼. 이 "열면 바로 실행되는" 경험은 한 번 써보면 돌아갈 수 없습니다.</p>
