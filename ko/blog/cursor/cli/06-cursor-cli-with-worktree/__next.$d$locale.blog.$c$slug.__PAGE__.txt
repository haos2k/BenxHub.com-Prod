<h2 id="왜-같이-쓰나">왜 같이 쓰나?</h2>
<table>
<thead>
<tr>
<th>방식</th>
<th>방법</th>
<th>적합한 경우</th>
</tr>

<td>Worktree + Cursor <strong>창</strong> 여러 개</td>

<td>Worktree + <strong>CLI</strong></td>
<td>터미널 여러 개, 각각 worktree에 <code>cd</code> 후 <code>cursor agent</code></td>
<td>키보드 중심 사용자 또는 서버/SSH 환경</td>

<p>공통점: 각 worktree는 독립 디렉터리 → 각각 자기 컨텍스트 → 서로 발을 밟지 않는 병렬 개발. 여러 클론이 다른 브랜치에서 동시에 일하는 것과 비슷합니다.</p>
<h2 id="기본-터미널-하나당-worktree-하나">기본: 터미널 하나당 worktree 하나</h2>
<p>이미 worktree를 만들어 두었다고 가정하면:</p>
<pre><code>~/projects/
├── my-app/                  ← main
├── my-app--feature-auth/    ← feature/auth
└── my-app--feature-payment/  ← feature/payment
</code></pre>
<p><strong>터미널 1</strong>(auth 작업):</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#79C0FF">cd</span><span style="color:#A5D6FF"> ~/projects/my-app--feature-auth</span></span>
<span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#A5D6FF"> "Implement JWT login"</span></span></code></pre></figure>
<p><strong>터미널 2</strong>(payment 작업):</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#79C0FF">cd</span><span style="color:#A5D6FF"> ~/projects/my-app--feature-payment</span></span>
<span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#A5D6FF"> "Add Stripe checkout flow"</span></span></code></pre></figure>
<p>CLI는 기본적으로 <strong>현재 작업 디렉터리</strong>를 컨텍스트로 쓰므로, 두 터미널은 각각 자기 worktree만 수정합니다. “CLI 에이전트 두 개가 병렬로 돌아가는” 구조 — Cursor 창 두 개를 열 필요 없고, 리소스 절약과 컨텍스트 전환 감소.</p>
<h2 id="디렉터리-안-바꾸고---path로-worktree-지정">디렉터리 안 바꾸고: <code>--path</code>로 worktree 지정</h2>
<p>메인 프로젝트 디렉터리에 있는데, CLI가 특정 worktree에서만 작업하게 하고 싶다면:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#79C0FF">cd</span><span style="color:#A5D6FF"> ~/projects/my-app</span></span>
<span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#A5D6FF"> "Add unit tests for feature/auth"</span><span style="color:#79C0FF"> --path</span><span style="color:#A5D6FF"> ../my-app--feature-auth</span></span></code></pre></figure>
<p><code>--path</code>로 “어느 디렉터리를 볼지”를 지정 — worktree 경로입니다. 한 번에 하나의 worktree만 다룰 때나, 스크립트에서 경로가 고정일 때 유용합니다.</p>
<h2 id="비대화형--worktree스크립트일괄-처리">비대화형 + Worktree(스크립트·일괄 처리)</h2>
<p>여러 worktree에 같은 종류의 작업을 순서대로 실행(예: 전부에 README 추가, 전부 lint 수정):</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E"># 예: 두 worktree 모두 "fix lint"</span></span>
<span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#A5D6FF"> "Fix all auto-fixable errors per .eslintrc"</span><span style="color:#79C0FF"> --path</span><span style="color:#A5D6FF"> ../my-app--feature-auth</span><span style="color:#79C0FF"> --no-interactive</span></span>
<span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#A5D6FF"> "Fix all auto-fixable errors per .eslintrc"</span><span style="color:#79C0FF"> --path</span><span style="color:#A5D6FF"> ../my-app--feature-payment</span><span style="color:#79C0FF"> --no-interactive</span></span></code></pre></figure>
<p>또는 루프로(환경에 맞게 경로 수정):</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FF7B72">for</span><span style="color:#E6EDF3"> dir </span><span style="color:#FF7B72">in</span><span style="color:#A5D6FF"> ../my-app--feature-auth</span><span style="color:#A5D6FF"> ../my-app--feature-payment</span><span style="color:#E6EDF3">; </span><span style="color:#FF7B72">do</span></span>
<span data-line=""><span style="color:#FFA657">  cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#A5D6FF"> "Fix linter errors"</span><span style="color:#79C0FF"> --path</span><span style="color:#A5D6FF"> "</span><span style="color:#E6EDF3">$dir</span><span style="color:#A5D6FF">"</span><span style="color:#79C0FF"> --no-interactive</span></span>
<span data-line=""><span style="color:#FF7B72">done</span></span></code></pre></figure>
<p>지시 한 번에 여러 브랜치 정리 — PR 올리기 전 마지막 점검에 적합합니다.</p>
<h2 id="worktree--여러-창과의-관계">“Worktree + 여러 창”과의 관계</h2>
<ul>
<li><strong>여러 창</strong>: Cursor 창마다 worktree 하나씩 열고, IDE의 Agent·Chat·Tab 자동완성 사용</li>
<li><strong>CLI + Worktree</strong>: 터미널 + <code>cursor agent</code> — “한 디렉터리, 한 컨텍스트”는 같고, 터미널만 더 열어서 병렬화</li>
</ul>
<p>조합도 가능: 메인 개발은 창에서, 서버에서는 CLI로 다른 브랜치 작은 수정 등.</p>
<h2 id="요약">요약</h2>
<ul>
<li><strong>Worktree</strong> = 여러 디렉터리·여러 브랜치, <strong>CLI</strong> = 현재 디렉터리 또는 <code>--path</code>에서 동작 → 자연스러운 조합</li>
<li><strong>병렬</strong>: 터미널 여러 개 열고, 각각 다른 worktree에 <code>cd</code>한 뒤 <code>cursor agent</code></li>
<li><strong>터미널 하나</strong>: <code>--path &#x3C;worktree-path></code>로 대상 worktree 지정</li>
<li><strong>스크립트·일괄</strong>: <code>--path</code> + <code>--no-interactive</code>로 여러 worktree에 같은 작업 실행</li>
</ul>

<p>메인 프로젝트 디렉터리에 있는데, CLI가 특정 worktree에서만 작업하게 하고 싶다면:</p>

<span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#A5D6FF"> "Add unit tests for feature/auth"</span><span style="color:#79C0FF"> --path</span><span style="color:#A5D6FF"> ../my-app--feature-auth</span></span></code></pre></figure>
<p><code>--path</code>로 “어느 디렉터리를 볼지”를 지정 — worktree 경로입니다. 한 번에 하나의 worktree만 다룰 때나, 스크립트에서 경로가 고정일 때 유용합니다.</p>
<h2 id="비대화형--worktree스크립트일괄-처리">비대화형 + Worktree(스크립트·일괄 처리)</h2>
<p>여러 worktree에 같은 종류의 작업을 순서대로 실행(예: 전부에 README 추가, 전부 lint 수정):</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E"># 예: 두 worktree 모두 "fix lint"</span></span>
<span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#A5D6FF"> "Fix all auto-fixable errors per .eslintrc"</span><span style="color:#79C0FF"> --path</span><span style="color:#A5D6FF"> ../my-app--feature-auth</span><span style="color:#79C0FF"> --no-interactive</span></span>
<span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#A5D6FF"> "Fix all auto-fixable errors per .eslintrc"</span><span style="color:#79C0FF"> --path</span><span style="color:#A5D6FF"> ../my-app--feature-payment</span><span style="color:#79C0FF"> --no-interactive</span></span></code></pre></figure>
<p>또는 루프로(환경에 맞게 경로 수정):</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FF7B72">for</span><span style="color:#E6EDF3"> dir </span><span style="color:#FF7B72">in</span><span style="color:#A5D6FF"> ../my-app--feature-auth</span><span style="color:#A5D6FF"> ../my-app--feature-payment</span><span style="color:#E6EDF3">; </span><span style="color:#FF7B72">do</span></span>
<span data-line=""><span style="color:#FFA657">  cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#A5D6FF"> "Fix linter errors"</span><span style="color:#79C0FF"> --path</span><span style="color:#A5D6FF"> "</span><span style="color:#E6EDF3">$dir</span><span style="color:#A5D6FF">"</span><span style="color:#79C0FF"> --no-interactive</span></span>
<span data-line=""><span style="color:#FF7B72">done</span></span></code></pre></figure>
<p>지시 한 번에 여러 브랜치 정리 — PR 올리기 전 마지막 점검에 적합합니다.</p>
<h2 id="worktree--여러-창과의-관계">“Worktree + 여러 창”과의 관계</h2>
<ul>
<li><strong>여러 창</strong>: Cursor 창마다 worktree 하나씩 열고, IDE의 Agent·Chat·Tab 자동완성 사용</li>
<li><strong>CLI + Worktree</strong>: 터미널 + <code>cursor agent</code> — “한 디렉터리, 한 컨텍스트”는 같고, 터미널만 더 열어서 병렬화</li>
</ul>
<p>조합도 가능: 메인 개발은 창에서, 서버에서는 CLI로 다른 브랜치 작은 수정 등.</p>
<h2 id="요약">요약</h2>
<ul>
<li><strong>Worktree</strong> = 여러 디렉터리·여러 브랜치, <strong>CLI</strong> = 현재 디렉터리 또는 <code>--path</code>에서 동작 → 자연스러운 조합</li>
<li><strong>병렬</strong>: 터미널 여러 개 열고, 각각 다른 worktree에 <code>cd</code>한 뒤 <code>cursor agent</code></li>
<li><strong>터미널 하나</strong>: <code>--path &#x3C;worktree-path></code>로 대상 worktree 지정</li>
<li><strong>스크립트·일괄</strong>: <code>--path</code> + <code>--no-interactive</code>로 여러 worktree에 같은 작업 실행</li>
</ul>
