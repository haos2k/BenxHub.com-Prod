1b:T4420,<p><code>cursor agent</code>가 코드를 자동으로 수정하고 테스트를 실행하고, 실패하면 AI가 다시 수정하게 — <strong>모든 테스트가 통과할 때까지 반복</strong>하는 shell 스크립트를 작성합니다. Y/N을 계속 누를 필요 없습니다. 루프를 AI에게 맡겨 두고 다른 일을 하다가, 터미널에 "tests passed"가 나오면 돌아오면 됩니다.</p>
<h2 id="핵심-개념">핵심 개념</h2>
<pre><code>while tests don't pass:
    run tests → collect error output
    feed error output to cursor agent
    cursor agent fixes the code
    run tests again
</code></pre>
<p>“테스트 실행 → 실패 → AI에게 수정 요청 → 반복” 루프를 통과할 때까지 돌리는 구조입니다. 단순하고 직접적이지만 효과적입니다.</p>
<h2 id="1단계-전제-조건-확인">1단계: 전제 조건 확인</h2>
<ul>
<li><code>cursor</code>가 설치되어 있고 로그인되어 있음(<code>cursor --version</code>으로 확인)</li>
<li>프로젝트에 <strong>터미널에서 실행하는 테스트 명령</strong>이 있음. 예:
<ul>
<li><code>npm test</code></li>
<li><code>pytest</code></li>
<li><code>go test ./...</code></li>
<li><code>cargo test</code></li>
</ul>
</li>
<li>테스트 실패 시 0이 아닌 종료 코드를 반환함(대부분 테스트 프레임워크는 기본이 그렇습니다)</li>
</ul>

26:T4420,<p><code>cursor agent</code>가 코드를 자동으로 수정하고 테스트를 실행하고, 실패하면 AI가 다시 수정하게 — <strong>모든 테스트가 통과할 때까지 반복</strong>하는 shell 스크립트를 작성합니다. Y/N을 계속 누를 필요 없습니다. 루프를 AI에게 맡겨 두고 다른 일을 하다가, 터미널에 "tests passed"가 나오면 돌아오면 됩니다.</p>
<h2 id="핵심-개념">핵심 개념</h2>
<pre><code>while tests don't pass:
    run tests → collect error output
    feed error output to cursor agent
    cursor agent fixes the code
    run tests again
</code></pre>
<p>“테스트 실행 → 실패 → AI에게 수정 요청 → 반복” 루프를 통과할 때까지 돌리는 구조입니다. 단순하고 직접적이지만 효과적입니다.</p>
<h2 id="1단계-전제-조건-확인">1단계: 전제 조건 확인</h2>
<ul>
<li><code>cursor</code>가 설치되어 있고 로그인되어 있음(<code>cursor --version</code>으로 확인)</li>
<li>프로젝트에 <strong>터미널에서 실행하는 테스트 명령</strong>이 있음. 예:
<ul>
<li><code>npm test</code></li>
<li><code>pytest</code></li>
<li><code>go test ./...</code></li>
<li><code>cargo test</code></li>
</ul>
</li>
<li>테스트 실패 시 0이 아닌 종료 코드를 반환함(대부분 테스트 프레임워크는 기본이 그렇습니다)</li>
</ul>
<h2 id="2단계-가장-단순한-스크립트">2단계: 가장 단순한 스크립트</h2>
<p><code>debug-loop.sh</code>를 만듭니다:</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E">#!/bin/bash</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#E6EDF3">MAX_LOOPS</span><span style="color:#FF7B72">=</span><span style="color:#A5D6FF">10</span><span style="color:#8B949E">        # max iterations to prevent truly infinite loops</span></span>

<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">chmod</span><span style="color:#A5D6FF"> +x</span><span style="color:#A5D6FF"> debug-loop.sh</span></span>
<span data-line=""><span style="color:#FFA657">./debug-loop.sh</span></span></code></pre></figure>
<p>이제 커피 마시거나 메시지 답하다가, 터미널에 <code>✅ Tests passed!</code>가 나오면 돌아오면 됩니다. MAX_LOOPS에 도달했는데도 통과하지 못하면 그때는 사람이 직접 확인할 차례입니다.</p>
<h2 id="4단계-프로젝트에-맞게-맞추기">4단계: 프로젝트에 맞게 맞추기</h2>
<p><strong>테스트 명령 변경</strong>(4번째 줄 근처):</p>

<h2 id="요약">요약</h2>
<ol>
<li><strong>스크립트 구조</strong>: 테스트 실행 → 실패 → AI에 넘김 → 통과하거나 한도까지 반복</li>

<li><strong>프롬프트는 구체적으로</strong>: 언어, 수정해도 되는 디렉터리, 테스트 파일은 건드리지 말 것 명시</li>
