<h2 id="클러스터-구축">클러스터 구축</h2>
<p>적용 시나리오: 중앙 관리·크로스 노드 스케줄링·마이그레이션을 하려면 클러스터부터 구축.</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># 첫 번째 노드에서 클러스터 만들기</span></span>
<span data-line=""><span style="color:#B392F0">pvecm</span><span style="color:#9ECBFF"> create</span><span style="color:#9ECBFF"> my-cluster</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># 다른 노드가 참가 (마스터 IP로 변경)</span></span>
<span data-line=""><span style="color:#B392F0">pvecm</span><span style="color:#9ECBFF"> add</span><span style="color:#F97583"> &#x3C;</span><span style="color:#9ECBFF">cluster-master-i</span><span style="color:#E1E4E8">p</span><span style="color:#F97583">></span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># 상태 확인</span></span>
<span data-line=""><span style="color:#B392F0">pvecm</span><span style="color:#9ECBFF"> status</span></span></code></pre></figure>
<blockquote>
<p>클러스터 구축 후 <strong>노드 호스트명 변경을 최대한 피하세요</strong>; 참가 전에 DNS·시간 동기화·네트워크가 모두 정상인지 확인 — 그렇지 않으면 온갖 이상한 문제가 생깁니다.</p>
</blockquote>
<h2 id="ha-고가용성-설정">HA (고가용성) 설정</h2>
<p>적용 시나리오: 어떤 노드가 다운되면 VM이 다른 노드에서 자동으로 시작되어 서비스가 중단되지 않음.</p>
<p>전제 조건:</p>
<ul>
<li>클러스터가 존재</li>
<li>VM 디스크가 <strong>공유 스토리지</strong>에 있음</li>
<li>올바른 <strong>fencing</strong> 메커니즘 — 스플릿 브레인 방지 (양쪽이 자신이 리더라고 생각하는 상황)</li>
</ul>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># VM 100을 HA 관리하에 두기</span></span>
<span data-line=""><span style="color:#B392F0">ha-manager</span><span style="color:#9ECBFF"> add</span><span style="color:#9ECBFF"> vm:100</span><span style="color:#79B8FF"> --maxrestart</span><span style="color:#79B8FF"> 3</span><span style="color:#79B8FF"> --maxrelocate</span><span style="color:#79B8FF"> 5</span></span></code></pre></figure>
<p>HA가 올바르게 설정되면 단일 노드 장애 시 사용자는 거의 알아차리지 못합니다 — 고양이가 항상 대체 수면 장소를 확보해 두는 것처럼.</p>
<h2 id="ceph-하이퍼컨버지드-스토리지">Ceph 하이퍼컨버지드 스토리지</h2>
<p>적용 시나리오: 여러 노드에서 공유 스토리지와 고가용성 모두 필요 — Ceph로 함께 해결.</p>
<p>권장 전제 조건:</p>
<ul>
<li>최소 <strong>3개 노드</strong> (Ceph는 단일 지점을 싫어함)</li>
<li>각 노드에 복수의 <strong>전용 디스크</strong></li>
<li>전용 스토리지 네트워크가 있으면 더 좋음</li>
</ul>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># Ceph 초기화</span></span>
<span data-line=""><span style="color:#B392F0">pveceph</span><span style="color:#9ECBFF"> init</span><span style="color:#79B8FF"> --network</span><span style="color:#9ECBFF"> 10.0.0.0/24</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># 각 데이터 디스크에 OSD 만들기</span></span>
<span data-line=""><span style="color:#B392F0">pveceph</span><span style="color:#9ECBFF"> osd</span><span style="color:#9ECBFF"> create</span><span style="color:#9ECBFF"> /dev/sdX</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># Pool 만들고 PVE에 연결</span></span>
<span data-line=""><span style="color:#B392F0">pveceph</span><span style="color:#9ECBFF"> pool</span><span style="color:#9ECBFF"> create</span><span style="color:#9ECBFF"> vm-data</span><span style="color:#79B8FF"> --add_storages</span></span></code></pre></figure>
<blockquote>
<p>Ceph는 <strong>베어 디스크를 직접 관리</strong>하는 것을 권장 — 하드웨어 RAID를 위에 쌓지 마세요. 그렇게 하면 Ceph의 데이터 보호와 관측성이 절반으로 줄어듭니다.</p>
</blockquote>
<h2 id="스토리지-복제">스토리지 복제</h2>
<p>적용 시나리오: 크로스 노드 이중화, 장애 시 빠른 인계.</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">pvesr</span><span style="color:#9ECBFF"> create-local-job</span><span style="color:#79B8FF"> 100</span><span style="color:#9ECBFF"> local-zfs</span><span style="color:#9ECBFF"> remote-zfs</span><span style="color:#79B8FF"> --schedule</span><span style="color:#9ECBFF"> "0 2 * * *"</span></span></code></pre></figure>
<h2 id="api와-자동화-통합">API와 자동화 통합</h2>
<p>적용 시나리오: 스크립트로 운영·CI/CD·다른 플랫폼과 통합. <strong>API 토큰</strong> 사용 권장 — root 비밀번호를 여기저기 붙여넣지 마세요.</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># API 토큰으로 VM 목록 가져오기</span></span>

<span data-line=""><span style="color:#79B8FF">  -H</span><span style="color:#9ECBFF"> "Authorization: PVEAPIToken=user@realm!tokenid=secret"</span><span style="color:#79B8FF"> \</span></span>
<span data-line=""><span style="color:#9ECBFF">  "https://&#x3C;PVE-IP>:8006/api2/json/nodes/&#x3C;node>/qemu"</span></span></code></pre></figure>
<p>자동화가 갖춰지면 반복 작업은 스크립트에 맡기고, 여러분은 커피와 고양이에 집중하면 됩니다.</p>

<h2 id="클러스터-구축">클러스터 구축</h2>
<p>적용 시나리오: 중앙 관리·크로스 노드 스케줄링·마이그레이션을 하려면 클러스터부터 구축.</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># 첫 번째 노드에서 클러스터 만들기</span></span>
<span data-line=""><span style="color:#B392F0">pvecm</span><span style="color:#9ECBFF"> create</span><span style="color:#9ECBFF"> my-cluster</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># 다른 노드가 참가 (마스터 IP로 변경)</span></span>
<span data-line=""><span style="color:#B392F0">pvecm</span><span style="color:#9ECBFF"> add</span><span style="color:#F97583"> &#x3C;</span><span style="color:#9ECBFF">cluster-master-i</span><span style="color:#E1E4E8">p</span><span style="color:#F97583">></span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># 상태 확인</span></span>
<span data-line=""><span style="color:#B392F0">pvecm</span><span style="color:#9ECBFF"> status</span></span></code></pre></figure>
<blockquote>
<p>클러스터 구축 후 <strong>노드 호스트명 변경을 최대한 피하세요</strong>; 참가 전에 DNS·시간 동기화·네트워크가 모두 정상인지 확인 — 그렇지 않으면 온갖 이상한 문제가 생깁니다.</p>
</blockquote>
<h2 id="ha-고가용성-설정">HA (고가용성) 설정</h2>
<p>적용 시나리오: 어떤 노드가 다운되면 VM이 다른 노드에서 자동으로 시작되어 서비스가 중단되지 않음.</p>
<p>전제 조건:</p>
<ul>
<li>클러스터가 존재</li>
<li>VM 디스크가 <strong>공유 스토리지</strong>에 있음</li>
<li>올바른 <strong>fencing</strong> 메커니즘 — 스플릿 브레인 방지 (양쪽이 자신이 리더라고 생각하는 상황)</li>
</ul>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># VM 100을 HA 관리하에 두기</span></span>
<span data-line=""><span style="color:#B392F0">ha-manager</span><span style="color:#9ECBFF"> add</span><span style="color:#9ECBFF"> vm:100</span><span style="color:#79B8FF"> --maxrestart</span><span style="color:#79B8FF"> 3</span><span style="color:#79B8FF"> --maxrelocate</span><span style="color:#79B8FF"> 5</span></span></code></pre></figure>
<p>HA가 올바르게 설정되면 단일 노드 장애 시 사용자는 거의 알아차리지 못합니다 — 고양이가 항상 대체 수면 장소를 확보해 두는 것처럼.</p>
<h2 id="ceph-하이퍼컨버지드-스토리지">Ceph 하이퍼컨버지드 스토리지</h2>
<p>적용 시나리오: 여러 노드에서 공유 스토리지와 고가용성 모두 필요 — Ceph로 함께 해결.</p>
<p>권장 전제 조건:</p>
<ul>
<li>최소 <strong>3개 노드</strong> (Ceph는 단일 지점을 싫어함)</li>
<li>각 노드에 복수의 <strong>전용 디스크</strong></li>
<li>전용 스토리지 네트워크가 있으면 더 좋음</li>
</ul>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># Ceph 초기화</span></span>
<span data-line=""><span style="color:#B392F0">pveceph</span><span style="color:#9ECBFF"> init</span><span style="color:#79B8FF"> --network</span><span style="color:#9ECBFF"> 10.0.0.0/24</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># 각 데이터 디스크에 OSD 만들기</span></span>
<span data-line=""><span style="color:#B392F0">pveceph</span><span style="color:#9ECBFF"> osd</span><span style="color:#9ECBFF"> create</span><span style="color:#9ECBFF"> /dev/sdX</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># Pool 만들고 PVE에 연결</span></span>
<span data-line=""><span style="color:#B392F0">pveceph</span><span style="color:#9ECBFF"> pool</span><span style="color:#9ECBFF"> create</span><span style="color:#9ECBFF"> vm-data</span><span style="color:#79B8FF"> --add_storages</span></span></code></pre></figure>
<blockquote>
<p>Ceph는 <strong>베어 디스크를 직접 관리</strong>하는 것을 권장 — 하드웨어 RAID를 위에 쌓지 마세요. 그렇게 하면 Ceph의 데이터 보호와 관측성이 절반으로 줄어듭니다.</p>
</blockquote>
<h2 id="스토리지-복제">스토리지 복제</h2>
<p>적용 시나리오: 크로스 노드 이중화, 장애 시 빠른 인계.</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">pvesr</span><span style="color:#9ECBFF"> create-local-job</span><span style="color:#79B8FF"> 100</span><span style="color:#9ECBFF"> local-zfs</span><span style="color:#9ECBFF"> remote-zfs</span><span style="color:#79B8FF"> --schedule</span><span style="color:#9ECBFF"> "0 2 * * *"</span></span></code></pre></figure>
<h2 id="api와-자동화-통합">API와 자동화 통합</h2>
<p>적용 시나리오: 스크립트로 운영·CI/CD·다른 플랫폼과 통합. <strong>API 토큰</strong> 사용 권장 — root 비밀번호를 여기저기 붙여넣지 마세요.</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># API 토큰으로 VM 목록 가져오기</span></span>

<span data-line=""><span style="color:#79B8FF">  -H</span><span style="color:#9ECBFF"> "Authorization: PVEAPIToken=user@realm!tokenid=secret"</span><span style="color:#79B8FF"> \</span></span>
