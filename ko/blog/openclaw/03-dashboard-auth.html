대시보드에서 계속 막히나요? OpenClaw 인증을 3분 안에 이해하기

2026년 3월 8일·3 min read

"Token? pairing? 나는 그냥 웹페이지 하나 열고 싶었을 뿐인데요."

매우 정상적인 반응입니다. 이 글의 목적은 로그인 화면 공포증을 없애는 것 입니다.

이번 글에서 배울 것

  • Gateway 와 대시보드의 관계 이해
  • 가장 흔한 세 가지 인증 상황 파악
  • 원격 접속 설정 방식 이해
  • UI 언어 변경하기

먼저 Gateway 를 실행하세요

대시보드는 창일 뿐이고, 실제로 일하는 것은 Gateway 입니다. Gateway 가 없으면 웹페이지는 껍데기뿐입니다.

"Gateway running" 같은 메시지가 보인 뒤에 다음 단계로 넘어가세요.

대시보드 열기

http://127.0.0.1:18789/

basePath 를 예를 들어 /openclaw 로 설정했다면:

http://127.0.0.1:18789/openclaw

인증: 도대체 뭘 입력해야 하나요?

경우 1: pairing required 가 뜬다

OpenClaw 가 "당신 누구세요? 이 장치는 아직 모릅니다"라고 묻는 상황입니다.

브라우저를 새로고침하면 들어갈 수 있을 것입니다.

경우 2: token 을 요구한다

온보딩 때 받은 token 을 여기 붙여 넣으면 됩니다. Settings 에 저장하면 보통 다음부터는 다시 붙이지 않아도 됩니다.

💡 Token 은 UI 설정에 저장됩니다. 비밀번호는 메모리 안에만 있다가 세션이 끝나면 사라집니다. 보안을 위한 의도적인 설계입니다.

경우 3: VPS 또는 LAN 에서 원격 접속

Gateway 가 로컬이 아니라 원격 서버에서 실행 중이라면:

  • token 또는 장치 pairing 이 필요합니다
  • unauthorized 가 뜨면 gateway.bind 와 token 입력값을 먼저 확인하세요

언어를 바꾸고 싶다면?

Control UI 는 여러 언어를 지원합니다.

Access 섹션에서 언어를 고르면 브라우저가 다음에도 기억합니다.
