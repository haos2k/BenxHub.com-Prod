3:T1225,<p>進到實際維運後，搞掛環境的往往不是「uv 不夠強」，而是<strong>流程跟習慣</strong>。下面這份清單可以直接當日常準則用——少踩一次雷，就多一次準時下班。</p>
<h2 id="推薦做法">推薦做法</h2>
<h3 id="1-uvlock-一定要-commit">1) uv.lock 一定要 commit</h3>
<p>lockfile 是重現性的基礎。不 commit 等於每人、每台機器、每次 CI 可能裝出不同依賴，重現 bug 會地獄難度。沒 lockfile 的專案，就像沒試穿過的新鞋，上戰場才知道磨腳。</p>
<h3 id="2-venv-不要-commit">2) .venv 不要 commit</h3>
<p>虛擬環境是本地產物，應該在 <code>.gitignore</code>。uv 會自動把 <code>.venv</code> 加進專案 ignore，確認一下就好。</p>
<h3 id="3-依賴能鎖就鎖">3) 依賴能鎖就鎖</h3>
<p><code>pyproject.toml</code> 裡避免裸寫 <code>requests</code>，盡量寫 <code>requests>=2.31,&#x3C;3</code> 或更精確。<code>uv add</code> 預設會加合理約束，手動改時別放太寬。</p>
<h3 id="4-ci-用-uv-sync-或-uv-pip-sync">4) CI 用 uv sync 或 uv pip sync</h3>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="yaml" data-theme="github-dark-default"><code data-language="yaml" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E"># GitHub Actions 範例</span></span>
<span data-line=""><span style="color:#E6EDF3">- </span><span style="color:#7EE787">run</span><span style="color:#E6EDF3">: </span><span style="color:#A5D6FF">uv sync</span></span>
<span data-line=""><span style="color:#E6EDF3">- </span><span style="color:#7EE787">run</span><span style="color:#E6EDF3">: </span><span style="color:#A5D6FF">uv run pytest</span></span></code></pre></figure>
<p>先 sync 再跑，確保環境與 lockfile 一致。別在 CI 裡 <code>uv add</code>，那會改 lockfile，容易造成非預期 diff。</p>
<h3 id="5-開發工具放-optional--dev">5) 開發工具放 optional / dev</h3>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> add</span><span style="color:#79C0FF"> --dev</span><span style="color:#A5D6FF"> pytest</span><span style="color:#A5D6FF"> ruff</span><span style="color:#A5D6FF"> mypy</span></span></code></pre></figure>
<p>測試、lint、型別檢查不影響生產依賴，也不會被打進 wheel。生產 image 只需要 <code>uv sync --no-dev</code>。</p>
<h2 id="常見誤區">常見誤區</h2>
<h3 id="誤區-1混用-pip-跟-uv-add">誤區 1：混用 pip 跟 uv add</h3>
<p>同一個 venv 裡不要又 <code>pip install</code> 又 <code>uv add</code>，lockfile 會對不上。選一條路走到底。</p>
<h3 id="誤區-2把-uvx-當專案工具用">誤區 2：把 uvx 當專案工具用</h3>
<p>專案要固定版本的工具（如 pytest、mypy）→ 用 <code>uv add --dev</code> + <code>uv run</code>。<br>
臨時試一下、一次性腳本 → 用 <code>uvx</code>。</p>
<h3 id="誤區-3不讀-pyprojecttoml-就手動改">誤區 3：不讀 pyproject.toml 就手動改</h3>
<p>改依賴盡量用 <code>uv add</code> / <code>uv remove</code>，避免格式跑掉或漏更新 lockfile。</p>
<h3 id="誤區-4ci-不安裝-uv">誤區 4：CI 不安裝 uv</h3>
<p>很多 CI 現在支援 uv，安裝快、執行更快。用官方 installer 或 <code>pip install uv</code> 都可，別堅持用 pip 解鎖依賴到天荒地老。</p>
<h3 id="誤區-5專案不用-requires-python">誤區 5：專案不用 requires-python</h3>
<p>在 <code>pyproject.toml</code> 標明 <code>requires-python = ">=3.12"</code> 等，讓工具跟協作者知道最低版本，避免「我這 3.12 能跑你那 3.8 爆」的慘劇。</p>
<hr>
<p>照這份清單做，不敢說零故障，但至少少走很多彎路。有問題再翻官方文件，多數坑都有人踩過了。<br>
祝開發順利，依賴乖乖裝、測試都綠燈、CI 不再等你等到天荒地老～ 🦦<br>
（對了，用 uv 之後你會發現：等 pip 轉圈圈的時間，夠你撸三輪貓了。）</p>
