3:T1eac,<p>同一個 Agent 跑完，你想要的「結果格式」可能完全不同：有時只需要最後一段文字、有時要 CI 能解析的 JSON、有時要即時知道 AI 現在在做什麼。</p>
<p><strong><code>--output-format</code></strong> 就是控制這件事的開關，三個選項，用途分很清楚。</p>
<h2 id="三種輸出格式">三種輸出格式</h2>
<table>
<thead>
<tr>
<th>格式</th>
<th>參數</th>
<th>適合</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>text</strong></td>
<td>預設，或 <code>--output-format text</code></td>
<td>人類閱讀、只要最終答案、寫進檔案</td>
</tr>
<tr>
<td><strong>json</strong></td>
<td><code>--output-format json</code></td>
<td>腳本解析、CI 判斷成功失敗、擷取欄位</td>
</tr>
<tr>
<td><strong>stream-json</strong></td>
<td><code>--output-format stream-json</code></td>
<td>即時進度、工具呼叫追蹤、長任務監控</td>
</tr>
</tbody>
</table>
<h2 id="text乾淨的最終答案">text：乾淨的最終答案</h2>
<p>不加 <code>--output-format</code> 時就是 text 模式——輸出只有最後回覆的內容，沒有工具呼叫、沒有中間步驟：</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#A5D6FF"> "這個 repo 的入口點是哪個檔案？"</span></span></code></pre></figure>
<p>在 CI 裡若只要把 Agent 的結論寫進一個檔：</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#A5D6FF"> "根據 CHANGELOG 產出本版 release notes"</span><span style="color:#FF7B72"> ></span><span style="color:#A5D6FF"> release_notes.txt</span></span></code></pre></figure>
<p>簡單，適合直接貼到文件或作為說明文字。</p>
<h2 id="json給腳本與-ci-解析">json：給腳本與 CI 解析</h2>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#79C0FF"> --output-format</span><span style="color:#A5D6FF"> json</span><span style="color:#A5D6FF"> "分析 src/ 的依賴關係，回傳 JSON：{ </span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">entry</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">: </span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">...</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">, </span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">deps</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">: [...] }"</span></span></code></pre></figure>
<p>輸出是結構化的 JSON，包含 <code>result</code>、<code>duration_ms</code> 等欄位，可能還有你 prompt 裡要求的自訂欄位。在 CI 裡可以用 <code>jq</code> 取欄位、判斷是否為空、或根據內容決定 job 是 pass 還是 fail：</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#79C0FF"> --output-format</span><span style="color:#A5D6FF"> json</span><span style="color:#A5D6FF"> "做簡短 code review，回傳 {</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">ok</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">: true/false, </span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">summary</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">: </span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">...</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">}"</span><span style="color:#FF7B72"> |</span><span style="color:#FFA657"> jq</span><span style="color:#79C0FF"> -r</span><span style="color:#A5D6FF"> '.result'</span></span></code></pre></figure>
<p>實際欄位以 Cursor 文件為準——<code>json</code> 格式的核心價值在於「讓程式讀」，不是讓人讀。</p>
<h2 id="stream-json即時進度追蹤">stream-json：即時進度追蹤</h2>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#79C0FF"> --output-format</span><span style="color:#A5D6FF"> stream-json</span><span style="color:#79C0FF"> --stream-partial-output</span><span style="color:#A5D6FF"> "分析專案並產出 analysis.txt"</span></span></code></pre></figure>
<p>每一行是一筆 JSON，代表一個事件——<code>system</code>、<code>assistant</code>、<code>tool_call</code>、<code>result</code> 之類的。<code>--stream-partial-output</code> 會讓助理回覆以增量方式出現，方便做即時字數或進度顯示。</p>
<p>可以解析 <code>tool_call</code> 的 started/completed，知道 Agent 正在讀哪個檔、寫哪個檔、花了多久——適合長任務、想在前端或 CI log 裡顯示「正在處理第 N 個檔案」的場合。</p>
<h2 id="ci-整合要點">CI 整合要點</h2>
<table>
<thead>
<tr>
<th>需求</th>
<th>建議</th>
</tr>
</thead>
<tbody>
<tr>
<td>只關心「跑完沒、結論是什麼」</td>
<td><code>text</code> + 重導向到檔或變數；看 exit code</td>
</tr>
<tr>
<td>要依內容決定 pass/fail</td>
<td><code>json</code> + <code>jq</code> 解析</td>
</tr>
<tr>
<td>要即時 log 或進度</td>
<td><code>stream-json</code> + 逐行解析 type/subtype</td>
</tr>
<tr>
<td>要 Agent 改檔</td>
<td>加上 <code>--force</code>（見 <a href="10-headless-scripts">10-headless-scripts</a>）</td>
</tr>
<tr>
<td>在 CI 跑</td>
<td>設 <code>CURSOR_API_KEY</code>；必要時用 <code>--model</code> 固定模型</td>
</tr>
</tbody>
</table>
<h2 id="失敗時怎麼處理">失敗時怎麼處理</h2>
<p>Agent 執行失敗時，CLI 通常會回傳非 0 的 exit code——腳本裡用 <code>if [ $? -ne 0 ]; then exit 1; fi</code> 或開頭加 <code>set -e</code>，讓 CI 正確拋出失敗。</p>
<p>若用 json 輸出，可以再多一層：檢查輸出裡是否有 <code>error</code> 欄位、或自訂的 <code>ok: false</code>，雙重保險，不讓假成功溜過去。</p>

<p>格式選對了，後面的腳本和 CI pipeline 才能順順地跑——不然就是在 stdout 裡用 <code>grep</code> 找關鍵字，那就有點尷尬了。</p>

<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#79C0FF"> --output-format</span><span style="color:#A5D6FF"> json</span><span style="color:#A5D6FF"> "做簡短 code review，回傳 {</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">ok</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">: true/false, </span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">summary</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">: </span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">...</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">}"</span><span style="color:#FF7B72"> |</span><span style="color:#FFA657"> jq</span><span style="color:#79C0FF"> -r</span><span style="color:#A5D6FF"> '.result'</span></span></code></pre></figure>
<p>實際欄位以 Cursor 文件為準——<code>json</code> 格式的核心價值在於「讓程式讀」，不是讓人讀。</p>
<h2 id="stream-json即時進度追蹤">stream-json：即時進度追蹤</h2>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#79C0FF"> --output-format</span><span style="color:#A5D6FF"> stream-json</span><span style="color:#79C0FF"> --stream-partial-output</span><span style="color:#A5D6FF"> "分析專案並產出 analysis.txt"</span></span></code></pre></figure>
<p>每一行是一筆 JSON，代表一個事件——<code>system</code>、<code>assistant</code>、<code>tool_call</code>、<code>result</code> 之類的。<code>--stream-partial-output</code> 會讓助理回覆以增量方式出現，方便做即時字數或進度顯示。</p>
<p>可以解析 <code>tool_call</code> 的 started/completed，知道 Agent 正在讀哪個檔、寫哪個檔、花了多久——適合長任務、想在前端或 CI log 裡顯示「正在處理第 N 個檔案」的場合。</p>

<h2 id="失敗時怎麼處理">失敗時怎麼處理</h2>
<p>Agent 執行失敗時，CLI 通常會回傳非 0 的 exit code——腳本裡用 <code>if [ $? -ne 0 ]; then exit 1; fi</code> 或開頭加 <code>set -e</code>，讓 CI 正確拋出失敗。</p>
<p>若用 json 輸出，可以再多一層：檢查輸出裡是否有 <code>error</code> 欄位、或自訂的 <code>ok: false</code>，雙重保險，不讓假成功溜過去。</p>
