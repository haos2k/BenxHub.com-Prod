8:T2544,<p>上一篇 <a href="08-worktree-merge">08-worktree-merge</a> 講了 Cursor 自動 worktree 與 Apply 策略。這篇接著談兩件事：<strong>Best-of-N</strong>（讓多個模型同時做同一題，你當評審挑一個）和 <strong>worktrees.json</strong>（worktree 建好後自動準備開發環境）。</p>
<h2 id="best-of-n一題多做你選最好的">Best-of-N：一題多做，你選最好的</h2>
<p>一個 prompt，Cursor 用多個模型同時在各自 worktree 裡跑，最後出現多張「卡片」，每張是一個模型的改動結果——你翻卡片、挑最好的那張按 <strong>Apply</strong>。</p>
<h3 id="什麼時候值得用">什麼時候值得用？</h3>
<table>
<thead>
<tr>
<th>情境</th>
<th>為什麼好用</th>
</tr>
</thead>
<tbody>
<tr>
<td>不確定哪個模型最適合這個 codebase</td>
<td>跑一次就是小型 benchmark，比自己猜準</td>
</tr>
<tr>
<td>難題怕單一模型漏掉 edge case</td>
<td>多個模型不同思路，容易補到對方的盲點</td>
</tr>
<tr>
<td>想比較程式碼品質與風格</td>
<td>同一份需求看三四種寫法，一目了然</td>
</tr>
<tr>
<td>任務很難、想提高一次就中的機率</td>
<td>多個模型各試一次，挑最好的再 Apply</td>
</tr>
</tbody>
</table>
<p>一句話：<strong>多個模型同時做同一題，你當評審挑一個</strong>。適合難題、想要品質、或對某個模型沒把握的改動。</p>
<h3 id="怎麼用">怎麼用</h3>
<p>在 Cursor 裡開 Agent 時，選擇多個模型或 Best-of-N 相關選項（依目前介面為準）。送出 prompt 後出現多張卡片，切換卡片比較各模型的改動，滿意的那張按 <strong>Apply</strong>。</p>
<p>若同一個 Best-of-N 裡你想 Apply 多張卡片（先 Apply A 再 Apply B），Cursor 可能會問：<strong>合併與衝突解決</strong> 還是 <strong>Full Overwrite</strong>——這部分邏輯跟 <a href="08-worktree-merge">08-worktree-merge</a> 一樣，不另外重複。</p>
<h2 id="worktreesjsonworktree-建好就有完整環境">worktrees.json：worktree 建好就有完整環境</h2>
<p>Cursor 建立 worktree 時，預設只帶主目錄已追蹤的檔案——不會幫你裝依賴、複製 <code>.env</code>、跑資料庫遷移。每次建了新 worktree 都要手動做這些，很快就會膩。</p>
<p><strong><code>.cursor/worktrees.json</code></strong> 解決這件事：指定「每個新 worktree 建立後要自動執行的指令」，一次設定、之後每個 worktree 建好就是完整環境。</p>
<h3 id="設定檔放哪">設定檔放哪</h3>
<p>放在<strong>專案根目錄</strong>的 <code>.cursor/worktrees.json</code>，Cursor 會自動讀到。</p>
<h3 id="三個設定鍵">三個設定鍵</h3>
<table>
<thead>
<tr>
<th>鍵</th>
<th>說明</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>setup-worktree</code></td>
<td>通用，所有作業系統都跑（除非有 OS 專用覆蓋）</td>
</tr>
<tr>
<td><code>setup-worktree-windows</code></td>
<td>Windows 專用，優先於 <code>setup-worktree</code></td>
</tr>
<tr>
<td><code>setup-worktree-unix</code></td>
<td>macOS / Linux 專用，優先於 <code>setup-worktree</code></td>
</tr>
</tbody>
</table>
<p>每個鍵可以是字串（腳本檔路徑）或陣列（一連串 shell 指令依序執行）。</p>

<h3 id="流程複雜改用腳本檔">流程複雜：改用腳本檔</h3>
<p>指令多到寫在 JSON 裡很難維護，改放腳本：</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="json" data-theme="github-dark-default"><code data-language="json" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#E6EDF3">{</span></span>
<span data-line=""><span style="color:#7EE787">  "setup-worktree-unix"</span><span style="color:#E6EDF3">: </span><span style="color:#A5D6FF">"setup-worktree-unix.sh"</span><span style="color:#E6EDF3">,</span></span>
<span data-line=""><span style="color:#7EE787">  "setup-worktree-windows"</span><span style="color:#E6EDF3">: </span><span style="color:#A5D6FF">"setup-worktree-windows.ps1"</span><span style="color:#E6EDF3">,</span></span>
<span data-line=""><span style="color:#7EE787">  "setup-worktree"</span><span style="color:#E6EDF3">: [</span><span style="color:#A5D6FF">"echo 'Using generic fallback'"</span><span style="color:#E6EDF3">]</span></span>
<span data-line=""><span style="color:#E6EDF3">}</span></span></code></pre></figure>
<p>腳本放在 <code>.cursor/</code> 目錄下，Windows 用 <code>.ps1</code>，記得在腳本裡用 <code>$env:ROOT_WORKTREE_PATH</code> 取得主目錄路徑。</p>
<blockquote>
<p>依賴安裝不要用 symlink 連進 worktree——容易跟主 worktree 打架。用 <code>npm ci</code>、<code>pnpm</code>、<code>bun</code>、<code>uv</code> 在 worktree 裡重新安裝比較穩。</p>
</blockquote>
<h2 id="worktree-清理與數量上限">Worktree 清理與數量上限</h2>
<p>Cursor 會自動管理 worktree 數量——每個 workspace 有上限（例如 20），超過就依最後使用時間刪最舊的。不同 repo 之間互不影響。</p>
<p>如果想調整，可以在設定裡找：</p>
<ul>
<li><code>cursor.worktreeMaxCount</code>：最多保留幾個 worktree</li>
<li><code>cursor.worktreeCleanupIntervalHours</code>：多久清理一次</li>
</ul>
<p>實際鍵名以 Cursor 當前版本為準。</p>
<h2 id="worktree-設定出了問題怎麼查">worktree 設定出了問題怎麼查</h2>
<p>依賴沒裝好、遷移沒跑——打開 Cursor 的 <strong>Output</strong> 面板，在 dropdown 選 <strong>「Worktrees Setup」</strong>，就能看建立時執行的指令與錯誤訊息。比對著 <code>worktrees.json</code> 和腳本來排查，通常很快能找到問題。</p>
<hr>
<p>Best-of-N 是「用數量換品質」——難題值得這樣投資。worktrees.json 是「把環境準備自動化」——設一次，之後省去重複的手動步驟。兩個都不難設，但第一次設好之後差異很明顯。</p>

<p>若同一個 Best-of-N 裡你想 Apply 多張卡片（先 Apply A 再 Apply B），Cursor 可能會問：<strong>合併與衝突解決</strong> 還是 <strong>Full Overwrite</strong>——這部分邏輯跟 <a href="08-worktree-merge">08-worktree-merge</a> 一樣，不另外重複。</p>
<h2 id="worktreesjsonworktree-建好就有完整環境">worktrees.json：worktree 建好就有完整環境</h2>
<p>Cursor 建立 worktree 時，預設只帶主目錄已追蹤的檔案——不會幫你裝依賴、複製 <code>.env</code>、跑資料庫遷移。每次建了新 worktree 都要手動做這些，很快就會膩。</p>
<p><strong><code>.cursor/worktrees.json</code></strong> 解決這件事：指定「每個新 worktree 建立後要自動執行的指令」，一次設定、之後每個 worktree 建好就是完整環境。</p>
<h3 id="設定檔放哪">設定檔放哪</h3>
<p>放在<strong>專案根目錄</strong>的 <code>.cursor/worktrees.json</code>，Cursor 會自動讀到。</p>
<h3 id="三個設定鍵">三個設定鍵</h3>
<table>
<thead>
<tr>
<th>鍵</th>
<th>說明</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>setup-worktree</code></td>
<td>通用，所有作業系統都跑（除非有 OS 專用覆蓋）</td>
</tr>
<tr>
<td><code>setup-worktree-windows</code></td>
<td>Windows 專用，優先於 <code>setup-worktree</code></td>
</tr>
<tr>
<td><code>setup-worktree-unix</code></td>
<td>macOS / Linux 專用，優先於 <code>setup-worktree</code></td>
</tr>
</tbody>
</table>
<p>每個鍵可以是字串（腳本檔路徑）或陣列（一連串 shell 指令依序執行）。</p>

<blockquote>
<p>依賴安裝不要用 symlink 連進 worktree——容易跟主 worktree 打架。用 <code>npm ci</code>、<code>pnpm</code>、<code>bun</code>、<code>uv</code> 在 worktree 裡重新安裝比較穩。</p>
</blockquote>
<h2 id="worktree-清理與數量上限">Worktree 清理與數量上限</h2>
<p>Cursor 會自動管理 worktree 數量——每個 workspace 有上限（例如 20），超過就依最後使用時間刪最舊的。不同 repo 之間互不影響。</p>
<p>如果想調整，可以在設定裡找：</p>
<ul>
<li><code>cursor.worktreeMaxCount</code>：最多保留幾個 worktree</li>
<li><code>cursor.worktreeCleanupIntervalHours</code>：多久清理一次</li>
</ul>
<p>實際鍵名以 Cursor 當前版本為準。</p>
<h2 id="worktree-設定出了問題怎麼查">worktree 設定出了問題怎麼查</h2>
<p>依賴沒裝好、遷移沒跑——打開 Cursor 的 <strong>Output</strong> 面板，在 dropdown 選 <strong>「Worktrees Setup」</strong>，就能看建立時執行的指令與錯誤訊息。比對著 <code>worktrees.json</code> 和腳本來排查，通常很快能找到問題。</p>
<hr>
<p>Best-of-N 是「用數量換品質」——難題值得這樣投資。worktrees.json 是「把環境準備自動化」——設一次，之後省去重複的手動步驟。兩個都不難設，但第一次設好之後差異很明顯。</p>
