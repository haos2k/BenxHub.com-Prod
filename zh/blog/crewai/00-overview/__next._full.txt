14:T149b,<p>最近「AI Agent」這個詞出現的頻率，跟推銷電話差不多。</p>
<p>你一定聽過了：「讓 AI 自己做事」、「多個 Agent 協作」、「自動化工作流」——但真的打開文件一看，又是一堆抽象概念和架構圖。這系列就是要把那些東西翻譯成你可以直接動手做的步驟。</p>
<p><strong>一句話版本：CrewAI 是讓多個 AI 角色分工合作、把複雜任務拆開做完的 Python 框架。</strong></p>
<h2 id="為什麼不是一個超強-ai就夠了">為什麼不是「一個超強 AI」就夠了？</h2>
<p>把所有事情丟給同一個 AI 做，問題不是它不夠聰明——是它很難同時扮演「嚴謹的研究員」和「有溫度的內容編輯」。就像你不會要同一個人同時負責代碼審查和客戶簡報，硬要它兼顧兩件性質完全不同的事，結果通常是兩件都做得普普通通。</p>
<p>CrewAI 的思路是：一個角色一種專長，把複雜任務拆給多個各司其職的 Agent，讓它們按順序、按邏輯把事情串起來。</p>
<p>你可以把它想成組一個小型專案團隊：</p>
<ul>
<li><strong>研究員 Agent</strong>：找資料、驗資訊</li>
<li><strong>分析師 Agent</strong>：整理重點、萃取結構</li>
<li><strong>編輯 Agent</strong>：潤稿、輸出可讀報告</li>
</ul>
<p>跑順的時候，效果像你有一個不會喊加班費的內容戰隊——但 API 費用還是會來，這點我不騙你。</p>
<h2 id="先把三個詞搞清楚">先把三個詞搞清楚</h2>
<p>整個 CrewAI 生態圍繞這三個概念展開，先記住它們，後面讀起來會省很多時間：</p>
<ul>
<li><strong><code>Agent</code></strong>：角色，定義「誰來做、擅長什麼、有什麼工具」</li>
<li><strong><code>Task</code></strong>：任務，定義「要做什麼、輸出格式是什麼、依賴哪個前置任務」</li>
<li><strong><code>Crew</code></strong>：團隊，把 Agent 和 Task 組在一起、決定執行流程</li>
</ul>
<p>大多數入門專案用 <code>Process.sequential</code> 就非常夠用——先 A 做完，再交給 B。可預期、好 debug、出事情好查。不要一開始就追求動態分派，那是你有穩定監控之後才值得碰的東西。</p>
<h2 id="這-10-篇怎麼讀">這 10 篇怎麼讀</h2>
<p>設計是線性的，每篇都建在前一篇的基礎上：</p>
<ol>
<li><a href="01-quick-start">快速上手</a>：10 分鐘跑通第一個 Crew，先看到成果再說</li>
<li><a href="02-agents-and-tasks">Agent 與 Task 入門</a>：角色和任務怎麼拆才不會亂</li>
<li><a href="03-crew-and-process">Crew 與 Process</a>：組隊邏輯與流程策略選擇</li>
<li><a href="04-tools-integration">Tools 整合</a>：讓 Agent 能查資料、讀檔、操作外部服務</li>
<li><a href="05-structured-output-pydantic">結構化輸出 Pydantic</a>：輸出格式固定下來，下游才能穩定接</li>
<li><a href="06-flow-basics">Flow 入門</a>：多個 Crew 如何協調成一條完整流程</li>
<li><a href="07-memory-and-knowledge">Memory 與 Knowledge</a>：讓 Agent 不再每次重學、記得業務知識</li>
<li><a href="08-debug-and-common-errors">除錯與常見錯誤</a>：踩雷地圖，先看省得自己重蹈</li>
<li><a href="09-production-best-practices">上線最佳實踐</a>：從 demo 走到可維運的生產環境</li>
</ol>
<h2 id="你需要準備什麼">你需要準備什麼？</h2>
<ul>
<li>Python 3.10 以上</li>
<li>套件環境工具（<code>uv</code>、<code>venv</code>、<code>poetry</code> 三選一，<code>uv</code> 最快）</li>
<li>一個 LLM API Key（OpenAI 或 Anthropic 都可以）</li>
</ul>
<p>不需要提前把文件讀完，也不需要對 LangChain 或其他框架有背景知識。這系列假設你只會 Python，其他的跟著走就好。</p>
<h2 id="一個在你開始前就很重要的心法">一個在你開始前就很重要的心法</h2>
<p>第一個版本不要追求炫技。</p>
<p>先讓流程可重現——同樣的輸入，跑出差不多的結果。你先做到「每次跑都穩定」，再談速度優化、成本控制、準確率提升。跳過這個順序去追進階功能，你遇到問題的時候會不知道錯在哪裡，除錯成本翻倍。</p>
<p>這跟打 RPG 一樣。先把主線破完，再刷裝備。</p>
<h2 id="常見問題">常見問題</h2>
<p><strong>Q：CrewAI 和 LangChain 有什麼差別？</strong><br>
LangChain 是比較底層的工具箱，幾乎什麼都可以做，但也要自己組裝很多東西。CrewAI 的定位更高層，直接提供「多 Agent 協作流程」的設計框架，適合你想快速把「多角色任務流」跑起來的場景。</p>
<p><strong>Q：一定要用 OpenAI 嗎？</strong><br>
不一定。CrewAI 支援多個 LLM 提供商，包括 Anthropic Claude、Google Gemini、本地跑的 Ollama 等。初學者用 OpenAI 最好設定，但後期可以替換。</p>
<p><strong>Q：這系列適合完全沒有 AI 開發背景的人嗎？</strong><br>
適合。你只需要會寫基本 Python，懂得怎麼裝套件、設環境變數就夠了。</p>
