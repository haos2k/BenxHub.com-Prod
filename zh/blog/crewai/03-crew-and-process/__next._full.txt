1b:T3252,<p>Agent 和 Task 設計完之後，還有一個問題要回答：<strong>誰來決定這些任務按什麼順序跑？</strong></p>
<p>答案就是 <code>Crew</code> 和 <code>Process</code>。</p>
<p>把 <code>Crew</code> 想成導演——它負責管理所有演員（Agent）和劇本（Task），決定誰先上場、怎麼流轉。<code>Process</code> 則是執行節奏，sequential 就是「按順序一個個來」，hierarchical 是「有一個管理者 Agent 自己決定分派順序」。</p>
<h2 id="九成新手專案用-sequential-就對了">九成新手專案，用 Sequential 就對了</h2>
<p>結論先說，不繞圈子：<strong><code>Process.sequential</code> 是你的預設選擇</strong>。</p>
<p>原因不是它比較高級，而是它最容易理解、最好 debug、出問題最好定位。任務 A 做完，結果交給任務 B，B 做完交給 C——清楚、線性、可預期。</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="python" data-theme="github-dark"><code data-language="python" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#F97583">from</span><span style="color:#E1E4E8"> crewai </span><span style="color:#F97583">import</span><span style="color:#E1E4E8"> Crew, Process</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#F97583">def</span><span style="color:#B392F0"> build_crew</span><span style="color:#E1E4E8">(agents, tasks) -> Crew:</span></span>
<span data-line=""><span style="color:#F97583">    return</span><span style="color:#E1E4E8"> Crew(</span></span>
<span data-line=""><span style="color:#FFAB70">        agents</span><span style="color:#F97583">=</span><span style="color:#E1E4E8">agents,</span></span>

<span data-line=""><span style="color:#E1E4E8">    )</span></span></code></pre></figure>
<p>這段看起來很平淡，但其實幫你做了一個很重要的決定：流程是確定的，不依賴模型的臨場判斷。這對新手來說是很大的穩定性保障。</p>
<p><code>verbose=True</code> 先開著——它會讓你在終端看到每個步驟的執行過程。除錯的時候你會很慶幸它開著。</p>
<h2 id="sequential-的核心優勢">Sequential 的核心優勢</h2>
<p>不是功能比較多，而是<strong>出問題的時候你知道去哪裡找</strong>：</p>
<ul>
<li>任務依賴關係清楚，每個 context 的資料流向都看得到</li>
<li>輸出可重現，同樣的輸入大概率得到類似的輸出</li>
<li>錯誤定位快，你知道是第幾步出了問題</li>
<li>成本可控，每個任務消耗多少 token 有跡可循</li>
</ul>
<p>對剛開始的人來說，這就像先用普通難度破主線——不要一開始就挑地獄模式。</p>
<h2 id="hierarchical-是什麼什麼時候才考慮">Hierarchical 是什麼，什麼時候才考慮</h2>
<p>Hierarchical 的差別是：它會有一個「管理者 Agent」（manager），由它決定任務怎麼分派給各個執行 Agent，整個流程是動態的，而不是你事先寫死的順序。</p>
<p>這聽起來很炫，但代價是複雜度大幅上升——你需要設計管理者的 prompt、處理它的分派邏輯、還要確保它不會做出你不預期的決定。</p>
<p>考慮 Hierarchical 的前提是：</p>
<ul>
<li>任務量非常多，且每次執行的任務組合不固定</li>
<li>你需要動態調整執行路徑（例如根據某個條件決定跳過某步驟）</li>
<li>你已經有穩定的監控、成本警戒、還有時間處理奇怪的 edge case</li>
</ul>
<p>如果你現在還在調 <code>expected_output</code> 讓輸出穩定，先不要碰 hierarchical。真的，先不要。</p>

<h2 id="常見問題">常見問題</h2>
<p><strong>Q：<code>verbose=True</code> 會拖慢執行速度嗎？</strong><br>
不會。它只是把執行過程印到 terminal，不影響實際 LLM 呼叫速度。生產環境可以關掉，開發和除錯期間建議開著。</p>
<p><strong>Q：sequential 的任務一定要按 list 順序執行嗎？</strong><br>
是的。tasks list 的順序就是執行順序。Task 的 context 可以指定吃某個前置任務的結果，但執行順序本身就是 list 的順序。</p>
<p><strong>Q：Crew 可以有幾個 Agent？</strong><br>
沒有硬性上限，但 2-5 個是最常見的設計。Agent 太多，協作成本和除錯難度都會增加。先從最小可行的設計開始。</p>

26:T3252,<p>Agent 和 Task 設計完之後，還有一個問題要回答：<strong>誰來決定這些任務按什麼順序跑？</strong></p>
<p>答案就是 <code>Crew</code> 和 <code>Process</code>。</p>
<p>把 <code>Crew</code> 想成導演——它負責管理所有演員（Agent）和劇本（Task），決定誰先上場、怎麼流轉。<code>Process</code> 則是執行節奏，sequential 就是「按順序一個個來」，hierarchical 是「有一個管理者 Agent 自己決定分派順序」。</p>
<h2 id="九成新手專案用-sequential-就對了">九成新手專案，用 Sequential 就對了</h2>
<p>結論先說，不繞圈子：<strong><code>Process.sequential</code> 是你的預設選擇</strong>。</p>
<p>原因不是它比較高級，而是它最容易理解、最好 debug、出問題最好定位。任務 A 做完，結果交給任務 B，B 做完交給 C——清楚、線性、可預期。</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="python" data-theme="github-dark"><code data-language="python" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#F97583">from</span><span style="color:#E1E4E8"> crewai </span><span style="color:#F97583">import</span><span style="color:#E1E4E8"> Crew, Process</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#F97583">def</span><span style="color:#B392F0"> build_crew</span><span style="color:#E1E4E8">(agents, tasks) -> Crew:</span></span>
<span data-line=""><span style="color:#F97583">    return</span><span style="color:#E1E4E8"> Crew(</span></span>
<span data-line=""><span style="color:#FFAB70">        agents</span><span style="color:#F97583">=</span><span style="color:#E1E4E8">agents,</span></span>
<span data-line=""><span style="color:#FFAB70">        tasks</span><span style="color:#F97583">=</span><span style="color:#E1E4E8">tasks,</span></span>
<span data-line=""><span style="color:#FFAB70">        process</span><span style="color:#F97583">=</span><span style="color:#E1E4E8">Process.sequential,</span></span>
<span data-line=""><span style="color:#FFAB70">        verbose</span><span style="color:#F97583">=</span><span style="color:#79B8FF">True</span><span style="color:#E1E4E8">,</span></span>
<span data-line=""><span style="color:#E1E4E8">    )</span></span></code></pre></figure>
<p>這段看起來很平淡，但其實幫你做了一個很重要的決定：流程是確定的，不依賴模型的臨場判斷。這對新手來說是很大的穩定性保障。</p>
<p><code>verbose=True</code> 先開著——它會讓你在終端看到每個步驟的執行過程。除錯的時候你會很慶幸它開著。</p>
<h2 id="sequential-的核心優勢">Sequential 的核心優勢</h2>
<p>不是功能比較多，而是<strong>出問題的時候你知道去哪裡找</strong>：</p>
<ul>
<li>任務依賴關係清楚，每個 context 的資料流向都看得到</li>
<li>輸出可重現，同樣的輸入大概率得到類似的輸出</li>
<li>錯誤定位快，你知道是第幾步出了問題</li>
<li>成本可控，每個任務消耗多少 token 有跡可循</li>
</ul>
<p>對剛開始的人來說，這就像先用普通難度破主線——不要一開始就挑地獄模式。</p>
<h2 id="hierarchical-是什麼什麼時候才考慮">Hierarchical 是什麼，什麼時候才考慮</h2>
<p>Hierarchical 的差別是：它會有一個「管理者 Agent」（manager），由它決定任務怎麼分派給各個執行 Agent，整個流程是動態的，而不是你事先寫死的順序。</p>
<p>這聽起來很炫，但代價是複雜度大幅上升——你需要設計管理者的 prompt、處理它的分派邏輯、還要確保它不會做出你不預期的決定。</p>
<p>考慮 Hierarchical 的前提是：</p>
<ul>
<li>任務量非常多，且每次執行的任務組合不固定</li>
<li>你需要動態調整執行路徑（例如根據某個條件決定跳過某步驟）</li>
<li>你已經有穩定的監控、成本警戒、還有時間處理奇怪的 edge case</li>
</ul>
<p>如果你現在還在調 <code>expected_output</code> 讓輸出穩定，先不要碰 hierarchical。真的，先不要。</p>
