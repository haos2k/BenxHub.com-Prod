<p>Homelab 裡面跑的大部分服務——Pi-hole、Nginx Proxy Manager、WireGuard、AdGuard Home——用 LXC 就夠了，沒必要為了一個 DNS 服務開一整台 VM。那就像為了煮泡麵把整間餐廳的瓦斯爐都打開一樣浪費。</p>
<h2 id="特權-vs-非特權容器">特權 vs 非特權容器</h2>
<p>PVE 的 LXC 有兩種模式，這個很重要（詳細說明可參考 <a href="https://pve.proxmox.com/wiki/Linux_Container">Proxmox LXC 官方文件</a>）：</p>
<p><strong>非特權容器（Unprivileged）</strong>——預設，也是你應該用的</p>
<p>容器裡的 root（UID 0）在主機上其實是個路人甲（高位 UID）。就算容器被攻破，攻擊者在主機上的權限也約等於零。</p>
<p><strong>特權容器（Privileged）</strong>——除非必要，否則別碰</p>
<p>容器內的 root 就是主機上的 root。跑 Docker-in-LXC 的時候可能需要，但安全風險比較高。</p>
<blockquote>
<p>生產環境一律用非特權容器。需要特權模式的時候，先想想能不能用 VM 替代。</p>
</blockquote>
<h2 id="建立第一個-lxc-容器">建立第一個 LXC 容器</h2>
<h3 id="方法一web-介面">方法一：Web 介面</h3>
<ol>
<li>先下載容器範本：左側 <code>local</code> 儲存 -> <code>CT Templates</code> -> <code>Templates</code> 按鈕 -> 選一個下載（推薦 Debian 12 或 Ubuntu 24.04）</li>
<li>右上角 <code>Create CT</code></li>
<li>填 Hostname、Password</li>
<li>選範本</li>
<li>配置磁碟大小（8 GB 通常夠）、CPU（1 核）、記憶體（512 MB）</li>
<li>設定網路（DHCP 或固定 IP）</li>
<li>完成</li>
</ol>

<h2 id="docker-in-lxchomelab-的熱門玩法">Docker-in-LXC：Homelab 的熱門玩法</h2>
<p>很多人的 Homelab 服務是用 Docker Compose 管理的。在 LXC 裡面跑 Docker 完全可行，設定也不複雜：</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># 1. 在 PVE 主機上修改容器設定</span></span>
<span data-line=""><span style="color:#6A737D"># 開啟 nesting 和 keyctl（Docker 需要）</span></span>
<span data-line=""><span style="color:#B392F0">pct</span><span style="color:#9ECBFF"> set</span><span style="color:#79B8FF"> 200</span><span style="color:#79B8FF"> --features</span><span style="color:#9ECBFF"> nesting=1,keyctl=</span><span style="color:#79B8FF">1</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># 如果非特權容器跑不動 Docker，可能需要改成特權：</span></span>
<span data-line=""><span style="color:#6A737D"># pct set 200 --unprivileged 0</span></span>
<span data-line=""><span style="color:#6A737D"># （但請先嘗試非特權 + nesting，大部分情況夠用）</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># 2. 進入容器裝 Docker</span></span>
<span data-line=""><span style="color:#B392F0">pct</span><span style="color:#9ECBFF"> enter</span><span style="color:#79B8FF"> 200</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># 容器內執行：</span></span>
<span data-line=""><span style="color:#B392F0">apt</span><span style="color:#9ECBFF"> update</span><span style="color:#E1E4E8"> &#x26;&#x26; </span><span style="color:#B392F0">apt</span><span style="color:#9ECBFF"> install</span><span style="color:#79B8FF"> -y</span><span style="color:#9ECBFF"> curl</span></span>
<span data-line=""><span style="color:#B392F0">curl</span><span style="color:#79B8FF"> -fsSL</span><span style="color:#9ECBFF"> https://get.docker.com</span><span style="color:#F97583"> |</span><span style="color:#B392F0"> sh</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># 3. 測試</span></span>
<span data-line=""><span style="color:#B392F0">docker</span><span style="color:#9ECBFF"> run</span><span style="color:#9ECBFF"> hello-world</span></span></code></pre></figure>
<blockquote>
<p>非特權容器 + <code>nesting=1</code> 在大部分情況下就能跑 Docker 了。只有少數需要存取特殊裝置的 Docker 容器才需要特權模式。先試非特權，不行再改。</p>
</blockquote>
<h2 id="bind-mount讓容器存取主機檔案">Bind Mount：讓容器存取主機檔案</h2>
<p>假設你的 PVE 主機上有一個 <code>/mnt/data</code> 目錄存放資料，你想讓容器也能讀寫：</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># 在 PVE 主機上設定</span></span>
<span data-line=""><span style="color:#B392F0">pct</span><span style="color:#9ECBFF"> set</span><span style="color:#79B8FF"> 200</span><span style="color:#79B8FF"> --mp0</span><span style="color:#9ECBFF"> /mnt/data,mp=/data</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># 重啟容器後，在容器內就能看到 /data 目錄</span></span>
<span data-line=""><span style="color:#B392F0">pct</span><span style="color:#9ECBFF"> reboot</span><span style="color:#79B8FF"> 200</span></span></code></pre></figure>
<p>這在 NAS 場景特別好用——PVE 主機掛載的硬碟直接分享給多個容器使用，不用搞 NFS。更多儲存掛載方式請看<a href="05-storage">儲存系統指南</a>。</p>
<blockquote>
<p>非特權容器的 Bind Mount 有 UID 映射問題。容器內的 root 寫的檔案，在主機上會變成高位 UID。解法是在容器設定裡加 <code>--mp0 /mnt/data,mp=/data,uid=0,gid=0</code>，或者乾脆用特權容器。</p>
</blockquote>

<h2 id="lxc-還是-docker">LXC 還是 Docker？</h2>
<p>這題常常被問到。答案是：<strong>不衝突，可以疊著用</strong>。</p>
<p>一個合理的 Homelab 架構可能長這樣：</p>
<ul>
<li>PVE 上面跑幾個 LXC 容器，每個容器跑一組相關的 Docker 服務</li>
<li>簡單不需要 Docker 的服務（Pi-hole 等）直接用 LXC 原生跑</li>
<li>需要完整 OS 或 Windows 的用 VM</li>
</ul>
<p>不需要選邊站，把對的工具用在對的場景就好。</p>
<h2 id="常見問題">常見問題</h2>
<h3 id="q-lxc-容器可以跑-docker-嗎">Q: LXC 容器可以跑 Docker 嗎？</h3>
<p>可以。在容器設定中啟用 <code>nesting=1</code> 和 <code>keyctl=1</code>，然後在容器內正常安裝 Docker 即可。大部分情況下用非特權容器就能跑，只有極少數需要特殊裝置存取的才要切換成特權模式。</p>
<h3 id="q-lxc-容器的安全性夠嗎會不會影響到主機">Q: LXC 容器的安全性夠嗎？會不會影響到主機？</h3>
<p>非特權容器的安全性很高。容器內的 root 在主機上只是普通使用者，就算容器被攻破，攻擊者也無法取得主機權限。生產環境一律建議使用非特權容器。</p>
<h3 id="q-lxc-跟-docker-有什麼不同該用哪個">Q: LXC 跟 Docker 有什麼不同？該用哪個？</h3>
<p>LXC 更像一台輕量的虛擬機，有完整的 init 系統和 SSH；Docker 是應用層級的容器，專注單一服務。兩者不衝突，很多人在 LXC 裡面跑 Docker，結合兩者的優點。</p>
<h3 id="q-lxc-容器可以跑-windows-嗎">Q: LXC 容器可以跑 Windows 嗎？</h3>
<p>不行。LXC 是作業系統級虛擬化，共享 Linux 核心，所以只能跑 Linux 系統。需要跑 Windows 請使用 <a href="03-vm-management">KVM 虛擬機</a>。</p>

<h2 id="特權-vs-非特權容器">特權 vs 非特權容器</h2>
<p>PVE 的 LXC 有兩種模式，這個很重要（詳細說明可參考 <a href="https://pve.proxmox.com/wiki/Linux_Container">Proxmox LXC 官方文件</a>）：</p>
<p><strong>非特權容器（Unprivileged）</strong>——預設，也是你應該用的</p>
<p>容器裡的 root（UID 0）在主機上其實是個路人甲（高位 UID）。就算容器被攻破，攻擊者在主機上的權限也約等於零。</p>
<p><strong>特權容器（Privileged）</strong>——除非必要，否則別碰</p>
<p>容器內的 root 就是主機上的 root。跑 Docker-in-LXC 的時候可能需要，但安全風險比較高。</p>
<blockquote>
<p>生產環境一律用非特權容器。需要特權模式的時候，先想想能不能用 VM 替代。</p>
</blockquote>
<h2 id="建立第一個-lxc-容器">建立第一個 LXC 容器</h2>
<h3 id="方法一web-介面">方法一：Web 介面</h3>

<li>先下載容器範本：左側 <code>local</code> 儲存 -> <code>CT Templates</code> -> <code>Templates</code> 按鈕 -> 選一個下載（推薦 Debian 12 或 Ubuntu 24.04）</li>

<li>配置磁碟大小（8 GB 通常夠）、CPU（1 核）、記憶體（512 MB）</li>
<li>設定網路（DHCP 或固定 IP）</li>
<li>完成</li>
</ol>

<h2 id="docker-in-lxchomelab-的熱門玩法">Docker-in-LXC：Homelab 的熱門玩法</h2>
<p>很多人的 Homelab 服務是用 Docker Compose 管理的。在 LXC 裡面跑 Docker 完全可行，設定也不複雜：</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># 1. 在 PVE 主機上修改容器設定</span></span>
<span data-line=""><span style="color:#6A737D"># 開啟 nesting 和 keyctl（Docker 需要）</span></span>
<span data-line=""><span style="color:#B392F0">pct</span><span style="color:#9ECBFF"> set</span><span style="color:#79B8FF"> 200</span><span style="color:#79B8FF"> --features</span><span style="color:#9ECBFF"> nesting=1,keyctl=</span><span style="color:#79B8FF">1</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># 如果非特權容器跑不動 Docker，可能需要改成特權：</span></span>
<span data-line=""><span style="color:#6A737D"># pct set 200 --unprivileged 0</span></span>
<span data-line=""><span style="color:#6A737D"># （但請先嘗試非特權 + nesting，大部分情況夠用）</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># 2. 進入容器裝 Docker</span></span>
<span data-line=""><span style="color:#B392F0">pct</span><span style="color:#9ECBFF"> enter</span><span style="color:#79B8FF"> 200</span></span>
<span data-line=""> </span>

<span data-line=""><span style="color:#B392F0">apt</span><span style="color:#9ECBFF"> update</span><span style="color:#E1E4E8"> &#x26;&#x26; </span><span style="color:#B392F0">apt</span><span style="color:#9ECBFF"> install</span><span style="color:#79B8FF"> -y</span><span style="color:#9ECBFF"> curl</span></span>
<span data-line=""><span style="color:#B392F0">curl</span><span style="color:#79B8FF"> -fsSL</span><span style="color:#9ECBFF"> https://get.docker.com</span><span style="color:#F97583"> |</span><span style="color:#B392F0"> sh</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># 3. 測試</span></span>
<span data-line=""><span style="color:#B392F0">docker</span><span style="color:#9ECBFF"> run</span><span style="color:#9ECBFF"> hello-world</span></span></code></pre></figure>
<blockquote>
<p>非特權容器 + <code>nesting=1</code> 在大部分情況下就能跑 Docker 了。只有少數需要存取特殊裝置的 Docker 容器才需要特權模式。先試非特權，不行再改。</p>
</blockquote>
<h2 id="bind-mount讓容器存取主機檔案">Bind Mount：讓容器存取主機檔案</h2>
<p>假設你的 PVE 主機上有一個 <code>/mnt/data</code> 目錄存放資料，你想讓容器也能讀寫：</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># 在 PVE 主機上設定</span></span>
<span data-line=""><span style="color:#B392F0">pct</span><span style="color:#9ECBFF"> set</span><span style="color:#79B8FF"> 200</span><span style="color:#79B8FF"> --mp0</span><span style="color:#9ECBFF"> /mnt/data,mp=/data</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># 重啟容器後，在容器內就能看到 /data 目錄</span></span>
<span data-line=""><span style="color:#B392F0">pct</span><span style="color:#9ECBFF"> reboot</span><span style="color:#79B8FF"> 200</span></span></code></pre></figure>
<p>這在 NAS 場景特別好用——PVE 主機掛載的硬碟直接分享給多個容器使用，不用搞 NFS。更多儲存掛載方式請看<a href="05-storage">儲存系統指南</a>。</p>
<blockquote>
<p>非特權容器的 Bind Mount 有 UID 映射問題。容器內的 root 寫的檔案，在主機上會變成高位 UID。解法是在容器設定裡加 <code>--mp0 /mnt/data,mp=/data,uid=0,gid=0</code>，或者乾脆用特權容器。</p>
</blockquote>

<h2 id="lxc-還是-docker">LXC 還是 Docker？</h2>
<p>這題常常被問到。答案是：<strong>不衝突，可以疊著用</strong>。</p>
<p>一個合理的 Homelab 架構可能長這樣：</p>
<ul>
<li>PVE 上面跑幾個 LXC 容器，每個容器跑一組相關的 Docker 服務</li>
<li>簡單不需要 Docker 的服務（Pi-hole 等）直接用 LXC 原生跑</li>
<li>需要完整 OS 或 Windows 的用 VM</li>
</ul>
<p>不需要選邊站，把對的工具用在對的場景就好。</p>
<h2 id="常見問題">常見問題</h2>
<h3 id="q-lxc-容器可以跑-docker-嗎">Q: LXC 容器可以跑 Docker 嗎？</h3>
<p>可以。在容器設定中啟用 <code>nesting=1</code> 和 <code>keyctl=1</code>，然後在容器內正常安裝 Docker 即可。大部分情況下用非特權容器就能跑，只有極少數需要特殊裝置存取的才要切換成特權模式。</p>
<h3 id="q-lxc-容器的安全性夠嗎會不會影響到主機">Q: LXC 容器的安全性夠嗎？會不會影響到主機？</h3>
<p>非特權容器的安全性很高。容器內的 root 在主機上只是普通使用者，就算容器被攻破，攻擊者也無法取得主機權限。生產環境一律建議使用非特權容器。</p>
<h3 id="q-lxc-跟-docker-有什麼不同該用哪個">Q: LXC 跟 Docker 有什麼不同？該用哪個？</h3>
<p>LXC 更像一台輕量的虛擬機，有完整的 init 系統和 SSH；Docker 是應用層級的容器，專注單一服務。兩者不衝突，很多人在 LXC 裡面跑 Docker，結合兩者的優點。</p>
<h3 id="q-lxc-容器可以跑-windows-嗎">Q: LXC 容器可以跑 Windows 嗎？</h3>
<p>不行。LXC 是作業系統級虛擬化，共享 Linux 核心，所以只能跑 Linux 系統。需要跑 Windows 請使用 <a href="03-vm-management">KVM 虛擬機</a>。</p>
