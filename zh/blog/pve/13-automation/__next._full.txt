<h2 id="cloud-initvm-的開箱即用設定">Cloud-init：VM 的開箱即用設定</h2>
<p>Cloud-init 是雲端映像的標準初始化工具。VM 第一次開機時，它會自動幫你設好主機名、網路、使用者帳號和 SSH Key。流程是：做一個範本，之後每台新 VM 都從範本 clone，開機就能用。如果你對 VM 範本還不熟，可以先回顧<a href="03-vm-management">VM 管理</a>裡的範本與快照章節。</p>
<h3 id="製作雲端映像範本">製作雲端映像範本</h3>

<h2 id="iac-最佳實踐">IaC 最佳實踐</h2>
<ul>
<li><strong>所有設定檔進 Git</strong>：Terraform、Ansible、Cloud-init 設定都要版本控制</li>
<li><strong>Secrets 不要硬寫</strong>：API Token 放環境變數或 Vault，不要 commit 進 repo（備份策略可參考<a href="07-backup-restore">備份與還原</a>）</li>
<li><strong>Terraform 狀態檔用遠端後端</strong>：S3 或 Consul，別放在本機</li>
<li><strong>範本定期更新</strong>：雲端映像每個月重做一次，帶最新的安全更新</li>
<li><strong>先 plan 再 apply</strong>：永遠先看 Terraform 要做什麼，確認了再執行</li>
</ul>
<blockquote>
<p>自動化的終極目標：所有基礎設施都能從 Git repo 重建。機器爆了不可怕，重跑一次 <code>terraform apply</code> 就好。</p>
</blockquote>
<hr>
<p>自動化的前期投入比較大，但回本速度很快。當你第三次手動建 VM 還在複製貼上 IP 的時候，就會後悔沒早點寫 Terraform。</p>
<p>延伸閱讀：<a href="https://pve.proxmox.com/pve-docs/api-viewer/index.html">Proxmox API 官方文件</a>、<a href="https://registry.terraform.io/providers/bpg/proxmox/latest/docs">Terraform Proxmox Provider（bpg/proxmox）</a>、<a href="https://cloudinit.readthedocs.io/en/latest/">Cloud-init 官方文件</a>。</p>
<h2 id="常見問題">常見問題</h2>
<h3 id="q-proxmox-cloud-init-範本做好後clone-一台-vm-要多久">Q: Proxmox Cloud-init 範本做好後，clone 一台 VM 要多久？</h3>
<p>Full Clone 約 1-3 分鐘（取決於磁碟大小和儲存速度），Linked Clone 只需幾秒。加上 Cloud-init 自動設定網路和 SSH Key，整個流程從 clone 到能 SSH 登入通常不超過 2 分鐘。</p>
<h3 id="q-proxmox-terraform-provider-該選哪個">Q: Proxmox Terraform Provider 該選哪個？</h3>
<p>目前社群最活躍的是 <code>bpg/proxmox</code>（原名 Telmate 已停止維護）。它支援 VM、LXC、Cloud-init、儲存等完整資源管理，建議用 0.50 以上版本。</p>
<h3 id="q-pve-api-token-跟帳號密碼登入有什麼差別">Q: PVE API Token 跟帳號密碼登入有什麼差別？</h3>
<p>API Token 不需要每次換 Ticket，可以直接在 Header 帶入驗證，適合長期自動化。還能設定 Token 的獨立權限（privsep）和到期日，比共用帳號密碼安全得多。</p>
<h3 id="q-ansible-和-terraform-在-pve-自動化中怎麼分工">Q: Ansible 和 Terraform 在 PVE 自動化中怎麼分工？</h3>
<p>Terraform 負責「建基礎設施」（建 VM、設網路、分配儲存），Ansible 負責「設定軟體」（裝套件、改設定檔、啟動服務）。兩者搭配 Cloud-init 形成完整的自動化流水線。</p>

<h2 id="cloud-initvm-的開箱即用設定">Cloud-init：VM 的開箱即用設定</h2>

<h2 id="iac-最佳實踐">IaC 最佳實踐</h2>
<ul>
<li><strong>所有設定檔進 Git</strong>：Terraform、Ansible、Cloud-init 設定都要版本控制</li>
<li><strong>Secrets 不要硬寫</strong>：API Token 放環境變數或 Vault，不要 commit 進 repo（備份策略可參考<a href="07-backup-restore">備份與還原</a>）</li>
<li><strong>Terraform 狀態檔用遠端後端</strong>：S3 或 Consul，別放在本機</li>
<li><strong>範本定期更新</strong>：雲端映像每個月重做一次，帶最新的安全更新</li>
<li><strong>先 plan 再 apply</strong>：永遠先看 Terraform 要做什麼，確認了再執行</li>
</ul>
<blockquote>
<p>自動化的終極目標：所有基礎設施都能從 Git repo 重建。機器爆了不可怕，重跑一次 <code>terraform apply</code> 就好。</p>
</blockquote>
<hr>
<p>自動化的前期投入比較大，但回本速度很快。當你第三次手動建 VM 還在複製貼上 IP 的時候，就會後悔沒早點寫 Terraform。</p>
<p>延伸閱讀：<a href="https://pve.proxmox.com/pve-docs/api-viewer/index.html">Proxmox API 官方文件</a>、<a href="https://registry.terraform.io/providers/bpg/proxmox/latest/docs">Terraform Proxmox Provider（bpg/proxmox）</a>、<a href="https://cloudinit.readthedocs.io/en/latest/">Cloud-init 官方文件</a>。</p>
<h2 id="常見問題">常見問題</h2>
<h3 id="q-proxmox-cloud-init-範本做好後clone-一台-vm-要多久">Q: Proxmox Cloud-init 範本做好後，clone 一台 VM 要多久？</h3>
<p>Full Clone 約 1-3 分鐘（取決於磁碟大小和儲存速度），Linked Clone 只需幾秒。加上 Cloud-init 自動設定網路和 SSH Key，整個流程從 clone 到能 SSH 登入通常不超過 2 分鐘。</p>
<h3 id="q-proxmox-terraform-provider-該選哪個">Q: Proxmox Terraform Provider 該選哪個？</h3>
<p>目前社群最活躍的是 <code>bpg/proxmox</code>（原名 Telmate 已停止維護）。它支援 VM、LXC、Cloud-init、儲存等完整資源管理，建議用 0.50 以上版本。</p>
<h3 id="q-pve-api-token-跟帳號密碼登入有什麼差別">Q: PVE API Token 跟帳號密碼登入有什麼差別？</h3>
<p>API Token 不需要每次換 Ticket，可以直接在 Header 帶入驗證，適合長期自動化。還能設定 Token 的獨立權限（privsep）和到期日，比共用帳號密碼安全得多。</p>
<h3 id="q-ansible-和-terraform-在-pve-自動化中怎麼分工">Q: Ansible 和 Terraform 在 PVE 自動化中怎麼分工？</h3>
<p>Terraform 負責「建基礎設施」（建 VM、設網路、分配儲存），Ansible 負責「設定軟體」（裝套件、改設定檔、啟動服務）。兩者搭配 Cloud-init 形成完整的自動化流水線。</p>
