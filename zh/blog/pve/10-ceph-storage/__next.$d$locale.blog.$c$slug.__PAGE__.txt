<h2 id="ceph-四大金剛">Ceph 四大金剛</h2>
<p>搞懂這四個元件，Ceph 就不神秘了：</p>
<ul>
<li><strong>MON（Monitor）</strong>：叢集的大腦，記錄誰在哪、資料放哪。部署 3 或 5 個（奇數，方便投票決定誰說了算）</li>
<li><strong>MGR（Manager）</strong>：收集統計資料、提供 Dashboard。至少 2 個，一個上班一個待命</li>
<li><strong>OSD（Object Storage Daemon）</strong>：真正幹活存資料的苦力。每顆硬碟對應一個 OSD，最少 3 個分散在不同節點</li>
<li><strong>MDS（Metadata Server）</strong>：只有用 CephFS 才需要，管檔案系統的目錄結構</li>
</ul>

<h2 id="crush-map-與故障域">CRUSH Map 與故障域</h2>
<p>CRUSH Map 決定「資料副本要放哪」。預設故障域是 <code>host</code>，意思是同一份資料的三個副本一定分散在不同節點上。這樣一台機器掛了，資料還是完整的——像把雞蛋分放三個籃子。</p>

<p>如果你需要多個節點共用 ISO、容器範本或備份目錄，CephFS 很方便：</p>

<h2 id="常見地雷">常見地雷</h2>
<ul>
<li><strong>不要在 Ceph 磁碟上疊硬體 RAID</strong>：Ceph 自己管資料冗餘，疊 RAID 等於把超人關進籠子裡還叫他飛</li>
<li><strong>不要設 <code>min_size=1</code></strong>：只剩一份副本還允許寫入，就是在走鋼絲沒掛安全繩</li>
<li><strong>不要混用 HDD 和 SSD 在同一個 Pool</strong>：快的被慢的拖住，誰都不開心</li>
<li><strong>磁碟規格盡量統一</strong>：大小不一的 OSD 會導致負載不均，像健身房裡一邊啞鈴 5 公斤一邊 20 公斤</li>
</ul>
<hr>
<p>Ceph 的學習曲線確實比 ZFS 陡一些（ZFS 和其他儲存方案可以回顧<a href="05-storage">存儲攻略</a>），但一旦跑起來，你就有了免費的分散式儲存，搭配<a href="09-high-availability">高可用 HA</a> 做到真正的零停機。值不值得，看你的場景規模。</p>
<p>更多 Ceph 架構細節可以參考 <a href="https://docs.ceph.com/en/latest/">Ceph 官方文件</a>，PVE 整合的部分則看 <a href="https://pve.proxmox.com/wiki/Deploy_Hyper-Converged_Ceph_Cluster">Proxmox Ceph 官方指南</a>和 <a href="https://pve.proxmox.com/pve-docs/pve-admin-guide.html#chapter_pveceph">PVE 管理手冊 - Ceph 章節</a>。</p>
<h2 id="常見問題">常見問題</h2>
<h3 id="q-pve-ceph-最少需要幾台節點">Q: PVE Ceph 最少需要幾台節點？</h3>
<p>最少 3 台節點，且建議為奇數。Ceph MON 需要投票機制維持一致性，3 台能容忍 1 台故障，5 台能容忍 2 台，低於 3 台無法保證資料安全。</p>
<h3 id="q-ceph-osd-可以用-hdd-嗎還是一定要-ssd">Q: Ceph OSD 可以用 HDD 嗎？還是一定要 SSD？</h3>
<p>HDD 可以用但效能差很多，建議用 NVMe SSD。如果預算有限，可以用 HDD 當資料碟搭配 NVMe 做 DB/WAL 加速，但同一個 Pool 裡不要混用 HDD 和 SSD。</p>
<h3 id="q-proxmox-ceph-跟-zfs-該怎麼選">Q: Proxmox Ceph 跟 ZFS 該怎麼選？</h3>
<p>單節點用 ZFS，多節點需要共享儲存選 Ceph。ZFS 設定簡單、適合本機存儲，Ceph 則提供跨節點的分散式冗餘，搭配 HA 可做到 VM 自動遷移不中斷。</p>
<h3 id="q-ceph-超融合對網路頻寬的要求是多少">Q: Ceph 超融合對網路頻寬的要求是多少？</h3>
<p>最低 10 Gbps 專用網路，建議 25 Gbps。Ceph 的資料複製和恢復都吃網路頻寬，1 Gbps 會嚴重瓶頸。同時建議開啟 Jumbo Frames（MTU 9000）減少封包開銷。</p>

<p>網路頻寬是 Ceph 的命脈。1 Gbps 跑 Ceph 就像用吸管喝珍珠奶茶——珍珠永遠卡住。至少 10GbE，能上 25GbE 更好。順便把 Jumbo Frames（MTU 9000）打開。網路規劃可以參考<a href="06-networking">網路管理</a>那篇的 Bonding 和 VLAN 設定。</p>
</blockquote>
<h2 id="ceph-四大金剛">Ceph 四大金剛</h2>
<p>搞懂這四個元件，Ceph 就不神秘了：</p>
<ul>
<li><strong>MON（Monitor）</strong>：叢集的大腦，記錄誰在哪、資料放哪。部署 3 或 5 個（奇數，方便投票決定誰說了算）</li>
<li><strong>MGR（Manager）</strong>：收集統計資料、提供 Dashboard。至少 2 個，一個上班一個待命</li>
<li><strong>OSD（Object Storage Daemon）</strong>：真正幹活存資料的苦力。每顆硬碟對應一個 OSD，最少 3 個分散在不同節點</li>
<li><strong>MDS（Metadata Server）</strong>：只有用 CephFS 才需要，管檔案系統的目錄結構</li>
</ul>

<h2 id="crush-map-與故障域">CRUSH Map 與故障域</h2>
<p>CRUSH Map 決定「資料副本要放哪」。預設故障域是 <code>host</code>，意思是同一份資料的三個副本一定分散在不同節點上。這樣一台機器掛了，資料還是完整的——像把雞蛋分放三個籃子。</p>

<h2 id="常見地雷">常見地雷</h2>
<ul>
<li><strong>不要在 Ceph 磁碟上疊硬體 RAID</strong>：Ceph 自己管資料冗餘，疊 RAID 等於把超人關進籠子裡還叫他飛</li>
<li><strong>不要設 <code>min_size=1</code></strong>：只剩一份副本還允許寫入，就是在走鋼絲沒掛安全繩</li>
<li><strong>不要混用 HDD 和 SSD 在同一個 Pool</strong>：快的被慢的拖住，誰都不開心</li>
<li><strong>磁碟規格盡量統一</strong>：大小不一的 OSD 會導致負載不均，像健身房裡一邊啞鈴 5 公斤一邊 20 公斤</li>
</ul>
<hr>
<p>Ceph 的學習曲線確實比 ZFS 陡一些（ZFS 和其他儲存方案可以回顧<a href="05-storage">存儲攻略</a>），但一旦跑起來，你就有了免費的分散式儲存，搭配<a href="09-high-availability">高可用 HA</a> 做到真正的零停機。值不值得，看你的場景規模。</p>
<p>更多 Ceph 架構細節可以參考 <a href="https://docs.ceph.com/en/latest/">Ceph 官方文件</a>，PVE 整合的部分則看 <a href="https://pve.proxmox.com/wiki/Deploy_Hyper-Converged_Ceph_Cluster">Proxmox Ceph 官方指南</a>和 <a href="https://pve.proxmox.com/pve-docs/pve-admin-guide.html#chapter_pveceph">PVE 管理手冊 - Ceph 章節</a>。</p>
<h2 id="常見問題">常見問題</h2>
<h3 id="q-pve-ceph-最少需要幾台節點">Q: PVE Ceph 最少需要幾台節點？</h3>
<p>最少 3 台節點，且建議為奇數。Ceph MON 需要投票機制維持一致性，3 台能容忍 1 台故障，5 台能容忍 2 台，低於 3 台無法保證資料安全。</p>
<h3 id="q-ceph-osd-可以用-hdd-嗎還是一定要-ssd">Q: Ceph OSD 可以用 HDD 嗎？還是一定要 SSD？</h3>
<p>HDD 可以用但效能差很多，建議用 NVMe SSD。如果預算有限，可以用 HDD 當資料碟搭配 NVMe 做 DB/WAL 加速，但同一個 Pool 裡不要混用 HDD 和 SSD。</p>
<h3 id="q-proxmox-ceph-跟-zfs-該怎麼選">Q: Proxmox Ceph 跟 ZFS 該怎麼選？</h3>
<p>單節點用 ZFS，多節點需要共享儲存選 Ceph。ZFS 設定簡單、適合本機存儲，Ceph 則提供跨節點的分散式冗餘，搭配 HA 可做到 VM 自動遷移不中斷。</p>
<h3 id="q-ceph-超融合對網路頻寬的要求是多少">Q: Ceph 超融合對網路頻寬的要求是多少？</h3>
<p>最低 10 Gbps 專用網路，建議 25 Gbps。Ceph 的資料複製和恢復都吃網路頻寬，1 Gbps 會嚴重瓶頸。同時建議開啟 Jumbo Frames（MTU 9000）減少封包開銷。</p>
