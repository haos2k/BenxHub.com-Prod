3:T2b6a,<p>系統跑起來了、服務也上線了，但你有沒有想過：誰能進來？進來之後能做什麼？防火牆管的是「門開給誰」，權限管的是「進來之後哪些抽屜能打開」。兩件事都做好，才不會某天醒來發現 VM 被人當礦機用。如果你的叢集還沒跑起來，可以先看看<a href="08-cluster">叢集管理</a>和<a href="06-networking">網路管理</a>那兩篇。</p>
<h2 id="防火牆三層洋蔥式防護">防火牆：三層洋蔥式防護</h2>
<p>PVE 的防火牆分三層，由外到內越來越細：</p>
<pre><code>┌──────────────────────────────────┐
│  Datacenter（整個叢集的通用規則）  │
├──────────────────────────────────┤
│  Host（每台節點自己的規則）        │
├──────────────────────────────────┤
│  VM/CT（每台虛擬機/容器的規則）    │
└──────────────────────────────────┘
</code></pre>
<p>規則處理順序也是這個方向：Datacenter 先看、Host 再看、VM/CT 最後看。沒有匹配到的流量？預設 <strong>DROP</strong>——不認識的一律不放行。</p>
<blockquote>
<p>超級重要：防火牆預設是<strong>關的</strong>。開啟之前，一定要先設好「允許你自己連進來」的規則，不然就是經典的「把自己鎖在門外」劇情。</p>
</blockquote>
<h3 id="設定叢集防火牆">設定叢集防火牆</h3>
<pre><code># /etc/pve/firewall/cluster.fw
[OPTIONS]
enable: 1
policy_in: DROP
policy_out: ACCEPT

[RULES]
IN ACCEPT -source 192.168.1.0/24 -p tcp -dport 8006  # Web GUI
IN ACCEPT -source 192.168.1.0/24 -p tcp -dport 22     # SSH
IN ACCEPT -p icmp                                       # Ping
</code></pre>
<h3 id="vm-層級防火牆">VM 層級防火牆</h3>
<pre><code># /etc/pve/firewall/&#x3C;vmid>.fw
[OPTIONS]
enable: 1
policy_in: DROP
policy_out: ACCEPT

[RULES]
GROUP web-server
IN ACCEPT -p tcp -dport 22 -source 10.0.0.0/8
</code></pre>
<h3 id="實用功能">實用功能</h3>
<p><strong>Security Group</strong>：定義一組規則，取個名字（如 <code>web-server</code>），套用到多台 VM。就像衣服的標籤——Web Server 的穿 Web Server 的制服，Database 穿 Database 的。</p>
<p><strong>IPSet</strong>：把一堆 IP 打包成一個集合，規則裡引用集合名稱就好。特殊的 <code>blacklist</code> IPSet 還能做全叢集黑名單。</p>

<h3 id="rbac-模型">RBAC 模型</h3>
<p>PVE 的權限模型就是經典的 RBAC（Role-Based Access Control）：</p>
<pre><code>使用者/群組 → 角色（Role） → 綁定到資源路徑（Path）
</code></pre>
<p>路徑長這樣：<code>/vms/100</code>（某台 VM）、<code>/storage/local-lvm</code>（某個儲存）、<code>/pool/dev</code>（某個資源池）。</p>

<h3 id="2fa-雙因素認證">2FA 雙因素認證</h3>
<p>所有管理員帳號都建議開 2FA。PVE 支援：</p>
<ul>
<li><strong>TOTP</strong>：Google Authenticator、Authy 那種六位數字</li>
<li><strong>WebAuthn/FIDO2</strong>：YubiKey 之類的硬體金鑰</li>
<li><strong>Recovery Keys</strong>：萬一手機掉了的救命繩</li>
</ul>
<p>設定路徑：Web GUI → Datacenter → Permissions → Two Factor</p>
<h2 id="安全黃金法則">安全黃金法則</h2>
<ol>
<li><strong>最小權限原則</strong>：給剛好夠用的權限，不要圖方便開 Administrator</li>
<li><strong>用群組管理</strong>：別一個一個使用者改權限，會改到懷疑人生</li>
<li><strong>API Token 取代密碼</strong>：腳本和自動化工具用 Token，設定期限、限制權限</li>
<li><strong>防火牆只開需要的埠</strong>：多開一個埠就多一個被攻擊的面</li>
<li><strong>定期檢查 ACL</strong>：人會離職、專案會結束，權限要跟著收回</li>
</ol>
<blockquote>
<p>弱密碼 + 管理介面對外 + root 帳號共用 = 資安事件倒數計時器。認真的。</p>
</blockquote>
<hr>
<p>防火牆跟權限管理不是最有趣的題目，但絕對是最值得花時間搞好的。花一個下午設定清楚，能省你好幾個失眠的夜晚。</p>
<p>更多細節可以查閱 <a href="https://pve.proxmox.com/wiki/Firewall">Proxmox 防火牆官方文件</a>、<a href="https://pve.proxmox.com/wiki/User_Management">PVE 使用者管理官方指南</a> 以及 <a href="https://pve.proxmox.com/pve-docs/pve-admin-guide.html#pveum_permission_management">PVE 管理手冊 - 權限章節</a>。</p>
<h2 id="常見問題">常見問題</h2>
<h3 id="q-pve-防火牆開啟後把自己鎖在外面怎麼辦">Q: PVE 防火牆開啟後把自己鎖在外面怎麼辦？</h3>
<p>直接到主機的實體 Console 或 IPMI 登入，編輯 <code>/etc/pve/firewall/cluster.fw</code> 把 <code>enable</code> 改為 0 暫時關閉防火牆，修好規則後再開回來。所以開啟前一定要先加好允許自己 IP 的規則。</p>
<h3 id="q-pve-的-rbac-權限可以限制到單台-vm-嗎">Q: PVE 的 RBAC 權限可以限制到單台 VM 嗎？</h3>
<p>可以。權限綁定路徑支援到 <code>/vms/{vmid}</code> 層級，也能用 <code>/pool/{poolname}</code> 批次管理。搭配群組和角色，可以精確控制每個使用者能操作哪些資源。</p>
<h3 id="q-proxmox-支援哪些-2fa-方式">Q: Proxmox 支援哪些 2FA 方式？</h3>
<p>支援 TOTP（如 Google Authenticator）、WebAuthn/FIDO2（如 YubiKey 硬體金鑰）和 Recovery Keys 備用碼。建議所有管理員帳號至少開啟 TOTP，搭配 Recovery Keys 做備援。</p>
<h3 id="q-pve-防火牆跟外部防火牆如-opnsense需要二選一嗎">Q: PVE 防火牆跟外部防火牆（如 OPNsense）需要二選一嗎？</h3>
<p>不用，兩者互補。外部防火牆管南北向流量（進出網路邊界），PVE 內建防火牆管東西向流量（VM 之間、節點之間），搭配使用能做到更細緻的微分段防護。</p>

<h2 id="防火牆三層洋蔥式防護">防火牆：三層洋蔥式防護</h2>
<p>PVE 的防火牆分三層，由外到內越來越細：</p>
<pre><code>┌──────────────────────────────────┐
│  Datacenter（整個叢集的通用規則）  │
├──────────────────────────────────┤
│  Host（每台節點自己的規則）        │
├──────────────────────────────────┤
│  VM/CT（每台虛擬機/容器的規則）    │
└──────────────────────────────────┘
</code></pre>
<p>規則處理順序也是這個方向：Datacenter 先看、Host 再看、VM/CT 最後看。沒有匹配到的流量？預設 <strong>DROP</strong>——不認識的一律不放行。</p>
<blockquote>
<p>超級重要：防火牆預設是<strong>關的</strong>。開啟之前，一定要先設好「允許你自己連進來」的規則，不然就是經典的「把自己鎖在門外」劇情。</p>
</blockquote>
<h3 id="設定叢集防火牆">設定叢集防火牆</h3>
<pre><code># /etc/pve/firewall/cluster.fw
[OPTIONS]
enable: 1
policy_in: DROP
policy_out: ACCEPT

[RULES]
IN ACCEPT -source 192.168.1.0/24 -p tcp -dport 8006  # Web GUI
IN ACCEPT -source 192.168.1.0/24 -p tcp -dport 22     # SSH
IN ACCEPT -p icmp                                       # Ping
</code></pre>
<h3 id="vm-層級防火牆">VM 層級防火牆</h3>
<pre><code># /etc/pve/firewall/&#x3C;vmid>.fw
[OPTIONS]
enable: 1
policy_in: DROP
policy_out: ACCEPT

[RULES]
GROUP web-server
IN ACCEPT -p tcp -dport 22 -source 10.0.0.0/8
</code></pre>

<h3 id="rbac-模型">RBAC 模型</h3>
<p>PVE 的權限模型就是經典的 RBAC（Role-Based Access Control）：</p>
<pre><code>使用者/群組 → 角色（Role） → 綁定到資源路徑（Path）
</code></pre>
<p>路徑長這樣：<code>/vms/100</code>（某台 VM）、<code>/storage/local-lvm</code>（某個儲存）、<code>/pool/dev</code>（某個資源池）。</p>

<h3 id="2fa-雙因素認證">2FA 雙因素認證</h3>
<p>所有管理員帳號都建議開 2FA。PVE 支援：</p>
<ul>
<li><strong>TOTP</strong>：Google Authenticator、Authy 那種六位數字</li>
<li><strong>WebAuthn/FIDO2</strong>：YubiKey 之類的硬體金鑰</li>
<li><strong>Recovery Keys</strong>：萬一手機掉了的救命繩</li>
</ul>
<p>設定路徑：Web GUI → Datacenter → Permissions → Two Factor</p>
<h2 id="安全黃金法則">安全黃金法則</h2>
<ol>
<li><strong>最小權限原則</strong>：給剛好夠用的權限，不要圖方便開 Administrator</li>
<li><strong>用群組管理</strong>：別一個一個使用者改權限，會改到懷疑人生</li>
<li><strong>API Token 取代密碼</strong>：腳本和自動化工具用 Token，設定期限、限制權限</li>
<li><strong>防火牆只開需要的埠</strong>：多開一個埠就多一個被攻擊的面</li>
<li><strong>定期檢查 ACL</strong>：人會離職、專案會結束，權限要跟著收回</li>
</ol>
<blockquote>
<p>弱密碼 + 管理介面對外 + root 帳號共用 = 資安事件倒數計時器。認真的。</p>
</blockquote>
<hr>
<p>防火牆跟權限管理不是最有趣的題目，但絕對是最值得花時間搞好的。花一個下午設定清楚，能省你好幾個失眠的夜晚。</p>

<h2 id="常見問題">常見問題</h2>
<h3 id="q-pve-防火牆開啟後把自己鎖在外面怎麼辦">Q: PVE 防火牆開啟後把自己鎖在外面怎麼辦？</h3>
<p>直接到主機的實體 Console 或 IPMI 登入，編輯 <code>/etc/pve/firewall/cluster.fw</code> 把 <code>enable</code> 改為 0 暫時關閉防火牆，修好規則後再開回來。所以開啟前一定要先加好允許自己 IP 的規則。</p>
<h3 id="q-pve-的-rbac-權限可以限制到單台-vm-嗎">Q: PVE 的 RBAC 權限可以限制到單台 VM 嗎？</h3>
<p>可以。權限綁定路徑支援到 <code>/vms/{vmid}</code> 層級，也能用 <code>/pool/{poolname}</code> 批次管理。搭配群組和角色，可以精確控制每個使用者能操作哪些資源。</p>
<h3 id="q-proxmox-支援哪些-2fa-方式">Q: Proxmox 支援哪些 2FA 方式？</h3>
<p>支援 TOTP（如 Google Authenticator）、WebAuthn/FIDO2（如 YubiKey 硬體金鑰）和 Recovery Keys 備用碼。建議所有管理員帳號至少開啟 TOTP，搭配 Recovery Keys 做備援。</p>
<h3 id="q-pve-防火牆跟外部防火牆如-opnsense需要二選一嗎">Q: PVE 防火牆跟外部防火牆（如 OPNsense）需要二選一嗎？</h3>
<p>不用，兩者互補。外部防火牆管南北向流量（進出網路邊界），PVE 內建防火牆管東西向流量（VM 之間、節點之間），搭配使用能做到更細緻的微分段防護。</p>
