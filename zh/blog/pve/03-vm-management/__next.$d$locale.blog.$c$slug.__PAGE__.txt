3:T411f,<p>建好第一台 VM 之後，你可能會覺得它跑起來「好像有點慢」。那是因為 PVE 的預設設定偏保守，就像買了一台新車卻一直用 Eco 模式在開——能動，但完全沒發揮實力。這篇教你怎麼把 VM 調到最佳狀態。</p>

<th>說明</th>

<td>Type</td>
<td><code>host</code></td>
<td>直通主機 CPU 指令集，效能最好</td>
</tr>
<tr>
<td>Cores</td>
<td>依需求</td>
<td>別給超過實體核心數（超賣可以，但慢）</td>

<td>競爭資源時的優先權重</td>

<td>模擬 NUMA 拓撲</td>
</tr>

<p>CPU Type 選 <code>host</code> 和選預設的 <code>kvm64</code> 差多少？<a href="https://www.storagereview.com/review/proxmox-ve-8-1-performance-tuning">StorageReview 的測試</a>顯示，光是換 CPU type 就能讓效能從裸機的 61% 跳到 85%。這是免費的效能，不拿白不拿。</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># 改 CPU 類型為 host（VM 需要先關機）</span></span>
<span data-line=""><span style="color:#B392F0">qm</span><span style="color:#9ECBFF"> set</span><span style="color:#79B8FF"> 100</span><span style="color:#79B8FF"> --cpu</span><span style="color:#9ECBFF"> host</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># 設定 2 核心</span></span>
<span data-line=""><span style="color:#B392F0">qm</span><span style="color:#9ECBFF"> set</span><span style="color:#79B8FF"> 100</span><span style="color:#79B8FF"> --cores</span><span style="color:#79B8FF"> 2</span></span></code></pre></figure>
<blockquote>
<p>如果你打算做 Live Migration（把 VM 搬到另一台 PVE 主機），CPU Type 選 <code>host</code> 會有相容性問題——兩台主機的 CPU 必須一樣。要遷移的 VM 建議選 <code>x86-64-v2-AES</code> 之類的通用類型。想了解叢集遷移的細節可以看<a href="08-cluster">叢集與高可用篇</a>。</p>
</blockquote>
<h2 id="記憶體ballooning-的藝術">記憶體：Ballooning 的藝術</h2>
<p>PVE 支援 Memory Ballooning——動態記憶體管理。你設一個最大值和最小值，VM 不需要那麼多記憶體的時候會自動歸還，需要的時候再拿回去。</p>
<p>聽起來很聰明，但實際上有時候會造成效能波動。我的建議是：</p>
<ul>
<li><strong>效能敏感的 VM</strong>：關掉 Ballooning，給固定記憶體</li>
<li><strong>一般用途的 VM</strong>：開 Ballooning，省記憶體給其他 VM 用</li>
</ul>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># 固定 4GB 記憶體（關閉 Ballooning）</span></span>
<span data-line=""><span style="color:#B392F0">qm</span><span style="color:#9ECBFF"> set</span><span style="color:#79B8FF"> 100</span><span style="color:#79B8FF"> --memory</span><span style="color:#79B8FF"> 4096</span><span style="color:#79B8FF"> --balloon</span><span style="color:#79B8FF"> 0</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># 動態記憶體：最小 1GB，最大 4GB</span></span>
<span data-line=""><span style="color:#B392F0">qm</span><span style="color:#9ECBFF"> set</span><span style="color:#79B8FF"> 100</span><span style="color:#79B8FF"> --memory</span><span style="color:#79B8FF"> 4096</span><span style="color:#79B8FF"> --balloon</span><span style="color:#79B8FF"> 1024</span></span></code></pre></figure>

<p>再加上一個容易忽略的設定：<strong>IO Thread</strong>。開了之後磁碟 I/O 有獨立的執行緒處理，不會卡住 VM 的主 CPU。</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># 啟用 IO Thread（需要先用 VirtIO-SCSI 控制器）</span></span>
<span data-line=""><span style="color:#B392F0">qm</span><span style="color:#9ECBFF"> set</span><span style="color:#79B8FF"> 100</span><span style="color:#79B8FF"> --scsihw</span><span style="color:#9ECBFF"> virtio-scsi-single</span></span>
<span data-line=""><span style="color:#B392F0">qm</span><span style="color:#9ECBFF"> set</span><span style="color:#79B8FF"> 100</span><span style="color:#79B8FF"> --scsi0</span><span style="color:#9ECBFF"> local-lvm:32,iothread=1,discard=on,ssd=</span><span style="color:#79B8FF">1</span></span></code></pre></figure>
<blockquote>
<p><code>discard=on</code> 和 <code>ssd=1</code> 是給 SSD 用的，讓 VM 內部的 TRIM 指令能穿透到實體磁碟。如果你的儲存後端是 HDD，這兩個不用開。更多儲存後端的選擇請看<a href="05-storage">儲存系統指南</a>。</p>
</blockquote>

<h2 id="vm-範本批量生產的秘密武器">VM 範本：批量生產的秘密武器</h2>
<p>如果你需要重複建立類似的 VM（例如測試環境），每次從 ISO 重新安裝太浪費時間。範本的概念就像做餅乾的模具——做好一個模型，之後壓出來的每一塊都一樣。</p>
<p>製作範本的標準流程：</p>
<ol>
<li>建一台 VM，裝好 OS</li>
<li>做好基本設定（更新、裝常用套件）</li>
<li>安裝 QEMU Guest Agent</li>
<li>清理暫存（<code>apt clean</code>、刪 bash history）</li>
<li>轉換成範本</li>
</ol>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># 在 VM 裡面裝 Guest Agent</span></span>
<span data-line=""><span style="color:#B392F0">apt</span><span style="color:#9ECBFF"> install</span><span style="color:#79B8FF"> -y</span><span style="color:#9ECBFF"> qemu-guest-agent</span></span>
<span data-line=""><span style="color:#B392F0">systemctl</span><span style="color:#9ECBFF"> enable</span><span style="color:#9ECBFF"> qemu-guest-agent</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># 清理後關機</span></span>
<span data-line=""><span style="color:#B392F0">apt</span><span style="color:#9ECBFF"> clean</span><span style="color:#E1E4E8"> &#x26;&#x26; </span><span style="color:#B392F0">rm</span><span style="color:#79B8FF"> -f</span><span style="color:#9ECBFF"> ~/.bash_history</span><span style="color:#E1E4E8"> &#x26;&#x26; </span><span style="color:#B392F0">poweroff</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># 在 PVE 主機上把 VM 轉成範本</span></span>
<span data-line=""><span style="color:#B392F0">qm</span><span style="color:#9ECBFF"> template</span><span style="color:#79B8FF"> 100</span></span></code></pre></figure>
<p>轉成範本之後，這台 VM 就變成唯讀的了。要用它的時候，右鍵 -> Clone，選 Linked Clone 幾秒鐘就能生出一台新的。</p>
<h2 id="qemu-guest-agent裝了就對了">QEMU Guest Agent：裝了就對了</h2>
<p><a href="https://pve.proxmox.com/wiki/Qemu-guest-agent">Guest Agent</a> 是裝在 VM 裡面的小程式，讓 PVE 能跟 VM 內部溝通。裝了之後你能：</p>
<ul>
<li>在 Web 介面直接看到 VM 的 IP（不用自己去查）</li>
<li>拍快照時自動凍結檔案系統（資料一致性）</li>
<li>優雅關機真的能優雅關（不然有時候 VM 裝聾作啞）</li>
</ul>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># Linux</span></span>
<span data-line=""><span style="color:#B392F0">apt</span><span style="color:#9ECBFF"> install</span><span style="color:#79B8FF"> -y</span><span style="color:#9ECBFF"> qemu-guest-agent</span></span>
<span data-line=""><span style="color:#B392F0">systemctl</span><span style="color:#9ECBFF"> enable</span><span style="color:#79B8FF"> --now</span><span style="color:#9ECBFF"> qemu-guest-agent</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># 然後在 PVE 的 VM Options 裡勾選 "QEMU Guest Agent"</span></span></code></pre></figure>
<blockquote>
<p>Windows VM 的話，Guest Agent 隨 <a href="https://fedorapeople.org/groups/virt/virtio-win/direct-downloads/stable-virtio/virtio-win.iso">VirtIO 驅動 ISO</a> 一起安裝。裝 VirtIO 驅動的時候順便裝 Guest Agent，一箭雙鵰。</p>
</blockquote>
<h2 id="效能調校速查">效能調校速查</h2>
<p>做完以下這些，你的 VM 效能會從「堪用」變成「接近裸機」：</p>
<ol>
<li>CPU Type 改 <code>host</code></li>
<li>磁碟用 VirtIO-SCSI + IO Thread</li>
<li>網卡用 VirtIO</li>
<li>安裝 QEMU Guest Agent</li>
<li>SSD 後端開 <code>discard=on,ssd=1</code></li>
<li>記憶體充足的話關掉 Ballooning</li>
</ol>
<p>這六步不用花錢，不用加硬體，純軟體設定就能讓效能提升 30% 以上。</p>
<h2 id="常見問題">常見問題</h2>
<h3 id="q-pve-的-vm-效能跟裸機差多少">Q: PVE 的 VM 效能跟裸機差多少？</h3>
<p>經過正確調校（CPU Type 設 host、磁碟用 VirtIO-SCSI + IO Thread、安裝 Guest Agent），VM 效能可達裸機的 85-95%。預設設定通常只有 60% 左右，所以調校非常重要。</p>
<h3 id="q-vm-快照和備份有什麼差別">Q: VM 快照和備份有什麼差別？</h3>
<p>快照是秒級的即時狀態保存，適合改設定前拍一張當保險；備份是把整台 VM 匯出到外部儲存，適合災難復原。快照不能取代備份，建議兩者搭配使用。</p>
<h3 id="q-qemu-guest-agent-一定要裝嗎">Q: QEMU Guest Agent 一定要裝嗎？</h3>
<p>強烈建議裝。沒裝的話 PVE 看不到 VM 的 IP、快照時檔案系統不會凍結（可能資料不一致）、優雅關機也可能失敗。裝了只有好處，沒有副作用。</p>
<h3 id="q-vm-範本是什麼什麼時候該用">Q: VM 範本是什麼？什麼時候該用？</h3>
<p>範本是唯讀的 VM 基底映像，當你需要重複建立類似配置的 VM 時特別好用。做好一個範本後，用 Linked Clone 幾秒就能生出新 VM，不用每次都從 ISO 重新安裝。</p>

9:T411f,<p>建好第一台 VM 之後，你可能會覺得它跑起來「好像有點慢」。那是因為 PVE 的預設設定偏保守，就像買了一台新車卻一直用 Eco 模式在開——能動，但完全沒發揮實力。這篇教你怎麼把 VM 調到最佳狀態。</p>
<h2 id="cpu-設定不只是給幾核">CPU 設定：不只是「給幾核」</h2>
<table>
<thead>
<tr>
<th>設定</th>
<th>建議值</th>
<th>說明</th>
</tr>
</thead>
<tbody>
<tr>
<td>Type</td>
<td><code>host</code></td>
<td>直通主機 CPU 指令集，效能最好</td>
</tr>
<tr>
<td>Cores</td>
<td>依需求</td>
<td>別給超過實體核心數（超賣可以，但慢）</td>
</tr>
<tr>
<td>CPU Units</td>
<td>1024（預設）</td>
<td>競爭資源時的優先權重</td>
</tr>
<tr>
<td>NUMA</td>
<td>多 socket 才需開</td>
<td>模擬 NUMA 拓撲</td>
</tr>
</tbody>
</table>
<p>CPU Type 選 <code>host</code> 和選預設的 <code>kvm64</code> 差多少？<a href="https://www.storagereview.com/review/proxmox-ve-8-1-performance-tuning">StorageReview 的測試</a>顯示，光是換 CPU type 就能讓效能從裸機的 61% 跳到 85%。這是免費的效能，不拿白不拿。</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># 改 CPU 類型為 host（VM 需要先關機）</span></span>
<span data-line=""><span style="color:#B392F0">qm</span><span style="color:#9ECBFF"> set</span><span style="color:#79B8FF"> 100</span><span style="color:#79B8FF"> --cpu</span><span style="color:#9ECBFF"> host</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># 設定 2 核心</span></span>
<span data-line=""><span style="color:#B392F0">qm</span><span style="color:#9ECBFF"> set</span><span style="color:#79B8FF"> 100</span><span style="color:#79B8FF"> --cores</span><span style="color:#79B8FF"> 2</span></span></code></pre></figure>
<blockquote>
<p>如果你打算做 Live Migration（把 VM 搬到另一台 PVE 主機），CPU Type 選 <code>host</code> 會有相容性問題——兩台主機的 CPU 必須一樣。要遷移的 VM 建議選 <code>x86-64-v2-AES</code> 之類的通用類型。想了解叢集遷移的細節可以看<a href="08-cluster">叢集與高可用篇</a>。</p>
</blockquote>
<h2 id="記憶體ballooning-的藝術">記憶體：Ballooning 的藝術</h2>
<p>PVE 支援 Memory Ballooning——動態記憶體管理。你設一個最大值和最小值，VM 不需要那麼多記憶體的時候會自動歸還，需要的時候再拿回去。</p>
<p>聽起來很聰明，但實際上有時候會造成效能波動。我的建議是：</p>
<ul>
<li><strong>效能敏感的 VM</strong>：關掉 Ballooning，給固定記憶體</li>
<li><strong>一般用途的 VM</strong>：開 Ballooning，省記憶體給其他 VM 用</li>
</ul>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># 固定 4GB 記憶體（關閉 Ballooning）</span></span>
<span data-line=""><span style="color:#B392F0">qm</span><span style="color:#9ECBFF"> set</span><span style="color:#79B8FF"> 100</span><span style="color:#79B8FF"> --memory</span><span style="color:#79B8FF"> 4096</span><span style="color:#79B8FF"> --balloon</span><span style="color:#79B8FF"> 0</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># 動態記憶體：最小 1GB，最大 4GB</span></span>
<span data-line=""><span style="color:#B392F0">qm</span><span style="color:#9ECBFF"> set</span><span style="color:#79B8FF"> 100</span><span style="color:#79B8FF"> --memory</span><span style="color:#79B8FF"> 4096</span><span style="color:#79B8FF"> --balloon</span><span style="color:#79B8FF"> 1024</span></span></code></pre></figure>

</tr>

<td>很好</td>

<p>再加上一個容易忽略的設定：<strong>IO Thread</strong>。開了之後磁碟 I/O 有獨立的執行緒處理，不會卡住 VM 的主 CPU。</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># 啟用 IO Thread（需要先用 VirtIO-SCSI 控制器）</span></span>
<span data-line=""><span style="color:#B392F0">qm</span><span style="color:#9ECBFF"> set</span><span style="color:#79B8FF"> 100</span><span style="color:#79B8FF"> --scsihw</span><span style="color:#9ECBFF"> virtio-scsi-single</span></span>
<span data-line=""><span style="color:#B392F0">qm</span><span style="color:#9ECBFF"> set</span><span style="color:#79B8FF"> 100</span><span style="color:#79B8FF"> --scsi0</span><span style="color:#9ECBFF"> local-lvm:32,iothread=1,discard=on,ssd=</span><span style="color:#79B8FF">1</span></span></code></pre></figure>
<blockquote>
<p><code>discard=on</code> 和 <code>ssd=1</code> 是給 SSD 用的，讓 VM 內部的 TRIM 指令能穿透到實體磁碟。如果你的儲存後端是 HDD，這兩個不用開。更多儲存後端的選擇請看<a href="05-storage">儲存系統指南</a>。</p>
</blockquote>

<h2 id="vm-範本批量生產的秘密武器">VM 範本：批量生產的秘密武器</h2>
<p>如果你需要重複建立類似的 VM（例如測試環境），每次從 ISO 重新安裝太浪費時間。範本的概念就像做餅乾的模具——做好一個模型，之後壓出來的每一塊都一樣。</p>
<p>製作範本的標準流程：</p>
<ol>
<li>建一台 VM，裝好 OS</li>
<li>做好基本設定（更新、裝常用套件）</li>
<li>安裝 QEMU Guest Agent</li>
<li>清理暫存（<code>apt clean</code>、刪 bash history）</li>
<li>轉換成範本</li>
</ol>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># 在 VM 裡面裝 Guest Agent</span></span>
<span data-line=""><span style="color:#B392F0">apt</span><span style="color:#9ECBFF"> install</span><span style="color:#79B8FF"> -y</span><span style="color:#9ECBFF"> qemu-guest-agent</span></span>
<span data-line=""><span style="color:#B392F0">systemctl</span><span style="color:#9ECBFF"> enable</span><span style="color:#9ECBFF"> qemu-guest-agent</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># 清理後關機</span></span>
<span data-line=""><span style="color:#B392F0">apt</span><span style="color:#9ECBFF"> clean</span><span style="color:#E1E4E8"> &#x26;&#x26; </span><span style="color:#B392F0">rm</span><span style="color:#79B8FF"> -f</span><span style="color:#9ECBFF"> ~/.bash_history</span><span style="color:#E1E4E8"> &#x26;&#x26; </span><span style="color:#B392F0">poweroff</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># 在 PVE 主機上把 VM 轉成範本</span></span>
<span data-line=""><span style="color:#B392F0">qm</span><span style="color:#9ECBFF"> template</span><span style="color:#79B8FF"> 100</span></span></code></pre></figure>
<p>轉成範本之後，這台 VM 就變成唯讀的了。要用它的時候，右鍵 -> Clone，選 Linked Clone 幾秒鐘就能生出一台新的。</p>
<h2 id="qemu-guest-agent裝了就對了">QEMU Guest Agent：裝了就對了</h2>
<p><a href="https://pve.proxmox.com/wiki/Qemu-guest-agent">Guest Agent</a> 是裝在 VM 裡面的小程式，讓 PVE 能跟 VM 內部溝通。裝了之後你能：</p>
<ul>
<li>在 Web 介面直接看到 VM 的 IP（不用自己去查）</li>
<li>拍快照時自動凍結檔案系統（資料一致性）</li>
<li>優雅關機真的能優雅關（不然有時候 VM 裝聾作啞）</li>
</ul>

<h2 id="效能調校速查">效能調校速查</h2>
<p>做完以下這些，你的 VM 效能會從「堪用」變成「接近裸機」：</p>
<ol>
<li>CPU Type 改 <code>host</code></li>
<li>磁碟用 VirtIO-SCSI + IO Thread</li>
<li>網卡用 VirtIO</li>
<li>安裝 QEMU Guest Agent</li>
<li>SSD 後端開 <code>discard=on,ssd=1</code></li>
<li>記憶體充足的話關掉 Ballooning</li>
</ol>
<p>這六步不用花錢，不用加硬體，純軟體設定就能讓效能提升 30% 以上。</p>
<h2 id="常見問題">常見問題</h2>
<h3 id="q-pve-的-vm-效能跟裸機差多少">Q: PVE 的 VM 效能跟裸機差多少？</h3>
<p>經過正確調校（CPU Type 設 host、磁碟用 VirtIO-SCSI + IO Thread、安裝 Guest Agent），VM 效能可達裸機的 85-95%。預設設定通常只有 60% 左右，所以調校非常重要。</p>
<h3 id="q-vm-快照和備份有什麼差別">Q: VM 快照和備份有什麼差別？</h3>
<p>快照是秒級的即時狀態保存，適合改設定前拍一張當保險；備份是把整台 VM 匯出到外部儲存，適合災難復原。快照不能取代備份，建議兩者搭配使用。</p>
<h3 id="q-qemu-guest-agent-一定要裝嗎">Q: QEMU Guest Agent 一定要裝嗎？</h3>
<p>強烈建議裝。沒裝的話 PVE 看不到 VM 的 IP、快照時檔案系統不會凍結（可能資料不一致）、優雅關機也可能失敗。裝了只有好處，沒有副作用。</p>
<h3 id="q-vm-範本是什麼什麼時候該用">Q: VM 範本是什麼？什麼時候該用？</h3>
<p>範本是唯讀的 VM 基底映像，當你需要重複建立類似配置的 VM 時特別好用。做好一個範本後，用 Linked Clone 幾秒就能生出新 VM，不用每次都從 ISO 重新安裝。</p>
