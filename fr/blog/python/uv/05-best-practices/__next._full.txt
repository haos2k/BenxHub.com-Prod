1b:T1600,<p>En pratique, les environnements cassent souvent non pas parce que « uv n'est pas assez puissant », mais à cause du <strong>processus et des habitudes</strong>. Cette checklist peut servir de guide au quotidien — chaque piège évité, c'est une fois de plus où vous partez à l'heure.</p>
<h2 id="pratiques-recommandées">Pratiques recommandées</h2>
<h3 id="1-toujours-versionner-uvlock">1) Toujours versionner uv.lock</h3>
<p>Le lockfile est la base de la reproductibilité. Ne pas le versionner, c'est laisser chaque personne, chaque machine, chaque run CI installer un arbre différent — reproduire un bug devient l'enfer. Un projet sans lockfile, c'est comme des chaussures jamais essayées : vous découvrez qu'elles font mal en plein combat.</p>
<h3 id="2-ne-jamais-versionner-venv">2) Ne jamais versionner .venv</h3>
<p>L'environnement virtuel est un artefact local — il doit être dans <code>.gitignore</code>. uv ajoute automatiquement <code>.venv</code> au fichier d'ignore du projet ; vérifiez juste qu'il y est.</p>
<h3 id="3-contraintez-les-dépendances-quand-cest-possible">3) Contraintez les dépendances quand c'est possible</h3>
<p>Dans <code>pyproject.toml</code>, évitez un simple <code>requests</code> — préférez <code>requests>=2.31,&#x3C;3</code> ou plus précis. <code>uv add</code> ajoute des contraintes raisonnables par défaut ; en édition manuelle, ne laissez pas la plage trop large.</p>
<h3 id="4-utilisez-uv-sync-ou-uv-pip-sync-en-ci">4) Utilisez uv sync ou uv pip sync en CI</h3>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="yaml" data-theme="github-dark"><code data-language="yaml" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># Exemple GitHub Actions</span></span>
<span data-line=""><span style="color:#E1E4E8">- </span><span style="color:#85E89D">run</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">uv sync</span></span>
<span data-line=""><span style="color:#E1E4E8">- </span><span style="color:#85E89D">run</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">uv run pytest</span></span></code></pre></figure>
<p>Sync d'abord, puis exécution — l'environnement reste aligné sur le lockfile. Ne lancez pas <code>uv add</code> en CI ; ça modifie le lockfile et peut créer des diffs inattendus.</p>
<h3 id="5-mettez-les-outils-de-dev-en-optional--dev">5) Mettez les outils de dev en optional / dev</h3>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">uv</span><span style="color:#9ECBFF"> add</span><span style="color:#79B8FF"> --dev</span><span style="color:#9ECBFF"> pytest</span><span style="color:#9ECBFF"> ruff</span><span style="color:#9ECBFF"> mypy</span></span></code></pre></figure>
<p>Tests, lint et typage n'impactent pas les dépendances de prod et ne sont pas emballés dans la wheel. Les images de prod n'ont besoin que de <code>uv sync --no-dev</code>.</p>
<h2 id="pièges-courants">Pièges courants</h2>
<h3 id="piège-1--mélanger-pip-et-uv-add">Piège 1 : Mélanger pip et uv add</h3>
<p>N'utilisez pas à la fois <code>pip install</code> et <code>uv add</code> dans le même venv — le lockfile se désynchronise. Choisissez une voie et tenez-vous-y.</p>
<h3 id="piège-2--utiliser-uvx-pour-les-outils-du-projet">Piège 2 : Utiliser uvx pour les outils du projet</h3>
<p>Outils du projet avec version fixée (pytest, mypy) → utilisez <code>uv add --dev</code> + <code>uv run</code>.
Usage ponctuel temporaire → utilisez <code>uvx</code>.</p>
<h3 id="piège-3--éditer-pyprojecttoml-à-la-main-sans-le-relire">Piège 3 : Éditer pyproject.toml à la main sans le relire</h3>
<p>Pour les changements de dépendances, préférez <code>uv add</code> / <code>uv remove</code> — évite les soucis de format et les oublis de mise à jour du lockfile.</p>
<h3 id="piège-4--ne-pas-installer-uv-en-ci">Piège 4 : Ne pas installer uv en CI</h3>
<p>Beaucoup de CI supportent uv — installation rapide, exécution encore plus rapide. Utilisez l'installateur officiel ou <code>pip install uv</code> ; ne restez pas indéfiniment sur pip pour la résolution.</p>
<h3 id="piège-5--pas-de-requires-python-dans-le-projet">Piège 5 : Pas de requires-python dans le projet</h3>
<p>Dans <code>pyproject.toml</code>, indiquez <code>requires-python = ">=3.12"</code> etc., pour que les outils et collaborateurs connaissent la version minimale. Évite le « ça tourne en 3.12 chez moi, ça plante en 3.8 chez toi ».</p>
<hr>
<p>Suivre cette checklist ne garantit pas zéro panne, mais vous éviterez bien des détours inutiles. En cas de doute, consultez la doc officielle — la plupart des pièges ont déjà été rencontrés.
Bon dev — que vos dépendances s'installent proprement, les tests restent verts et la CI arrête de vous faire attendre ! 🦦
(Et après avoir utilisé uv, vous réaliserez : le temps que vous passiez à regarder le spinner de pip suffit maintenant à caresser le chat trois fois.)</p>

<p>Pour les changements de dépendances, préférez <code>uv add</code> / <code>uv remove</code> — évite les soucis de format et les oublis de mise à jour du lockfile.</p>
<h3 id="piège-4--ne-pas-installer-uv-en-ci">Piège 4 : Ne pas installer uv en CI</h3>
<p>Beaucoup de CI supportent uv — installation rapide, exécution encore plus rapide. Utilisez l'installateur officiel ou <code>pip install uv</code> ; ne restez pas indéfiniment sur pip pour la résolution.</p>
<h3 id="piège-5--pas-de-requires-python-dans-le-projet">Piège 5 : Pas de requires-python dans le projet</h3>
<p>Dans <code>pyproject.toml</code>, indiquez <code>requires-python = ">=3.12"</code> etc., pour que les outils et collaborateurs connaissent la version minimale. Évite le « ça tourne en 3.12 chez moi, ça plante en 3.8 chez toi ».</p>
<hr>
<p>Suivre cette checklist ne garantit pas zéro panne, mais vous éviterez bien des détours inutiles. En cas de doute, consultez la doc officielle — la plupart des pièges ont déjà été rencontrés.
Bon dev — que vos dépendances s'installent proprement, les tests restent verts et la CI arrête de vous faire attendre ! 🦦
(Et après avoir utilisé uv, vous réaliserez : le temps que vous passiez à regarder le spinner de pip suffit maintenant à caresser le chat trois fois.)</p>
