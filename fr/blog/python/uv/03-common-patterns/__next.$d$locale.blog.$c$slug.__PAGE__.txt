<h2 id="modèle-1--ajouter-et-retirer-des-dépendances">Modèle 1 : Ajouter et retirer des dépendances</h2>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E"># Ajouter une dépendance</span></span>
<span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> add</span><span style="color:#A5D6FF"> requests</span></span>
<span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> add</span><span style="color:#A5D6FF"> "requests>=2.31,&#x3C;3"</span><span style="color:#8B949E">   # avec contraintes de version</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#8B949E"># Dépendances de dev (tests, lint, typage)</span></span>
<span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> add</span><span style="color:#79C0FF"> --dev</span><span style="color:#A5D6FF"> pytest</span><span style="color:#A5D6FF"> ruff</span><span style="color:#A5D6FF"> mypy</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#8B949E"># Retirer</span></span>
<span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> remove</span><span style="color:#A5D6FF"> requests</span></span></code></pre></figure>
<p><code>uv add</code> met à jour en même temps <code>pyproject.toml</code>, <code>uv.lock</code> et <code>.venv</code> — une seule commande suffit.</p>
<h2 id="modèle-2--uv-run-pour-exécuter-les-commandes-du-projet">Modèle 2 : uv run pour exécuter les commandes du projet</h2>
<p>Pour les scripts, CLI et tests du projet, utilisez toujours <code>uv run</code> :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> run</span><span style="color:#A5D6FF"> python</span><span style="color:#A5D6FF"> main.py</span></span>
<span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> run</span><span style="color:#A5D6FF"> pytest</span></span>
<span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> run</span><span style="color:#A5D6FF"> ruff</span><span style="color:#A5D6FF"> check</span><span style="color:#A5D6FF"> .</span></span>
<span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> run</span><span style="color:#A5D6FF"> mypy</span><span style="color:#A5D6FF"> src/</span></span></code></pre></figure>
<p>Pas d'activation, pas de risque de mauvais Python.</p>
<h2 id="modèle-3--uvx-pour-lancer-des-outils-cli-autonomes">Modèle 3 : uvx pour lancer des outils CLI autonomes</h2>
<p>Vous voulez lancer un outil temporairement sans l'ajouter au projet ? Utilisez <code>uvx</code> (équivalent à <code>uv tool run</code>) :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E"># À la demande, jetable</span></span>
<span data-line=""><span style="color:#FFA657">uvx</span><span style="color:#A5D6FF"> ruff</span><span style="color:#A5D6FF"> check</span><span style="color:#A5D6FF"> .</span></span>
<span data-line=""><span style="color:#FFA657">uvx</span><span style="color:#A5D6FF"> pycowsay</span><span style="color:#A5D6FF"> "hello uv"</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#8B949E"># Fixer une version</span></span>
<span data-line=""><span style="color:#FFA657">uvx</span><span style="color:#A5D6FF"> ruff@0.5.0</span><span style="color:#A5D6FF"> check</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#8B949E"># Quand le nom du paquet et la commande diffèrent</span></span>
<span data-line=""><span style="color:#FFA657">uvx</span><span style="color:#79C0FF"> --from</span><span style="color:#A5D6FF"> httpie</span><span style="color:#A5D6FF"> http</span><span style="color:#A5D6FF"> https://httpbin.org/get</span></span></code></pre></figure>
<p>uvx crée un environnement temporaire pour exécuter l'outil sans polluer le projet — comme goûter sans acheter le paquet. Idéal pour les « je veux juste essayer ».</p>
<h2 id="modèle-4--dépendances-inline-pour-scripts-pep-723">Modèle 4 : Dépendances inline pour scripts (PEP 723)</h2>
<p>Un seul script, pas envie de créer un projet ? Utilisez les métadonnées inline :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="python" data-theme="github-dark-default"><code data-language="python" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E"># /// script</span></span>
<span data-line=""><span style="color:#8B949E"># dependencies = ["requests", "rich"]</span></span>
<span data-line=""><span style="color:#8B949E"># ///</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#FF7B72">import</span><span style="color:#E6EDF3"> requests</span></span>
<span data-line=""><span style="color:#FF7B72">from</span><span style="color:#E6EDF3"> rich.pretty </span><span style="color:#FF7B72">import</span><span style="color:#E6EDF3"> pprint</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#E6EDF3">r </span><span style="color:#FF7B72">=</span><span style="color:#E6EDF3"> requests.get(</span><span style="color:#A5D6FF">"https://api.github.com/zen"</span><span style="color:#E6EDF3">)</span></span>
<span data-line=""><span style="color:#E6EDF3">pprint(r.text)</span></span></code></pre></figure>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> add</span><span style="color:#79C0FF"> --script</span><span style="color:#A5D6FF"> fetch.py</span><span style="color:#A5D6FF"> requests</span><span style="color:#A5D6FF"> rich</span></span>
<span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> run</span><span style="color:#A5D6FF"> fetch.py</span></span></code></pre></figure>
<p>Ou en une ligne :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> run</span><span style="color:#79C0FF"> --with</span><span style="color:#A5D6FF"> requests</span><span style="color:#79C0FF"> --with</span><span style="color:#A5D6FF"> rich</span><span style="color:#A5D6FF"> fetch.py</span></span></code></pre></figure>
<h2 id="modèle-5--migrer-depuis-requirementstxt">Modèle 5 : Migrer depuis requirements.txt</h2>
<p>Un projet existant avec un <code>requirements.txt</code> ? Intégrez-le directement :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> add</span><span style="color:#79C0FF"> -r</span><span style="color:#A5D6FF"> requirements.txt</span></span></code></pre></figure>
<p>Ou compiler vers un lockfile puis synchroniser :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> pip</span><span style="color:#A5D6FF"> compile</span><span style="color:#A5D6FF"> requirements.in</span><span style="color:#79C0FF"> -o</span><span style="color:#A5D6FF"> requirements.txt</span></span>
<span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> pip</span><span style="color:#A5D6FF"> sync</span><span style="color:#A5D6FF"> requirements.txt</span></span></code></pre></figure>
<p>Après migration, considérez <code>pyproject.toml</code> comme la source de vérité — <code>requirements.txt</code> peut servir de format d'export.</p>

<h2 id="modèle-5--migrer-depuis-requirementstxt">Modèle 5 : Migrer depuis requirements.txt</h2>
<p>Un projet existant avec un <code>requirements.txt</code> ? Intégrez-le directement :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> add</span><span style="color:#79C0FF"> -r</span><span style="color:#A5D6FF"> requirements.txt</span></span></code></pre></figure>
<p>Ou compiler vers un lockfile puis synchroniser :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> pip</span><span style="color:#A5D6FF"> compile</span><span style="color:#A5D6FF"> requirements.in</span><span style="color:#79C0FF"> -o</span><span style="color:#A5D6FF"> requirements.txt</span></span>
<span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> pip</span><span style="color:#A5D6FF"> sync</span><span style="color:#A5D6FF"> requirements.txt</span></span></code></pre></figure>
<p>Après migration, considérez <code>pyproject.toml</code> comme la source de vérité — <code>requirements.txt</code> peut servir de format d'export.</p>
