1b:T184c,<p>Avant de taper des commandes au hasard, intégrez ces quatre concepts : vous y verrez plus clair sur « où vont les dépendances, à quoi sert le lockfile, quand le venv est créé ». Comme lire les descriptions des compétences avant de jouer — sinon vous mourrez sans comprendre pourquoi.</p>
<h2 id="concept-1--pyprojecttoml-est-la-carte-didentité-du-projet">Concept 1 : pyproject.toml est la carte d'identité du projet</h2>
<p>Les métadonnées du projet et les dépendances vivent ici — c'est le format standard PEP 518.</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="toml" data-theme="github-dark-default"><code data-language="toml" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#E6EDF3">[</span><span style="color:#FFA657">project</span><span style="color:#E6EDF3">]</span></span>
<span data-line=""><span style="color:#E6EDF3">name = </span><span style="color:#A5D6FF">"my-app"</span></span>
<span data-line=""><span style="color:#E6EDF3">version = </span><span style="color:#A5D6FF">"0.1.0"</span></span>
<span data-line=""><span style="color:#E6EDF3">requires-python = </span><span style="color:#A5D6FF">">=3.12"</span></span>
<span data-line=""><span style="color:#E6EDF3">dependencies = [</span></span>
<span data-line=""><span style="color:#A5D6FF">    "requests>=2.31"</span><span style="color:#E6EDF3">,</span></span>
<span data-line=""><span style="color:#E6EDF3">]</span></span></code></pre></figure>
<ul>
<li><strong>Édition manuelle</strong> : modifiez <code>pyproject.toml</code> directement</li>
<li><strong>Piloté par commandes</strong> : <code>uv add requests</code> et <code>uv remove requests</code> le mettent à jour automatiquement</li>
</ul>
<blockquote>
<p>Ne mélangez pas les deux — soit vous éditez à la main, soit vous utilisez les commandes. Les deux en même temps créent des conflits.</p>
</blockquote>
<h2 id="concept-2--uvlock-est-un-instantané-des-dépendances">Concept 2 : uv.lock est un instantané des dépendances</h2>
<p><code>pyproject.toml</code> dit « ce que je veux » (ex. <code>requests>=2.31</code>). <code>uv.lock</code> enregistre « ce qui a réellement été installé » — jusqu'à chaque dépendance transitive.</p>
<ul>
<li><strong>Pourquoi un lockfile ?</strong> Garantir que tout le monde — équipe, CI, prod — installe exactement le même arbre de dépendances. Fini le « ça marche chez moi, ça casse chez toi ».</li>
<li><strong>Faut-il le versionner ?</strong> Oui. <code>uv.lock</code> doit être dans le contrôle de version pour que l'équipe et la CI utilisent le même arbre.</li>
</ul>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E"># Mettre à jour le lockfile (ex. mettre à niveau un paquet)</span></span>
<span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> lock</span><span style="color:#79C0FF"> --upgrade-package</span><span style="color:#A5D6FF"> requests</span></span></code></pre></figure>
<h2 id="concept-3--venv-est-le-bac-à-sable-du-projet">Concept 3 : .venv est le bac à sable du projet</h2>
<p>uv crée <code>.venv</code> à la racine du projet — tous les paquets de <code>uv add</code> vont dedans, isolés du Python système.</p>
<ul>
<li><strong>Faut-il l'activer à la main ?</strong> Non. <code>uv run</code> utilise automatiquement cet environnement.</li>
<li><strong>Faut-il le versionner ?</strong> Non. <code>.venv</code> doit être dans <code>.gitignore</code>.</li>
</ul>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E"># Synchroniser manuellement l'environnement (ex. après un clone)</span></span>
<span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> sync</span></span>
<span data-line=""><span style="color:#79C0FF">source</span><span style="color:#A5D6FF"> .venv/bin/activate</span><span style="color:#8B949E">  # après ça vous pouvez utiliser python, pytest, etc. directement</span></span></code></pre></figure>
<h2 id="concept-4--uv-run-est-le-point-dentrée-sans-effort">Concept 4 : uv run est le point d'entrée sans effort</h2>
<p><code>uv run</code> va :</p>
<ol>
<li>Vérifier que le lockfile est cohérent avec pyproject.toml</li>
<li>S'assurer que .venv est synchronisé avec le lockfile</li>
<li>Exécuter la commande demandée dans le bon environnement</li>
</ol>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> run</span><span style="color:#A5D6FF"> python</span><span style="color:#A5D6FF"> main.py</span></span>
<span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> run</span><span style="color:#A5D6FF"> pytest</span></span>
<span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> run</span><span style="color:#A5D6FF"> flask</span><span style="color:#A5D6FF"> run</span><span style="color:#79C0FF"> -p</span><span style="color:#79C0FF"> 3000</span></span></code></pre></figure>
<p>Pas besoin de penser à activer, pas de risque de mauvais environnement — confiez tout à uv. Comme un chat qui trouve la litière sans y penser. Une fois que vous avez goûté à ce « lance et ça tourne », on ne revient pas en arrière.</p>

<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E"># Synchroniser manuellement l'environnement (ex. après un clone)</span></span>
<span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> sync</span></span>
<span data-line=""><span style="color:#79C0FF">source</span><span style="color:#A5D6FF"> .venv/bin/activate</span><span style="color:#8B949E">  # après ça vous pouvez utiliser python, pytest, etc. directement</span></span></code></pre></figure>
<h2 id="concept-4--uv-run-est-le-point-dentrée-sans-effort">Concept 4 : uv run est le point d'entrée sans effort</h2>
<p><code>uv run</code> va :</p>
<ol>
<li>Vérifier que le lockfile est cohérent avec pyproject.toml</li>
<li>S'assurer que .venv est synchronisé avec le lockfile</li>
<li>Exécuter la commande demandée dans le bon environnement</li>
</ol>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> run</span><span style="color:#A5D6FF"> python</span><span style="color:#A5D6FF"> main.py</span></span>
<span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> run</span><span style="color:#A5D6FF"> pytest</span></span>
<span data-line=""><span style="color:#FFA657">uv</span><span style="color:#A5D6FF"> run</span><span style="color:#A5D6FF"> flask</span><span style="color:#A5D6FF"> run</span><span style="color:#79C0FF"> -p</span><span style="color:#79C0FF"> 3000</span></span></code></pre></figure>
<p>Pas besoin de penser à activer, pas de risque de mauvais environnement — confiez tout à uv. Comme un chat qui trouve la litière sans y penser. Une fois que vous avez goûté à ce « lance et ça tourne », on ne revient pas en arrière.</p>
