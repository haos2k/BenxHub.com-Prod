1b:T33a8,<p>Le but de cet article est simple : <strong>laisser de côté la philosophie et faire tourner Envoy Gateway tout de suite.</strong> Si vous atteignez le service d'exemple avec succès, vous aurez déjà fait plus que tous ceux qui sont encore bloqués sur la page d'accueil de la documentation.</p>
<h2 id="prérequis">Prérequis</h2>
<p>Vous avez besoin d'au moins un cluster Kubernetes fonctionnel, par exemple :</p>
<ul>
<li>En local : <code>kind</code>, <code>minikube</code>, <code>k3d</code></li>
<li>Dans le cloud : EKS, GKE, AKS</li>
<li>Homelab : K3s + MetalLB fonctionne aussi</li>
</ul>
<p>Il vous faudra également :</p>
<ul>
<li><code>kubectl</code></li>
<li><code>helm</code></li>
<li>Un cluster capable de provisionner une adresse <code>LoadBalancer</code>, ou un cluster où l'utilisation de <code>port-forward</code> vous convient</li>
</ul>
<blockquote>
<p>⚠️ Si votre cluster ne prend pas en charge <code>LoadBalancer</code>, la documentation officielle recommande de l'associer à MetalLB. Ne pas avoir d'adresse externe n'est pas la fin du monde : vous testerez simplement via <code>port-forward</code>.</p>
</blockquote>
<h2 id="étape-1--installer-envoy-gateway">Étape 1 : installer Envoy Gateway</h2>
<p>Installez le plan de contrôle :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">helm</span><span style="color:#9ECBFF"> install</span><span style="color:#9ECBFF"> eg</span><span style="color:#9ECBFF"> oci://docker.io/envoyproxy/gateway-helm</span><span style="color:#79B8FF"> \</span></span>
<span data-line=""><span style="color:#79B8FF">  --version</span><span style="color:#9ECBFF"> v1.7.0</span><span style="color:#79B8FF"> \</span></span>
<span data-line=""><span style="color:#79B8FF">  -n</span><span style="color:#9ECBFF"> envoy-gateway-system</span><span style="color:#79B8FF"> \</span></span>
<span data-line=""><span style="color:#79B8FF">  --create-namespace</span></span></code></pre></figure>
<p>Attendez qu'il soit prêt :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">kubectl</span><span style="color:#9ECBFF"> wait</span><span style="color:#79B8FF"> --timeout=5m</span><span style="color:#79B8FF"> -n</span><span style="color:#9ECBFF"> envoy-gateway-system</span><span style="color:#79B8FF"> \</span></span>

<p>Une fois cette étape terminée, le contrôleur Envoy Gateway tourne dans votre cluster. Il peut désormais lire les ressources <code>Gateway API</code> et générer la configuration Envoy correspondante.</p>

<h2 id="étape-3--vérifier-que-le-trafic-circule">Étape 3 : vérifier que le trafic circule</h2>
<h3 id="option-a--le-cluster-possède-un-loadbalancer">Option A : le cluster possède un <code>LoadBalancer</code></h3>
<p>Récupérez l'adresse du Gateway :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#F97583">export</span><span style="color:#E1E4E8"> GATEWAY_HOST</span><span style="color:#F97583">=</span><span style="color:#E1E4E8">$(</span><span style="color:#B392F0">kubectl</span><span style="color:#9ECBFF"> get</span><span style="color:#9ECBFF"> gateway/eg</span><span style="color:#79B8FF"> -o</span><span style="color:#9ECBFF"> jsonpath='{.status.addresses[0].value}'</span><span style="color:#E1E4E8">)</span></span></code></pre></figure>
<p>Envoyez une requête :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">curl</span><span style="color:#79B8FF"> --verbose</span><span style="color:#79B8FF"> \</span></span>
<span data-line=""><span style="color:#79B8FF">  --header</span><span style="color:#9ECBFF"> "Host: www.example.com"</span><span style="color:#79B8FF"> \</span></span>
<span data-line=""><span style="color:#9ECBFF">  http://</span><span style="color:#E1E4E8">$GATEWAY_HOST</span><span style="color:#9ECBFF">/get</span></span></code></pre></figure>
<p>Si vous obtenez un HTTP <code>200</code>, cela signifie :</p>
<ul>
<li>Le Gateway sert correctement d'entrée</li>
<li>Le HTTPRoute a bien été attaché</li>
<li>Le service backend est correctement ciblé par le routage</li>
</ul>
<h3 id="option-b--pas-de-loadbalancer--utiliser-port-forward">Option B : pas de <code>LoadBalancer</code> — utiliser <code>port-forward</code></h3>
<p>Trouvez le service Envoy :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#F97583">export</span><span style="color:#E1E4E8"> ENVOY_SERVICE</span><span style="color:#F97583">=</span><span style="color:#E1E4E8">$(</span><span style="color:#B392F0">kubectl</span><span style="color:#9ECBFF"> get</span><span style="color:#9ECBFF"> svc</span><span style="color:#79B8FF"> -n</span><span style="color:#9ECBFF"> envoy-gateway-system</span><span style="color:#79B8FF"> \</span></span>
<span data-line=""><span style="color:#79B8FF">  --selector=gateway.envoyproxy.io/owning-gateway-namespace=default,gateway.envoyproxy.io/owning-gateway-name=eg</span><span style="color:#79B8FF"> \</span></span>
<span data-line=""><span style="color:#79B8FF">  -o</span><span style="color:#9ECBFF"> jsonpath='{.items[0].metadata.name}'</span><span style="color:#E1E4E8">)</span></span></code></pre></figure>
<p>Redirigez le port local <code>8888</code> vers le port <code>80</code> du Gateway :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">kubectl</span><span style="color:#79B8FF"> -n</span><span style="color:#9ECBFF"> envoy-gateway-system</span><span style="color:#9ECBFF"> port-forward</span><span style="color:#9ECBFF"> service/</span><span style="color:#E1E4E8">${ENVOY_SERVICE} </span><span style="color:#9ECBFF">8888:80</span></span></code></pre></figure>
<p>Dans un autre terminal :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">curl</span><span style="color:#79B8FF"> --verbose</span><span style="color:#79B8FF"> \</span></span>
<span data-line=""><span style="color:#79B8FF">  --header</span><span style="color:#9ECBFF"> "Host: www.example.com"</span><span style="color:#79B8FF"> \</span></span>

<p>C'est le chemin de test local. Cela donne un peu l'impression d'entrer par la porte de derrière, mais si cela valide le routage, c'est très bien ; parfois, l'ingénierie consiste d'abord à "faire marcher", puis à rendre ça élégant.</p>
<h2 id="où-regarder-quand-ça-casse">Où regarder quand ça casse</h2>
<p>Les problèmes les plus courants ne viennent pas du fait qu'Envoy Gateway serait cassé, mais du fait qu'un maillon de la chaîne ne s'est pas connecté :</p>
<table>
<thead>
<tr>
<th>Symptôme</th>
<th>À vérifier en premier</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>gateway/eg</code> n'a pas d'adresse</td>
<td>Le cluster dispose-t-il d'une implémentation <code>LoadBalancer</code> ?</td>
</tr>
<tr>
<td><code>curl</code> renvoie 404 ou 503</td>
<td>État de <code>HTTPRoute</code>, <code>Service</code> et des Pods backend</td>
</tr>
<tr>
<td><code>kubectl wait</code> reste bloqué</td>
<td>Les Pods de <code>envoy-gateway-system</code> sont-ils en cours d'exécution ?</td>
</tr>
</tbody>
</table>
<p>Commandes utiles :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">kubectl</span><span style="color:#9ECBFF"> get</span><span style="color:#9ECBFF"> pods</span><span style="color:#79B8FF"> -n</span><span style="color:#9ECBFF"> envoy-gateway-system</span></span>

<span data-line=""><span style="color:#B392F0">kubectl</span><span style="color:#9ECBFF"> get</span><span style="color:#9ECBFF"> httproute</span><span style="color:#79B8FF"> -A</span></span>
<span data-line=""><span style="color:#B392F0">kubectl</span><span style="color:#9ECBFF"> get</span><span style="color:#9ECBFF"> svc,pod</span><span style="color:#79B8FF"> -n</span><span style="color:#9ECBFF"> default</span></span></code></pre></figure>
<p>Pour creuser le status du Gateway :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">kubectl</span><span style="color:#9ECBFF"> get</span><span style="color:#9ECBFF"> gateway/eg</span><span style="color:#79B8FF"> -o</span><span style="color:#9ECBFF"> yaml</span></span></code></pre></figure>

<h2 id="ce-que-vous-venez-réellement-de-faire">Ce que vous venez réellement de faire</h2>
<p>Vous n'avez exécuté que quelques commandes, mais vous avez complété toute une chaîne de bout en bout :</p>
<ol>

<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">curl</span><span style="color:#79B8FF"> --verbose</span><span style="color:#79B8FF"> \</span></span>
