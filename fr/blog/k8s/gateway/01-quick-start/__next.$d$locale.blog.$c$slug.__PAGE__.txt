8:T3448,<p>Le but de cet article est simple : <strong>laisser de côté la philosophie et faire tourner Envoy Gateway tout de suite.</strong> Si vous atteignez le service d'exemple avec succès, vous aurez déjà fait plus que tous ceux qui sont encore bloqués sur la page d'accueil de la documentation.</p>
<h2 id="prérequis">Prérequis</h2>
<p>Vous avez besoin d'au moins un cluster Kubernetes fonctionnel, par exemple :</p>
<ul>
<li>En local : <code>kind</code>, <code>minikube</code>, <code>k3d</code></li>
<li>Dans le cloud : EKS, GKE, AKS</li>
<li>Homelab : K3s + MetalLB fonctionne aussi</li>
</ul>
<p>Il vous faudra également :</p>
<ul>
<li><code>kubectl</code></li>
<li><code>helm</code></li>
<li>Un cluster capable de provisionner une adresse <code>LoadBalancer</code>, ou un cluster où l'utilisation de <code>port-forward</code> vous convient</li>
</ul>
<blockquote>
<p>⚠️ Si votre cluster ne prend pas en charge <code>LoadBalancer</code>, la documentation officielle recommande de l'associer à MetalLB. Ne pas avoir d'adresse externe n'est pas la fin du monde : vous testerez simplement via <code>port-forward</code>.</p>
</blockquote>
<h2 id="étape-1--installer-envoy-gateway">Étape 1 : installer Envoy Gateway</h2>
<p>Installez le plan de contrôle :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">helm</span><span style="color:#A5D6FF"> install</span><span style="color:#A5D6FF"> eg</span><span style="color:#A5D6FF"> oci://docker.io/envoyproxy/gateway-helm</span><span style="color:#FF7B72"> \</span></span>
<span data-line=""><span style="color:#79C0FF">  --version</span><span style="color:#A5D6FF"> v1.7.0</span><span style="color:#FF7B72"> \</span></span>
<span data-line=""><span style="color:#79C0FF">  -n</span><span style="color:#A5D6FF"> envoy-gateway-system</span><span style="color:#FF7B72"> \</span></span>
<span data-line=""><span style="color:#79C0FF">  --create-namespace</span></span></code></pre></figure>
<p>Attendez qu'il soit prêt :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">kubectl</span><span style="color:#A5D6FF"> wait</span><span style="color:#79C0FF"> --timeout=5m</span><span style="color:#79C0FF"> -n</span><span style="color:#A5D6FF"> envoy-gateway-system</span><span style="color:#FF7B72"> \</span></span>
<span data-line=""><span style="color:#A5D6FF">  deployment/envoy-gateway</span><span style="color:#FF7B72"> \</span></span>
<span data-line=""><span style="color:#79C0FF">  --for=condition=Available</span></span></code></pre></figure>
<p>Une fois cette étape terminée, le contrôleur Envoy Gateway tourne dans votre cluster. Il peut désormais lire les ressources <code>Gateway API</code> et générer la configuration Envoy correspondante.</p>
<h2 id="étape-2--appliquer-les-ressources-officielles-du-quickstart">Étape 2 : appliquer les ressources officielles du quickstart</h2>
<p>Le dépôt officiel fournit un exemple groupé qui inclut :</p>
<ul>
<li><code>GatewayClass</code></li>
<li><code>Gateway</code></li>
<li><code>HTTPRoute</code></li>
<li>Une application backend d'exemple</li>
</ul>
<p>Appliquez-le directement :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">kubectl</span><span style="color:#A5D6FF"> apply</span><span style="color:#79C0FF"> -f</span><span style="color:#FF7B72"> \</span></span>
<span data-line=""><span style="color:#A5D6FF">  https://github.com/envoyproxy/gateway/releases/download/v1.7.0/quickstart.yaml</span><span style="color:#FF7B72"> \</span></span>
<span data-line=""><span style="color:#79C0FF">  -n</span><span style="color:#A5D6FF"> default</span></span></code></pre></figure>
<p>Voyez cela comme l'équipe officielle qui vous prépare une scène de démonstration complète. Faites-la d'abord fonctionner, puis démontez-la ensuite pour comprendre les détails.</p>
<h2 id="étape-3--vérifier-que-le-trafic-circule">Étape 3 : vérifier que le trafic circule</h2>
<h3 id="option-a--le-cluster-possède-un-loadbalancer">Option A : le cluster possède un <code>LoadBalancer</code></h3>
<p>Récupérez l'adresse du Gateway :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FF7B72">export</span><span style="color:#E6EDF3"> GATEWAY_HOST</span><span style="color:#FF7B72">=</span><span style="color:#E6EDF3">$(</span><span style="color:#FFA657">kubectl</span><span style="color:#A5D6FF"> get</span><span style="color:#A5D6FF"> gateway/eg</span><span style="color:#79C0FF"> -o</span><span style="color:#A5D6FF"> jsonpath='{.status.addresses[0].value}'</span><span style="color:#E6EDF3">)</span></span></code></pre></figure>
<p>Envoyez une requête :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">curl</span><span style="color:#79C0FF"> --verbose</span><span style="color:#FF7B72"> \</span></span>
<span data-line=""><span style="color:#79C0FF">  --header</span><span style="color:#A5D6FF"> "Host: www.example.com"</span><span style="color:#FF7B72"> \</span></span>
<span data-line=""><span style="color:#A5D6FF">  http://</span><span style="color:#E6EDF3">$GATEWAY_HOST</span><span style="color:#A5D6FF">/get</span></span></code></pre></figure>
<p>Si vous obtenez un HTTP <code>200</code>, cela signifie :</p>
<ul>
<li>Le Gateway sert correctement d'entrée</li>
<li>Le HTTPRoute a bien été attaché</li>
<li>Le service backend est correctement ciblé par le routage</li>
</ul>
<h3 id="option-b--pas-de-loadbalancer--utiliser-port-forward">Option B : pas de <code>LoadBalancer</code> — utiliser <code>port-forward</code></h3>
<p>Trouvez le service Envoy :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FF7B72">export</span><span style="color:#E6EDF3"> ENVOY_SERVICE</span><span style="color:#FF7B72">=</span><span style="color:#E6EDF3">$(</span><span style="color:#FFA657">kubectl</span><span style="color:#A5D6FF"> get</span><span style="color:#A5D6FF"> svc</span><span style="color:#79C0FF"> -n</span><span style="color:#A5D6FF"> envoy-gateway-system</span><span style="color:#FF7B72"> \</span></span>
<span data-line=""><span style="color:#79C0FF">  --selector=gateway.envoyproxy.io/owning-gateway-namespace=default,gateway.envoyproxy.io/owning-gateway-name=eg</span><span style="color:#FF7B72"> \</span></span>
<span data-line=""><span style="color:#79C0FF">  -o</span><span style="color:#A5D6FF"> jsonpath='{.items[0].metadata.name}'</span><span style="color:#E6EDF3">)</span></span></code></pre></figure>
<p>Redirigez le port local <code>8888</code> vers le port <code>80</code> du Gateway :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">kubectl</span><span style="color:#79C0FF"> -n</span><span style="color:#A5D6FF"> envoy-gateway-system</span><span style="color:#A5D6FF"> port-forward</span><span style="color:#A5D6FF"> service/</span><span style="color:#E6EDF3">${ENVOY_SERVICE} </span><span style="color:#A5D6FF">8888:80</span></span></code></pre></figure>
<p>Dans un autre terminal :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">curl</span><span style="color:#79C0FF"> --verbose</span><span style="color:#FF7B72"> \</span></span>
<span data-line=""><span style="color:#79C0FF">  --header</span><span style="color:#A5D6FF"> "Host: www.example.com"</span><span style="color:#FF7B72"> \</span></span>
<span data-line=""><span style="color:#A5D6FF">  http://localhost:8888/get</span></span></code></pre></figure>
<p>C'est le chemin de test local. Cela donne un peu l'impression d'entrer par la porte de derrière, mais si cela valide le routage, c'est très bien ; parfois, l'ingénierie consiste d'abord à "faire marcher", puis à rendre ça élégant.</p>
<h2 id="où-regarder-quand-ça-casse">Où regarder quand ça casse</h2>
<p>Les problèmes les plus courants ne viennent pas du fait qu'Envoy Gateway serait cassé, mais du fait qu'un maillon de la chaîne ne s'est pas connecté :</p>
<table>
<thead>
<tr>
<th>Symptôme</th>
<th>À vérifier en premier</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>gateway/eg</code> n'a pas d'adresse</td>
<td>Le cluster dispose-t-il d'une implémentation <code>LoadBalancer</code> ?</td>
</tr>
<tr>
<td><code>curl</code> renvoie 404 ou 503</td>
<td>État de <code>HTTPRoute</code>, <code>Service</code> et des Pods backend</td>
</tr>
<tr>
<td><code>kubectl wait</code> reste bloqué</td>
<td>Les Pods de <code>envoy-gateway-system</code> sont-ils en cours d'exécution ?</td>
</tr>
</tbody>
</table>
<p>Commandes utiles :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">kubectl</span><span style="color:#A5D6FF"> get</span><span style="color:#A5D6FF"> pods</span><span style="color:#79C0FF"> -n</span><span style="color:#A5D6FF"> envoy-gateway-system</span></span>

<span data-line=""><span style="color:#FFA657">kubectl</span><span style="color:#A5D6FF"> get</span><span style="color:#A5D6FF"> httproute</span><span style="color:#79C0FF"> -A</span></span>

<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">kubectl</span><span style="color:#A5D6FF"> get</span><span style="color:#A5D6FF"> gateway/eg</span><span style="color:#79C0FF"> -o</span><span style="color:#A5D6FF"> yaml</span></span></code></pre></figure>

<h2 id="ce-que-vous-venez-réellement-de-faire">Ce que vous venez réellement de faire</h2>
<p>Vous n'avez exécuté que quelques commandes, mais vous avez complété toute une chaîne de bout en bout :</p>
<ol>
<li>Installation de <code>Envoy Gateway</code></li>
<li>Création d'un <code>GatewayClass</code> pour indiquer au cluster quel contrôleur de gateway utiliser</li>
<li>Création d'un <code>Gateway</code> qui déclare le port et le protocole d'entrée</li>
<li>Création d'un <code>HTTPRoute</code> qui route le trafic vers le service backend</li>
<li>Envoy Gateway a traduit ces déclarations en configuration que Envoy Proxy peut exécuter</li>
</ol>
<p>C'est exactement pour cela que Gateway API vaut la peine d'être utilisé. Vous écrivez des ressources Kubernetes, vous ne maintenez pas à la main une pile de fichiers de configuration proxy.</p>

<p>⚠️ Si votre cluster ne prend pas en charge <code>LoadBalancer</code>, la documentation officielle recommande de l'associer à MetalLB. Ne pas avoir d'adresse externe n'est pas la fin du monde : vous testerez simplement via <code>port-forward</code>.</p>
</blockquote>

<h2 id="étape-3--vérifier-que-le-trafic-circule">Étape 3 : vérifier que le trafic circule</h2>
<h3 id="option-a--le-cluster-possède-un-loadbalancer">Option A : le cluster possède un <code>LoadBalancer</code></h3>
<p>Récupérez l'adresse du Gateway :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FF7B72">export</span><span style="color:#E6EDF3"> GATEWAY_HOST</span><span style="color:#FF7B72">=</span><span style="color:#E6EDF3">$(</span><span style="color:#FFA657">kubectl</span><span style="color:#A5D6FF"> get</span><span style="color:#A5D6FF"> gateway/eg</span><span style="color:#79C0FF"> -o</span><span style="color:#A5D6FF"> jsonpath='{.status.addresses[0].value}'</span><span style="color:#E6EDF3">)</span></span></code></pre></figure>
<p>Envoyez une requête :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">curl</span><span style="color:#79C0FF"> --verbose</span><span style="color:#FF7B72"> \</span></span>
<span data-line=""><span style="color:#79C0FF">  --header</span><span style="color:#A5D6FF"> "Host: www.example.com"</span><span style="color:#FF7B72"> \</span></span>
<span data-line=""><span style="color:#A5D6FF">  http://</span><span style="color:#E6EDF3">$GATEWAY_HOST</span><span style="color:#A5D6FF">/get</span></span></code></pre></figure>

<ul>
<li>Le Gateway sert correctement d'entrée</li>
<li>Le HTTPRoute a bien été attaché</li>
<li>Le service backend est correctement ciblé par le routage</li>
</ul>
<h3 id="option-b--pas-de-loadbalancer--utiliser-port-forward">Option B : pas de <code>LoadBalancer</code> — utiliser <code>port-forward</code></h3>
<p>Trouvez le service Envoy :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FF7B72">export</span><span style="color:#E6EDF3"> ENVOY_SERVICE</span><span style="color:#FF7B72">=</span><span style="color:#E6EDF3">$(</span><span style="color:#FFA657">kubectl</span><span style="color:#A5D6FF"> get</span><span style="color:#A5D6FF"> svc</span><span style="color:#79C0FF"> -n</span><span style="color:#A5D6FF"> envoy-gateway-system</span><span style="color:#FF7B72"> \</span></span>

<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">kubectl</span><span style="color:#79C0FF"> -n</span><span style="color:#A5D6FF"> envoy-gateway-system</span><span style="color:#A5D6FF"> port-forward</span><span style="color:#A5D6FF"> service/</span><span style="color:#E6EDF3">${ENVOY_SERVICE} </span><span style="color:#A5D6FF">8888:80</span></span></code></pre></figure>

<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">curl</span><span style="color:#79C0FF"> --verbose</span><span style="color:#FF7B72"> \</span></span>

<h2 id="ce-que-vous-venez-réellement-de-faire">Ce que vous venez réellement de faire</h2>
<p>Vous n'avez exécuté que quelques commandes, mais vous avez complété toute une chaîne de bout en bout :</p>
<ol>
<li>Installation de <code>Envoy Gateway</code></li>
<li>Création d'un <code>GatewayClass</code> pour indiquer au cluster quel contrôleur de gateway utiliser</li>
<li>Création d'un <code>Gateway</code> qui déclare le port et le protocole d'entrée</li>
<li>Création d'un <code>HTTPRoute</code> qui route le trafic vers le service backend</li>
<li>Envoy Gateway a traduit ces déclarations en configuration que Envoy Proxy peut exécuter</li>
</ol>
<p>C'est exactement pour cela que Gateway API vaut la peine d'être utilisé. Vous écrivez des ressources Kubernetes, vous ne maintenez pas à la main une pile de fichiers de configuration proxy.</p>
