1a:T1fe4,<p>Si vous êtes arrivé jusqu'ici, vous avez déjà fait passer OpenClaw de zéro à fonctionnel. Bravo.</p>
<p>Ce dernier article rassemble les habitudes qui rendent votre installation plus stable et plus facile à maintenir.</p>
<h2 id="ce-que-vous-allez-apprendre">Ce que vous allez apprendre</h2>
<ul>
<li>Trouver le fichier de config et comprendre les deux modes d'édition</li>
<li>Reconnaître la structure d'une config minimale fonctionnelle</li>
<li>Stocker les clés API en sécurité avec les variables d'environnement</li>
<li>Utiliser la commande de débogage la plus utile et lire les erreurs courantes</li>
<li>Choisir la bonne piste de release</li>
</ul>
<hr>
<h2 id="où-se-trouve-le-fichier-de-config-">Où se trouve le fichier de config ?</h2>
<pre><code>~/.openclaw/openclaw.json
</code></pre>
<p>Le format est <strong>JSON5</strong> : commentaires et virgules finales autorisés. Bien plus agréable que du JSON brut.</p>
<p>Vous pouvez l'éditer de deux façons :</p>
<ul>
<li><strong>Mode formulaire</strong> dans l'interface de contrôle pour une approche débutant</li>
<li><strong>Raw JSON</strong> pour précision et rapidité</li>
</ul>
<p>Les deux modes éditent le même fichier et enregistrent au même chemin.</p>
<hr>

<h2 id="la-bonne-façon-de-stocker-les-clés-api">La bonne façon de stocker les clés API</h2>
<p><strong>Évitez d'enfouir les clés API en dur dans la config.</strong></p>
<p>Les variables d'environnement sont plus sûres :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E"># Mettez ça dans .env ou dans l'environnement système</span></span>
<span data-line=""><span style="color:#E6EDF3">ANTHROPIC_API_KEY</span><span style="color:#FF7B72">=</span><span style="color:#A5D6FF">sk-ant-xxxxx</span></span></code></pre></figure>
<blockquote>
<p>⚠️ Si la Gateway tourne comme service système (ex. <code>systemd</code>), assurez-vous que le service charge votre <code>.env</code>. Sinon l'assistant peut échouer car il ne voit pas la clé API, avec des erreurs du type « Shell env off ».</p>
</blockquote>

<h2 id="loutil-de-débogage-universel">L'outil de débogage universel</h2>
<p>Quand quelque chose ne va pas, commencez par :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">openclaw</span><span style="color:#A5D6FF"> logs</span><span style="color:#79C0FF"> --follow</span></span></code></pre></figure>
<p>Les logs en temps réel répondent à un nombre surprenant de questions.</p>
<p>Erreurs courantes :</p>
<table>
<thead>
<tr>
<th>Message d'erreur</th>
<th>Cause probable</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>HTTP 429</code></td>
<td>Trop de requêtes API, limite de débit atteinte</td>
</tr>
<tr>
<td><code>unauthorized</code></td>
<td>Problème de token ou de <code>gateway.bind</code></td>
</tr>
<tr>
<td><code>content tool_use input field required</code></td>
<td>Problème de compatibilité modèle, consultez la doc</td>
</tr>
<tr>
<td>Contexte tronqué</td>
<td>Démarrez une nouvelle session ou compactez le contexte comme recommandé</td>
</tr>
</tbody>
</table>

<hr>
<h2 id="la-bonne-façon-de-stocker-les-clés-api">La bonne façon de stocker les clés API</h2>
<p><strong>Évitez d'enfouir les clés API en dur dans la config.</strong></p>
<p>Les variables d'environnement sont plus sûres :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E"># Mettez ça dans .env ou dans l'environnement système</span></span>
<span data-line=""><span style="color:#E6EDF3">ANTHROPIC_API_KEY</span><span style="color:#FF7B72">=</span><span style="color:#A5D6FF">sk-ant-xxxxx</span></span></code></pre></figure>
<blockquote>
<p>⚠️ Si la Gateway tourne comme service système (ex. <code>systemd</code>), assurez-vous que le service charge votre <code>.env</code>. Sinon l'assistant peut échouer car il ne voit pas la clé API, avec des erreurs du type « Shell env off ».</p>
</blockquote>

<h2 id="loutil-de-débogage-universel">L'outil de débogage universel</h2>
<p>Quand quelque chose ne va pas, commencez par :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">openclaw</span><span style="color:#A5D6FF"> logs</span><span style="color:#79C0FF"> --follow</span></span></code></pre></figure>

<th>Cause probable</th>
</tr>

</tr>
<tr>
<td><code>unauthorized</code></td>
<td>Problème de token ou de <code>gateway.bind</code></td>
</tr>
<tr>
<td><code>content tool_use input field required</code></td>
<td>Problème de compatibilité modèle, consultez la doc</td>
</tr>
<tr>
<td>Contexte tronqué</td>
<td>Démarrez une nouvelle session ou compactez le contexte comme recommandé</td>
</tr>
</tbody>
</table>
