Votre assistant disparaît quand votre portable s'endort ? Déplacez la Gateway sur un VPS

8 mars 2026·3 min read

Votre assistant ne devrait pas passer hors ligne juste parce que votre portable a décidé de faire la sieste.

Cet article montre comment déplacer la Gateway dans le cloud et garder votre assistant en ligne toute la journée.

Ce que vous allez apprendre

  • Savoir où une Gateway peut tourner
  • Réaliser un déploiement VPS de base
  • Comprendre l'authentification à distance
  • Utiliser Tailscale pour un réseau privé sûr
  • Comprendre la différence entre Gateway et Node

Où peut tourner la Gateway ?

Emplacement Idéal pour
Ordinateur local Tests personnels et usage occasionnel
VPS / serveur cloud Disponibilité 24/7
NAS familial / vieux PC Toujours allumé sans facture VPS

À quoi ressemble l'installation sur VPS ?

Connectez-vous à votre VPS (de préférence Ubuntu ou Debian), puis suivez les étapes d'installation Linux sur docs.openclaw.ai. C'est quasiment la même chose qu'une installation locale, mais sur une machine distante.

Bases de l'authentification à distance

Une fois la Gateway sur un VPS, OpenClaw doit toujours confirmer que vous êtes autorisé :

  • Vous devez utiliser un token ou l'appairage d'appareil
  • Si vous voyez unauthorized, vérifiez gateway.bind et confirmez que le token est correct

Tailscale est l'option la plus propre

Tailscale est un VPN qui fait que votre téléphone, ordinateur et VPS semblent être sur le même réseau privé :

  1. Installez Tailscale sur votre VPS et sur votre ordinateur
  2. Définissez gateway.bind: tailnet
  3. Connectez-vous à la Gateway via Tailscale depuis n'importe quel appareil

💡 Tailscale peut aussi exposer du HTTPS avec Serve, ce qui est en général bien plus sûr qu'exposer un port brut directement.

Qu'est-ce qu'un Node ?

Voici la partie cool : la Gateway et le Node peuvent vivre sur des machines différentes.

  • Gateway : tourne sur le VPS et gère les conversations, la mémoire, Telegram et tout le « cerveau »
  • Node : tourne sur votre ordinateur à la maison et fournit les « mains » : contrôle du navigateur, accès aux fichiers locaux, interaction à l'écran

Exemple concret : vous êtes dehors, vous envoyez un message à votre assistant sur Telegram pour qu'il ouvre un navigateur sur votre PC à la maison et vérifie un site. La Gateway envoie la tâche au Node à la maison, puis vous renvoie le résultat.

En quoi c'est différent du SSH ?

Avec SSH, vous vous connectez et tapez les commandes vous-même. Avec un Node, c'est l'assistant qui le fait pour vous, intégré aux Skills, espaces de travail et conversations.

Suite

Une fois la Gateway sur un VPS, votre assistant est toujours de service. Ensuite, nous le ferons travailler automatiquement avec des planifications.
