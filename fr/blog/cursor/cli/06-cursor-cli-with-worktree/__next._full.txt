1a:T1fd6,<p><strong>Worktree</strong> permet d'avoir plusieurs répertoires (chacun sur une branche différente) pour le même dépôt. <strong>Cursor CLI</strong> agit sur le répertoire où elle est lancée. Combinez les deux et vous avez plusieurs terminaux qui exécutent des Agents CLI en parallèle sur des branches différentes — sans plusieurs fenêtres Cursor, du multitâche pur au clavier.</p>
<h2 id="pourquoi-les-combiner-">Pourquoi les combiner ?</h2>
<table>
<thead>
<tr>
<th>Approche</th>
<th>Comment</th>
<th>Idéal pour</th>
</tr>
</thead>
<tbody>
<tr>
<td>Worktree + plusieurs <strong>fenêtres</strong> Cursor</td>
<td>Une fenêtre par worktree</td>
<td>Utilisateurs IDE qui veulent l'arborescence et l'aperçu</td>
</tr>
<tr>
<td>Worktree + <strong>CLI</strong></td>
<td>Plusieurs terminaux, chacun en <code>cd</code> dans un worktree, lancer <code>cursor agent</code></td>
<td>Utilisateurs clavier-first ou environnements serveur/SSH</td>
</tr>
</tbody>
</table>
<p>Point commun : chaque worktree est un répertoire indépendant → chacun a son contexte → développement parallèle sans se marcher sur les pieds. Comme avoir plusieurs clones qui travaillent sur des branches différentes en même temps.</p>
<h2 id="utilisation-de-base--un-terminal-par-worktree">Utilisation de base : un terminal par worktree</h2>
<p>En supposant que vous avez déjà créé vos worktrees :</p>
<pre><code>~/projects/
├── my-app/                  ← main
├── my-app--feature-auth/    ← feature/auth
└── my-app--feature-payment/  ← feature/payment
</code></pre>
<p><strong>Terminal 1</strong> (sur auth) :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#79B8FF">cd</span><span style="color:#9ECBFF"> ~/projects/my-app--feature-auth</span></span>
<span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#9ECBFF"> "Implement JWT login"</span></span></code></pre></figure>
<p><strong>Terminal 2</strong> (sur payment) :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#79B8FF">cd</span><span style="color:#9ECBFF"> ~/projects/my-app--feature-payment</span></span>
<span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#9ECBFF"> "Add Stripe checkout flow"</span></span></code></pre></figure>
<p>La CLI prend par défaut le <strong>répertoire de travail courant</strong> comme contexte, donc les deux terminaux ne modifient que leur worktree respectif. C'est « deux Agents CLI en parallèle » — pas besoin d'ouvrir deux fenêtres Cursor, moins de ressources et pas de changement de contexte.</p>
<h2 id="sans-changer-de-répertoire----path-pour-cibler-un-worktree">Sans changer de répertoire : <code>--path</code> pour cibler un worktree</h2>
<p>Vous êtes dans le répertoire principal mais voulez que la CLI travaille sur un worktree précis :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#79B8FF">cd</span><span style="color:#9ECBFF"> ~/projects/my-app</span></span>
<span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#9ECBFF"> "Add unit tests for feature/auth"</span><span style="color:#79B8FF"> --path</span><span style="color:#9ECBFF"> ../my-app--feature-auth</span></span></code></pre></figure>
<p><code>--path</code> indique sur quel répertoire travailler — le chemin du worktree. Utile pour traiter un worktree à la fois ou quand le chemin est fixe dans un script.</p>
<h2 id="non-interactif--worktree-scripts--traitements-par-lot">Non interactif + Worktree (scripts / traitements par lot)</h2>
<p>Exécuter le même type de tâche sur plusieurs worktrees à la suite (ex. ajouter un README partout, corriger le lint partout) :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># Exemple : "fix lint" sur les deux worktrees</span></span>
<span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#9ECBFF"> "Fix all auto-fixable errors per .eslintrc"</span><span style="color:#79B8FF"> --path</span><span style="color:#9ECBFF"> ../my-app--feature-auth</span><span style="color:#79B8FF"> --no-interactive</span></span>
<span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#9ECBFF"> "Fix all auto-fixable errors per .eslintrc"</span><span style="color:#79B8FF"> --path</span><span style="color:#9ECBFF"> ../my-app--feature-payment</span><span style="color:#79B8FF"> --no-interactive</span></span></code></pre></figure>
<p>Ou avec une boucle (adaptez les chemins à votre setup) :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#F97583">for</span><span style="color:#E1E4E8"> dir </span><span style="color:#F97583">in</span><span style="color:#9ECBFF"> ../my-app--feature-auth</span><span style="color:#9ECBFF"> ../my-app--feature-payment</span><span style="color:#E1E4E8">; </span><span style="color:#F97583">do</span></span>
<span data-line=""><span style="color:#B392F0">  cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#9ECBFF"> "Fix linter errors"</span><span style="color:#79B8FF"> --path</span><span style="color:#9ECBFF"> "</span><span style="color:#E1E4E8">$dir</span><span style="color:#9ECBFF">"</span><span style="color:#79B8FF"> --no-interactive</span></span>
<span data-line=""><span style="color:#F97583">done</span></span></code></pre></figure>
<p>Une instruction, plusieurs branches nettoyées d'un coup — pratique pour un dernier passage avant les PR.</p>
<h2 id="lien-avec--worktree--plusieurs-fenêtres-">Lien avec « Worktree + plusieurs fenêtres »</h2>
<ul>
<li><strong>Plusieurs fenêtres</strong> : chaque fenêtre Cursor ouvre un worktree, avec l'Agent, le Chat et la complétion Tab de l'IDE.</li>
<li><strong>CLI + Worktree</strong> : terminal + <code>cursor agent</code> — même idée « un répertoire, un contexte », il suffit d'ouvrir plus de terminaux pour paralléliser.</li>
</ul>
<p>Vous pouvez aussi mixer : développement principal dans la fenêtre, et CLI sur le serveur pour de petits correctifs sur une autre branche.</p>
<h2 id="résumé">Résumé</h2>
<ul>
<li><strong>Worktree</strong> = plusieurs répertoires, plusieurs branches ; <strong>CLI</strong> = agit sur le répertoire courant ou <code>--path</code> → couple naturel.</li>
<li><strong>Parallèle</strong> : ouvrez plusieurs terminaux, chacun en <code>cd</code> dans un worktree différent, puis lancez <code>cursor agent</code>.</li>
<li><strong>Un seul terminal</strong> : utilisez <code>--path &#x3C;worktree-path></code> pour cibler le worktree voulu.</li>
<li><strong>Scripts / lots</strong> : <code>--path</code> + <code>--no-interactive</code> pour la même tâche sur plusieurs worktrees.</li>
</ul>

<span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#9ECBFF"> "Implement JWT login"</span></span></code></pre></figure>
<p><strong>Terminal 2</strong> (sur payment) :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#79B8FF">cd</span><span style="color:#9ECBFF"> ~/projects/my-app--feature-payment</span></span>
<span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#9ECBFF"> "Add Stripe checkout flow"</span></span></code></pre></figure>
<p>La CLI prend par défaut le <strong>répertoire de travail courant</strong> comme contexte, donc les deux terminaux ne modifient que leur worktree respectif. C'est « deux Agents CLI en parallèle » — pas besoin d'ouvrir deux fenêtres Cursor, moins de ressources et pas de changement de contexte.</p>
<h2 id="sans-changer-de-répertoire----path-pour-cibler-un-worktree">Sans changer de répertoire : <code>--path</code> pour cibler un worktree</h2>
<p>Vous êtes dans le répertoire principal mais voulez que la CLI travaille sur un worktree précis :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#79B8FF">cd</span><span style="color:#9ECBFF"> ~/projects/my-app</span></span>
<span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#9ECBFF"> "Add unit tests for feature/auth"</span><span style="color:#79B8FF"> --path</span><span style="color:#9ECBFF"> ../my-app--feature-auth</span></span></code></pre></figure>
<p><code>--path</code> indique sur quel répertoire travailler — le chemin du worktree. Utile pour traiter un worktree à la fois ou quand le chemin est fixe dans un script.</p>
<h2 id="non-interactif--worktree-scripts--traitements-par-lot">Non interactif + Worktree (scripts / traitements par lot)</h2>
<p>Exécuter le même type de tâche sur plusieurs worktrees à la suite (ex. ajouter un README partout, corriger le lint partout) :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># Exemple : "fix lint" sur les deux worktrees</span></span>
<span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#9ECBFF"> "Fix all auto-fixable errors per .eslintrc"</span><span style="color:#79B8FF"> --path</span><span style="color:#9ECBFF"> ../my-app--feature-auth</span><span style="color:#79B8FF"> --no-interactive</span></span>
<span data-line=""><span style="color:#B392F0">cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#9ECBFF"> "Fix all auto-fixable errors per .eslintrc"</span><span style="color:#79B8FF"> --path</span><span style="color:#9ECBFF"> ../my-app--feature-payment</span><span style="color:#79B8FF"> --no-interactive</span></span></code></pre></figure>
<p>Ou avec une boucle (adaptez les chemins à votre setup) :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#F97583">for</span><span style="color:#E1E4E8"> dir </span><span style="color:#F97583">in</span><span style="color:#9ECBFF"> ../my-app--feature-auth</span><span style="color:#9ECBFF"> ../my-app--feature-payment</span><span style="color:#E1E4E8">; </span><span style="color:#F97583">do</span></span>
<span data-line=""><span style="color:#B392F0">  cursor</span><span style="color:#9ECBFF"> agent</span><span style="color:#9ECBFF"> "Fix linter errors"</span><span style="color:#79B8FF"> --path</span><span style="color:#9ECBFF"> "</span><span style="color:#E1E4E8">$dir</span><span style="color:#9ECBFF">"</span><span style="color:#79B8FF"> --no-interactive</span></span>
<span data-line=""><span style="color:#F97583">done</span></span></code></pre></figure>
<p>Une instruction, plusieurs branches nettoyées d'un coup — pratique pour un dernier passage avant les PR.</p>
<h2 id="lien-avec--worktree--plusieurs-fenêtres-">Lien avec « Worktree + plusieurs fenêtres »</h2>
<ul>
<li><strong>Plusieurs fenêtres</strong> : chaque fenêtre Cursor ouvre un worktree, avec l'Agent, le Chat et la complétion Tab de l'IDE.</li>
<li><strong>CLI + Worktree</strong> : terminal + <code>cursor agent</code> — même idée « un répertoire, un contexte », il suffit d'ouvrir plus de terminaux pour paralléliser.</li>
</ul>
<p>Vous pouvez aussi mixer : développement principal dans la fenêtre, et CLI sur le serveur pour de petits correctifs sur une autre branche.</p>
<h2 id="résumé">Résumé</h2>
<ul>
<li><strong>Worktree</strong> = plusieurs répertoires, plusieurs branches ; <strong>CLI</strong> = agit sur le répertoire courant ou <code>--path</code> → couple naturel.</li>
<li><strong>Parallèle</strong> : ouvrez plusieurs terminaux, chacun en <code>cd</code> dans un worktree différent, puis lancez <code>cursor agent</code>.</li>
<li><strong>Un seul terminal</strong> : utilisez <code>--path &#x3C;worktree-path></code> pour cibler le worktree voulu.</li>
<li><strong>Scripts / lots</strong> : <code>--path</code> + <code>--no-interactive</code> pour la même tâche sur plusieurs worktrees.</li>
</ul>
