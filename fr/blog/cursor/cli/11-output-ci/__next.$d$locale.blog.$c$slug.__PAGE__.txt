3:T2375,<p>Le billet précédent <a href="10-headless-scripts">10-headless-scripts</a> utilisait <code>-p --force</code> pour modifier des fichiers depuis des scripts. Celui-ci porte sur le <strong>format de sortie</strong> : pour une même exécution de l’Agent vous pouvez choisir « texte final uniquement », « JSON structuré complet » ou « JSON en stream pendant l’exécution » — en CI vous parsez les résultats, mesurez le temps ou affichez la progression avec ces trois formats.</p>

<table>
<thead>
<tr>
<th>Format</th>
<th>Option</th>
<th>Idéal pour</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>text</strong></td>
<td>Par défaut, ou <code>--output-format text</code></td>
<td>Lecture humaine, réponse finale seule, écriture dans un fichier</td>
</tr>
<tr>
<td><strong>json</strong></td>
<td><code>--output-format json</code></td>
<td>Parsing dans des scripts, pass/fail CI, extraction de champs</td>

<tr>

<td><code>--output-format stream-json</code></td>

<h3 id="text--réponse-finale-propre">text : Réponse finale propre</h3>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#A5D6FF"> "What is the entry point of this repo?"</span></span></code></pre></figure>
<p>Sans <code>--output-format</code> vous obtenez du texte : la sortie est <strong>uniquement la réponse finale</strong>, sans tool calls ni étapes intermédiaires — pratique pour coller dans la doc ou comme courte description.</p>
<p>En CI, pour écrire la conclusion de l’Agent dans un fichier :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#A5D6FF"> "Generate release notes for this version from CHANGELOG"</span><span style="color:#FF7B72"> ></span><span style="color:#A5D6FF"> release_notes.txt</span></span></code></pre></figure>
<h3 id="json--pour-scripts-et-ci">json : Pour scripts et CI</h3>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#79C0FF"> --output-format</span><span style="color:#A5D6FF"> json</span><span style="color:#A5D6FF"> "Analyze src/ dependencies and return JSON: { </span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">entry</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">: </span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">...</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">, </span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">deps</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">: [...] }"</span></span></code></pre></figure>
<p>La sortie est du JSON structuré, avec éventuellement <code>result</code>, <code>duration_ms</code> ou des champs demandés dans le prompt.<br>
En CI vous pouvez :</p>
<ul>
<li>Utiliser <code>jq</code> pour extraire des champs, vérifier le vide ou chercher des mots-clés</li>
<li>Utiliser le code de sortie et le contenu pour décider du pass/fail du job</li>
</ul>
<p>Exemple conceptuel :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#79C0FF"> --output-format</span><span style="color:#A5D6FF"> json</span><span style="color:#A5D6FF"> "Do a short code review; return {</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">ok</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">: true/false, </span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">summary</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">: </span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">...</span><span style="color:#FF7B72">\"</span><span style="color:#A5D6FF">}"</span><span style="color:#FF7B72"> |</span><span style="color:#FFA657"> jq</span><span style="color:#79C0FF"> -r</span><span style="color:#A5D6FF"> '.result'</span></span>
<span data-line=""><span style="color:#8B949E"># Then use .ok or .summary for next steps or to fail the build</span></span></code></pre></figure>
<p>Les champs exacts dépendent de la doc Cursor ; l’idée est « json pour parsing programmatique ».</p>
<h3 id="stream-json--progression-en-direct-et-suivi-des-outils">stream-json : Progression en direct et suivi des outils</h3>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#79C0FF"> --output-format</span><span style="color:#A5D6FF"> stream-json</span><span style="color:#79C0FF"> --stream-partial-output</span><span style="color:#A5D6FF"> "Analyze project and write analysis.txt"</span></span></code></pre></figure>
<ul>
<li>Chaque ligne est un événement JSON (ex. <code>system</code>, <code>assistant</code>, <code>tool_call</code>, <code>result</code>)</li>
<li><code>--stream-partial-output</code> envoie le texte de l’assistant en <strong>deltas incrémentales</strong>, pour afficher « nombre de caractères en direct » ou « % de progression »</li>
<li>Parsez tool_call started/completed pour voir quel fichier l’Agent lit/écrit et combien de temps ça prend</li>
</ul>
<p>Utile pour : runs longs, afficher « traitement du fichier N » dans les logs CI ou une UI, ou compter les tool calls et la durée.</p>
<h2 id="conseils-dintégration-ci">Conseils d’intégration CI</h2>
<table>
<thead>
<tr>
<th>Besoin</th>
<th>Suggestion</th>
</tr>
</thead>
<tbody>
<tr>
<td>Seulement « est-ce terminé et quelle est la conclusion ? »</td>
<td><code>text</code> + redirection vers fichier ou variable ; vérifier le code de sortie</td>
</tr>
<tr>
<td>Pass/fail selon le contenu</td>
<td><code>json</code> + parsing avec <code>jq</code></td>
</tr>
<tr>
<td>Log ou progression en direct</td>
<td><code>stream-json</code> + parsing ligne à ligne par type/sous-type</td>
</tr>
<tr>
<td>L’Agent doit modifier des fichiers</td>
<td>Ajoutez <code>--force</code> (voir <a href="10-headless-scripts">10-headless-scripts</a>)</td>
</tr>
<tr>
<td>Exécution en CI</td>
<td>Définissez <code>CURSOR_API_KEY</code> ; utilisez <code>--model</code> pour figer le modèle si besoin</td>
</tr>
</tbody>
</table>
<h2 id="gestion-des-échecs">Gestion des échecs</h2>
<ul>
<li>Quand l’exécution de l’Agent échoue, la CLI renvoie en général un <strong>code de sortie non nul</strong></li>
<li>Dans les scripts utilisez <code>if [ $? -ne 0 ]; then exit 1; fi</code> ou <code>set -e</code> pour que la CI échoue correctement</li>
<li>Avec json vous pouvez aussi vérifier un champ <code>error</code> ou votre <code>ok: false</code> personnalisé pour plus de sécurité</li>
</ul>
<h2 id="résumé">Résumé</h2>
<ul>
<li><strong>text</strong> : Par défaut, lisible, sortie minimale ; bon pour écrire dans un fichier ou comme description</li>
<li><strong>json</strong> : Structuré pour <code>jq</code> ou scripts ; bon pour les décisions CI et l’extraction</li>
<li><strong>stream-json</strong> + <strong>--stream-partial-output</strong> : Flux d’événements en direct ; bon pour la progression et le suivi des outils</li>
<li>En CI : définissez <code>CURSOR_API_KEY</code>, respectez le code de sortie et parsez le JSON pour pass/fail quand nécessaire</li>
</ul>

<h3 id="stream-json--progression-en-direct-et-suivi-des-outils">stream-json : Progression en direct et suivi des outils</h3>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#79C0FF"> --output-format</span><span style="color:#A5D6FF"> stream-json</span><span style="color:#79C0FF"> --stream-partial-output</span><span style="color:#A5D6FF"> "Analyze project and write analysis.txt"</span></span></code></pre></figure>
<ul>
<li>Chaque ligne est un événement JSON (ex. <code>system</code>, <code>assistant</code>, <code>tool_call</code>, <code>result</code>)</li>
<li><code>--stream-partial-output</code> envoie le texte de l’assistant en <strong>deltas incrémentales</strong>, pour afficher « nombre de caractères en direct » ou « % de progression »</li>
<li>Parsez tool_call started/completed pour voir quel fichier l’Agent lit/écrit et combien de temps ça prend</li>
</ul>
<p>Utile pour : runs longs, afficher « traitement du fichier N » dans les logs CI ou une UI, ou compter les tool calls et la durée.</p>

<h2 id="gestion-des-échecs">Gestion des échecs</h2>
<ul>
<li>Quand l’exécution de l’Agent échoue, la CLI renvoie en général un <strong>code de sortie non nul</strong></li>
<li>Dans les scripts utilisez <code>if [ $? -ne 0 ]; then exit 1; fi</code> ou <code>set -e</code> pour que la CI échoue correctement</li>
<li>Avec json vous pouvez aussi vérifier un champ <code>error</code> ou votre <code>ok: false</code> personnalisé pour plus de sécurité</li>
</ul>
<h2 id="résumé">Résumé</h2>
<ul>
<li><strong>text</strong> : Par défaut, lisible, sortie minimale ; bon pour écrire dans un fichier ou comme description</li>
<li><strong>json</strong> : Structuré pour <code>jq</code> ou scripts ; bon pour les décisions CI et l’extraction</li>
<li><strong>stream-json</strong> + <strong>--stream-partial-output</strong> : Flux d’événements en direct ; bon pour la progression et le suivi des outils</li>
<li>En CI : définissez <code>CURSOR_API_KEY</code>, respectez le code de sortie et parsez le JSON pour pass/fail quand nécessaire</li>
</ul>
