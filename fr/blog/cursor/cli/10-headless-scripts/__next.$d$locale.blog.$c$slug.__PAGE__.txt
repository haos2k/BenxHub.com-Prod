3:T2292,<p><a href="04-non-interactive">04-non-interactive</a> a couvert <code>--no-interactive</code> pour que l’Agent aille au bout sans vous attendre. Ce billet va plus loin : <strong>mode headless</strong> avec <strong><code>-p</code> / <code>--print</code></strong> pour des runs « sortie terminal uniquement », plus <strong><code>--force</code></strong> (ou <code>--yolo</code>) pour que l’Agent <strong>modifie réellement les fichiers du projet</strong> — adapté à la CI, JSDoc par lot, correction lint auto et génération de rapports.</p>
<p>En bref : <strong>pas de fenêtre Cursor, pas de confirmation clavier ; un script appelle la CLI pour modifier le code, puis le script continue.</strong></p>
<h2 id="--print--non-interactif-sortie-vers-le-terminal">--print : non interactif, sortie vers le terminal</h2>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#A5D6FF"> "What does this project do?"</span></span>
<span data-line=""><span style="color:#8B949E"># or</span></span>
<span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> --print</span><span style="color:#A5D6FF"> "List all API endpoints under src/"</span></span></code></pre></figure>
<ul>
<li><strong>Sans <code>--force</code></strong> : l’Agent peut lire les fichiers, chercher dans le code et renvoyer une analyse, mais <strong>n’écrit pas dans les fichiers</strong> — il ne fait que suggérer ou imprimer dans la sortie</li>
<li>Utile pour : Q&#x26;A, analyse, écriture de rapports vers stdout, piping ou parsing dans des scripts</li>
</ul>
<p>Donc <code>-p</code> seul signifie « exécuter jusqu’au bout, sortie vers le terminal » ; s’il modifie des fichiers dépend de l’ajout de <code>--force</code>.</p>
<h2 id="--force--autoriser-lédition-directe-des-fichiers">--force : autoriser l’édition directe des fichiers</h2>
<p>Avec <code>--print</code> et <strong><code>--force</code></strong> (ou <strong><code>--yolo</code></strong>), l’Agent <strong>peut créer, modifier et supprimer des fichiers</strong> sans demander O/N :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#79C0FF"> --force</span><span style="color:#A5D6FF"> "Refactor src/utils.js to ES6+ syntax"</span></span></code></pre></figure>
<table>
<thead>
<tr>
<th>Cas d’usage</th>
<th>Exemple</th>
</tr>
</thead>
<tbody>
<tr>
<td>Refactor d’un fichier</td>
<td><code>agent -p --force "Refactor src/foo.ts to use async/await"</code></td>
</tr>
<tr>
<td>Corriger le lint selon la config</td>
<td><code>agent -p --force "Fix all auto-fixable errors per .eslintrc"</code></td>
</tr>
<tr>
<td>JSDoc par lot</td>
<td>Voir l’exemple de script ci-dessous</td>
</tr>
<tr>
<td>Générer un fichier dans le projet</td>

</tr>
</tbody>
</table>

</blockquote>
<h2 id="exemple-de-script--jsdoc-par-lot">Exemple de script : JSDoc par lot</h2>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E">#!/bin/bash</span></span>
<span data-line=""><span style="color:#8B949E"># For each .js under src/, ask Agent to add JSDoc and write directly</span></span>
<span data-line=""><span style="color:#FFA657">find</span><span style="color:#A5D6FF"> src/</span><span style="color:#79C0FF"> -name</span><span style="color:#A5D6FF"> "*.js"</span><span style="color:#FF7B72"> |</span><span style="color:#FF7B72"> while</span><span style="color:#79C0FF"> read</span><span style="color:#79C0FF"> -r</span><span style="color:#A5D6FF"> file</span><span style="color:#E6EDF3">; </span><span style="color:#FF7B72">do</span></span>
<span data-line=""><span style="color:#79C0FF">  echo</span><span style="color:#A5D6FF"> "Processing </span><span style="color:#E6EDF3">$file</span><span style="color:#A5D6FF">..."</span></span>
<span data-line=""><span style="color:#FFA657">  cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#79C0FF"> --force</span><span style="color:#A5D6FF"> "Add full JSDoc comments to </span><span style="color:#E6EDF3">$file</span><span style="color:#A5D6FF">, editing the file in place"</span></span>
<span data-line=""><span style="color:#FF7B72">done</span></span></code></pre></figure>
<p>Chaque fichier est lu et écrit par l’Agent ; exécutez sur une copie du projet ou une branche, ou testez d’abord sur un ou deux fichiers.</p>
<h2 id="exemple-de-script--revue-de-code-auto-et-écriture-du-rapport">Exemple de script : revue de code auto et écriture du rapport</h2>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#8B949E">#!/bin/bash</span></span>
<span data-line=""><span style="color:#FFA657">cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#79C0FF"> -p</span><span style="color:#79C0FF"> --force</span><span style="color:#79C0FF"> --output-format</span><span style="color:#A5D6FF"> text</span><span style="color:#FF7B72"> \</span></span>
<span data-line=""><span style="color:#A5D6FF">  "Do a code review of recent changes: readability, potential bugs, security, best practices. Write conclusions and concrete suggestions to review.txt"</span></span></code></pre></figure>
<p><code>--output-format text</code> garde la sortie en texte brut pour écriture dans un fichier ou piping vers <code>grep</code>/scripts. Le prochain billet couvre <code>json</code> et <code>stream-json</code>.</p>
<h2 id="environnement--clé-api">Environnement : clé API</h2>
<p>Le mode headless tourne souvent là où il n’y a pas de fenêtre Cursor (ex. CI, machine distante), donc il faut l’auth :</p>
<ul>
<li>Variable d’environnement : <code>export CURSOR_API_KEY=your_key</code></li>
<li>Ou exécutez <code>cursor auth login</code> dans cet environnement d’abord (si supporté)</li>
</ul>
<p>Sans ça vous aurez des erreurs et l’Agent ne tournera pas.</p>
<h2 id="différence-avec---no-interactive-en-bref">Différence avec --no-interactive (en bref)</h2>
<table>
<thead>
<tr>
<th>Mode</th>
<th>Usage typique</th>
<th>Modifie les fichiers ?</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>--no-interactive</code></td>
<td>Run en terminal, voir la sortie pas à pas, pas de touche</td>
<td>Peut modifier, mais peut demander (selon config)</td>
</tr>
<tr>
<td><code>-p</code> / <code>--print</code></td>
<td>Scripts, CI, totalement non interactif, sortie vers stdout</td>
<td>Par défaut non</td>
</tr>
<tr>
<td><code>-p --force</code></td>
<td>Idem, mais autoriser l’Agent à modifier les fichiers</td>
<td>Oui, sans demander</td>
</tr>
</tbody>
</table>
<p>Donc : <strong>pour des scripts qui « modifient vraiment les fichiers »</strong>, utilisez <code>-p --force</code> ; pour de l’analyse ou des rapports uniquement vers le terminal, <code>-p</code> suffit.</p>
<h2 id="résumé">Résumé</h2>
<ul>
<li><strong><code>-p</code> / <code>--print</code></strong> : non interactif, sortie vers le terminal à la fin ; par défaut pas d’édition de fichiers</li>
<li><strong><code>--force</code> / <code>--yolo</code></strong> : en mode print, autoriser l’Agent à modifier les fichiers ; utile pour scripts et CI</li>
<li>En scripts/CI, définissez <code>CURSOR_API_KEY</code> ou complétez le login</li>
<li>Testez sur un petit périmètre avant de lancer sur tout le repo</li>
</ul>

<p><code>--output-format text</code> garde la sortie en texte brut pour écriture dans un fichier ou piping vers <code>grep</code>/scripts. Le prochain billet couvre <code>json</code> et <code>stream-json</code>.</p>
<h2 id="environnement--clé-api">Environnement : clé API</h2>
<p>Le mode headless tourne souvent là où il n’y a pas de fenêtre Cursor (ex. CI, machine distante), donc il faut l’auth :</p>
<ul>
<li>Variable d’environnement : <code>export CURSOR_API_KEY=your_key</code></li>
<li>Ou exécutez <code>cursor auth login</code> dans cet environnement d’abord (si supporté)</li>
</ul>
<p>Sans ça vous aurez des erreurs et l’Agent ne tournera pas.</p>
<h2 id="différence-avec---no-interactive-en-bref">Différence avec --no-interactive (en bref)</h2>
<table>
<thead>
<tr>
<th>Mode</th>
<th>Usage typique</th>
<th>Modifie les fichiers ?</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>--no-interactive</code></td>
<td>Run en terminal, voir la sortie pas à pas, pas de touche</td>
<td>Peut modifier, mais peut demander (selon config)</td>
</tr>
<tr>
<td><code>-p</code> / <code>--print</code></td>

<p>Donc : <strong>pour des scripts qui « modifient vraiment les fichiers »</strong>, utilisez <code>-p --force</code> ; pour de l’analyse ou des rapports uniquement vers le terminal, <code>-p</code> suffit.</p>
<h2 id="résumé">Résumé</h2>
<ul>
<li><strong><code>-p</code> / <code>--print</code></strong> : non interactif, sortie vers le terminal à la fin ; par défaut pas d’édition de fichiers</li>
<li><strong><code>--force</code> / <code>--yolo</code></strong> : en mode print, autoriser l’Agent à modifier les fichiers ; utile pour scripts et CI</li>
<li>En scripts/CI, définissez <code>CURSOR_API_KEY</code> ou complétez le login</li>
<li>Testez sur un petit périmètre avant de lancer sur tout le repo</li>
</ul>
