1b:T4414,<p>Écrivez un script shell qui fait que <code>cursor agent</code> corrige le code automatiquement, lance les tests, et s'ils échouent laisse l'IA corriger à nouveau — <strong>en répétant jusqu'à ce que tous les tests passent</strong>. Pas besoin de rester à appuyer sur O/N. Confiez la boucle à l'IA et allez faire autre chose — revenez quand le terminal affiche « tests passed ».</p>
<h2 id="concept-central">Concept central</h2>
<pre><code>while tests don't pass:
    run tests → collect error output
    feed error output to cursor agent
    cursor agent fixes the code
    run tests again
</code></pre>
<p>C'est une boucle « lancer les tests → échec → demander à l'IA de corriger → répéter » jusqu'au vert. Simple et direct, mais efficace.</p>
<h2 id="étape-1--vérifier-les-prérequis">Étape 1 : Vérifier les prérequis</h2>
<ul>
<li><code>cursor</code> est installé et connecté (<code>cursor --version</code> pour vérifier)</li>
<li>Le projet a une <strong>commande de test qui s'exécute dans le terminal</strong>, par exemple :
<ul>
<li><code>npm test</code></li>
<li><code>pytest</code></li>
<li><code>go test ./...</code></li>
<li><code>cargo test</code></li>
</ul>
</li>
<li>Les tests renvoient un code de sortie non nul en cas d'échec (c'est le cas par défaut pour presque tous les frameworks)</li>
</ul>

26:T4414,<p>Écrivez un script shell qui fait que <code>cursor agent</code> corrige le code automatiquement, lance les tests, et s'ils échouent laisse l'IA corriger à nouveau — <strong>en répétant jusqu'à ce que tous les tests passent</strong>. Pas besoin de rester à appuyer sur O/N. Confiez la boucle à l'IA et allez faire autre chose — revenez quand le terminal affiche « tests passed ».</p>
<h2 id="concept-central">Concept central</h2>
<pre><code>while tests don't pass:
    run tests → collect error output
    feed error output to cursor agent
    cursor agent fixes the code
    run tests again
</code></pre>
<p>C'est une boucle « lancer les tests → échec → demander à l'IA de corriger → répéter » jusqu'au vert. Simple et direct, mais efficace.</p>
<h2 id="étape-1--vérifier-les-prérequis">Étape 1 : Vérifier les prérequis</h2>
<ul>
<li><code>cursor</code> est installé et connecté (<code>cursor --version</code> pour vérifier)</li>
<li>Le projet a une <strong>commande de test qui s'exécute dans le terminal</strong>, par exemple :
<ul>
<li><code>npm test</code></li>
<li><code>pytest</code></li>
<li><code>go test ./...</code></li>
<li><code>cargo test</code></li>
</ul>
</li>
<li>Les tests renvoient un code de sortie non nul en cas d'échec (c'est le cas par défaut pour presque tous les frameworks)</li>
</ul>
<h2 id="étape-2--le-script-le-plus-simple">Étape 2 : Le script le plus simple</h2>
<p>Créez <code>debug-loop.sh</code> :</p>

<span data-line=""> </span>
<span data-line=""><span style="color:#E6EDF3">MAX_LOOPS</span><span style="color:#FF7B72">=</span><span style="color:#A5D6FF">10</span><span style="color:#8B949E">        # max iterations to prevent truly infinite loops</span></span>

<span data-line=""><span style="color:#E6EDF3">  TEST_OUTPUT</span><span style="color:#FF7B72">=</span><span style="color:#E6EDF3">$(</span><span style="color:#79C0FF">eval</span><span style="color:#A5D6FF"> "</span><span style="color:#E6EDF3">$TEST_CMD</span><span style="color:#A5D6FF">"</span><span style="color:#FF7B72"> 2>&#x26;1</span><span style="color:#E6EDF3">)</span></span>

<h2 id="étape-3--lancer-le-script">Étape 3 : Lancer le script</h2>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#0d1117;color:#e6edf3" tabindex="0" data-language="bash" data-theme="github-dark-default"><code data-language="bash" data-theme="github-dark-default" style="display: grid;"><span data-line=""><span style="color:#FFA657">chmod</span><span style="color:#A5D6FF"> +x</span><span style="color:#A5D6FF"> debug-loop.sh</span></span>

<span data-line=""><span style="color:#FF7B72">  if</span><span style="color:#E6EDF3"> [ $EXIT_CODE </span><span style="color:#FF7B72">-eq</span><span style="color:#79C0FF"> 0</span><span style="color:#E6EDF3"> ]; </span><span style="color:#FF7B72">then</span></span>
<span data-line=""><span style="color:#79C0FF">    echo</span><span style="color:#A5D6FF"> "✅ Tests passed! Completed in $((</span><span style="color:#FFA657">loop</span><span style="color:#A5D6FF"> + </span><span style="color:#79C0FF">1</span><span style="color:#A5D6FF">)) loop(s)."</span></span>
<span data-line=""><span style="color:#79C0FF">    exit</span><span style="color:#79C0FF"> 0</span></span>
<span data-line=""><span style="color:#FF7B72">  fi</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#79C0FF">  echo</span><span style="color:#A5D6FF"> "❌ Failed. Log saved to </span><span style="color:#E6EDF3">$LOG_FILE</span><span style="color:#A5D6FF">"</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#FFA657">  cursor</span><span style="color:#A5D6FF"> agent</span><span style="color:#A5D6FF"> "Tests failed with the following errors. Please fix the code to make the tests pass:</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#E6EDF3">$TEST_OUTPUT</span><span style="color:#A5D6FF">"</span><span style="color:#79C0FF"> --model</span><span style="color:#A5D6FF"> gpt-codex-5.3-high</span><span style="color:#79C0FF"> --no-interactive</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#E6EDF3">  loop</span><span style="color:#FF7B72">=</span><span style="color:#E6EDF3">$((</span><span style="color:#FFA657">loop</span><span style="color:#A5D6FF"> +</span><span style="color:#79C0FF"> 1</span><span style="color:#E6EDF3">))</span></span>
<span data-line=""><span style="color:#FF7B72">done</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#79C0FF">echo</span><span style="color:#A5D6FF"> "⚠️  Reached max loops. Stopping. Check the logs in </span><span style="color:#E6EDF3">$LOG_DIR</span><span style="color:#A5D6FF">/."</span></span>
<span data-line=""><span style="color:#79C0FF">exit</span><span style="color:#79C0FF"> 1</span></span></code></pre></figure>
<p>Utile pour revoir « ce qui a échoué à quelle itération » après coup.</p>
<h2 id="points-de-vigilance">Points de vigilance</h2>
<table>
<thead>
<tr>
<th>Risque</th>
<th>Comment limiter</th>
</tr>
</thead>
<tbody>
<tr>
<td>L'IA casse plus de fichiers</td>
<td>Faites un <code>git commit</code> avant pour figer l'état, <code>git checkout .</code> pour revenir en arrière si besoin</td>
</tr>
<tr>
<td>Trop de boucles consomment le quota</td>
<td>Fixez un <code>MAX_LOOPS</code> raisonnable (5–15 recommandé)</td>
</tr>
<tr>
<td>L'IA modifie les fichiers de test</td>
<td>Dites explicitement dans le prompt « do not modify test files »</td>
</tr>
<tr>
<td>Échecs différents à chaque boucle</td>
<td>Gardez les logs (version améliorée) pour analyser après</td>
</tr>
</tbody>
</table>
<h2 id="résumé">Résumé</h2>
<ol>
<li><strong>Structure du script</strong> : lancer les tests → échec → donner la sortie à l'IA → répéter jusqu'à succès ou limite</li>
<li><strong>Paramètres clés</strong> : <code>TEST_CMD</code> (commande de test), <code>MAX_LOOPS</code> (nombre max d'itérations)</li>
<li><strong>Soyez précis dans le prompt</strong> : indiquez le langage, restreignez les répertoires à modifier, ne pas toucher aux tests</li>
<li><strong>Faites un <code>git commit</code> avant</strong> — facile de revenir en arrière si ça dérape, et l'esprit tranquille</li>
</ol>
