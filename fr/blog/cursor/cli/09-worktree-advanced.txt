1b:T2ca9,<p>Le billet précédent <a href="08-worktree-merge">08-worktree-merge</a> couvrait le worktree automatique de Cursor et l’Apply. Celui-ci va plus loin sur deux points : <strong>Best-of-N</strong> (même prompt, plusieurs modèles en parallèle, puis vous en choisissez un à Apply) et <strong>worktrees.json</strong> (installer les deps, lancer les migrations, copier <code>.env</code> à la création d’un worktree).</p>
<h2 id="best-of-n--un-prompt-plusieurs-modèles-à-la-fois">Best-of-N : un prompt, plusieurs modèles à la fois</h2>
<p><strong>Best-of-N</strong> signifie : vous envoyez une tâche, Cursor lance <strong>plusieurs modèles</strong> dans des worktrees séparés et vous obtenez plusieurs « cartes », chacune avec les changements d’un modèle — <strong>choisissez-en une et faites Apply</strong>.</p>
<h3 id="quand-utiliser-best-of-n-">Quand utiliser Best-of-N ?</h3>
<table>
<thead>
<tr>
<th>Situation</th>
<th>Pourquoi ça aide</th>
</tr>
</thead>
<tbody>
<tr>
<td>Pas sûr du modèle qui convient le mieux à votre codebase</td>
<td>Lancez une fois, comparez les sorties, petit benchmark</td>
</tr>
<tr>
<td>Problème difficile, un seul modèle peut rater des edge cases</td>
<td>Modèles différents, approches différentes, plus de couverture</td>
</tr>
<tr>
<td>Comparer la qualité du code</td>
<td>Même requête, style et structure différents côte à côte</td>
</tr>
<tr>
<td>Tâche difficile, vous voulez plus de succès « du premier coup »</td>
<td>Plusieurs modèles essaient une fois chacun, Apply le meilleur</td>
</tr>
</tbody>
</table>
<p>En bref : <strong>plusieurs modèles font la même tâche, vous en choisissez un</strong> — surtout pour les tâches difficiles ou quand la qualité compte.</p>
<h3 id="comment-lutiliser">Comment l’utiliser</h3>
<p>Dans Cursor, au démarrage d’un Agent, choisissez « plusieurs modèles » ou l’option Best-of-N (selon l’UI actuelle). Après l’envoi du prompt vous verrez plusieurs cartes ; naviguez entre elles pour comparer puis <strong>Apply</strong> celle que vous voulez sur main.</p>
<p>Si vous appliquez plus d’une carte du même run Best-of-N (ex. Apply A puis B), Cursor peut demander : <strong>merge avec résolution de conflits</strong> ou <strong>Full Overwrite</strong> (remplacer tout le fichier).</p>
<h2 id="worktreesjson--préparer-lenvironnement-à-la-création-dun-worktree">worktrees.json : préparer l’environnement à la création d’un worktree</h2>
<p>Quand Cursor crée un worktree, il copie par défaut les <strong>fichiers suivis</strong> du répertoire principal mais n’installe pas les deps, ne copie pas <code>.env</code> ni n’exécute les migrations DB.<br>
Avec <strong><code>.cursor/worktrees.json</code></strong> vous pouvez indiquer <strong>des commandes à exécuter après chaque nouveau worktree</strong>, ex. <code>npm ci</code>, <code>cp .env</code>, <code>npm run db:migrate</code>.</p>
<h3 id="où-se-trouve-la-config-">Où se trouve la config ?</h3>
<p>Cursor cherche dans l’ordre :</p>
<ol>
<li>Racine du projet : <code>.cursor/worktrees.json</code></li>
<li>Chemin du worktree</li>
</ol>
<p>En général on la met à la <strong>racine du projet</strong> : <code>.cursor/worktrees.json</code>.</p>
<h3 id="trois-clés-de-config">Trois clés de config</h3>
<table>
<thead>
<tr>
<th>Clé</th>
<th>Description</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>setup-worktree</code></td>
<td>Générique ; utilisé sur tous les OS si aucune clé spécifique n’est définie</td>
</tr>
<tr>
<td><code>setup-worktree-windows</code></td>
<td>Windows uniquement ; remplace <code>setup-worktree</code></td>
</tr>
<tr>
<td><code>setup-worktree-unix</code></td>
<td>macOS / Linux uniquement ; remplace <code>setup-worktree</code></td>
</tr>
</tbody>
</table>
<p>Chaque clé peut être :</p>
<ul>
<li><strong>String</strong> : chemin vers un script (relatif au répertoire contenant <code>.cursor/worktrees.json</code>)</li>
<li><strong>Array</strong> : liste de commandes shell, exécutées dans l’ordre</li>
</ul>

Sous Windows utilisez <code>.ps1</code> et dans le script <code>$env:ROOT_WORKTREE_PATH</code> pour le chemin du répertoire principal.</p>
<blockquote>
<p>Astuce : évitez de symlinker les deps dans le worktree — ça peut entrer en conflit avec le worktree principal ; utilisez <code>npm ci</code>, <code>pnpm</code>, <code>bun</code>, <code>uv</code>, etc. pour une installation fraîche.</p>
</blockquote>
<h2 id="nettoyage-et-limites-des-worktrees">Nettoyage et limites des worktrees</h2>
<p>Cursor gère le nombre de worktrees pour ne pas saturer le disque :</p>
<ul>
<li>Chaque workspace a un <strong>nombre max de worktrees</strong> (ex. 20)</li>
<li>Au-delà, les <strong>moins récemment utilisés</strong> sont supprimés</li>
<li>Le nettoyage est <strong>par workspace</strong> ; les repos différents ne s’impactent pas</li>
</ul>
<p>Pour ajuster (si votre version de Cursor le permet), cherchez des paramètres du type :</p>
<ul>
<li><code>cursor.worktreeMaxCount</code> : nombre max de worktrees à garder</li>
<li><code>cursor.worktreeCleanupIntervalHours</code> : fréquence du nettoyage</li>
</ul>
<p>Les noms exacts dépendent de la config actuelle de Cursor.</p>
<h2 id="déboguer-le-setup-worktree">Déboguer le setup worktree</h2>
<p>Si après création d’un worktree les deps ne sont pas installés ou les migrations pas exécutées, ouvrez le panneau <strong>Output</strong> de Cursor, choisissez <strong>« Worktrees Setup »</strong> dans la liste et consultez les commandes et erreurs exécutées à la création — utile pour déboguer <code>worktrees.json</code> ou les scripts.</p>
<h2 id="résumé">Résumé</h2>
<ul>
<li><strong>Best-of-N</strong> : Même prompt, plusieurs modèles en parallèle dans des worktrees séparés ; comparez et Apply une carte ; utile pour benchmark, tâches difficiles et qualité</li>
<li><strong>worktrees.json</strong> : Dans <code>.cursor/worktrees.json</code> utilisez <code>setup-worktree</code> / <code>setup-worktree-windows</code> / <code>setup-worktree-unix</code> pour exécuter des commandes ou scripts après création</li>
<li>Utilisez <code>$ROOT_WORKTREE_PATH</code> (Unix) ou <code>%ROOT_WORKTREE_PATH%</code> / <code>$env:ROOT_WORKTREE_PATH</code> (Windows) pour copier <code>.env</code> etc. depuis main</li>
<li>Les worktrees ont une limite et un nettoyage auto ; débogage via Output → Worktrees Setup</li>
</ul>

26:T2ca9,<p>Le billet précédent <a href="08-worktree-merge">08-worktree-merge</a> couvrait le worktree automatique de Cursor et l’Apply. Celui-ci va plus loin sur deux points : <strong>Best-of-N</strong> (même prompt, plusieurs modèles en parallèle, puis vous en choisissez un à Apply) et <strong>worktrees.json</strong> (installer les deps, lancer les migrations, copier <code>.env</code> à la création d’un worktree).</p>
<h2 id="best-of-n--un-prompt-plusieurs-modèles-à-la-fois">Best-of-N : un prompt, plusieurs modèles à la fois</h2>
<p><strong>Best-of-N</strong> signifie : vous envoyez une tâche, Cursor lance <strong>plusieurs modèles</strong> dans des worktrees séparés et vous obtenez plusieurs « cartes », chacune avec les changements d’un modèle — <strong>choisissez-en une et faites Apply</strong>.</p>
<h3 id="quand-utiliser-best-of-n-">Quand utiliser Best-of-N ?</h3>
<table>
<thead>
<tr>
<th>Situation</th>
<th>Pourquoi ça aide</th>
</tr>
</thead>
<tbody>
<tr>
<td>Pas sûr du modèle qui convient le mieux à votre codebase</td>
<td>Lancez une fois, comparez les sorties, petit benchmark</td>
</tr>
<tr>
<td>Problème difficile, un seul modèle peut rater des edge cases</td>
<td>Modèles différents, approches différentes, plus de couverture</td>
</tr>
<tr>
<td>Comparer la qualité du code</td>
<td>Même requête, style et structure différents côte à côte</td>
</tr>
<tr>
<td>Tâche difficile, vous voulez plus de succès « du premier coup »</td>
<td>Plusieurs modèles essaient une fois chacun, Apply le meilleur</td>
</tr>
</tbody>
</table>
<p>En bref : <strong>plusieurs modèles font la même tâche, vous en choisissez un</strong> — surtout pour les tâches difficiles ou quand la qualité compte.</p>
<h3 id="comment-lutiliser">Comment l’utiliser</h3>
<p>Dans Cursor, au démarrage d’un Agent, choisissez « plusieurs modèles » ou l’option Best-of-N (selon l’UI actuelle). Après l’envoi du prompt vous verrez plusieurs cartes ; naviguez entre elles pour comparer puis <strong>Apply</strong> celle que vous voulez sur main.</p>
<p>Si vous appliquez plus d’une carte du même run Best-of-N (ex. Apply A puis B), Cursor peut demander : <strong>merge avec résolution de conflits</strong> ou <strong>Full Overwrite</strong> (remplacer tout le fichier).</p>
<h2 id="worktreesjson--préparer-lenvironnement-à-la-création-dun-worktree">worktrees.json : préparer l’environnement à la création d’un worktree</h2>
<p>Quand Cursor crée un worktree, il copie par défaut les <strong>fichiers suivis</strong> du répertoire principal mais n’installe pas les deps, ne copie pas <code>.env</code> ni n’exécute les migrations DB.<br>
Avec <strong><code>.cursor/worktrees.json</code></strong> vous pouvez indiquer <strong>des commandes à exécuter après chaque nouveau worktree</strong>, ex. <code>npm ci</code>, <code>cp .env</code>, <code>npm run db:migrate</code>.</p>
<h3 id="où-se-trouve-la-config-">Où se trouve la config ?</h3>
<p>Cursor cherche dans l’ordre :</p>
<ol>
<li>Racine du projet : <code>.cursor/worktrees.json</code></li>
<li>Chemin du worktree</li>
</ol>
<p>En général on la met à la <strong>racine du projet</strong> : <code>.cursor/worktrees.json</code>.</p>
<h3 id="trois-clés-de-config">Trois clés de config</h3>
<table>
<thead>
<tr>
<th>Clé</th>
<th>Description</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>setup-worktree</code></td>
<td>Générique ; utilisé sur tous les OS si aucune clé spécifique n’est définie</td>
</tr>
<tr>
<td><code>setup-worktree-windows</code></td>
<td>Windows uniquement ; remplace <code>setup-worktree</code></td>
</tr>
<tr>
<td><code>setup-worktree-unix</code></td>
<td>macOS / Linux uniquement ; remplace <code>setup-worktree</code></td>
</tr>
</tbody>
</table>
<p>Chaque clé peut être :</p>
<ul>
<li><strong>String</strong> : chemin vers un script (relatif au répertoire contenant <code>.cursor/worktrees.json</code>)</li>
<li><strong>Array</strong> : liste de commandes shell, exécutées dans l’ordre</li>
</ul>

<h3 id="plus-complexe--utiliser-des-scripts">Plus complexe : utiliser des scripts</h3>
<p>Pour beaucoup de commandes ou de logique, utilisez un script et référencez-le dans <code>worktrees.json</code> :</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="json" data-theme="github-dark"><code data-language="json" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#E1E4E8">{</span></span>
<span data-line=""><span style="color:#79B8FF">  "setup-worktree-unix"</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">"setup-worktree-unix.sh"</span><span style="color:#E1E4E8">,</span></span>
<span data-line=""><span style="color:#79B8FF">  "setup-worktree-windows"</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">"setup-worktree-windows.ps1"</span><span style="color:#E1E4E8">,</span></span>
<span data-line=""><span style="color:#79B8FF">  "setup-worktree"</span><span style="color:#E1E4E8">: [</span><span style="color:#9ECBFF">"echo 'Using generic fallback'"</span><span style="color:#E1E4E8">]</span></span>
<span data-line=""><span style="color:#E1E4E8">}</span></span></code></pre></figure>
<p>Placez les scripts sous <code>.cursor/</code>, ex. <code>.cursor/setup-worktree-unix.sh</code>, avec <code>npm ci</code>, copie de <code>.env</code>, <code>chmod</code>, migrations, etc.<br>
Sous Windows utilisez <code>.ps1</code> et dans le script <code>$env:ROOT_WORKTREE_PATH</code> pour le chemin du répertoire principal.</p>
<blockquote>
<p>Astuce : évitez de symlinker les deps dans le worktree — ça peut entrer en conflit avec le worktree principal ; utilisez <code>npm ci</code>, <code>pnpm</code>, <code>bun</code>, <code>uv</code>, etc. pour une installation fraîche.</p>
</blockquote>
<h2 id="nettoyage-et-limites-des-worktrees">Nettoyage et limites des worktrees</h2>
<p>Cursor gère le nombre de worktrees pour ne pas saturer le disque :</p>
<ul>
<li>Chaque workspace a un <strong>nombre max de worktrees</strong> (ex. 20)</li>
<li>Au-delà, les <strong>moins récemment utilisés</strong> sont supprimés</li>
<li>Le nettoyage est <strong>par workspace</strong> ; les repos différents ne s’impactent pas</li>
</ul>
<p>Pour ajuster (si votre version de Cursor le permet), cherchez des paramètres du type :</p>
<ul>
<li><code>cursor.worktreeMaxCount</code> : nombre max de worktrees à garder</li>
<li><code>cursor.worktreeCleanupIntervalHours</code> : fréquence du nettoyage</li>
</ul>
<p>Les noms exacts dépendent de la config actuelle de Cursor.</p>
<h2 id="déboguer-le-setup-worktree">Déboguer le setup worktree</h2>
<p>Si après création d’un worktree les deps ne sont pas installés ou les migrations pas exécutées, ouvrez le panneau <strong>Output</strong> de Cursor, choisissez <strong>« Worktrees Setup »</strong> dans la liste et consultez les commandes et erreurs exécutées à la création — utile pour déboguer <code>worktrees.json</code> ou les scripts.</p>
<h2 id="résumé">Résumé</h2>
<ul>
<li><strong>Best-of-N</strong> : Même prompt, plusieurs modèles en parallèle dans des worktrees séparés ; comparez et Apply une carte ; utile pour benchmark, tâches difficiles et qualité</li>
<li><strong>worktrees.json</strong> : Dans <code>.cursor/worktrees.json</code> utilisez <code>setup-worktree</code> / <code>setup-worktree-windows</code> / <code>setup-worktree-unix</code> pour exécuter des commandes ou scripts après création</li>
<li>Utilisez <code>$ROOT_WORKTREE_PATH</code> (Unix) ou <code>%ROOT_WORKTREE_PATH%</code> / <code>$env:ROOT_WORKTREE_PATH</code> (Windows) pour copier <code>.env</code> etc. depuis main</li>
<li>Les worktrees ont une limite et un nettoyage auto ; débogage via Output → Worktrees Setup</li>
</ul>
