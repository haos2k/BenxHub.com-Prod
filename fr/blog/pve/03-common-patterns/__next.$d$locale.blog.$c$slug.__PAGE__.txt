3:T20e1,<p>Cet article se concentre sur <strong>les cinq opérations quotidiennes les plus courantes</strong>, avec des modèles pratiques utilisables tout de suite. Maîtrisez ces modèles et vous gérerez 80 % des scénarios — les 20 % restants sont pour la section avancée.</p>
<h2 id="modèle-1--sauvegarder-une-machine-virtuelle">Modèle 1 : Sauvegarder une machine virtuelle</h2>
<p>Objectif : conserver une sauvegarde périodique permettant une restauration — ainsi si ça casse, vous ne repartez pas de zéro.</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># Sauvegarde manuelle de la VM 100 vers local (mode snapshot — la VM reste en marche)</span></span>
<span data-line=""><span style="color:#B392F0">vzdump</span><span style="color:#79B8FF"> 100</span><span style="color:#79B8FF"> --storage</span><span style="color:#9ECBFF"> local</span><span style="color:#79B8FF"> --mode</span><span style="color:#9ECBFF"> snapshot</span><span style="color:#79B8FF"> --compress</span><span style="color:#9ECBFF"> zstd</span></span></code></pre></figure>
<p>Planifiez-la dans : <code>Datacenter -> Sauvegarde -> Ajouter</code>, définissez une heure (ex. 02:00 quotidien). Configurez et oubliez.</p>
<blockquote>
<p>Le mode <code>snapshot</code> permet de sauvegarder pendant que la VM tourne — comme photographier un chat qui dort sans le réveiller.</p>
</blockquote>
<h2 id="modèle-2--cloner-une-machine-virtuelle">Modèle 2 : Cloner une machine virtuelle</h2>
<p>Objectif : copier rapidement un environnement existant sans réinstaller from scratch.</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># Clone complet (disque indépendant, entièrement autonome)</span></span>
<span data-line=""><span style="color:#B392F0">qm</span><span style="color:#9ECBFF"> clone</span><span style="color:#79B8FF"> 100</span><span style="color:#79B8FF"> 101</span><span style="color:#79B8FF"> --name</span><span style="color:#9ECBFF"> clone-vm</span><span style="color:#79B8FF"> --full</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># Clone lié (partage le disque de base, économise l'espace)</span></span>
<span data-line=""><span style="color:#B392F0">qm</span><span style="color:#9ECBFF"> clone</span><span style="color:#79B8FF"> 100</span><span style="color:#79B8FF"> 102</span><span style="color:#79B8FF"> --name</span><span style="color:#9ECBFF"> linked-clone</span><span style="color:#79B8FF"> --linked</span></span></code></pre></figure>
<p>Différence en une phrase : <strong>full</strong> = indépendant, prend de l'espace ; <strong>linked</strong> = économise l'espace, mais dépend du disque parent. Ne supprimez pas le disque parent — les clones liés casseront avec lui.</p>
<h2 id="modèle-3--migration-à-chaud">Modèle 3 : Migration à chaud</h2>
<p>Objectif : déplacer une VM vers un autre nœud sans l'arrêter — pas d'interruption de service.</p>
<p>Prérequis : le nœud cible doit pouvoir accéder au <strong>même disque</strong> (stockage partagé idéal).</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#B392F0">qm</span><span style="color:#9ECBFF"> migrate</span><span style="color:#79B8FF"> 100</span><span style="color:#F97583"> &#x3C;</span><span style="color:#9ECBFF">nœud-cibl</span><span style="color:#E1E4E8">e</span><span style="color:#F97583">></span><span style="color:#79B8FF"> --live</span></span></code></pre></figure>
<blockquote>
<p>Si le disque est sur <code>local</code>, il faut généralement migrer le disque d'abord ou passer au stockage partagé — sinon migrate vous dira « je ne trouve pas le disque ».</p>
</blockquote>
<h2 id="modèle-4--créer-un-conteneur-lxc">Modèle 4 : Créer un conteneur LXC</h2>
<p>Objectif : lancer rapidement un environnement Linux léger pour faire tourner un service — utilise moins de ressources qu'une VM.</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># Mettre à jour la liste des modèles d'abord</span></span>
<span data-line=""><span style="color:#B392F0">pveam</span><span style="color:#9ECBFF"> update</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># Télécharger le modèle Debian</span></span>
<span data-line=""><span style="color:#B392F0">pveam</span><span style="color:#9ECBFF"> download</span><span style="color:#9ECBFF"> local</span><span style="color:#9ECBFF"> debian-12-standard_12.2-1_amd64.tar.zst</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># Créer le conteneur</span></span>
<span data-line=""><span style="color:#B392F0">pct</span><span style="color:#9ECBFF"> create</span><span style="color:#79B8FF"> 200</span><span style="color:#9ECBFF"> local:vztmpl/debian-12-standard_12.2-1_amd64.tar.zst</span><span style="color:#79B8FF"> \</span></span>
<span data-line=""><span style="color:#79B8FF">  --hostname</span><span style="color:#9ECBFF"> my-app</span><span style="color:#79B8FF"> \</span></span>
<span data-line=""><span style="color:#79B8FF">  --memory</span><span style="color:#79B8FF"> 512</span><span style="color:#79B8FF"> \</span></span>
<span data-line=""><span style="color:#79B8FF">  --cores</span><span style="color:#79B8FF"> 1</span><span style="color:#79B8FF"> \</span></span>
<span data-line=""><span style="color:#79B8FF">  --net0</span><span style="color:#9ECBFF"> name=eth0,bridge=vmbr0,ip=dhcp</span><span style="color:#79B8FF"> \</span></span>
<span data-line=""><span style="color:#79B8FF">  --rootfs</span><span style="color:#9ECBFF"> local-lvm:8</span></span></code></pre></figure>
<p>LXC démarre vite et consomme peu — idéal pour faire tourner beaucoup de petits services. Comme une portée de loutres, chacune avec très peu de surcoût.</p>
<h2 id="modèle-5--snapshots-et-retour-arrière">Modèle 5 : Snapshots et retour arrière</h2>
<p>Objectif : avant une mise à jour majeure ou un changement de configuration, laisser un point de restauration auquel « revenir ».</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># Créer un snapshot</span></span>
<span data-line=""><span style="color:#B392F0">qm</span><span style="color:#9ECBFF"> snapshot</span><span style="color:#79B8FF"> 100</span><span style="color:#9ECBFF"> before-update</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># Quelque chose s'est mal passé ? Retour arrière</span></span>
<span data-line=""><span style="color:#B392F0">qm</span><span style="color:#9ECBFF"> rollback</span><span style="color:#79B8FF"> 100</span><span style="color:#9ECBFF"> before-update</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># Tout va bien ? Supprimer le snapshot</span></span>
<span data-line=""><span style="color:#B392F0">qm</span><span style="color:#9ECBFF"> delsnapshot</span><span style="color:#79B8FF"> 100</span><span style="color:#9ECBFF"> before-update</span></span></code></pre></figure>
<p>Prenez l'habitude de faire un snapshot avant les opérations majeures : snapshot d'abord, puis agir. Le temps de débogage économisé pourra être consacré à mieux.</p>

<h2 id="modèle-5--snapshots-et-retour-arrière">Modèle 5 : Snapshots et retour arrière</h2>
<p>Objectif : avant une mise à jour majeure ou un changement de configuration, laisser un point de restauration auquel « revenir ».</p>
<figure data-rehype-pretty-code-figure=""><pre style="background-color:#24292e;color:#e1e4e8" tabindex="0" data-language="bash" data-theme="github-dark"><code data-language="bash" data-theme="github-dark" style="display: grid;"><span data-line=""><span style="color:#6A737D"># Créer un snapshot</span></span>
<span data-line=""><span style="color:#B392F0">qm</span><span style="color:#9ECBFF"> snapshot</span><span style="color:#79B8FF"> 100</span><span style="color:#9ECBFF"> before-update</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># Quelque chose s'est mal passé ? Retour arrière</span></span>
<span data-line=""><span style="color:#B392F0">qm</span><span style="color:#9ECBFF"> rollback</span><span style="color:#79B8FF"> 100</span><span style="color:#9ECBFF"> before-update</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#6A737D"># Tout va bien ? Supprimer le snapshot</span></span>
<span data-line=""><span style="color:#B392F0">qm</span><span style="color:#9ECBFF"> delsnapshot</span><span style="color:#79B8FF"> 100</span><span style="color:#9ECBFF"> before-update</span></span></code></pre></figure>
<p>Prenez l'habitude de faire un snapshot avant les opérations majeures : snapshot d'abord, puis agir. Le temps de débogage économisé pourra être consacré à mieux.</p>
